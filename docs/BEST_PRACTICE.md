# Best Practices

**English** · [中文](BEST_PRACTICE.zh.md)

Working conventions for None-Curve. Follow these when changing the app or its documentation.

## App language

- **The web app UI is English only.** No Chinese (or other CJK) text anywhere a user can see or hear it: visible text, button labels, placeholders, `title`, `aria-label`, `alt`, error messages, and the page `<title>`.
- Keep all source under `src/` in English, including code comments, so the rule can be checked mechanically.

Check before committing (should print nothing):

```bash
grep -rnP '[\x{3000}-\x{9fff}\x{ff00}-\x{ffef}]' src index.html
```

## Documentation language

- Every document has **separate English and Chinese editions**; never mix both languages in one file.
- English is the default: `NAME.md` is English, `NAME.zh.md` is Chinese.
- Each edition starts with a language switch linking to the other, for example `**English** · [中文](NAME.zh.md)`.
- When you change one edition, update the other in the same change so they stay in step.
- In Chinese documents, refer to interface elements by their English labels (the UI is English), with a Chinese explanation where helpful.

Current pairs: `README.md` / `README.zh.md`, `docs/USER_GUIDE.md` / `docs/USER_GUIDE.zh.md`, `docs/PRD.md` / `docs/PRD.zh.md`, `docs/PHASE.md` / `docs/PHASE.zh.md`, `docs/BEST_PRACTICE.md` / `docs/BEST_PRACTICE.zh.md`, `docs/EXPERIMENTAL_PLAN.md` / `docs/EXPERIMENTAL_PLAN.zh.md`, `docs/SOUND_PLAN.md` / `docs/SOUND_PLAN.zh.md`.

## Tests

- Tests live in `tests/`, by area (`tests/geometry`, `tests/export`, `tests/font`, `tests/sound`, `tests/specimen`, `tests/state`, `tests/worker`, and `tests/scripts` for the Jira sync in `scripts/`); slow ones go in `tests/slow`.
- `npm test` runs the fast suite (about 15 s). `npm run test:slow` runs the slow one (the whole 42 s Sound test track, and every glyph of both fixture fonts; about 5 minutes); it runs only when asked for by name.
- `npm run build` type-checks the tests and scripts as well (`tsconfig.test.json`).
- `npm run lint` runs ESLint (`eslint.config.js`): the recommended JavaScript, TypeScript and React hooks rules, except three React Compiler checks that flag this code's established patterns (the config says which and why). A leading underscore marks a name left unused on purpose. A hook dependency left out on purpose gets `// eslint-disable-next-line react-hooks/exhaustive-deps`, with the reason in a comment on the line above; other rules are not switched off line by line without such a reason.
- Layout is Prettier's (`.prettierrc.json`: no semicolons, single quotes, 120 columns): run `npm run format` before committing. It formats code and config only; Markdown, YAML and JSON are kept as written (`.prettierignore`). The commit that first formatted everything is listed in `.git-blame-ignore-revs` (`git config blame.ignoreRevsFile .git-blame-ignore-revs` makes `git blame` skip it).
- Run `npm run lint`, `npm run format:check` and `npm test` before opening a pull request into `develop`. CI runs `npm run lint`, `npm run format:check`, `npm test` and `npm run build` on every pull request into `develop` and every push to it, and the Pages deploy runs `npm test` before it builds.
- Fixture fonts are open-licensed only (OFL: STIX Two Text and Roboto), each with its `OFL-*.txt` beside it in `tests/fixtures/fonts`. Never add a font that may not be redistributed.
- A test that finds a bug in `src/` stays in, as `it.skip` with a `BUG:` comment that says what is wrong, until the bug is fixed.
- Generated files are not committed. The Sound test track is rendered by `npm run test-track` (from `scripts/test-track.ts`) into `test-audio/sound-test.wav`, which git ignores; a test checks that it renders the same samples every time.
- Code that needs browser APIs the tests cannot run (MediaRecorder, canvas capture, Web Audio, tab visibility) is split into pure modules and a controller that receives those APIs as injected dependencies, with a thin page singleton on top. The video recorder is the model: `RecordingController` (`src/export/recorder.ts`) takes its clock and timers, the sound engine, the canvas, MediaRecorder, the tab's visibility, and `save` as `RecorderDeps`, and `tests/export/recorder.test.ts` drives every take through fakes of them, so nothing touches the DOM. Canvas drawing takes a painter (`src/export/drawArtboard.ts`), so a recording fake checks it against the SVG export.
- Never make a real download. Tests pass a fake `save` (or another injected sink) and never call `downloadFile`. A browser check that exports or records first stubs `HTMLAnchorElement.prototype.click` to collect the link instead of following it, and keeps `URL.revokeObjectURL` a no-op so the collected blob can still be read.
- `tests/sound/neutral.test.ts` pins Sound with the Response settings at their neutral values (Strength 100%, Motion contrast, Pitch reactive, and Melody tracking 0) to its outputs at commit 4a54e5d, before those settings existed: exact, except the analyser's readings, which it hashes to 10 significant digits (see the next point). The live scheduler's hash leaves out the presets whose start turns Thorn on (Flare): Thorn turns change their live frames on purpose, and `tests/sound/turns.test.ts` tests Flare instead. Never edit the test, its hashes included: when it fails, a change has reached the neutral path, so fix the change. The only exceptions are a pin taken again from an export of 4a54e5d (as for the readings, and for the scheduler without Flare, `32a8121b`), and, for an intended change that moves every live value (Crumple losing Detail in NOCUR-60, the finer slider steps in NOCUR-63), a pin from the new code taken only after proving that undoing just that change gives the old hashes back, recorded in a comment beside the hash.
- Hash numbers that come from `Math` functions (`log`, `exp`, `sin`, and the like) rounded, not exact. V8's x64 and arm64 builds can differ in their last bit (`Math.log2` and `Math.log10` do), and CI runs on Linux x64 while a Mac with Apple silicon is arm64, so an exact hash pinned on one fails on the other. `neutral.test.ts` rounds such numbers to 10 significant digits, which both agree on and which still catches a change of one part in ten million. Pin a hash only after checking it on both, for example with the official x64 build of Node under Rosetta.
- Count flashes the way the screen shows them. `lettersOnScreen` in `tests/sound/flash.test.ts` counts a move between levels from any frame shown within the last 250 ms (`SPREAD_MS`, the same span as `LIVE_LIMITS.switchSpanMs`), and a frame's changes once, so a change that reaches the screen over several frames counts once and one spread thinly over frames is not missed.
- Check Sound in the browser with the tab visible. The sound is read on `requestAnimationFrame`, so a hidden or covered tab (a hidden browser pane included) gets no frames or only bursts of them, and the letters stop following the sound; "Live · N fps" shows the geometry rate, not how often the sound is read, so it does not reveal this.

## Branches, pull requests, and Jira

- Work happens on a branch `feature/NOCUR-<number>-<short-name>` off `develop`, named after the Jira issue it does (NOCUR is the project's key), and is merged into `develop` by a pull request. `main` is the release branch: a pull request from `develop` into `main` releases, and every push to `main` deploys Pages.
- `.github/workflows/jira.yml` (`scripts/jira-pr-sync.ts`) moves the issues a pull request names: to In Progress while it is open (when it opens, reopens, gets a push, or is edited), to Done when it merges. A pull request names an issue by its key in the branch name, the title, or the keys that start a line of the body beginning with `Jira:` (`Jira: NOCUR-57, NOCUR-58`). That line ends at its first word that is not a key, so `Jira: NOCUR-60 (split from NOCUR-41)` names NOCUR-60 only, and a key anywhere else in the body, such as a parent mentioned in passing, does not count.
- Issues only move forward. Opening moves only an issue still in To Do, so one already in In Progress, In Review, or Done stays where it is; merging moves any issue not yet done; a pull request closed without merging moves nothing. An issue is done when its pull request merges into `develop`, not when it is released; a release pull request names no issue and moves none.
- Put the key in the branch name or the title when the pull request opens; one added later moves its issue at the next push or edit. GitHub runs no workflow for a pull request that conflicts with its base, so its issue moves once the conflict is resolved and pushed.
- Issues move only through pull requests. By hand, update an issue's description, and after each release add its date and pull request to the release record, NOCUR-28.
- The workflow reads three repository secrets: `JIRA_BASE_URL` (`https://<site>.atlassian.net`), `JIRA_EMAIL`, and `JIRA_API_TOKEN`, an Atlassian API token of that account (the moves are recorded under its name). Without them it only warns, so the check never fails for want of them; GitHub gives no secrets to a pull request from a fork, so the issues of one are moved by hand. It first checks the account with Jira, because Jira answers a token that has expired or been revoked as if no one were signed in, and every issue would look unknown: the check fails instead, and the fix is a new token in `JIRA_API_TOKEN` and a re-run of the failed job. It also fails when Jira refuses a call or cannot be reached, or when `JIRA_BASE_URL` is not an `https` address, and warns for a key Jira does not know. The site's address is masked in the log.
- The script reads the pull request from the event file, never from text placed in a shell command, so a title or body cannot run anything.

## Geometry and the workers

- Glyph geometry is computed only in the geometry worker (`src/geometry/geometry.worker.ts`, its logic in `workerCore.ts`), never on the page. The canvas, the text preview, live Sound frames, and SVG and PNG export all ask the page's client (`src/state/geometryClient.ts`): exports through `ensure()`, live frames through `prefetchJobs()`. Do not add a main-thread fallback; when the worker cannot run, the canvas says so and asks for a reload.
- The page never imports an effect module or the pipeline, not even for a constant: whatever a page module imports is bundled into the page, the whole module with it. The effects' limits and fallbacks and the cheap readers of their settings (on or off, folds, sizes) live in `src/geometry/limits.ts`, which the effects import too; the cache key in `src/geometry/paramsKey.ts`; what the export dialog needs before a font build in `src/export/fontPlan.ts`. The page loads the font build (`src/export/fontFile.ts`, which runs the pipeline) only for a build that cannot run in its worker, and the export dialog's body (`ExportBody.tsx`), like the Experimental and Sound panels, when it is first opened. When `npm run build` warns of a chunk over 500 kB, such code has reached the page: move it out rather than raising the limit.
- The client runs a pool of geometry workers (`poolSize`: one fewer than the logical cores, 2 to 4; the `workers` option sets it, and tests pass `workers: 1` or inject `createWorker`, which is called once per worker). One request from an asker is one request: the client shares it out glyph by glyph (all of a glyph's parameter sets to one worker, each part in the request's order, under the same request id) and it ends only when every part has ended. Callers never see the workers. A glyph goes back to the worker that computed it before unless that worker would get more than its share, weighed by the times the worker reports with each `results` message (`times`; null for a result its cache already held, which says nothing of the cost). A glyph a worker is computing stays with it when the new request asks for it again. Each worker keeps 1/N of the glyph cache's limits (the `font` message carries `workers`). A stuck or failing worker is restarted on its own and ends only its part.
- The protocol (`src/geometry/protocol.ts`): every compute request has an id and ends with exactly one answer, on every path (a font the worker does not have included): `done` (with `stopped` when a newer request or a `cancel` stopped it between glyphs) or `failed` (with a reason). A request carries one or more jobs (a parameter key and its glyphs), run in order; each `results` message holds one job's key. The worker sends `glyph` before each glyph: the page's heartbeat, which also names the key and the glyph to blame. Results are packed glyphs (`src/geometry/packed.ts`), their typed arrays transferred, never object graphs; only the glyph a request names in `stats` (the selected glyph; none for exports) carries its pipeline statistics, and the others arrive lean. A new message type keeps these rules.
- One live frame is one request. Its letters can react by different amounts (the shared values, and a quiet and a strong level), and while Thorn is on they show Thorn's settings by turn groups (`THORN_TURNS` in `src/sound/types.ts`), so its letters may show up to 15 parameter sets (3 levels × 5 turn groups), and with the shared values, which a frame always asks for, up to 16. `prefetchJobs()` sends them all as the jobs of a single request, the shared values first, and the frame is committed only when all of them have arrived. Each job lists only the glyphs its set needs: the shared set every glyph shown, or with Thorn turns only those of the letters that show it and the selected glyph (`FrameJob.within`, `shownGlyphs`); each other set its own letters' glyphs. Never send a frame's parameter sets as separate requests: a newer request supersedes the one in flight. Live results are kept apart from editing results, least recently used first out: twice the most sets of the last four live requests, at least 6 and at most `LIVE_KEPT_KEYS` (32), so the sets of the frame on screen stay while the next one computes.
- The client: a worker silent for 60 s on a glyph has that glyph marked failed ("Took longer than 60 s; try lighter settings") and is restarted, with the font sent again; restarts are counted for the whole pool, and after more than 3 within 60 s every worker is stopped and geometry stops until the next font, with the canvas saying why (a worker that cannot start leaves the pool; when none is left geometry stops too). New settings replace a worker stuck for 750 ms or more on a canvas glyph the new request does not ask for (one replacement in the whole pool at most every 2 s, never for a live frame, and never a worker busy with the ahead or plan lane, whose stores it would lose). Keep heavy settings fast inside the pipeline, as the Experimental vertex budget does (EXPERIMENTAL_PLAN §4.10), rather than raising these limits.
- Font export runs in a worker of its own for each build (`src/export/fontExport.worker.ts`). Cancel terminates it at once, and so does a minute without progress. Only when that worker cannot start does the build run on the page.
- Test the worker logic and the client without a browser: `tests/worker` runs `workerCore` with a fake `post`, and the client with a fake worker and fake timers.

## Renderers and flags

- The canvas and the preview draw their letters with one of three renderers: SVG (`SpecimenView`, the reference), Canvas2D (`src/render/canvas2d.ts`) or WebGL2 (`src/render/webgl2.ts`, the default). WebGL falls back to Canvas2D when it cannot start or loses its context, and Canvas2D to SVG. Backgrounds, grids, guides and the block hit stay in an SVG underlay (`SpecimenUnderlay`); the canvas renderers draw only the glyph layer, from `GlideStore` without React re-rendering per frame. Recording and every export keep drawing the CPU scene, unchanged.
- Every renderer draws straight segments only (miter joins with a bevel fallback, never round ones), and Whorl's glide follows the faceted ring on the GPU too: the shaders' JS mirror (`gpuReference.ts`) is tested against `morphAt` on real plans (`tests/render/gpuVsMorph.test.ts`). A change to a plan's maths changes `planData.ts`, `morph.ts`, the shaders and the mirror together.
- Runtime switches (`src/state/flags.ts`), read once at start-up from the URL, then `localStorage` (`none-curve:render`, `none-curve:precompute`, `none-curve:workerplans`): `?render=svg|canvas|webgl`, `?precompute=0|1` (a loaded file's features and Sound's commits planned for the whole file, and the geometry and Glide plans of a window around the playhead; see below; files over `PRECOMPUTE_LIMITS.maxSeconds` (6 minutes) and the microphone stay on the live path), `?workerplans=0|1` (Glide's plans made in the geometry workers) and `?probe=1` (`window.__noneCurveFrames` for the measurement driver; it hashes every drawn frame, so measure timing without it). Renderers always emit the `nc-draw` and `nc-draw-preview` user timing measures.
- The geometry pool has three lanes: `canvas` (as before; `isComputing()` reports only this one), `plan` (Glide plans on demand) and `ahead` (the precompute window, pinned per glyph to one worker so Glide chains stay in one worker). Canvas work always goes first; no lane cancels another's request.
- Precompute (`?precompute=1`, NOCUR-85; every number is in `PRECOMPUTE_LIMITS`, `src/sound/timelineTypes.ts`):
  - **Plan.** Features are measured linearly from 0 (`featureTimeline.ts`, `measuredUntil()`), and the planner (`planner.ts`) plans the whole file from 0 in idle slices on the main thread, `planAheadMs` past the playhead first. Commits are stored compactly (`planStore.ts`: interned strings, params, letters and looks); past `planMaxBytes`, commits farther than `planThinMs` from the playhead keep only a thin record (edges plus a hash of their keys) and are planned again, and checked against the hash, when the playhead comes near (the refill pass follows the playhead as it plays on). The budget is checked after every slice, also once the whole file is planned, and after a thin the shared tables are rebuilt a slice at a time. While playing, all of a frame's planning stays within `planTickMs`; the background slice shrinks when frames are slow.
  - **Window.** Geometry is made for `[playhead − windowBehindMs, playhead + windowAheadMs]` (10 s / 30 s). The near ring (`nearMs`) is filled first, in media order, with Glide's chain steps; the rest by weighted distance (a moment behind counts `behindWeight` times its distance), glyphs only. Work goes to the workers as leases of about `leaseMs` of work each (at least `leaseMinGlyphs`), deduplicated by `index|paramsKey`. The window's bounds move in `windowStepMs` steps; between steps the director only moves the playhead (`AheadGeometry.setPlayhead`). After a seek only the commit due may show, never a ready one from before the jump.
  - **Budgets and eviction.** Glyphs are packed (`src/geometry/packed.ts`, typed arrays, transferred from the workers). The page store (`src/state/aheadStore.ts`) holds `pageStoreBytes`, the glyphs it keeps unpacked for the canvas included (an eighth of it at most), each worker `workerStoreBytes` (only with Glide on, only the part ahead). The page store evicts down to 90 % when over budget: orphans (glyphs no commit of the current plan uses) first, oldest first, then the farthest by weighted distance; glyphs used near the playhead are never evicted, and a result farther than everything kept is dropped. The workers evict the glyph whose newest use is farthest ahead. Not FIFO and not plain LRU: after a seek, glyphs near the old spot stay until the budget needs the room.
  - **Invalidation.** Any input change (mappings, Drive letters, Response except Glide, base params, text, Sensitivity, Release) re-plans the whole file from 0 as a new generation: smoothing, the flash budget and seeds carry state forward, so the plan cannot be patched. Geometry is content-addressed by `index|paramsKey`: on a new generation every glyph becomes an orphan, and the new window's uses revive those whose key is unchanged, so only moments whose params changed are computed again (a colour mapping keeps all of it, a typography mapping most; a geometry slider none). Glide plan records are keyed by lineage and dropped on a new generation, Glide time or decimation level. A font or file change clears the stores.
  - **Priority.** Background work runs at the lowest priority: it pauses while settling (an edit in the last `settleMs`, or the pointer still down after one; a drag costs one generation), stops while the page is hidden, and pauses during the director's back-off (when it cannot take over for `tryMs` while the plan covers the playhead, it pauses the ahead lane for `backoffMs`, doubling after each failed try, and keeps what is stored). While paused, the idle loop warms the window around the playhead, so the first play takes over at once.
  - **Buffered bar.** The director offers `{ durationMs, plannedMs, ready }` to `bufferStore` (`src/sound/bufferStore.ts`), which publishes at most every `bufferEveryMs` and only when something moved by `QUANTUM` of the file (about a pixel), at once on a new plan, file or level. `BufferedBar.tsx` draws it as two straight layers under the Position slider (the plan lighter, ready geometry stronger), `aria-hidden`, with a visually hidden description on the slider's `aria-describedby`. `AheadGeometry.readyRanges()` gives the ready spans from a per-commit memo, kept in media order, that evictions take back; a commit counts as ready only when the page's ahead store holds its glyphs (the canvas's small stores evict without telling it), and the memo forgets commits more than `memoMarginMs` beyond the window. While an edit waits to be planned, the bar drops back at once.
  - **Probe.** `ProbeState.precompute` (`?probe=1`) adds `plannedMs`, `measuredMs`, `planBytes`, `planCpuMs`, `store {entries, points, bytes, evictions, orphans}`, `workers {bytes}`, `readyAheadMs`, `readyBehindMs`, `firstPlayLiveFrames`, `reuse {hits, misses}` and `paused` (`settling`, `hidden`, `backoff` or null).

## Slider ranges

- Every Geometry and Experimental slider's range and step is written once, in `src/state/sliderScales.ts`: `SLIDER_RANGES`, keyed by the slider's Sound target id (`"group.key"`, `"experimental.effect.key"`), and `TOLERANCE` for the logarithmic Tolerance slider.
- The panel spreads that entry into its range input (or names the target on `SliderField`), and Sound (`src/sound/mapping.ts`) and the saved-session check read the same entry, so a live or restored value is always one the slider can produce.
- Every slider has a number box (`SliderNumber`, on `NumberField`) that reads the same entry: it shows the value in its label's unit (`scale` 100 for a share shown in percent), and a typed value is clamped to the range and rounded to the step before it is committed. Tolerance's and Reach's boxes take the value itself (Tolerance in hundredths of a unit, rounded by `roundTolerance`; Reach in % of the canvas to 0.01 %).
- Never write a slider's min, max, or step anywhere else; to change a range, change its entry. A new slider gets its entry there first. `sliderRange(id)` throws for an id that has none, so a typo fails at once.
- The Sound tab's own sliders follow the same rule from `src/sound/types.ts`: Sensitivity and Release from `SOUND_LIMITS` (`minSensitivity`, `maxSensitivity`, `sensitivityStep`; `minReleaseMs`, `maxReleaseMs`, `releaseStepMs`), and Strength, Motion contrast, Pitch reactive, and Melody tracking from `RESPONSE_LIMITS`. The store keeps the response values as fractions (Strength 1 is 100%) and the panel shows them in percent of the same entry; `clampResponse` and the saved-session check (`SOUND_RANGES` in `persist.ts`) read those entries too.
- Video limits are written once, in `VIDEO_LIMITS` (`src/export/videoFormat.ts`): the largest side and area, the 10-minute cap, the bitrate range, the audio delay range, and the recorder's timings. The Record options and the recorder read them from there.

## Saved settings and undo

- The session (the settings, the canvas view buttons, the text, the preview's look, the export precision, the Sound mappings, the Sound tab's Response group (Sensitivity, Strength, Motion contrast, Release, Pitch reactive, Melody tracking), and which font and glyph were open) is saved in `localStorage` under one versioned key, `none-curve:session` (`src/state/persist.ts`), a moment after each change. `none-curve:restoring` is set while restored settings are first drawn, so a visit that crashed doing that starts the next one at the default settings. Small per-browser conveniences (the chosen tab, panel splits, Show all explanations) keep their own `none-curve:` keys.
- Not saved: Drive letters, the audio source, the recording options (Format, Length, Include audio, Use the preview look), live values, dialogs, the theme, and zoom and pan. Sensitivity, Release, and the four response values are saved.
- A saved session is read once, on start, leaf by leaf against the defaults: a wrong type or an unknown choice falls back to the default, a number out of range is clamped into it, and unknown keys are dropped, so a damaged or older entry never breaks the app. A new setting needs a default in `initialState`, and its range or choices in `persist.ts` (`RANGES`, `CHOICES`, `ENUMS`), unless it is a slider in `SLIDER_RANGES`, whose entry is used. The Sound settings are one optional `sound` block read by `readSound`, against `SOUND_LIMITS` and `RESPONSE_LIMITS`.
- Adding a setting, or a block that earlier sessions lack, needs no migration: a missing value reads as its default. The `sound` block was added this way, and sessions stayed at version 2.
- Renaming or moving a saved setting, or renaming a Sound feature or target id, needs a migration: raise `SESSION_VERSION` and add a step to `MIGRATIONS` that turns the old names into the new ones, so earlier sessions keep their values (the step from sessions without a version renames Phase 9's effects and the merged Sound features). Changing a slider's range needs one too: a Sound row's Depth and Range are shares of its slider's travel, so the same share now means another value (version 3 rescales the rows on the six Experimental sliders that were let down to 0, so they move the same values as before). Never reuse an old name for something else. A newer session read by an older app is read as far as it fits.
- Wrap every `localStorage` access in `try`/`catch`: storage may be blocked or full, and the app then works without saving.
- Undo (`src/state/history.ts`): changes are recorded where they are made (App's `edit` and text setters, the mapping store, and the Response group, which records Sensitivity and Release before it sets them on the engine), never in the reducer, which stays pure. Settings change through `edit`; the canvas view, glyph selection, export settings, and imports use `dispatch` and are not undone. Record each change with a key naming what it changes (`edit` works it out from the settings that changed), so one slider drag is one step, and wrap a change made of several updates (a preset Load, Freeze, a target with what it switches on, Reset sound) in `undoHistory.transaction`. Reset all (`src/state/reset.ts`) is not a step: `resetHistory` puts the history's part back to `START_SNAPSHOT` through `UndoHistory.startOver`, which also clears the history, so it cannot be undone; the reducer's `resetAll` action returns `initialState`, and `resetAll` in `src/App.tsx` resets what lies outside the history. Live Sound frames never dispatch, so they never enter the history, and neither do the recording options or a recording.
