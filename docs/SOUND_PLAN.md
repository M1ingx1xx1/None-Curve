**Scope:** A new **Sound** tab beside **Geometry** and **Experimental**. Live sound (a local audio file or the microphone) drives the parameters that already exist in both tabs, so the letters move with the music: anchors jump on the beat, outlines crumple when it gets loud, petals open on the bass.

## 1. Goals

- Sound drives **existing parameters only**, in both the Geometry tab (Curve flattening, Random anchors, Squaring, Anchors, Grid & angles, Distortion) and the Experimental tab (Crumple, Ripple, Whorl, Slipstream, Thorn, Seed). There are no new deformation operators.
- Two kinds of drive:
  - **Continuous:** a feature such as loudness moves a slider up and down.
  - **Jumps:** a seed moves on, so the anchors jump to new places: on each beat, or more often the higher a feature reads. A beat can also step a value to its next choice, such as the next angle (still to do).
- It runs live, at a frame rate that adapts to how heavy the settings are.
- Audio stays in the browser: decoded and analysed locally, never uploaded.
- Switching Sound off restores the slider values exactly.
- The moving letters can be saved as a video with their sound: an audio file's rendered offline from its plan, the microphone's recorded in real time (§9).

This replaces the earlier "Sound-driven carved letterforms" direction (PRD section 11). That direction planned new carving operators, a timeline, audio spread across the letters of a text, and recipe export; those are dropped.

## 2. Highest rule: no curves

Sound changes nothing but parameter values, and only within each slider's own range, read from the same table the slider is built from (§8; a seed: whole numbers within its field's range). Every letter on screen is therefore a result the sliders and seed fields could produce by hand, computed by the same pipeline: it keeps straight edges only, and it is validated like every other result. With Motion contrast or Pitch reactive (§5.2), the letters of one frame may sit at up to three strengths (quiet, shared, and strong). Each strength is a set of values of its own: every driven slider's live offset is scaled, then clamped to the slider's ends and rounded to its step, so each letter is still a set of slider values. While Thorn is on, the letters also fall into five turn groups, each showing the settings that move the thorns (Thorn's own, the Experimental seed, and the others of §5.3) as it took them at its last turn, so one frame may show up to 15 sets (three strengths times five groups); each is still ordinary slider values and seeds. Freeze writes the shared values only (§9). Frames are shown one after another as they are computed. There is no tweening or morphing between frames, which would invent in-between outlines the pipeline never made. Distortion's **few anchors** mode, which only the Flicker preset's Load sets (§7), is part of the settings like any other: sound never turns it on or off.

## 3. Sound sources

- **File** (the default): any audio file the browser can decode (WAV, MP3, AAC, OGG, FLAC, depending on the browser). It has play, pause, loop, and a position slider, and plays through the speakers.
- **Microphone:** starts only when the user presses **Start listening**, after the browser asks for permission; choosing **Microphone** only shows that button and pauses the file. It is not played back, so there is no feedback loop (a video take can still put its sound into the file, §9). Stop listening, switching source, and closing the tab release the microphone, and an indicator shows while it is active.
- There is no **Off** source (the first versions had one, as the default): Pause stops a file, Stop listening stops the microphone, and choosing **File** releases the microphone.
- Invalid, empty, silent, and unsupported input each get their own message. So do the microphone's troubles: access refused, no microphone, a microphone that would not open (busy in another app, or the browser aborted it), one that opened but could not be connected to the analysers, one that stopped while listening (unplugged, or access withdrawn), and a page that is not secure. An error the browser does not name reads as unsupported, never as a busy device.

## 4. Audio features

The features are computed every animation frame from Web Audio `AnalyserNode`s: a 2048-point FFT at 44.1 and 48 kHz (doubled at 88.2 and 96 kHz, so the window stays about 43 ms), with time-domain samples for the level and the pitch. A 20 Hz high-pass in front of the analysers removes DC offset from what is measured.

**Stereo measuring branch.** After the high-pass, the sound is also up-mixed to exactly two channels (a gain node with the speaker rules, so a mono source becomes identical left and right), split, and measured by one analyser per channel; these give Pan. The three analysers are read one after another, and the audio thread can render in between (in Chrome up to about one frame in 300). So each frame checks that the mixed-down samples are the mean of left and right, and reads all three again, up to 3 times; when none agree, Pan uses the last left and right that did. (A source of more than two channels never agrees, so after one held frame its reads are used as they are.) The speakers still get the file as before, and the microphone is still only measured, never played.

There are 11 features in five groups, listed in this order in the Sound tab (`FEATURES` in `src/sound/mapping.ts`). All run 0–1 except Pan.

| Group | Feature | Definition | Normalised |
|---|---|---|---|
| Loudness | **Level** | Short-time RMS (DC offset removed), in dB | −60 dB → 0, 0 dB → 1, shifted by **Sensitivity** |
| | **Swell** | Level, smoothed slowly: rise 300 ms, fall 2 s, whatever **Release** says | As Level |
| Bands | **Bass** | Energy 20–250 Hz | Against a slowly adapting running maximum of its own |
| | **Mids** | Energy 250–2000 Hz | Same |
| | **Treble** | Energy 2000 Hz – Nyquist | Same |
| Tone | **Brightness** | Spectral centroid of 20 Hz – 20 kHz, on a log-frequency scale | 100 Hz → 0, 8 kHz → 1 |
| | **Pitch** | Fundamental by YIN (threshold 0.15) on the mixed-down samples, decimated to at most 24 kHz first. An unvoiced frame holds the last note; silence gives 0. | 55 Hz → 0, 1760 Hz → 1, on a log scale (5 octaves) |
| | **Melody** | A pulse on each new note: the pitch moves at least half a semitone from the note it settled on and holds there for 70 ms, at least 100 ms after the last note. The settled note follows nearby frames slowly (400 ms), so vibrato averages out, and a new note settles on the mean of the frames that held it. A steady note, vibrato up to about ±80 cents at 5 to 7 Hz, noise, an octave error or a drum hit under a held note, and the first note after silence (a short slide into it included) give none. | The move's size, full at 2 semitones, times the pitch confidence (below); then falls back with the Release time |
| Rhythm | **Beat** | Onsets from two detectors on spectral flux: one over the whole spectrum, and one over 20–150 Hz only (the kick detector), since a bass drum can hide in the full-band flux under broadband sound. Each fires above an adaptive threshold (the median of the last second × a factor, 1.5 for the full band and 3 for the kick band, plus a floor, and at least half the last onset's flux as it decays, so a hit's own tail does not fire again), at least 100 ms apart. Every kick also fires the full-band detector, so one hit heard by both is one onset. Either fires only while the sound's energy rises (the energy gate, below), so a steady sound, a buzzy bass included, gives no beats. As a feature it is a pulse, the larger of the two detectors' pulses. | 1 on each onset, then falling back with the Release time |
| | **Activity** | How busy the sound is: the larger of **Change**, how far the full-band spectral flux that Beat judges rises above its median of the last second (held between judged frames), and **Pace**, Beat's onsets per second over the last 2 s; smoothed as one | Change against the largest such rise lately (a running maximum that halves every 3 s), never against less than the Beat flux floor or a quarter of the frame's compressed spectrum: near 0 on steady sound, tones and noise alike, high on attacks. Pace: 8 a second → 1 |
| Stereo | **Pan** | (R − L) / (R + L) of the left and right RMS (DC offset removed) | −1 (left) to 1 (right): the only two-sided feature |

Pan needs a stereo file in practice: a mono file, or a mono microphone, reads centred.

**Merged from 20.** Phase 3 first measured 20 features in six groups. They were merged into these 10: Low, Mid, and High became Bass, Mids, and Treble; the six narrow bands (Sub, Bass, Low mid, High mid, Presence, Air), Noisiness, and stereo Width were dropped; Kick became Beat's second detector; Change and Pace became Activity, which takes the larger of the two rather than their mean, since a mean would halve the range and never reach 1; and Balance became Pan. Phase H added Melody, the eleventh.

- **Release** (called Smoothing until phase H; the slider's id is now `sound-release`): each continuous feature follows the sound with a fast attack (10 ms, fixed) and a slower release (default 150 ms, 20–1000 ms in steps of 1, set with **Release**), so the letters react at once but do not flicker. Some have their own: Swell (above); Pitch moves both ways in 30 ms, and falls to 0 in silence with the release time; Pan moves both ways with the release time; Beat and Melody jump and fall back with the release time.
- **Pitch confidence** (`pitchConfidence` in the frame): how sure the Pitch reading is, 0–1. It is high on a clear single note, low on noise or a quiet note, and 0 while unvoiced or silent; it rises with the attack and falls with Release. It is not a feature: it has no meter and cannot be mapped. Melody is scaled by it; Pitch reactive also needs a clear note (§5.2).
- **Melody range** (`pitchLow` and `pitchHigh` in the frame; `followRange` and `melodyRange` in `features.ts`): where Pitch reactive places the pitch (§5.2), on Pitch's 0–1 scale, from the lowest to the highest note Melody settled on lately. It starts as an octave around the first settled note; a new lowest or highest note widens it with a 150 ms time constant (`melodyRangeAttackMs`); both ends close in on the note heard (between notes, the last one) with 8 s (`melodyRangeReleaseMs`); and the first note more than 8 s after the last starts it afresh. It is always at least 12 semitones wide around its notes (`melodyRangeMinSt`), within 0–1, so a steady voice does not sweep the text with every wobble. Left out: a note still settling after a fresh start (a slide into it), the frames Melody leaves its settled note at (a drum hit, an octave error, vibrato), and notes within a semitone of either end of Pitch's scale, where a chord or the full mix reads (about 55 Hz, with high confidence). Before any note it is 0 to 1, all of Pitch (as in `SILENT_FRAME`). Like the confidence, it is not a feature.
- **Melody's known limits:** ±80 cent vibrato at 4.5 Hz still gives about 5 pulses at 120 fps; a sung melody with ±80 cent vibrato misses some note changes; notes 150 ms long catch 3 to 4 changes in 5, notes of 200 ms all of them.
- **Silence gate:** below the silence threshold, continuous features fall to 0 and no beats fire. A band whose own energy is below the silence threshold reads 0, even while another band is loud. Swell falls with its own 2 s, and Activity's Pace as the last beats leave its 2 s window.
- **Sensitivity** also scales the magnitudes the onset flux compares, ln(1 + 1000 g m) with g = 10^(Sensitivity / 20), so it reaches Beat too. This differs from the first spec's formula, ln(1 + 1000 m), where Sensitivity could not help a quiet source's onsets.
- Onsets are judged at most about 60 times a second, so the thresholds mean the same on 120 Hz and faster displays.
- **Beat's energy gate** (`onsetRiseDb` and the settings after it in `SOUND_LIMITS`): a steady low note rich in harmonics (a sawtooth, square, or buzzy bass below about 140 Hz) fools the flux, since the analyser's window spans neighbouring harmonics and each bin swings at a rate the frame rate aliases to a few to 19 swings a second, while the flux median stays near 0. Such a note fired Beat 5–11 times a second, and kicks over it were half missed among the false beats. So either detector fires only while some octave band has risen at least 2 dB above its loudest in the last 100 ms. The bands start at 20 Hz (20–40, 40–80 Hz, and so on; the last runs to Nyquist); the kick detector looks only at the bands starting below 150 Hz. Band energy is in dB after Sensitivity, never below the silence threshold. A band's earlier energy stops counting once the band has fallen 12 dB below it since: the sound died away between two hits, so a second hit as loud as the first is new (without this, hats at 12 a second fell from 6.9 beats a second to 1.2). Measured: steady sawtooth basses rise at most 2.0 dB, hits at least 2.3 dB and mostly 5 dB or more; a steady buzz dips at most 9.4 dB, while hits at 10 a second fall 14–27 dB between them. Known limit: a hit masked by a louder sound in its own octave (a kick 12 dB under a bass note) is missed; under a full sawtooth bass, some real kicks are held back too.
- Zero denominators are handled and outliers are clamped.

## 5. Mappings

A mapping connects one feature to one target parameter. The Sound tab holds up to 8 mappings, each with an on/off switch. Any of the 11 features can drive any target; what it does depends on the target.

- **Slider targets** (any feature → a slider):
  - live position = slider position + **Depth** × feature, clamped to the slider's ends, then rounded to the slider's step. Positions are measured along the slider as drawn (0–1), so on an ordinary slider this is slider value + Depth × feature × the slider's full range, and a curved slider, the logarithmic Tolerance or the cubic Thorn · Reach, moves evenly along its track.
  - Depth runs from −100% to 100%. Negative Depth turns it down as the sound gets louder. Pan runs −1 to 1, so it moves the slider both ways: one way for sound on the left, the other for sound on the right.
  - Beat is a pulse, so on a slider the value leaps by Depth on each onset and falls back to the slider value over the Release time. Melody works the same way on each new note.
  - The Response group's Strength and Melody tracking act on this sum (§5.1); Motion contrast and Pitch reactive act per letter afterwards (§5.2).
- **Seed targets** (jumps): Distortion · Seed, Random anchors · Seed, and the Experimental Seed. A new seed puts every anchor somewhere new, so the seed moves on by one on each jump. The row's Depth knob is **Rate** (0–100%) instead:
  - With Beat, the seed moves on with the onsets: Rate 100% on every onset, 50% on every other one, 25% on every fourth.
  - With any other feature, it jumps at up to 4.8 times a second × Rate × the feature's value (Pan by its size, to either side). A gap between measured frames counts as at most 100 ms, so a stall does not release a burst of jumps.
  - All seeds that jump in the same frame jump together, and the flash limit (§10), which the seeds share with the driven sliders, skips the jumps beyond it.
  - The live seed is a whole number within the field's range (0–999 999), wrapping past the largest to 0, so every live frame is still a set of values the panel can produce (§2).
  - The sign means nothing for a Rate: picking a seed for a row with a negative Depth makes it positive.
- **Step** (still to do): a value with a few choices moves to the next one on every beat, for example Allowed directions (the angle step) 15° → 30° → 45° → 90°, Sides, or Rings.
- **Several mappings on one target:** on a slider, their contributions add up, then the sum is clamped. On a seed, each mapping counts towards its jumps, and the seed moves on by at most one per frame. Each row names its target, and the driven slider's marker shows the combined live value.
- **Picking a target switches on what it needs:**
  - When the user picks a target whose setting is off (its step, effect, or mode; §6), that setting is switched on, and a notice under the row says what changed, for example "Turned on Ripple.", "Set Noise amplitude to 40.", or "Turned off Random anchors. Set Mode to Adaptive." The same happens for the row **Add mapping** adds, which prefers a target that already acts: it adds Level at +50%, on Distortion · Noise amplitude if no row uses it yet, otherwise on the first unused target that acts.
  - Switching the row to another target, or removing it, never turns anything off.
  - **Load** is the one exception (§7): it resets the Geometry and Experimental settings to their defaults before it sets a preset up, so it can turn things off, and it says so under the Preset row. It is one undo step, so Undo brings back the settings and the mappings from before. Picking a target by hand still only switches on what that target needs; it resets nothing.
  - If the user turns the setting off again later, the row says why its target does nothing and offers an **Enable** button, which switches it on again and shows the notice.
  - With the keyboard, browsing the Target list switches nothing on along the way: the choice applies on Enter or when focus leaves the list. A pick with the mouse applies at once.
- **Drag to map** (NOCUR-75), as in Ableton or Bitwig: a feature is dragged from its meter in the Input box and dropped on any control that is a target (§6), in any tab: the Geometry and Experimental sliders, seeds and checkboxes, the Typography sliders, a colour (its Hue or Lightness) and a variable axis. The drop adds a row, on, at Depth +50% (Rate 50% on a seed; a switch starts in Toggle), and switches on what the target needs exactly as Add mapping does, with the same notice; the row and what it switches on are one undo step. A feature already mapped to that target is not mapped twice: the row there is marked instead, and if it is off it is switched on, with what its target needs, in one undo step. At 8 rows nothing is added. Semantics are unchanged: a dropped row is an ordinary row.
- **Base values stay put:**
  - The sliders keep their own values and do not move while Sound is live; a thin marker on each driven slider shows the live value.
  - A seed field keeps its own seed; a small live number beside it shows the live seed. The Distortion and Random anchors statistics show the live seed too, since they describe the letters as shown.
  - Depth or Rate 0, or a switched-off mapping, gives exactly the slider value or seed.
  - A mapping to a target whose step, effect, or mode is off does nothing, and its row says so.
  - With no font loaded there are no letters to move, so Sound does not drive: nothing changes, the markers and live seeds stay hidden, the status bar does not say Live, and seeds do not jump. It starts driving once a font is loaded; when the font goes, the sliders and seeds are restored exactly.
- **Saved and undone with the settings:**
  - The mappings and the seven Response values (Sensitivity, Strength, Motion contrast, Release, Pitch reactive, Melody tracking, Glide; §5.1) are saved in the browser with the settings and restored on the next visit. Drive letters is not saved: it starts on, or off with reduced motion (§10). The source and the recording options (§9) are not saved either.
  - Adding or removing a row, changing its feature, target, or on/off switch, a Depth or Rate drag (one step per drag), a drag of any of the seven sound knobs (one step per drag), Reset sound, picking a target together with what it switches on, Load, and Freeze are each one undo step, in the same history as the settings. Undo and redo also clear the notices of what the last Load or a picked target did, since they no longer describe the state. Live frames never enter the history.

### 5.1 Response controls

The Response settings set how the letters answer the sound, over every mapping. Its seven knobs (Sensitivity and Release in the Input box, the other four in the Response box):

| Control | Range, step | Default | What it does |
|---|---|---|---|
| **Sensitivity** | −24 to +24 dB, 1 dB | 0 dB | Gain on the input before measuring (§4) |
| **Strength** | 0–400%, 1% | 150% | Multiplies each slider target's summed offset before it is clamped, so 200% moves the letters twice as far until the slider's end. It also multiplies each seed's Rate, which still stops at 100%. At 0% Sound stops driving, as on Pause: exact restore, the seeds back on their fields, no markers, and the Mappings group says "Strength is 0%: the letters hold still." |
| **Motion contrast** | 0–100%, 1% | 0% | Each letter reacts by its own amount (§5.2) |
| **Release** | 20–1000 ms, 1 ms | 150 ms | How slowly the readings fall back (§4) |
| **Pitch reactive** | 0–200%, 1% | 0% | The recent melody's low notes move the letters on the left more, its high notes those on the right; it needs a clear single note (§5.2) |
| **Melody tracking** | 0–200%, 1% | 0% | Adds 0.5 × Melody tracking × the Melody pulse to the feature of every slider mapping (capped at 1), except Pan rows and rows that read Melody. Seeds are left alone. So the letters move on each new note, even at a steady loudness. |
| **Glide** | 0–1000 ms, 10 ms | 150 ms | Display only (§5.4): each new live shape is reached over this time instead of at once. Not neutral by default, but it changes no computed shape, so the pinned hashes hold; `NEUTRAL_RESPONSE` keeps 0 ms, and `DEFAULT_RESPONSE` is the neutral values with 150 ms. |

- The neutral values (`NEUTRAL_RESPONSE`, Strength 100%) behave exactly as before phase H, so saved sessions and presets look the same, except where Thorn is on: its settings now reach the letters by turns (§5.3), which changes Flare's live frames on purpose. `tests/sound/neutral.test.ts` pins this against 4a54e5d, with Flare left out of its scheduler hash (§12). The defaults (`DEFAULT_RESPONSE`) are the neutral values with Strength 150% (NOCUR-91, so the letters react more strongly to the music) and Glide 150 ms.
- `ResponseSettings`, `RESPONSE_LIMITS` and `NEUTRAL_RESPONSE` live in `src/sound/types.ts`; Strength and Melody tracking are applied in `modulate` and `JumpTracker.advance`, Motion contrast and Pitch reactive in `src/sound/letters.ts` and the scheduler.
- **Saved:** the session stores all seven (`Session.sound`). On reading, each value must be a finite number, is clamped to its range and rounded to its step, and otherwise reads as its default. A session saved before phase H reads the defaults. Session version 4 (NOCUR-91) moves a Strength saved at the old default, exactly 100%, to the new 150%; any other Strength stays as chosen.
- **Undone:** each drag is one step (`sound:<field>`); Reset sound puts all seven back to their defaults in one step and is disabled while they are already there.
- Presets' Load leaves all seven alone (§7).

### 5.2 Per-letter response

Motion contrast and Pitch reactive act on each letter, one glyph occurrence of the text, rather than on the mappings (`src/sound/letters.ts`).

- **Letters** (`letterSlots`): one slot per occurrence, in the order the canvas places them (lines, then glyphs; spaces and missing glyphs counted). A slot has its glyph id, where it sits across the text block, and its share of the text (its advance over the sum of the drawn letters' advances). Spaces and missing glyphs always show the shared level.
- **Weights:** in each frame every drawn letter gets a weight, its Motion contrast gain times its Pitch reactive weight. Both are exactly 1 at 0%.
  - **Motion contrast** is balanced: at 100% a letter's gain runs from 1/3.6 to 3.6, spread evenly in log space around 1 (3.6^±c at a setting c). Each letter mixes a stable share of its own (38%, from a hash of its place in the text) with a slow wave (6 s, shifted letter by letter), so which letters lead drifts every few seconds. At 100% about 17% of the letters are quiet, 67% shared and 17% strong: Strength sets the overall amount, Motion contrast the spread.
  - **Pitch reactive:** the recent melody's low notes weigh the letters on the left more, its high notes those on the right. Each letter's weight is a bell around the pitch's place across the text block (`pitchWeight`), and that place is where the pitch sits in the melody's range (`pitchPlace`, `pitchLow` to `pitchHigh`, §4), so a tune sweeps the whole text whatever its register. On the first rise through a melody each new highest note sits at the right edge, since the range widens with it; once the range has been heard, each note gets its own place. It needs a clear single note, such as a voice or one instrument.
    - **Why the melody's range:** on Pitch's whole 55–1760 Hz scale an octave is a fifth of the text, so ordinary melodies barely moved the strong letters: C4 and C5 leaps put their mean position (0 the left end of the text, 1 the right end) at 0.46 and 0.62, against 0.15 and 0.82 in the melody's range.
    - **Known limit:** at 200%, a fast octave leap can occasionally be held back by the flash limit (§10): on C4 and C5 in turn, 2 notes a second, 10 of the 11 leaps land, against all 11 at 100%.
- **Three levels:** the weights are sorted into three levels, quiet, shared (1) and strong. Their gains are fixed per setting (they do not change with time or with the sound), so without Thorn turns (§5.3) a frame needs at most three parameter sets, and a steady sound only moves letters between sets already computed. At Motion contrast 100% alone the gains are 1/3.6, 1 and 3.6; with Pitch reactive the quiet and strong gains change too, within fixed limits. The boundaries lie halfway, in log space, between 1 and each level's gain.
- **Hysteresis:** to leave its level, a letter's weight must pass the boundary by 15% of the boundary's distance from 1 (in log space), so a letter wavering near a boundary stays where it is.
- **A level's values** (`levelPosition`, `levelSets`): the shared values with every driven slider's offset from its own slider position scaled by the level's gain, then clamped to the slider's ends and rounded to its step; a result still within the slider value's own step keeps the exact slider value, as `modulate` does. So every level is a set the sliders could produce (§2). It is monotone in the shared position: a level turns back only when the shared value does (§10). Seeds, values the flash limit holds, and Thorn's derived canvas em come with the shared values. Thorn's own sliders are never scaled, and while Thorn is on no other turn target is either (§5.3): a letter takes those from its turn group, so the levels then scale only Distortion's sliders and Crumple's and Ripple's Amount. This also ends the strong letters' outsized thorns: Reach is a cubic slider, so a scaled position gave a strong letter up to about 47 times the shared reach. Since the offset is scaled, a slider that moves down (a negative Depth, or Pan to one side) moves down at every level.
- **Folding:** a level whose values equal the shared ones (for example on a coarse slider whose scaled offset stays in the same step) is the shared level, so its letters use the shared results. A frame where no letter is off the shared level (and, with Thorn turns, every group shows the live Thorn settings, §5.3) asks for nothing extra.
- **Seeds stay global:** every letter shares the live seeds; only while Thorn is on do the seeds that move the thorns (the Experimental seed and Random anchors' seed) reach the letters one turn group at a time (§5.3), and Distortion's seed stays shared. A jump moves every letter at once, so the levels add no flash edges of their own for seeds, and Freeze can write the seed. Strength scales the Rate; Motion contrast and Pitch reactive leave the seeds alone.
- **The shared level is what the panel shows:** the markers, the live seeds, the status bar's description, and the statistics of the selected glyph all show the shared values, and Freeze writes them (§9). Every letter then takes the shared shape, which is already computed, so the switch is instant; with Thorn turns, only for the letters whose group showed the live Thorn settings, and the glyphs of the others are computed then (§5.3).
- **Text and typography:** another number of letters (a text edit) starts the levels afresh, and the first assignment is no flash edge. The same text set differently (tracking, line height, alignment, slant) keeps each letter's level.
- **Known limitation:** on a coarse slider (Ripple · Sides, Whorl · Rings and Sides, Curve flattening · Segments per curve; with Thorn off, since with Thorn on the levels leave them alone), quiet and strong letters spread apart only after the shared value has left its base step.
- **Cost:** a frame asks for up to three parameter sets (with Thorn turns, up to 15 for the letters and the shared set besides, §5.3), so Motion contrast and Pitch reactive can lower the frame rate (§8).

### 5.3 Thorn turns

While Sound drives the letters with Thorn on, the settings that move the thorns reach the letters a few at a time, so that at most about a fifth of the letters' thorns change at once and each letter's thorns at most once every 1.25 s (`THORN_TURNS = { groups: 5, gapMs: 250 }` in `src/sound/types.ts`; `turnGroups` and `ThornTurns` in `src/sound/letters.ts`, driven by the scheduler in `live.ts`). Before, a beat on the Seed re-picked every letter's thorns at once, and Thorn picked its anchors on the outline after every warp, so any small move upstream re-picked almost every thorn on every frame; Thorn now picks its anchors on the letter before Distortion and follows them through the warps (EXPERIMENTAL_PLAN §4.8), and the turns pace what is left.

- **Turn targets** (`isTurnTarget`): while Thorn is on, every target except Distortion's sliders and seed, Crumple's and Ripple's Amount, and Thorn's Reach. So Thorn's other sliders, the Experimental seed (which Crumple and Slipstream share, so they re-seed by turns too), every Geometry step before Distortion (Thorn picks its anchors on the letter they make, Random anchors' seed included), and every other slider of Crumple, Ripple, Whorl, and Slipstream. The thorns keep their anchors and directions through Distortion and through Crumple's and Ripple's Amount, so those stay continuous and shared, as with Thorn off. Reach sets only how long the thorns are, not where they sit or which way they point, so it stays shared too: a Trigger on Beat grows and sinks every letter's thorns together, back to none between hits when the slider sits at 0 (by turns, each group took Reach at its own turn, so the letters showed thorns out of step with the beat and never all returned to their plain shapes). Thorn's derived canvas em is not a turn target: it follows the canvas at once.
- **Groups** (`turnGroups`): the drawn letters are split into 5 turn groups of whole glyph ids, so every copy of a glyph turns together and a group costs no glyph twice. They are balanced by letter count, at most ceil(N / 5) letters each: glyphs go largest first (ties in the order of a hash of the glyph id) to the group with the most room, so each group's letters lie all over the text rather than sweeping it in reading order. Only a glyph that fits whole in no group is split, by occurrence, over as few groups as hold it. With fewer than five drawn letters some groups are empty. The same letters set differently keep their groups.
- **A turn:** each letter shows its level's values (§5.2) with the turn state its group took at its last turn. A turn hands the current live turn state to the next group, round robin, once the last turn has reached the screen and 250 ms have passed since. The group takes it when its own state differs: another seed or number of thorns, a slider at least half a flash swing (5% of its travel) away, or a slider the sound has put back on its own value where the group's is not (so quiet ends exactly on the sliders). A group that has kept its state for two rounds (`THORN_SETTLE_MS`, 2 × 5 × 250 ms = 2.5 s) takes any difference, so a sound that keeps a slider moving by less than 5% of its travel (a Follow on Whorl Amount, whose travel is −4 to 4) still reaches the letters; before, it never did, and the letters stayed on their sliders. While another group differs, a group that does not, or holds no letter, gives its turn up: the turn passes 250 ms with nothing changed, so the groups after it do not wait on it, and even a short text's letters turn at most once every 5 × 250 ms.
- **Hits on the beat** (`pulsedTargets`, `ThornTurns.setPulsed`): the sliders and switches a Trigger or Toggle mapping drives are not taken by turns. Every group takes their live values on every update, so a hit shows on every letter together and the letters return to their sliders together after it; the flash limit still counts them. By turns, each group took a hit at its own turn, so the letters were out of step with the beat and never all on their plain shapes at once.
- **Levels do not scale them:** while Thorn is on, Motion contrast and Pitch reactive leave every turn target at the group's value; they still scale Distortion's sliders and Crumple's and Ripple's Amount (§5.2).
- **Flash limit:** a turn is a change of its own from the same budget (§10). Its size is the group's share of the text times how far its turn targets' sliders move (in slider travel), a new seed counting as a whole travel; a turn of 10% or more takes an edge. A turn the budget refuses waits, the group keeping its state, and is asked again on the next update.
- **Starting afresh:** every group takes the live state at once, as no turn and with nothing charged, when Sound starts driving (Play, Start listening, Drive letters, after any stop), when Thorn is switched on (Use thorn), and when the letters change (a text edit, or a font or text case that changes the glyphs; the same text restyled keeps its groups). Adding or removing a mapping starts nothing afresh: its changes reach the groups by turns. A slider moved by hand that the sound does not drive reaches every group at once, as without Sound.
- **What stays shared:** the markers, the live seeds, the status bar, the selected glyph's statistics, and Freeze keep to the shared live values, not a group's (§9).
- **With Thorn off,** nothing goes by turns: the scheduler's requests, commits and Freeze are exactly as before Thorn turns (§12).
- **Every letter is still a result the sliders and seed fields could produce:** a group's state is a set of live values the sliders and seeds had, and the letter's level is applied as in §5.2.
- **Cost:** a frame's letters show at most one parameter set per level and group, 15 in all, asked for in one request together with the shared set (§8). Since groups are whole glyph ids, each set is computed only for the glyphs of the letters that show it, and the shared set only for those that show the shared values (and the selected glyph, for its statistics), so without levels each glyph is computed about once a frame, as before.

### 5.4 Glide (NOCUR-74)

- **What it is:** a display-time tween between live shapes. The live scheduler, its cache, the flash limit, the markers, the status, Freeze and the exports never see it; only the canvas, the preview and the videos draw the in-between scene. `SceneGlide` (`src/specimen/glide.ts`) is pure with an injected clock; `GlideStore` and `useSceneGlide` (`src/state/useGlide.ts`) run it on `requestAnimationFrame` and stop the loop when nothing moves; `<Glided>` (`src/components/Glided.tsx`) re-renders only the three views each frame.
- **When:** while Sound drives the letters (`useLiveDriving`), and once more for the scene shown when it stops. A change of font or text (another glyph sequence) shows at once. Glide 0 and `prefers-reduced-motion` show every scene at once, exactly as before. Easing is cubic ease-out over Glide's time; a shape that arrives mid-glide starts from what is on screen, and a glide at least 99 % done (`GLIDE_LIMITS.arrived`) counts as arrived.
- **Correspondence** (`src/specimen/morph.ts`): an outline whose contours cross (overlapping pieces, as many fonts draw letters, or a self-crossing contour) is paired as its merged outline (`mergeOverlaps`, cached per glyph; not on Whorl's path), so a counter that is only a gap between pieces pairs with the hole Burst makes instead of that hole growing from its centroid; progress 0 and 1 still return the glyphs themselves (NOCUR-93). Contours are paired greedily by centroid distance over size plus the log ratio of their areas, outlines with outlines and holes with holes (above 48 contours only the 4 nearest are tried); pairs further apart than half their sizes added up, or with areas more than 4 times apart, are never made. When the two outlines wind opposite ways (judged by their largest contour; Whorl above Amount 1 merges with the other winding), the new outline's contours are reversed first. An unpaired contour grows from, or shrinks into, the closest points of the other outline (over all its contours) when those lie within its size on average, otherwise its centroid. Equal anchor counts with a small move (≤ 0.35 × size, from the start shift that moves least) pair anchor to anchor; otherwise the union of both anchor sets goes to the other contour by closest point, kept in order: every anchor's closest point is found, the longest run that keeps the order (starting from the first anchor's closest point) is kept, and the others are placed between their neighbours by arc length. Both ends are exact: progress 0 and 1 return the old and the new outline. Anchors only the old outline had are dropped when within 0.004 em of a straight run; while they outnumber the new outline's anchors, the tolerance doubles up to 0.05 em, and a leftover contour whose size or thickness is within it goes too, so repeated glides do not pile up anchors. In-betweens over 12,000 points change at once.
- **Trajectories** (`src/specimen/trajectory.ts`, `whorlGlide.ts`): spikes and every effect but Whorl go straight (they grow and sink straight from their base); Whorl swirls along paths built from straight lines. The worker's `PolygonGlyph.motion.whorl` carries the centre, sides, rings, radius, per-ring turn, the outline before Whorl, and whether Whorl is the last effect to reshape it. When only Whorl's turn changed and it is last, the glide is Whorl's mesh turning part of the way: the pre-Whorl outline is cut at the mesh's creases, each point keeps its triangle's barycentric weights, each mesh corner travels round its ring polygon by `along` (straight pieces from polygon corner to corner, even in angle within each piece), and a glide that goes on starts from the corners as shown; folds and the outer region follow exactly. Otherwise, when Whorl's settings changed, anchors are paired on the outlines with Whorl's turn undone exactly (the inverse of each mesh triangle; where the letter folds, the layer nearest the pre-Whorl outline), and each anchor sweeps round the polygon by Whorl's change of turn at the size of its base (where it sits on the outline it was paired on), the rest of its move added in a straight line, so effects after Whorl still move straight relative to their base. Sides changes join the two polygons halfway. A new effect with its own path adds a `TrajectoryModel` and its data to `GlyphMotion`.
- **Keyframes** (NOCUR-91; `src/sound/keyframes.ts`): while Glide is above 0, a large change of shape passes through real in-between shapes instead of one morph from the old outline to the new. A change is large when an Experimental effect switches on or off (as Return to plain does on every beat, §5.5) or one of an effect's strength fields moves at least 25% of its slider's travel (`KEYFRAME_LIMITS.minShare`). It gets two keyframes, at 1/3 and 2/3 of the way (`KEYFRAME_LIMITS.count`): each effect's strength fields (`KEYFRAME_FIELDS`: Crumple Amount; Ripple Amount and Petals; Whorl Amount; Slipstream Strength, Slip, Cuts and Trails; Thorn Reach, Refraction and Dent; Dissolve Amount, Spread and Specks) go that part of the way, an effect switching on grows from 0 and one switching off fades to 0 while it stays on, and every other value is already the new one. The geometry pipeline computes each keyframe like any frame, so it is faceted, straight lines only (§2); its glyphs are computed before the frame shows, on the live path (`LiveCommit.keyframes` in `live.ts`) and in the precomputed plan alike. Glide then morphs leg by leg (`src/specimen/glide.ts`): the eased progress runs over the legs evenly, each leg a morph of its own along its effect's path (Trajectories, above). There is no control of its own; Glide 0 means no keyframes.
- **Cost:** pairing runs on the main thread within 6 ms per animation frame (`GLIDE_LIMITS.planBudgetMs`), round-robin from where the last frame stopped and at least one glyph per frame, so no glyph waits forever; a glyph not paired yet holds its on-screen shape and starts its full glide when paired. Plans are cached per old and new outline (WeakMap), and repeated letters share one in-between per frame. Measured on 54 glyphs with a new shape every 33 ms: retarget 0.1–0.5 ms; frames with pairing average 6–7 ms, frames that only interpolate 0.1–1.3 ms; a single large Dissolve glyph can take up to about 50 ms once. Per glyph (Roboto, Node): the Whorl mesh glide plans in 0.1–0.3 ms and draws a frame in about 11 µs; Whorl with Thorn 3 ms and 27 µs; a Burst seed 0.8 ms and 7 µs; Dissolve grain 4.9 ms and 58 µs.
- **Saved:** `glideMs` is part of `Session.sound`; a session without it reads 150 ms. Checked in `tests/specimen/glide.test.ts` (exact ends, straight spikes, closest-point pairing in order, a rotated start, a reversed winding, a split contour growing from the outline, gradual settling, Whorl paths in straight pieces, the exact unturn, the mesh glide following Whorl and going on without a jump, hole pairing, continuity on retarget, Glide 0 and no Sound identical, the budget and its fairness) and `tests/state/persist.test.ts`.

### 5.5 Return to plain (NOCUR-87)

- **What it is:** a switch in the Transport (`ResponseSettings.plain`, 0 or 1) with its **Hold** knob (`holdMs`, 0–3000 ms in steps of 10, 200 ms by default; 50–1000 ms before NOCUR-91). On, the letters rest on their plain shapes (every Experimental effect off, Geometry as set) and each beat shows the effects switched on in the Experimental tab for Hold; below 80 ms, 0 included, a beat shows them for the shortest pulse, 80 ms (`SHAPING_LIMITS.pulseMs`). With Glide on, each switch passes through keyframes (§5.4). It turns the beat-trigger examples (an effect at rest on 0, a Trigger row on Beat) into one control that needs no row per effect.
- **How:** `plainPulse` (`mapping.ts`) is a hidden Trigger row on Beat with Smooth set to Hold, shaped with the rows (`LiveScheduler.shapedMappings`) under the id `PLAIN_PULSE_ID`. In `modulate`, every Use switch of `PLAIN_SWITCHES` that is on in the base becomes a driven switch, turned off unless that pulse is above 0. So the plain look is just switches flipping: the flash limit sees both edges, the planner gets it through the same scheduler inputs, and the base the canvas shows when Sound stops is the sliders' own.
- **Thorn turns:** the Use switches count as pulsed targets while it is on (`pulsedTargets(mappings, also)`), so every letter changes together; Thorn itself switching off clears the turns, and on the next beat every group starts on the live state at once.
- **Saved and undone** with the Response values (`Session.sound`); a session without them reads off and 200 ms. Reset sound leaves them alone. Checked in `tests/sound/turns.test.ts` (Return to plain: the switches off between beats and on during the pulse; every letter plain, then the design, then plain again, beat after beat).

## 6. Targets

**Geometry tab**, where "anchor jumping" lives:

|---|---|---|

| Distortion · **Noise amplitude** | Level, or Beat (a pulse) | Anchors shake harder when loud, or kick out on the beat and settle |
| Distortion · **Noise frequency** | Brightness | Brighter sound gives a finer, jitterier edge |

| Random anchors **Randomness** | Level | Loud: anchors scatter; quiet: they line up evenly |
| Random anchors **Density** | Bass, stepped | Fewer, chunkier anchors on the bass |
| Curve flattening · **Tolerance** | Level | Loud passages get coarser, more polygonal |
| **Squaring** amount | Mids | Bowls square off with the voice |
| Anchors · **Anchor spacing** / **Anchor reduction** | Treble / Level | Anchors densify or drop out |
| **Grid** size | Bass, stepped | Snaps to a coarser grid on the bass |
| Grid & angles · **Allowed directions** (the angle step) | Beat → Step (still to do) | Edges lock to 15°, 30°, 45°, 90° in turn |

Also targets, with no suggested drive: Curve flattening · Segments per curve and Corner angle, and Distortion · Normal bias. The full list, in panel order, is `TARGETS` in `src/sound/mapping.ts` (README, Targets): 42 targets, of which the three seeds are jump targets and the rest sliders. Allowed directions becomes a target with Step mappings.

**Experimental tab**: Crumple Amount / Facet size / Turn; Ripple Amount / Wavelength / Sides / Center X / Center Y / Fade / Petals; Whorl Amount / Rings / Sides; Slipstream Direction / Strength / Slip / Gust size / Gustiness / Cuts / Trails; Thorn Anchors / Reach / Root / Spread / Width / Refraction / Flute width (Reach, a share of the canvas diagonal, moves along the panel's cubic slider); and the shared **Seed** (Beat at Rate 100%), listed last as its group sits at the bottom of the tab. The Target list shows it as just "Seed"; every other target reads "Section · Label", such as "Distortion · Seed". Older saved settings that lack a field read it as the panel shows it: Thorn Root 50% and Flute width 10%, and 0 for Crumple Turn, Ripple Petals, Slipstream Slip, Cuts, and Trails, and Thorn Refraction. Settings saved while Crumple had Detail (Phase 9, until NOCUR-60) load with that value ignored and any row on Crumple · Detail dropped. Rows on Thorn · Reach saved while Reach was a share of the em keep their depth, which now moves the cubic slider.

**Beyond the sliders (NOCUR-73)**: the effects' switches (each Use …, Ripple Reverse, Thorn Burst and Reverse: 0/1, Trigger or Toggle only, no Depth, Range, or Curve, applied before the other targets, so a row that switches Thorn on lets Thorn's slider rows and its Burst and Reverse switch rows act in the same frame); Typography Size / Tracking / Line height / Slant (the Typography tab's ranges); the text and background colours' Hue (0–360°, clamped at both ends, not wrapped) and Lightness (0–1), in OKLCH with the chroma kept; and one target per axis of the loaded variable font (`axis.<tag>`), from the font's own value over the axis. A row on an axis the font lacks is kept, saved, and inactive. Typography and colours reach the canvas as the commit's `look` and are never scaled by letter levels; none of these go by Thorn turns except Thorn's own switches. Axis values reach the glyphs through the font's instance (`LoadedFont.at`, cached) and join the geometry key only while they differ from the font's own. With none of them mapped, every frame and key is as before (README, More targets).

## 7. Presets

Presets are ready-made starting points (`PRESETS` in `src/sound/presets.ts`): each sets a few slider values to start from as well as its mappings. Most keep to the Geometry tab and its default sliders, so the letters stay readable while it is quiet, and none turns on more than one Experimental effect.

Choosing a preset in the **Preset** list only selects it. **Load** (`presetSettings`, pure):

1. Resets every Geometry and Experimental setting to its default (Curve flattening, Random anchors, Squaring, Anchors, Grid & angles, Distortion, and every Experimental effect), keeping the three seeds (Distortion, Random anchors, and the Experimental seed). Typography, Color, the canvas, and the Sound tab's source, Drive letters, and the Response group (§5.1) are left alone.
2. Sets the preset's start values.
3. Replaces the mappings with the preset's, and clears the earlier row notices.
4. Shows a notice under the Preset row: "Loaded X.", then "Turned off …." for the Experimental effects that were on and are now off (Crumple, Ripple, Whorl, Slipstream, Thorn), then "Turned off Random anchors." when that happened, then "Other Geometry and Experimental settings back to defaults (seeds kept)." when any other setting the preset does not set went back to its default. For example: "Loaded Bloom. Turned off Crumple and Slipstream. Other Geometry and Experimental settings back to defaults (seeds kept)." The notice stays until the next Load, until another preset is chosen in the list, or until an undo or redo, and screen readers announce it.

Load is one undo step: Undo puts back the settings and the mappings from before it, seeds and all.

So every preset starts from the same letters, whatever was set before, and its rows need nothing switched on. Should a row still need something, it is switched on as when its target is picked by hand (§5), row by row, with the row's notice. Picking a target by hand still only switches on what it needs; it resets nothing.

Depth is in brackets, as a share of the slider's travel (negative turns the slider down); on a seed it is Rate. Start values list only what differs from the defaults.

| Preset | Mappings | Start values | Experimental effect | What you see |
|---|---|---|---|---|
| **Flicker** | Level → Distortion · Noise amplitude (90%); Beat → Distortion · Noise amplitude (30%); Beat → Distortion · Seed (Rate 100%) | Few anchors on; Noise amplitude 2; Normal bias 90% | None | On every beat a few other anchors of each letter jump while the rest hold the letter; louder sound and each beat throw them further |
| **Scatter** | Level → Random anchors · Randomness (90%); Level → Random anchors · Density (−9%); Beat → Random anchors · Seed (Rate 50%) | Random anchors on; Density 10; Randomness 5% | None | Anchors are placed afresh on every other beat: close and even while it is quiet, fewer and further from even as it gets louder |
| **Pixel** | Bass → Grid & angles · Grid size (70%); Treble → Anchors · Anchor reduction (40%) | Snap to grid on | None | The letters snap to a grid that the bass makes coarser; hiss and cymbals drop anchors |
| **Low poly** | Level → Curve flattening · Tolerance (70%); Brightness → Anchors · Anchor reduction (40%) | Merge joined curves on | None | Loud passages flatten the curves into fewer, longer sides; bright sound drops anchors |
| **Block** | Swell → Squaring · Amount (90%); Beat → Squaring · Amount (30%) | None (the defaults) | None | The round strokes square off as the music swells, and a little more on each beat |
| **Jitter** | Treble → Distortion · Noise amplitude (60%); Brightness → Distortion · Noise frequency (30%) | Noise amplitude 2; Noise frequency 20 | None | Hiss and cymbals make the outlines tremble; brighter sound makes the tremor finer |
| **Facet** | Level → Curve flattening · Segments per curve (−15%); Beat → Curve flattening · Segments per curve (−5%); Pitch → Curve flattening · Segments per curve (20%) | Mode Fixed segments; Merge joined curves on; Segments per curve 6 | None | Curves break into a few straight sides as it gets louder and on each beat; higher notes smooth them again |
| **Bloom** | Beat → Ripple · Amount (10%); Bass → Ripple · Petals (5%) | Ripple on, Amount 30% | Ripple | Ripples run through the letters and swell on each beat; the bass bends them into petals |
| **Flare** | Beat → Seed (Rate 100%); Level → Thorn · Reach (50%); Beat → Thorn · Anchors (15%) | Thorn on, Anchors 1, Reach 0%, Root 25% | Thorn | Thorns shoot out of a few anchors per letter as it gets louder; on every beat they jump somewhere new and briefly multiply |
| **Gale** | Level → Slipstream · Slip (50%); Beat → Slipstream · Cuts (40%); Activity → Slipstream · Trails (35%) | Slipstream on, Strength 0%, Slip 0% em, Cuts 0, Trails 0 | Slipstream | Loudness slides slices of the letters past each other; beats cut slits along the stream and busy passages draw trails |

- **Flicker** turns on Distortion's **few anchors** mode. It has no control of its own and is not a Sound target: only this preset sets it, and Reset distortion, or loading another preset, turns it off. Only 1–5 anchors of each letter move, never its corners or extremes, each by at least 60% of the amplitude, and a new seed picks a new set (README, Vertex distortion; PRD, P1). The tiny amplitude, 2, keeps Distortion on, so the Seed row acts while it is quiet.
- **Jitter**'s amplitude of 2 likewise keeps its Noise frequency row acting while it is quiet.
- **Low poly** merges joined curves, so a large Tolerance reaches whole bowls (unmerged, each font curve keeps at least one edge). **Facet** merges them too, so its segments count per merged curve, a quarter of a bowl, not per font curve.
- **Flare** starts at Reach 0, so there are no thorns, and no root pull, while it is quiet; its Root of 25% (half the default) keeps the strokes readable. At full level its Reach row moves the cubic slider halfway, to an eighth of the canvas diagonal (about 3.8 em on the default canvas); it was 30% while Reach was a share of the em. Thorn is on from the start, so its Seed row needs nothing switched on, and Crumple stays off. Its rows are unchanged since Thorn turns (§5.3), which pace them: a beat's new seed and number of thorns, and the louder Reach, reach about a fifth of the letters at a time, each letter at most once every 1.25 s, rather than every letter at once.
- **Gale** starts with Strength, Slip, Cuts, and Trails at 0, so nothing streams while it is quiet. It never drives Strength: the stretch would push the letters into their neighbours.
- **Bloom**'s Petals row moves the petals between 0% and 10% only, once the bass is up (the slider's step is 10%, and 20% is hard to read).
- **Retuned in phase 3:** when the features were merged, the rows on Kick moved to Beat (with smaller depths for Block, Facet, and Bloom), Low poly's Noisiness row became Brightness, and Pixel and Jitter read Bass and Treble. When the Experimental effects were reworked, Flare and Gale were rebuilt for Thorn and Slipstream. Every preset was looked at on Arial and Georgia in silence, in a full mix, at a beat peak, and at full loudness: the letters stay readable.

## 8. Architecture and performance

- **New code in `src/sound/`:**
  - `types.ts`: shared types, limits, and the silent feature frame; the Response settings (`ResponseSettings`, `RESPONSE_LIMITS`, `NEUTRAL_RESPONSE`, `clampResponse`, §5.1).
  - `engine.ts`: the Web Audio graph and its sources, with the stereo measuring branch (§4), and the recording tap (`startRecordingAudio`, `stopRecordingAudio`, §9).
  - `useSound.ts`: React hooks for the engine and its frames.
  - `features.ts`: feature extraction from spectrum, samples, and the left and right channels, with pitch confidence and Melody (testable without audio).
  - `mapping.ts`: the features (`FEATURES`, in five groups), the targets (sliders and seeds, each with what it needs to act and the changes that switch it on, `activate`), and slider values + features + mappings + jumps + Response settings → live parameters (`modulate`, a pure function; Strength and Melody tracking act here). Each slider target takes its range and step from `src/state/sliderScales.ts` (`SLIDER_RANGES`, keyed by target id, `TOLERANCE` for the logarithmic Tolerance slider, and `THORN_REACH` for the cubic Thorn Reach slider), the same table the panels build their range inputs from, so a live value is always one the slider itself can produce and the two cannot drift apart.
  - `flash.ts`: the flash limit's shared budget (`FlashBudget`, `FLASH_LIMITS`, §10), which the driven sliders and the seeds' jumps both draw from (pure).
  - `jumps.ts`: `JumpTracker`, which counts the jumps of each driven seed from the measured frames (each Rate times Strength) and takes each jump frame from the flash budget, and `JUMP_LIMITS`, whose `maxRate` (4.8) follows from `FLASH_LIMITS` (pure, testable without audio).
  - `letters.ts`: the letters of the text (`letterSlots`), their weights, the three levels and the assignment with hysteresis, each level's values (`levelPosition`, `levelSets`), the size of a move between levels (`switchSwing`), and the frame's extra jobs (`buildLetterFrame`, `levelKeyAt`), §5.2; and Thorn turns, §5.3: the turn targets (`isTurnTarget`), the turn groups (`turnGroups`), the turn state (`thornState`, `thornDiffers`, `turnSwing`), the groups' states (`ThornTurns`), and each group's level sets (`turnSets`) (pure).
  - `mappingStore.ts`: a small store, with a hook, for the mappings, the four Response values, and the Drive letters switch; it follows `prefers-reduced-motion` while the page is open. Its changes are recorded for undo (`src/state/history.ts`), and the mappings and Response values are saved with the session (`src/state/persist.ts`), together with the engine's Sensitivity and Release; Drive letters is neither.
  - `keyframes.ts`: the in-between parameter sets of a large change while Glide is on (`keyframes`, `KEYFRAME_LIMITS`, `KEYFRAME_FIELDS`, §5.4; pure).
  - `presets.ts`: the presets (`PRESETS`, §7), each with its name, the one line its ⓘ shows, its start values, and its mappings; and `presetSettings` (pure), which gives what Load leaves: the settings (every Geometry and Experimental group reset, seeds kept, then the start values), the groups that changed, and the notice.

The marker itself is `src/components/LiveMarker.tsx`, and the live seed beside a seed field is `src/components/LiveSeed.tsx`.

- **Pipeline unchanged; live requests carry a `live` flag.** Live parameters go to the geometry worker as compute requests marked `live`, and the worker already drops a superseded request between glyphs. The flag only keeps live results in the separate live cache (below); the geometry is computed the same way, and only in the worker: the page never computes glyphs itself. The scheduler asks the worker for a live frame's glyphs first (`geometryClient.prefetchJobs`) and hands the frame to React only once they have all arrived, so each frame renders once, complete (§2). The client shares that one request out among its pool of workers (2 to 4, glyph by glyph) and it ends only when every worker's part is back, so it is still one frame in flight; with Thorn Burst and Dissolve on, a 200-character Roboto frame takes 698 ms with four workers against 2334 ms with one (README, Geometry worker). Commits stay at most 30 a second, and a commit that never renders stops holding up the next one 1 s after it was committed.
- **One request per frame, in jobs:** a compute request carries `jobs`, each a parameter set with its key and glyph ids (`GeometryJob` in `src/geometry/types.ts`). A live frame is one request: job 0 is the shared parameters for every glyph the canvas shows (the request as before phase H), then the strong level, then the quiet one, each with only the glyph ids of its letters, each once, in reading order. With Thorn turns (§5.3), the turn groups' sets follow, each with only its letters' glyph ids, and job 0 is asked only for the glyphs of the letters that show the shared values and the selected glyph (`FrameJob.within`, `shownGlyphs` in `src/state/geometryClient.ts`), so a frame whose letters show up to 15 sets still computes each glyph about once without levels. The worker computes the jobs in order and the glyphs within each, flushes its results at the end of every job (so each `results` message names one key), names the key in its heartbeat, and ends with one `done`; a newer request still stops it between glyphs. The client (`computeJobs`, `prefetchJobs`) sends only the missing (key, glyph) pairs, waits for a request in flight only when it covers all of them, and lets only job 0's results stand in for a glyph while other settings are computed. With neutral Response settings and Thorn off, the request is exactly the one before phase H.
- **No font, no drive:** the scheduler is told whether a font is loaded. Without one it commits nothing, shows no markers or live seeds, reports no live status, and the seeds do not jump; when the font goes while Sound drives, the sliders and seeds are restored exactly (§10).
- **What follows the live parameters:** the letters (each at its level, and with Thorn on its turn group's state), the text preview (each letter its own shape), a video take (§9), the snap grid drawn on the canvas, and the status bar's description (the last two from the shared values). What keeps the slider values: the sliders, the SVG, PNG and OTF exports, Fit text and Free in the Typography tab, which measure the slider letters, as exports do, and where the text block sits (below).
- **A still text block** (`placementScene` in `src/specimen/artboard.ts`, `useGeometry` in `src/state/useDerivedGeometry.ts`): while Sound drives the letters, the block is placed on the artboard by the letters at the slider values (the slider scene), not by the live frames, and the live letters are drawn at that place. The lines and pens come from the advances, so they are the same in both; only the box measured on the outlines differs. So Sound never moves the block, whatever the effects, seeds, presets, or Response settings. Before, layout measured each live frame's outlines (without their thorns), so seed jumps, Motion contrast, Pitch reactive, and presets such as Jitter, Flicker, Scatter, and Gale still shook the block from frame to frame.
  - The slider letters are usually kept from normal editing. When the sliders, text, font, or typography change while Sound drives the letters, the glyphs still missing are asked for once those have rested 200 ms (`SLIDER_SCENE_DELAY_MS`), one ordinary request per change rather than one per frame of a drag. Until they arrive, the block keeps the slider letters last placed in full for the same shaped text; with none (a new text), the live layout stands in.
  - The warning "The text runs past the canvas edge" is measured on the slider letters too, as the exports use them. A live letter warped further than its slider letter can therefore reach past the artboard edge without the warning: the canvas still shows it, and the preview and a video cut it off at the edge.
  - Freeze changes the sliders, so the block may move once then. Videos draw the same scene at the same place, so they are still too. With Sound off nothing changes.
- **Adaptive frame rate:**
  - Features update every animation frame (`requestAnimationFrame`), so a hidden or covered tab gets none: the letters stop following the sound until the tab is shown again (a recording already stops when the tab is hidden, §9).
  - At most one geometry request is in flight; the next is sent when the last one finishes, so the frame rate follows the cost.
  - The rate is capped at 30 fps, and the Sound tab shows it.
  - Below about 8 fps it suggests lighter settings or a shorter text.
- **Quantised live values:** each value is rounded to its slider's step (seeds are whole numbers already), so repeated values hit the geometry cache instead of recomputing.
- **Separate live cache:** live frames use a small cache of their own in the worker (about 600 entries), so a song does not evict the cached results of normal editing. The page keeps the results of the live parameter sets of two frames, the frame on screen and the one being computed: twice the most sets any of the last 4 live requests asked for, at least 6 (two frames of three levels) and at most 32 (`LIVE_KEPT_KEYS`: two frames of up to 16 sets with Thorn turns, the 15 the letters show and the shared set). It drops the least recently asked for first, so a set still on screen is never dropped while another frame computes, and once the frames are small again it keeps 6 as before.
- **Scope:** only the glyphs in the text and the selected glyph are computed, as today.
- **Idle audio:** the audio context is created inside the first user gesture that needs it (choosing a file or a source, Play, Start listening), suspended after 2 s with nothing playing or listening, and resumed by Play and Start listening. Caveat: in Safari, playback restarted by media keys after that may stay silent until the user presses Play.
- **Measured cost:**

With Crumple, Ripple, Whorl and Slipstream all on, a frame takes about 41 ms (about 24 fps). A repeated value hits the cache in under 0.1 ms, and placing the glyphs and laying out the artboard on the page takes about 0.3 ms per render. Measured again with phase 3 in place, the same within run-to-run noise: 2.4 ms, all three 12 ms, and everything on 37–41 ms (24–27 fps). These Experimental figures predate the rework of Crumple, Slipstream, and Thorn (EXPERIMENTAL_PLAN §4.9), which made each heavier (about 0.6–0.9 ms per glyph at its defaults); the phase H table below measures them again. NOCUR-60 took Crumple's rework back, so its figure here again describes the current Crumple.

## 9. Freeze, export, and repeatability

- **Freeze** writes the live values on screen into the sliders, and the live seeds on screen into the seed fields, and pauses the sound (it pauses the file or stops listening), so the frozen look stays on screen. It is then ordinary, repeatable settings, and one undo step; press Play or Start listening to go on. It is available whenever Sound drives the letters (it does not blink with the beat); pressed while the shared live values match the sliders and seeds, for example between two drum hits, it only pauses. It writes the shared values (§5.2): letters on the quiet or strong level take them too, and so do Thorn turn groups showing older Thorn settings (§5.3). Since it changes the sliders, the text block may move once then (§8). Freeze is off while a video is recorded.
- The SVG, PNG and OTF exports always use the slider values, never live audio. While Sound is live, the Export dialog says so and points to Freeze (the note is hidden for Video).
- Live output depends on timing and is not repeatable; frozen settings are. A recorded microphone video keeps one performance; an audio file's rendered video comes out the same every time (below).
- **Video of an audio file** (NOCUR-91, Export → **Video — sound**; `videoRender.ts`, `videoEncode.ts`, `VideoRender.tsx`): rendered offline instead of recorded. The chosen **Time range** (Start and End in seconds, 0.1 s steps; the whole file by default, at most 10 minutes, at least 0.1 s) is rendered frame by frame from the precomputed plan, the same plan playback uses: each frame at media time t shows what playback shows when t is heard (the planned commits up to t, built into scenes as the canvas builds them, the letters at their levels, the text block placed by the slider letters), glided into with Glide's time and keyframes (§5.4) on the video's own clock, and drawn by `drawArtboard`. So it is faster than real time, smooth however heavy the effects, and identical every time. It is encoded with WebCodecs through the Mediabunny library into MP4, or WebM when MP4 cannot be written ("This browser cannot write MP4: saved as WebM."), with the file's sound for the same stretch when Include audio is on ("This browser cannot encode the sound: the video has none." where it cannot). Options shared with Record: Format, Frame rate, Include audio, and Use the preview look; there is no Length, as the Time range sets it. Size and bitrate as below. A file longer than 6 minutes (the precompute limit) cannot be rendered. The dialog shows the stretch and its length, a progress bar with Cancel ("Cancelled: nothing was saved."), and then the saved file and the stretch. Closing the dialog stops a render.
- **Video of the microphone** (built in phase H for both sources; since NOCUR-91 only the microphone, which has no file to render, is recorded live): records the canvas as it moves with the sound, in real time, every letter at its own level (and with Thorn on, its turn group's state), with the sound. The text block stays where the slider letters place it (§8), so the video does not shake.
  - **Start:** Record in the Sound tab's Record group, or Video in the Export dialog (the live Record shows there when the source is the microphone), whose Record closes the dialog and starts the take in the same click. With an audio file the Record group shows a short note and **Export video…**, which opens Export on Video. A take starts the file (from the current Position) or the microphone if it is not running, waits for the sound and the first drawn frame, and at the end pauses or stops listening only if Record started it. Whole file plays the file from its start with Loop off for the take, and gives Loop back unless the user changed it.
  - **Frames:** a hidden canvas (`RecordingCanvas`) draws the artboard again for every frame shown (`drawArtboard`, nonzero fill, straight segments only). A frame clock at the take's **Frame rate** (24, 25, 30, 50 or 60 fps; 30 by default) takes the canvas as it is (`captureStream(0)` and `requestFrame`, or a capture at that rate where `requestFrame` is missing), each frame due a whole number of frames after the first; a late clock skips the frames it missed. A requested frame is captured only at the canvas's next change, so every tick touches the canvas (one pixel copied onto itself) in the same task, and the frame is taken at the next rendering update; with nothing drawn, the last drawing repeats. The rate is about the chosen one, best effort: frames land on rendering updates, so 60 fps on a 60 Hz screen can drop some, and the file is variable-rate (`MediaRecorder` has no frame-rate setting). Without `requestFrame` no frame clock runs: the browser's capture at that rate takes the canvas when it changes. The pictures change at the live rate, at most 30 a second.
  - **Look:** the canvas in its Color settings, or with Use the preview look, the bottom-right preview's colours and blur; where the browser cannot blur a canvas, the take is recorded without blur and says so. Videos have no transparency: the background colour is always painted.
  - **Size:** the canvas size times its export scale, as PNG, scaled down to fit 3840 px on the long side and 3840 × 2160 in area, in even numbers. Video bitrate 4.5 bits per pixel a second at 30 fps, scaled with the frame rate, within 2–12 Mbps (the cap wins from about 1080p at 30 fps up, so there 50 and 60 fps get about the bitrate of 30) (10 minutes are at most about 0.9 GB at any rate, held in memory); audio 128 kbps.
  - **Format:** MP4 (H.264, AAC) when the browser can write it, else WebM (VP9 or VP8, Opus) with the note "MP4 isn't supported in this browser: saved as WebM." Candidates are tried in order until one starts.
  - **Sound:** the source as heard (the file, or the microphone, which still never reaches the speakers) goes through a delay into the video's audio track. The delay is the time from the sound leaving the audio graph to its letters (`liveLatencyMs`): on the live path the measured live latency, plus, for the file, the output latency (the audio context's base and output latency, about 200 ms on a Bluetooth headset), because the live path holds the file's frames back until they are heard, as the planned commits are timed; while planned commits show, the output latency plus one display frame, at least 40 ms. To that it adds 37 ms (half the analysis window and one display frame) and half a video frame (the average wait for the frame clock), within 40–400 ms, 90 ms and half a frame before any live frame; it is set once at the start. What the listener hears does not change.
  - **End:** the take stops and saves at its Length (Until stopped, 5, 10, 15, 30 or 60 s, or Whole file), at the 10-minute cap, when the sound stops, ends or switches, when the tab is hidden, when the canvas size or scale changes, when the font is closed, and on a recorder error (what was recorded is saved). Stop asks for the canvas as it is at once; then it (and its frame clock) runs 100 ms longer for its last frame, the clock asking for none within 10 ms of the recorder's stop; at its Length, or when the file pauses or ends, the audio delay plus 100 ms, so the end of the sound still in the delay is in the file; a hidden tab, an error, or a size or font change stop it at once. Each end says why, and the saved file's name, length and size ("Saved Roboto-Regular-video.webm: 0:05, 1200 × 800 px.").
  - **File name:** family, style and `video` (or `video-preview` with the preview look), saved once through the same download as the other exports.
  - The options (Format, Length, Frame rate, Include audio, Use the preview look) last for the visit: not saved, not undone, and locked during a take. Closing the page during a take asks first.

## 10. Safety and accessibility

- **Flashing:** fast swings can flash (the WCAG three-flashes threshold).
  - **One budget for all mappings** (built, `FlashBudget` in `src/sound/flash.ts`): every large change (an edge) on screen, from any driven slider or any seed, takes from one shared budget of 6 edges in any 1.25 s, so Sound makes at most 3 flashes a second however many mappings it has. Edges are counted on the measured frames' times over 1.25 s, a little over a second, so frames that reach the screen up to a quarter second later (waiting for the geometry) still keep to 6 in any second on screen. Edges of one measured frame (the sliders' turn and the seeds' jump together) reach the screen together and count once.
  - Continuous mappings (built): each driven slider has a direction and the extreme it has reached that way; moving back from it is a turn. A frame is an edge when the sliders' moves back add up to 10% of a slider's travel: one slider swinging that far, or several smaller swings together, so sliders swinging in step by under 10% each cannot get round the limit. Turns are counted on the slider positions as shown, after rounding to the step. When the budget is spent, the sliders moving back keep their last values until it frees up, and the others pass; the held value is one the slider produced a moment ago (§2), and the markers and Freeze use it too.
  - Beat on a slider is a continuous mapping too, so the same limit holds its pulses.
  - Seeds (built): a jump frame (all seeds that jump in the same frame) is one edge from the same budget. A jump over the limit is skipped, not put off or saved up, since a late jump would no longer follow the sound. With other features, 4.8 jumps a second (at Rate 100% and the feature at 1) is the most the limit allows on average with no slider swinging; busy sliders leave fewer jumps.
  - **Letters on other levels** (§5.2), so that every letter on screen keeps to the limit:
    - **Spread rule:** a driven slider's move back is the largest of its shared move and the move of each level some drawn letter shows (on screen, in the last update, or about to). A level is a monotone image of the shared position (`levelPosition`), so it turns only when the shared value does, its extreme is the image of the shared extreme, and holding the shared value holds every level. Clamping at the slider's ends only shrinks a level's move. With no letter off the shared level the limit runs exactly as before.
    - **Switch measure:** letters moving between levels are a change of their own (`switchSwing`): for each drawn letter that changes level, its share of the text times how far apart the two levels' sliders lie (summed over the driven sliders, in slider travel). A move of 10% or more is an edge from the same budget. It is measured from the levels of the frame the screen shows or is about to show, not from the last update, since several updates can pass before the next frame starts, and also from the levels of every frame shown within the last 250 ms (`LIVE_LIMITS.switchSpanMs`, `screenTrail`), whichever move is larger: a note change reaches the screen over several frames (the pitch is smoothed, and frames come up to 30 a second), each below 10%, and so counts as the one change it shows as. It is charged once per shown frame, and after a move that took from the budget the trail starts afresh from the frame that shows it. In the same measured frame as a slider turn or a seed jump it counts once. When the budget is spent, every letter keeps the level on screen. Direction is ignored, which errs on the safe side. A Motion contrast drift alone stays far below 10% (at most about 2%), so it is never held; a jump of the pitch at Pitch reactive 200% that moves many letters at once is an edge.
    - **Hysteresis** keeps a letter near a boundary from flipping back and forth (§5.2).
    - **Resets:** stopping, a change of Motion contrast or Pitch reactive, and a text edit (another number of letters) start the levels afresh, and the first assignment is no edge, as a target's first appearance is none. A Strength or Melody tracking drag keeps them, so level switches during the drag still take from the budget; the same text restyled keeps them too.
  - **Thorn turns** (§5.3), so that the thorns too keep to the limit: a turn is a change of its own, measured like a move between levels, the group's share of the text times how far its turn targets' sliders move (summed, in slider travel), a new seed counting as a whole travel. A turn of 10% or more takes an edge from the same budget, on the measured frame's time. A turn the budget refuses is not skipped, as a seed's jump is: it waits, the group keeps the state it shows, and it is asked again on the next update. Turns start afresh, every group at once and with no edge, as the levels do (§5.3). With Thorn off there are no turns and the limit runs exactly as before.
  - Pausing, stopping, turning Drive letters off, Strength at 0%, or the font going away returns the sliders and seeds to their own values (exact restore), and playing again starts from them. The budget keeps its edges across that, and the return itself spends one edge (it always shows, whatever the budget says), so a quick pause and play cannot let a second burst through.
  - On the test track, Beat → Distortion · Seed jumps 1.89 times a second on the kick alone (the beat rate) and is held to about 4.3–4.5 a second on 8 beats a second, with at most 6 seed changes on screen in any second.
- **Reduced motion:** with `prefers-reduced-motion`, **Drive letters** starts off (the meters still work) and the Sound tab says why; turning reduced motion on while the page is open switches it off too.
- **Microphone:** only on an explicit click, with a visible indicator, released when stopped.
- **No network:** nothing is uploaded, and no audio leaves the browser. A video is saved as a download on the user's own computer.

## 11. Interface

All labels are in English and short, with explanations behind ⓘ.

- A third tab, **Sound**, beside Geometry and Experimental. The chosen tab is remembered as now. The tab's controls load the first time it is opened, and stay loaded. Its groups, in order: Source, Levels, Mappings, Response, Record.
- **Source:** File / Microphone, File by default (there is no Off). File has Choose file, play/pause, Loop, position, and the file name. Microphone has Start listening / Stop listening and the active indicator; choosing it pauses the file, and choosing File releases the microphone.
- **Layout** (NOCUR-71): five boxes, like a synth plugin: Transport (the source, Drive letters, Preset and Load, Freeze, and the frame rate), Input (Sensitivity and Release knobs beside the meters), Response (four knobs), Modulation (the mappings), and Record (foldable). Every numeric setting is a knob (`Knob.tsx`: drag, keys, double-click for the default, the value typed in a number box) with the range and step of the slider it replaced.
- **Meters** (in the Input box):
  - A strip of 11 small vertical LED meters, one per feature, with short captions (LVL … PAN; the full name is the tooltip and accessible name). Under the strip one line gives the number of Level, or of the meter under the pointer or with keyboard focus (one tab stop; Left and Right move along the meters), with one ⓘ that explains every group in plain words. Pitch confidence has no meter.
  - The numbers: Level in dB, Pitch in Hz ("—" in silence), Pan as the side it leans to ("L 40", "R 40", or "C" within 5% of the centre), the rest in percent; "—" while nothing plays. A meter lights whole segments; Pan's light up or down from the centre (right or left).
  - Beat is a pulse: it jumps to full on each onset and falls back. Like every meter, it moves without transitions, so it works the same with reduced motion.
  - The meters move every frame, the numbers at most 10 times a second, and the values screen readers get at most 4 times a second.
- **Drive letters:** an on/off switch (a checkbox with `role="switch"`, drawn as a small track and knob in the theme's colours); sound moves the letters only while it is on. With reduced motion it starts off and says why (§10). At Strength 0% a note under it says "Strength is 0%: the letters hold still."
- **Mappings:**
  - **Preset** and **Load**, above the rows, with an ⓘ that says what Load resets and that Undo brings back the settings and mappings from before, and lists each preset with one line. Choosing in the list only selects, so browsing it with the keyboard replaces nothing; Load applies the preset (§7). Under the row, a status line says what the last Load did ("Loaded X. Turned off ….
