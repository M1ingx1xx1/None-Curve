# Vector Poly-Font Editor

## 项目实施计划与技术架构

## 产品概述

Vector Poly-Font Editor 是一款纯客户端 Web 应用，用于将字体轮廓转换为可编辑的多边形。设计师载入 `.ttf` 或 `.otf` 文件，检查并调整生成的轮廓，然后导出仅包含多边形路径的 SVG，或生成字体文件。

核心工作流：

```text
载入字体 → 解析字形轮廓 → 展平曲线 → 调整几何形状
          → 在视口中检查 → 导出 SVG 或字体
```

需要区分的是，“仅多边形”表示导出的字形轮廓由直线段组成。SVG 可以直接用 `M` 和 `L` 命令表示。生成字体文件则是另一项工程工作：必须将编辑后的多边形转换为有效字形，并保留所需的字体元数据和度量信息。

# 阶段 A：架构与技术栈

## 1. 建议的技术栈

| 范畴       | 建议技术                       | 职责                                     |
| ---------- | ------------------------------ | ---------------------------------------- |
| UI         | React                          | 控件、文件处理、应用外壳                 |
| 构建与部署 | Webpack                        | 开发服务器、打包、构建 GitHub Pages 版本 |
| 几何渲染   | Paper.js                       | 路径构建、展平、Canvas 渲染              |
| 字体解析   | opentype.js                    | 读取字体元数据、度量信息和字形轮廓       |
| 状态管理   | UI 框架 + 专用几何状态仓库     | 几何重新计算时仍保持控件响应流畅         |
| SVG 导出   | 自定义序列化器或 Paper.js 导出 | 输出明确的`M`/`L` 轮廓               |
| OTF 生成   | 字体生成库或自定义流水线       | 组装字形轮廓、度量信息和字体表           |

UI 层使用 React；几何核心应避免依赖特定框架。将几何操作保存在独立的 TypeScript 模块中，便于测试和复用。


### 组件职责

- **画布视口：** 绘制选中字形或样张，提供缩放和平移，并显示参考线及编辑辅助层。
- **控制面板：** 按设计任务分组展示具名参数，并标注单位、范围和简洁的视觉效果说明。
- **文件输入输出：** 在本地校验并解析字体文件，显示解析错误和字体元数据。
- **几何引擎：** 将解析出的轮廓转换为多边形轮廓，并执行重采样、吸附和扰动。
- **导出引擎：** 将当前几何序列化为 SVG，或将完整字形集交给字体构建器。
- **样张视图：** 预览字符或文本串的间距与字偶距效果。

### 原始曲线骨架视图

解析后的原始轮廓应与派生多边形几何同时保留。在骨架模式中绘制原始曲线段、曲线上锚点、曲线外控制点，以及连接它们的控制柄。原始结构中的点与展平后生成的多边形顶点应采用不同视觉样式，便于设计师对照曲线原稿和解构结果。字体二次曲线每段有一个曲线外控制点；三次曲线每段有两个。

## 3. 数据流

```text
.ttf / .otf
    │
    ▼
文件载入器 ──► opentype.js
                    │
                    │ 字形命令 + 度量信息
                    ▼
               几何适配器
                    │
                    ▼
             已解析的原始曲线
                    │
                    ├── 骨架叠加层（锚点、控制柄、控制点）
                    ▼
          Paper.js Path / 轮廓
                    │
                    ├── 展平曲线
                    ├── 重采样或简化
                    ├── 网格吸附 / 角度锁定
                    └── 添加顶点位移
                    │
                    ▼
             规范多边形几何
                │             │
                ▼             ▼
             画布渲染器    导出引擎
                          ├── M/L SVG
                          └── 字体生成
```

将**规范多边形几何**作为唯一事实来源。画布和导出器都应使用它，而不是各自重新计算路径。将字体度量信息与轮廓一并保存，使字形预览和导出能够保留字宽（advance width）与左右边距（side bearings）。

## 4. 状态与实时更新策略

将状态分为三层：

1. **文档状态：** 已载入字体、当前选中字形、字形度量信息、导出元数据。
2. **参数状态：** 每段曲线细分数或展平容差、目标点间距、吸附、抖动和显示选项。
3. **派生几何：** 当前字形或样张经过处理后的多边形轮廓。

为保证滑块操作流畅，应立即更新控件状态，再单独安排几何计算。使用 `requestAnimationFrame` 合并连续快速更新。处理较大的字形集时，可将重新计算移入 Web Worker，并传递紧凑的类型化数组或序列化轮廓数据。

建议的更新流程：

```text
滑块输入 → 更新参数值 → 安排重新计算
          → 生成派生几何 → 更新画布
```

避免每次几何更新都重建无关的 UI 组件。可按字形和参数组合缓存几何结果。拖动控件期间可以先渲染低成本预览，控件停下后再计算最终精度的几何。

# 阶段 B：核心矢量算法

## 1. 消除曲线：线性化

字体轮廓通常由二次或三次贝塞尔曲线段组成。线性化是用一串相连的直线段近似每条曲线。

Paper.js 的 `path.flatten(tolerance)` 会对曲线采样，直到直线近似与曲线之间的偏差不超过指定几何容差。容差越小，通常生成的线段越多、近似越精确；容差越大，线段越少，折面感也越明显。

编辑器还应提供直接的**每段曲线线段数**控制，让设计师指定每条原始曲线拆成几段直线。对于指定线段数 `N` 的曲线，在 `t = i/N`（`i = 0…N`）处采样，再将相邻采样点连接成直线。这种控制直观且结果可预测；基于容差的展平则是自适应的：曲率较大的位置增加线段，接近直线的位置减少线段。两者应作为可切换的模式呈现，避免让人以为同一个滑块同时控制两种行为。在固定线段数模式下，可加入最低质量检查，或对近似误差明显过大的曲线显示提示。

```text
原始曲线：              展平后的轮廓：

      ╭───╮             •──•──•
    ╭─╯   ╰─╮            \      \
   ●         ●            •──────•
```

容差必须对应清楚的坐标系。UI 可以将其呈现为设计空间或预览空间中的距离，再由几何引擎换算为字体单位。由于字形会缩放显示，需明确该控制是否与显示缩放无关。

展平后应验证闭合轮廓仍保持闭合，且输出中只包含直线段。

## 2. 重采样与锚点控制

展平控制曲线近似误差，但不能保证点间距均匀，也不能保证锚点分布符合设计师的预期。重采样是控制点分布的第二种手段。

### 细分：增加点

对每一条线段：

1. 计算线段长度。
2. 将线段分割成多个不超过目标间距的小段。
3. 在各个分割位置插入新点。

这会增加锚点密度，同时让新增点保持在线段原有的多边形边上。

```text
之前：  A────────────B
之后：  A──•──•──•───B
```

细分会增加控制点，但无法还原展平时已经舍弃的曲率。

### 简化：减少点

Ramer-Douglas-Peucker（RDP）算法会减少点序列，同时让简化后的线与原始线之间的偏差保持在指定距离阈值内。它能保留整体轮廓，但可能移除小角、狭窄细节或刻意设计的折面。

应在展平后使用该算法，并考虑保护极值点、角点或用户固定的锚点等关键特征。不要把简化和展平容差当作同一个控制：展平容差决定曲线近似程度；简化则决定如何减少已有点序列。

## 3. 几何变换

### 网格吸附

网格大小为 `g` 时，将每个坐标四舍五入到最近的网格倍数：

```text
x' = round(x / g) × g
y' = round(y / g) × g
```

网格吸附可以让几何形状显得利落、对齐，但网格过大会扭曲字腔和较窄的字干。应允许设计师独立开关吸附，并在视口中显示网格。

### 角度锁定

角度锁定会把边的方向限制在一组允许的角度内，例如 0°、45°、90° 和 135°。给定一条边的向量后，先计算其角度并找出最近的允许角度，再按指定约束（例如保持边长或端点位置）重新计算端点。

UI 应说明操作时哪个锚点保持固定，否则用户可能会遇到意料之外的形状移动。

### 顶点偏移与噪声

噪声会移动顶点，以产生可控的不规则感。基本模型是为每个顶点施加确定性偏移：

```text
p' = p + amplitude × noise(seed, vertexIndex, frequency)
```

**法线偏向（normal bias）**控制位移主要沿轮廓的垂直方向、沿轮廓切线方向，或介于两者之间。稳定的随机种子可让形状在重绘和导出时保持一致。若种子不稳定，字形可能每次画布重绘时都发生变化。

按明确顺序执行变形。例如：

```text
展平 → 重采样 / 简化 → 吸附 / 角度锁定 → 抖动
```

这些操作通常不能随意交换顺序，因此应在 UI 或导出元数据中记录处理顺序。

# 阶段 C：设计师与开发者协作及 UI 规范

## 1. 共享词汇

| 开发术语                             | 面向设计师的术语       | 控件改变的内容                     |
| ------------------------------------ | ---------------------- | ---------------------------------- |
| 展平容差（Flatten tolerance）        | 曲线近似度             | 曲线与多边形近似轮廓之间的最大偏差 |
| 每段曲线线段数（Segments per curve） | 每段曲线拆分出的直线数 | 每条原始曲线段生成的直边数量       |
| 细分步长（Subdivision step）         | 锚点间距 / 密度        | 沿多边形边添加锚点的距离           |
| 简化 epsilon                         | 锚点精简               | 被移除的几何细节数量               |
| Vertex                               | 锚点                   | 字形轮廓上的可编辑点               |
| 轮廓绕向（Contour winding）          | 路径方向               | 描述轮廓的方向；与字腔的解释有关   |
| 字宽（Advance width）                | 字符间距宽度           | 文本排版时为该字形预留的水平距离   |
| 左右边距（Side bearing）             | 左 / 右留白            | 字形轮廓与字宽边界之间的空间       |
| 法线向量（Normal vector）            | 轮廓垂线方向           | 与轮廓边垂直的方向                 |
| Seed                                 | 变化种子               | 可重复生成噪声图样的起始值         |
| 坐标单位                             | 字体单位 / 设计单位    | 轮廓与度量信息使用的内部单位       |

设计师界面中如需呈现库或实现细节，应同时提供解释，不要只展示内部术语。

## 2. 视口布局与线框逻辑

```text
┌───────────────────────────────────────────────────────────┐
│ 字体名称 · 字形数量                    导入  SVG  OTF    │
├────────────┬──────────────────────────────┬───────────────┤
│ 字形列表   │                              │ 控制面板      │
│ A B C ...  │          画布视口            │ 解构          │
│            │                              │ 几何 / 网格   │
│            │   基线 ──────────────────── │ 扰动          │
│            │   大写字高 ──────────────── │ 导出          │
├────────────┴──────────────────────────────┴───────────────┤
│ 轮廓 / 填充 · 缩放 · 当前字形 · 处理状态                   │
└───────────────────────────────────────────────────────────┘
```

### 轮廓模式

显示：

- 多边形轮廓与锚点。
- 可选的顶点编号和轮廓方向。
- 可用时显示边界框、基线、x-height、小写字高、大写字高以及升部 / 降部参考线。
- 启用吸附时显示网格。
- 当前字形的选中状态；后续还可支持单个锚点的选中状态。
- **骨架**叠加层：显示原始曲线上的锚点、曲线外控制点和控制柄；提供开关，以便对照原始曲线结构和生成的多边形顶点。

可将方向向量作为可选的诊断叠加层。除非用户可以直接编辑，否则应将它称为轮廓方向指示；多边形边本身没有贝塞尔控制柄。

### 填充模式

以实心字形检查整体轮廓。支持单字形视图和文本样张视图，方便评估节奏、间距、字腔和重复字形。解析器和导出流水线支持时应保留字宽与字偶距，并明确提示字体中不受支持的特性。

## 3. 控制面板规范

采用紧凑、高对比度的控件，展示明确标签、数值和重置操作。按设计意图分组，而不是按代码模块分组。

### 组 1：解构

- **展平模式：** 自适应曲线近似，或固定每段曲线的线段数。
- **曲线近似度：** 展平容差。
- **每段曲线线段数：** 固定线段数模式下，每条原始曲线生成的直线段数量（整数）。
- **锚点间距：** 锚点之间的目标最大距离。
- **锚点精简：** 可选的简化阈值。
- 添加简短效果提示，例如：“容差越低，越贴近原始曲线”以及“每段曲线线段越多，近似越精细”。

### 组 2：几何与网格

- **网格吸附：** 开 / 关。
- **网格大小：** 以设计单位表示的网格间隔。
- **角度锁定：** 关闭、45°，或 45° 与 90° 约束。
- **固定锚点行为：** 说明操作时固定的是首点、质心还是选中锚点。

### 组 3：扰动 / 抖动

- **噪声幅度：** 最大位移量。
- **噪声频率：** 沿轮廓变化的快慢。
- **法线偏向：** 切线方向与垂直轮廓方向之间的位移比例。
- **种子：** 数值输入框或重新生成按钮，用于获得可重复的变化。
- 明确提供噪声幅度为零的状态和快速重置操作。

### 组 4：导出选项

- **SVG 规范：** 单位、viewBox 行为、填充规则和数值精度。
- **OTF 元数据：** 字族名称、字形样式、每 em 单位数以及命名字段。
- **字体覆盖范围：** 当前选中字形、当前字符集或所有已解析字形。
- 下载前显示校验摘要，包括缺失或不受支持的字形数据。

## 4. 滑块、公式与设计效果对应关系

| UI 控件        | 几何关系                       | 常见视觉效果                           |
| -------------- | ------------------------------ | -------------------------------------- |
| 曲线近似度     | 曲线与线段之间的误差阈值       | 数值越低，轮廓越平滑、锚点越多         |
| 每段曲线线段数 | 每段原始曲线固定生成的线段数量 | 数值越高，越贴近曲线且顶点越多         |
| 锚点间距       | 细分后线段的最大长度           | 数值越低，锚点越密、间距越均匀         |
| 锚点精简       | RDP 距离阈值                   | 数值越高，锚点越少、轮廓越简化         |
| 网格大小       | 坐标量化间隔                   | 数值越大，对齐感越强，形状改变也越明显 |
| 角度锁定       | 取最近的允许边角度             | 约束越强，边缘越几何化                 |
| 噪声幅度       | 顶点最大位移量                 | 数值越大，轮廓越粗糙或不规则           |
| 噪声频率       | 沿轮廓变化的频率               | 数值越高，扰动越密集、尺度越小         |
| 法线偏向       | 切线与法线方向的位移混合比例   | 越偏法线方向，对外轮廓的影响越明显     |

# 阶段 D：分步实施路线图

## 里程碑 1：MVP

**目标：** 验证单个字体、单个字形的完整多边形处理流程。

- 搭建 React、TypeScript 与 Webpack。
- 加入本地字体文件载入和基础错误处理。
- 使用 opentype.js 解析字体并选择字形。
- 将字形轮廓转换为 Paper.js 几何对象。
- 展平曲线并渲染多边形。
- 导出只包含明确 `M` 和 `L` 命令的 SVG。
- 验证导出中没有 `C` 或 `Q` 命令，且闭合轮廓得到保留。

**验收结果：** 用户能够载入字体、查看某个字形的多边形近似结果、调整基础展平参数并下载 SVG。

## 里程碑 2：交互式锚点控制与参数滑块

**目标：** 将多边形变为响应式设计工作区。

- 添加多边形锚点标记、原始曲线骨架叠加层（曲线上锚点、曲线外控制点和控制柄），以及轮廓 / 填充显示模式。
- 添加自适应展平容差和固定每段曲线线段数两种模式，以及锚点间距与简化控制。
- 添加缩放、平移、字形选择和样张预览。
- 将 UI 控件状态与派生几何分离。
- 合并连续的滑块更新；若性能分析发现主线程受阻，则使用 Web Worker。
- 添加重置功能和可复现的参数预设。

**验收结果：** 设计师能够比较不同几何版本，并理解控件对锚点密度与轮廓形态的影响。

## 里程碑 3：高级几何约束与 OTF 生成

**目标：** 从 SVG 输出扩展到可复用的字体输出。

- 实现网格吸附、角度锁定。
- 添加确定性顶点噪声和法线偏向。
- 定义字体元数据和字形覆盖范围选项。
- 构建或集成支持多边形轮廓及所需字体表的字体写入器。
- 保留字宽、左右边距、轮廓闭合和字腔处理。
- 通过解析器重新打开生成字体，并预览代表性字形，以验证输出。

OTF 生成不只是写入路径：输出还需要有效的字形记录、度量信息、命名、字符映射以及其他必需字体表。在确定实现方案前，应确认所选字体写入器支持目标轮廓格式和浏览器端下载流程。

**验收结果：** 用户能够导出轮廓由多边形组成、并保留受支持字形集基础度量信息的字体文件。

## 里程碑 4：完善体验与 GitHub Pages 部署

**目标：** 交付稳定、统一且可作为静态站点运行的工具。

- 完成深色 Brutalist / 瑞士极简主义视觉系统。
- 打磨字体排印、间距、焦点状态、提示信息和键盘操作体验。
- 补齐空状态、载入状态、错误状态和导出进度状态。
- 使用具有复杂轮廓、字腔和大量字形的代表性字体进行检查。
- 配置 Webpack 的 public path，使其适配 GitHub Pages 仓库 URL。
- 添加 GitHub Actions 工作流，构建并发布静态应用。
- 确认所有文件处理和导出均可在浏览器中完成，无需服务器。

**验收结果：** 应用部署至 GitHub Pages，且全部已文档化的工作流程都能在浏览器中完成。
