# Vector Poly-Font Editor

[English](PHASE.md) · **中文**

## 项目实施计划与技术架构

## 产品概述

Vector Poly-Font Editor 是一款纯客户端 Web 应用，用于将字体轮廓转换为可编辑的多边形。设计师载入 `.ttf` 或 `.otf` 文件，检查并调整生成的轮廓，然后导出仅包含多边形路径的 SVG，或生成字体文件。

核心工作流：

```text
载入字体 → 解析字形轮廓 → 展平曲线 → 调整几何形状
          → 在视口中检查 → 导出 SVG 或字体
```

字体编辑器是主工具，约占产品与设计重点的 70%。声音是次要扩展，约占 30%；它驱动字体编辑器现有的几何参数，不应成为使用核心字体流程的前置条件。这是规划投入比例，不是界面面积的硬性要求。默认入口仍是字体编辑器。

需要区分的是，“仅多边形”表示导出的字形轮廓由直线段组成。SVG 可以直接用 `M` 和 `L` 命令表示。生成字体文件则是另一项工程工作：必须将编辑后的多边形转换为有效字形，并保留所需的字体元数据和度量信息。

# 阶段 A：架构与技术栈

## 1. 建议的技术栈

> **实际采用（实现状态）：** 构建为 Vite（而非 Webpack）；字体解析用 fontkit（支持 TTF / OTF / WOFF / WOFF2）；几何核心为自写的纯 TypeScript 模块（`src/geometry/`，未使用 Paper.js），画布用 SVG 渲染；SVG 导出为自写序列化器（`src/export/svg.ts`）；OTF 生成用 opentype.js 写入、fontkit 回读校验（`src/export/fontFile.ts`）。下表保留为最初建议。

| 范畴       | 建议技术                       | 职责                                     |
| ---------- | ------------------------------ | ---------------------------------------- |
| UI         | React                          | 控件、文件处理、应用外壳                 |
| 构建与部署 | Webpack                        | 开发服务器、打包、构建 GitHub Pages 版本 |
| 几何渲染   | Paper.js                       | 路径构建、展平、Canvas 渲染              |
| 字体解析   | opentype.js                    | 读取字体元数据、度量信息和字形轮廓       |
| 状态管理   | UI 框架 + 专用几何状态仓库     | 几何重新计算时仍保持控件响应流畅         |
| SVG 导出   | 自定义序列化器或 Paper.js 导出 | 输出明确的`M`/`L` 轮廓               |
| OTF 生成   | 字体生成库或自定义流水线       | 组装字形轮廓、度量信息和字体表           |

UI 层使用 React；几何核心应避免依赖特定框架。将几何操作保存在独立的 TypeScript 模块中，便于测试和复用。

### 组件职责

- **画布视口：** 绘制选中字形或样张，提供缩放和平移，并显示参考线及编辑辅助层。
- **控制面板：** 按设计任务分组展示具名参数，并标注单位、范围和简洁的视觉效果说明。
- **文件输入输出：** 在本地校验并解析字体文件，显示解析错误和字体元数据。
- **几何引擎：** 将解析出的轮廓转换为多边形轮廓，并执行重采样、吸附和扰动。
- **导出引擎：** 将当前几何序列化为 SVG，或将完整字形集交给字体构建器。
- **样张视图：** 预览字符或文本串的间距与字偶距效果。

### 原始曲线骨架视图

解析后的原始轮廓应与派生多边形几何同时保留。在骨架模式中绘制原始曲线段、曲线上锚点、曲线外控制点，以及连接它们的控制柄。原始结构中的点与展平后生成的多边形顶点应采用不同视觉样式，便于设计师对照曲线原稿和解构结果。字体二次曲线每段有一个曲线外控制点；三次曲线每段有两个。

## 3. 数据流

```text
.ttf / .otf
    │
    ▼
文件载入器 ──► opentype.js
                    │
                    │ 字形命令 + 度量信息
                    ▼
               几何适配器
                    │
                    ▼
             已解析的原始曲线
                    │
                    ├── 骨架叠加层（锚点、控制柄、控制点）
                    ▼
          Paper.js Path / 轮廓
                    │
                    ├── 展平曲线
                    ├── 重采样或简化
                    ├── 网格吸附 / 角度锁定
                    └── 添加顶点位移
                    │
                    ▼
             规范多边形几何
                │             │
                ▼             ▼
             画布渲染器    导出引擎
                          ├── M/L SVG
                          └── 字体生成
```

将**规范多边形几何**作为唯一事实来源。画布和导出器都应使用它，而不是各自重新计算路径。将字体度量信息与轮廓一并保存，使字形预览和导出能够保留字宽（advance width）与左右边距（side bearings）。

## 4. 状态与实时更新策略

将状态分为三层：

1. **文档状态：** 已载入字体、当前选中字形、字形度量信息、导出元数据。
2. **参数状态：** 每段曲线细分数或展平容差、目标点间距、吸附、抖动和显示选项。
3. **派生几何：** 当前字形或样张经过处理后的多边形轮廓。

为保证滑块操作流畅，应立即更新控件状态，再单独安排几何计算。使用 `requestAnimationFrame` 合并连续快速更新。处理较大的字形集时，可将重新计算移入 Web Worker，并传递紧凑的类型化数组或序列化轮廓数据。

实时字形画布是主要反馈区域，参数变化时应持续可见。载入字体只建立可编辑预览，不生成结果文件；导出是用户明确触发的独立操作。重新计算较耗时时保留最近一次有效预览并标示处理中，不要用仅有导出结果的页面替代画布。

建议的更新流程：

```text
滑块输入 → 更新参数值 → 安排重新计算
          → 生成派生几何 → 更新画布
```

避免每次几何更新都重建无关的 UI 组件。可按字形和参数组合缓存几何结果。拖动控件期间可以先渲染低成本预览，控件停下后再计算最终精度的几何。

# 阶段 B：核心矢量算法

## 1. 消除曲线：线性化

字体轮廓通常由二次或三次贝塞尔曲线段组成。线性化是用一串相连的直线段近似每条曲线。

Paper.js 的 `path.flatten(tolerance)` 会对曲线采样，直到直线近似与曲线之间的偏差不超过指定几何容差。容差越小，通常生成的线段越多、近似越精确；容差越大，线段越少，折面感也越明显。

编辑器还应提供直接的**每段曲线线段数**控制，让设计师指定每条原始曲线拆成几段直线。对于指定线段数 `N` 的曲线，在 `t = i/N`（`i = 0…N`）处采样，再将相邻采样点连接成直线。这种控制直观且结果可预测；基于容差的展平则是自适应的：曲率较大的位置增加线段，接近直线的位置减少线段。两者应作为可切换的模式呈现，避免让人以为同一个滑块同时控制两种行为。在固定线段数模式下，可加入最低质量检查，或对近似误差明显过大的曲线显示提示。

```text
原始曲线：              展平后的轮廓：

      ╭───╮             •──•──•
    ╭─╯   ╰─╮            \      \
   ●         ●            •──────•
```

容差必须对应清楚的坐标系。UI 可以将其呈现为设计空间或预览空间中的距离，再由几何引擎换算为字体单位。由于字形会缩放显示，需明确该控制是否与显示缩放无关。

展平后应验证闭合轮廓仍保持闭合，且输出中只包含直线段。

## 2. 重采样与锚点控制

展平控制曲线近似误差，但不能保证点间距均匀，也不能保证锚点分布符合设计师的预期。重采样是控制点分布的第二种手段。

### 细分：增加点

对每一条线段：

1. 计算线段长度。
2. 将线段分割成多个不超过目标间距的小段。
3. 在各个分割位置插入新点。

这会增加锚点密度，同时让新增点保持在线段原有的多边形边上。

```text
之前：  A────────────B
之后：  A──•──•──•───B
```

细分会增加控制点，但无法还原展平时已经舍弃的曲率。

### 简化：减少点

Ramer-Douglas-Peucker（RDP）算法会减少点序列，同时让简化后的线与原始线之间的偏差保持在指定距离阈值内。它能保留整体轮廓，但可能移除小角、狭窄细节或刻意设计的折面。

应在展平后使用该算法，并考虑保护极值点、角点或用户固定的锚点等关键特征。不要把简化和展平容差当作同一个控制：展平容差决定曲线近似程度；简化则决定如何减少已有点序列。

## 3. 几何变换

### 网格吸附

网格大小为 `g` 时，将每个坐标四舍五入到最近的网格倍数：

```text
x' = round(x / g) × g
y' = round(y / g) × g
```

网格吸附可以让几何形状显得利落、对齐，但网格过大会扭曲字腔和较窄的字干。应允许设计师独立开关吸附，并在视口中显示网格。

### 角度锁定

角度锁定会把边的方向限制在一组允许的角度内，例如 0°、45°、90° 和 135°。给定一条边的向量后，先计算其角度并找出最近的允许角度，再按指定约束（例如保持边长或端点位置）重新计算端点。

UI 应说明操作时哪个锚点保持固定，否则用户可能会遇到意料之外的形状移动。

### 顶点偏移与噪声

噪声会移动顶点，以产生可控的不规则感。基本模型是为每个顶点施加确定性偏移：

```text
p' = p + amplitude × noise(seed, vertexIndex, frequency)
```

**法线偏向（normal bias）**控制位移主要沿轮廓的垂直方向、沿轮廓切线方向，或介于两者之间。稳定的随机种子可让形状在重绘和导出时保持一致。若种子不稳定，字形可能每次画布重绘时都发生变化。

按明确顺序执行变形。例如：

```text
展平 → 重采样 / 简化 → 吸附 / 角度锁定 → 抖动
```

这些操作通常不能随意交换顺序，因此应在 UI 或导出元数据中记录处理顺序。

# 阶段 C：设计师与开发者协作及 UI 规范

## 1. 共享词汇

| 开发术语                             | 面向设计师的术语       | 控件改变的内容                     |
| ------------------------------------ | ---------------------- | ---------------------------------- |
| 展平容差（Flatten tolerance）        | 曲线近似度             | 曲线与多边形近似轮廓之间的最大偏差 |
| 每段曲线线段数（Segments per curve） | 每段曲线拆分出的直线数 | 每条原始曲线段生成的直边数量       |
| 细分步长（Subdivision step）         | 锚点间距 / 密度        | 沿多边形边添加锚点的距离           |
| 简化 epsilon                         | 锚点精简               | 被移除的几何细节数量               |
| Vertex                               | 锚点                   | 字形轮廓上的可编辑点               |
| 轮廓绕向（Contour winding）          | 路径方向               | 描述轮廓的方向；与字腔的解释有关   |
| 字宽（Advance width）                | 字符间距宽度           | 文本排版时为该字形预留的水平距离   |
| 左右边距（Side bearing）             | 左 / 右留白            | 字形轮廓与字宽边界之间的空间       |
| 法线向量（Normal vector）            | 轮廓垂线方向           | 与轮廓边垂直的方向                 |
| Seed                                 | 变化种子               | 可重复生成噪声图样的起始值         |
| 坐标单位                             | 字体单位 / 设计单位    | 轮廓与度量信息使用的内部单位       |

设计师界面中如需呈现库或实现细节，应同时提供解释，不要只展示内部术语。

## 2. 视口布局与线框逻辑

```text
┌───────────────────────────────────────────────────────────┐
│ 字体名称 · 字形数量                              导入  导出 │
├──────────────────────┬───────────────────────────────────────┤
│ 左侧控制面板         │ 右侧实时画布                          │
│ 字形选择             │ 原始骨架 / 当前多边形                 │
│ 解构                 │ 轮廓 / 填充渲染                       │
│ 几何与网格           │ 参考线与样张预览                      │
│ 扰动 / 声音          │ 控件变化时同步更新                    │
│ 导出选项             │                                       │
├──────────────────────┴───────────────────────────────────────┤
│ 预览模式 · 缩放 · 当前字形 · 处理状态                        │
└──────────────────────────────────────────────────────────────┘
```

### 轮廓模式

显示：

- 多边形轮廓与锚点。
- 可选的顶点编号和轮廓方向。
- 可用时显示边界框、基线、x-height、小写字高、大写字高以及升部 / 降部参考线。
- 启用吸附时显示网格。
- 当前字形的选中状态；后续还可支持单个锚点的选中状态。
- **骨架**叠加层：显示原始曲线上的锚点、曲线外控制点和控制柄；提供开关，以便对照原始曲线结构和生成的多边形顶点。

可将方向向量作为可选的诊断叠加层。除非用户可以直接编辑，否则应将它称为轮廓方向指示；多边形边本身没有贝塞尔控制柄。

视觉形态参考为 `resources/reference/font_change_sample.png`：它展示曲线轮廓向不同细节密度多边形轮廓的变化，用于指导实时画布和线段数控制的预览效果，不要求像素级复刻。

### 填充模式

以实心字形检查整体轮廓；编辑时持续显示渲染结果。支持单字形视图和文本样张视图，方便评估节奏、间距、字腔和重复字形。解析器和导出流水线支持时应保留字宽与字偶距，并明确提示字体中不受支持的特性。

## 3. 控制面板规范

采用紧凑、高对比度的控件，展示明确标签、数值和重置操作。按设计意图分组，而不是按代码模块分组。

### 组 1：解构

- **展平模式：** 自适应曲线近似，或固定每段曲线的线段数。
- **曲线近似度：** 展平容差。
- **每段曲线线段数：** 固定线段数模式下，每条原始曲线生成的直线段数量（整数）。
- **锚点间距：** 锚点之间的目标最大距离。
- **锚点精简：** 可选的简化阈值。
- 添加简短效果提示，例如：“容差越低，越贴近原始曲线”以及“每段曲线线段越多，近似越精细”。

### 组 2：几何与网格

- **网格吸附：** 开 / 关。
- **网格大小：** 以设计单位表示的网格间隔。
- **角度锁定：** 关闭、45°，或 45° 与 90° 约束。
- **固定锚点行为：** 说明操作时固定的是首点、质心还是选中锚点。

### 组 3：扰动 / 抖动

- **噪声幅度：** 最大位移量。
- **噪声频率：** 沿轮廓变化的快慢。
- **法线偏向：** 切线方向与垂直轮廓方向之间的位移比例。
- **种子：** 数值输入框或重新生成按钮，用于获得可重复的变化。
- 明确提供噪声幅度为零的状态和快速重置操作。

### 组 4：导出选项

- **SVG 规范：** 单位、viewBox 行为、填充规则和数值精度。
- **OTF 元数据：** 字族名称、字形样式、每 em 单位数以及命名字段。
- **字体覆盖范围：** 当前选中字形、当前字符集或所有已解析字形。
- **视频**（阶段 H）：Format（MP4 或 WebM）、Length、Include audio 和 Use the preview look；尺寸一行显示视频的像素、帧率和格式。
- 下载前显示校验摘要，包括缺失或不受支持的字形数据。

## 4. 滑块、公式与设计效果对应关系

| UI 控件        | 几何关系                       | 常见视觉效果                           |
| -------------- | ------------------------------ | -------------------------------------- |
| 曲线近似度     | 曲线与线段之间的误差阈值       | 数值越低，轮廓越平滑、锚点越多         |
| 每段曲线线段数 | 每段原始曲线固定生成的线段数量 | 数值越高，越贴近曲线且顶点越多         |
| 锚点间距       | 细分后线段的最大长度           | 数值越低，锚点越密、间距越均匀         |
| 锚点精简       | RDP 距离阈值                   | 数值越高，锚点越少、轮廓越简化         |
| 网格大小       | 坐标量化间隔                   | 数值越大，对齐感越强，形状改变也越明显 |
| 角度锁定       | 取最近的允许边角度             | 约束越强，边缘越几何化                 |
| 噪声幅度       | 顶点最大位移量                 | 数值越大，轮廓越粗糙或不规则           |
| 噪声频率       | 沿轮廓变化的频率               | 数值越高，扰动越密集、尺度越小         |
| 法线偏向       | 切线与法线方向的位移混合比例   | 越偏法线方向，对外轮廓的影响越明显     |

# 阶段 D：分步实施路线图

# 阶段 E：声音驱动几何

> **实现状态：** 进行中。第 1、2 阶段已完成：第 1、2 步；第 3 步中的连续映射（滑块位置 + Depth × 特征，截断后取整到滑块档位）；第 4 步（同一时间最多一个几何请求，上限 30 fps，实时帧使用单独的缓存，连续映射带闪烁限制）；以及第 5 步中的 Source、电平表、Sensitivity、Smoothing（现名 Release）、Reset sound、带 Drive letters 开关的映射列表、Freeze、滑块上的实时值标记，和 Sound 标签页与状态栏中的 "Live · N fps"。第 3、4 阶段中也已完成：10 个特征，分五组，含 Pitch 和 Pan（第 2 步），以及它们需要的立体声分支（第 1 步）；三个种子上的 Jump 映射（带 Rate 和闪烁限制），以及滑块上的 Beat 脉冲（第 3 步）；会自己打开所需设置的目标（连同重做后的 Experimental 效果的滑块共 43 个）、紧凑的电平表、实时种子、带 Preset 和 Load 的十个预设、作为默认来源且没有 Off 的 File，以及改为开关的 Drive letters（第 5 步）。第 3 步中的 Step 映射（Allowed directions、Sides、Rings）和实时 SVG 重绘的测量尚未实现；视频录制（第 6 步）已在阶段 H 中完成。阶段 F（见下文）把闪烁限制改成滑块和种子共用的一份额度，给 Beat 加上对持续低音的门控，让 Sound 在没有载入字体时不驱动，并在两次访问之间保存映射。见 [SOUND_PLAN.zh.md](SOUND_PLAN.zh.md)。

这是次要产品路线（约占规划重点的 30%）。Sound 标签页用实时声音驱动 Geometry 和 Experimental 中已有的参数。该功能保持可选；关闭时，字体工具的表现与之前完全相同。

产品要求以 [PRD 第 11 节](PRD.zh.md#11-声音驱动几何新增产品方向) 和详细的 [声音计划](SOUND_PLAN.zh.md) 为准。

1. **音频引擎：** 通过 Web Audio 接入 File（默认）和 Microphone 两种来源，在本地解码和分析；没有 Off 来源。音频上下文在第一次需要它的用户操作中创建，空闲时暂停。麦克风只在用户明确点击后启动，停止时释放。
   - 在 20 Hz 高通之后，一条立体声测量分支（上混到两个声道、一个声道分离器和两个分析器）给出左右声道；单声道来源读作居中。左右声道的读数会与混合后的数据块核对，如果两次读取之间音频线程渲染了新数据就重新读取；仍对不上时，保持上一对对得上的读数。扬声器和麦克风的连接方式不变。
2. **特征：** 对每个分析帧计算的纯函数，共 10 个，分五组（`src/sound/mapping.ts` 中的 `FEATURES`），由第 3 阶段最初测量的 20 个合并而来（阶段 H 在 Tone 中加入第 11 个：Melody）：
   - Loudness：Level（RMS）和 Swell（缓慢平滑的 Level：上升 300 ms，回落 2 s）。
   - Bands：Bass / Mids / Treble 频带能量（20–250 Hz、250–2000 Hz、2000 Hz 到奈奎斯特频率），每个都与自己最近最响的时刻相比。
   - Tone：Brightness（频谱质心）；Pitch（在降到最多 24 kHz 的采样上用 YIN 求音高，55 Hz → 0 到 1760 Hz → 1，对数刻度；无音高时保持上一个音，静音时为 0）。
   - Rhythm：Beat（基于频谱通量和自适应阈值的起音，来自两个检测器：整个频谱，以及专门听底鼓的 20–150 Hz；一道能量门只在检测器所听的某个倍频程频带比它最近 100 ms 内的最大值高出至少 2 dB 时才让它触发，所以持续的嗡嗡低音不会产生节拍），一个在起音时跳到 1、再按释放时间回落的脉冲；Activity（取 Change 和 Pace 中较大的那个：Change 是频谱通量比最近中位数高出多少，相对于最近这种高出量的最大值，但比较基准从不低于这一帧压缩后频谱的四分之一，所以持续的声音（包括噪声）保持在 0 附近；Pace 是最近 2 s 内每秒的 Beat 起音数 ÷ 8）。
   - Stereo：Pan（左 −1 到右 +1，唯一的双向特征）。
   - 快速起音、可调释放和静音门限（Swell 和 Pitch 有自己固定的时间）。
   - 开销：在 48 kHz 下每帧约 90 µs（加入第 3 阶段的特征之前约 35 µs；合并成 10 个之后不变）。
3. **调制：** 一个纯函数，把滑块值、特征和映射转换为实时参数，并取整到滑块档位、截断到范围内。连续映射把 Depth × 特征 加到滑块位置上（沿滑块的绘制方向，0–1），所以对数刻度的滑块（如 Tolerance）沿滑道均匀移动。事件映射分为 Jump（种子）、Step（可选值）和脉冲（跃起后回落）。整个 Sound，滑块和种子加在一起，由一份共用额度限制在每秒 3 次闪烁以内（`src/sound/flash.ts`）。
   - Jump：三个种子（Distortion · Seed、Random anchors · Seed、Experimental 的 Seed）是 `jump` 类型的目标（`src/sound/jumps.ts`）。Depth 就是 Rate（0–100%）：配 Beat 时，Rate 100% 每次起音种子前进一个（50%：每隔一次起音，25%：每四次起音）；配其他特征时，每秒最多跳 4.8 次 × Rate × 特征值。每个跳变帧都从被驱动滑块共用的闪烁额度中扣一次大变化：滑块和种子加在一起，任意 1.25 s 内最多 6 次（同一帧中一起跳的种子只算一次）；超出的跳变直接跳过，所以滑块忙碌时种子跳得更少。种子始终是字段范围内（0–999 999）的整数，超过最大值后回到 0，所以每一个实时帧仍然是面板本身能得到的一组值。
   - 脉冲：Beat 的脉冲用在任意滑块上。
   - Step：尚未实现。
   - 每个目标还会说明自己起作用需要什么，以及如何打开（`activate`），供 Sound 标签页自动打开所需设置。
4. **实时调度：**
   - 同一时间最多只有一个几何请求在处理，所以帧率随计算量调整，上限 30 fps。
   - 先请求实时帧需要的字形，等它们全部到齐后才把这一帧交给 React（每秒最多 30 次），所以每一帧只渲染一次，而且是完整的。
   - 只有载入了字体，Sound 才会驱动；没有字体时什么都不动。
   - 流程不变；实时请求带 `live` 标记，Worker 会把它们的结果分开保存。
   - 实时帧使用单独的小缓存。
   - 只在 Sound 能驱动时统计种子的跳变。暂停、停止或关闭 Drive letters 时，种子完全回到字段中的值（再次播放时从这些值开始）；共用的闪烁额度在这期间保留，精确恢复本身也从中扣一次大变化。Freeze 把实时种子写入种子字段。
   - 在 Worker 中测量（Arial，24 个不同字形）：种子跳一次会重新计算每个字形，用时约 2–3.5 ms；Level → Noise amplitude 每帧 2.4 ms，三个映射一起 12 ms，所有 Experimental 效果全开 37–41 ms（24–27 fps）。Experimental 的数字测于 Crumple、Slipstream 和 Thorn 重做之前，重做让它们都变重了。
5. **界面：** 第三个标签页 **Sound**，包含：
   - Source（File 或 Microphone）、电平表、Sensitivity、Smoothing（阶段 H 中改名为 Release 并移入 Response 组），以及 Drive letters 开关。电平表每个特征一行（名称、条、数值），分五组，每组有一个 ⓘ；Pan 从中间向两边填充，显示为 "L 40" / "R 40" / "C"，Pitch 以 Hz 显示，Beat 是脉冲条，取代了原来的指示灯（开启减少动态效果时仍然工作）。
   - 带预设的映射列表。Feature 列表与电平表分组相同；目标显示为 "Section · Label"，Experimental 的种子只显示 "Seed"；在种子上，Depth 显示为 Rate。选中一个设置处于关闭状态的目标时，会打开该设置并在这一行下面说明（"Turned on Ripple."）；不会再自动关闭任何东西。如果用户之后又关掉了设置，这一行会说明原因并提供 Enable。用键盘时，按 Enter 或焦点离开列表时才应用目标。Add mapping 优先选已经起作用的目标。在 Preset 列表中选择只是选中；Load 把 Geometry 和 Experimental 的设置恢复为默认值（保留种子），设好预设的起始值，用预设的映射替换当前映射，并在 Preset 一行下方说明关闭了什么，这些合起来是一个撤销步骤；一个 ⓘ 列出每个预设，各一行说明。映射在两次访问之间保存。
   - Freeze 和 Reset sound。
   - 被驱动滑块上的实时值标记，以及被驱动的种子字段旁边显示实时种子的小数字。
   - 状态栏中的 "Live · N fps"。
6. **视频录制：** 已在阶段 H（见下文）中完成。

流水线：

```text
音频文件 / 麦克风 → Web Audio 分析器（混合后；左右声道）→ 11 个特征（Loudness、Bands、Tone、Rhythm、Stereo）
滑块值 + 种子 + 特征 + 映射 → 实时参数（取整到滑块档位并截断；种子按跳变次数前进）
实时参数 → 现有几何流程（Worker）→ 画布        Freeze → 滑块值和种子 → 导出
```

阶段验收：

# 阶段 F：稳健性、会话保存与测试

> **实现状态：** 已完成（分支 `feature/robustness-fixes`）。繁重的设置和较大的字体都有上限，不会卡住或溢出；导出的字体保留字偶距和行距；刷新页面后会话仍在；每项设置都能撤销；自动测试在 CI 中运行，每次部署前也会运行。详见 README 的“保存与撤销”“性能”“导出”和“测试”。

1. **几何 Worker：** Worker 的逻辑移到 `src/geometry/workerCore.ts`，字形只在 Worker 中计算，从不在页面上计算。
   - 每个请求都有编号，并且一定以“完成”或“失败”作答；Worker 在每个字形之前发一次心跳；退回到结果仍保留着的设置时，正在进行的请求立即取消。
   - 忙碌的 Worker 连续 60 秒没有任何消息，就重启并重新发送字体，它正在算的字形标记为失败（“Took longer than 60 s; try lighter settings”）；60 秒内重启超过 3 次时，几何计算停止，直到载入另一款字体。
   - 已被新设置取代的某个字形算了 750 毫秒时，放弃它：立即换一个新 Worker（最多每 2 秒一次，声音的实时帧从不这样做）。
   - Worker 无法启动、打不开字体、反复失败或反复没有响应时，画布显示提示；除了 Worker 打不开字体的情况，提示都会请用户重新载入页面。
2. **Experimental 的合并与顶点预算：**
   - 合并折叠后的轮廓时，落在单元边上的交叉点精确取整（整数运算），第一次结果不干净时在精细一倍的网格上再试一次，否则保持轮廓原样（“Overlaps could not be merged; the outline is left as it is.”）。合并碎片使用迭代的并查集，所以几万个点的字形也不会栈溢出；顶点和交点过多的合并会提前停止（`maxHot`）。
   - 每个字形的 Experimental 效果最多增加 6000 个顶点、最多合并 30 000 个点（`EXPERIMENTAL_LIMITS`，`src/geometry/budget.ts`）。超出时轮廓会被简化（Ramer–Douglas–Peucker，从变形的漂移容差开始，最多翻倍 12 次），面板显示“Simplified: these settings make too many vertices or crossings, so the outline was reduced (tolerance N u).”，状态栏显示“(simplified)”。超出上限的合并会在更粗的简化上再试，只有最粗的简化也放不下时才保持不合并（“Too complex to merge; lower the settings.”）。会产生超过上限 16 倍顶点的变形不用在这个字形上（“This glyph is left without crumple: too complex.”，其他效果同理）。预算只取决于字形和设置，所以画布、预览和导出的文件一致。
3. **交叉检测与取整：** 沿线段的扫描（`SegmentSweep`，线段达到 64 条时可改为沿 y 方向或某条对角线扫描），以及合并时 128 个点以上的轮廓按水平条带建立的线段索引（`RingIndex`），让长轮廓的交叉检测保持快速；导出取整时，每个轮廓只与包围盒相距两个取整步长以内的轮廓比较，自交超过 2000 处的轮廓视为一团乱线，所以约 500 000 处自交的星形也只需不到一秒就能取整。
4. **字体导出：**
   - 字体在它自己的 Worker 中生成（`src/export/fontExport.worker.ts`），对话框中显示进度，可以 Cancel，60 秒没有进度时报告“The export stopped responding.”；尚未计算的字形先计算。对话框会估算轮廓点数，生成会很大或很慢时给出提示。
   - 源字体的成对字偶距（GPOS 的字偶调整，或旧式 `kern` 表）写成 GPOS 的 `kern` 特性（`src/font/kerning.ts`、`src/export/gpos.ts`）。
   - OS/2 第 4 版并设置 `USE_TYPO_METRICS`，排版度量等于源字体的 `hhea`，所以遵循这个标志的应用排出的行距都与画布相同（Windows 上伸和下伸仍会加大，以包住超出它们的轮廓，所以只有忽略这个标志的应用会把行距排得更大）。
   - 字体集合（`.ttc` / `.otc`）打开时带字面菜单；切换字面时保留视图，新字面有当前选中的字母时也保留它。
5. **预览：** 右下角的预览就是 SVG 导出本身，缩小绘制，使用导出精度；透明背景显示为棋盘格，导出会失败时显示“Export would fail: …”。
6. **会话保存与撤销：**
   - 设置、文字、声音映射、选中的字形和字体保存在 `localStorage` 中（`src/state/persist.ts`），下次访问时恢复；读取时检查每个值，上次访问如果在绘制时关闭，则改用默认值。
   - 撤销与重做（`src/state/history.ts`）覆盖所有设置、文字和声音映射，最多 100 步；一次滑块拖动、一段连续输入、一次预设 Load 和一次 Freeze 各算一步，声音的实时帧从不记录。
7. **声音：**
   - Beat 的能量门：只在检测器所听的某个倍频程频带比它最近 100 ms 内的最大值高出至少 2 dB 时才触发，所以持续的嗡嗡低音不会产生节拍。
   - 所有被驱动的滑块和种子共用一份闪烁额度（`src/sound/flash.ts`）：加在一起每秒最多 3 次闪烁。
   - 只有载入了字体，Sound 才会驱动；实时帧的字形在显示之前先请求；滑块的范围和刻度来自同一个模块（`src/state/sliderScales.ts`）；麦克风的错误各有自己的提示。
8. **打包：** React 单独放在一个代码块里，Experimental 和 Sound 两个面板在第一次打开时才加载。
9. **测试与 CI：** Vitest（`npm test`，快速测试，18 个文件，约 15 秒；`npm run test:slow`，测试字体的逐字形检查和测试音轨，约 3 分钟）。测试字体是 STIX Two Text 和 Roboto（SIL OFL 授权）。测试音轨由 `npm run test-track` 生成，不提交到仓库。`.github/workflows/test.yml` 在每个合并到 `develop` 的拉取请求和每次推送到 `develop` 时运行 `npm ci`、`npm test` 和 `npm run build`；Pages 部署在构建之前先运行 `npm test`。

阶段验收：

# 阶段 G：横跨画布的 Thorn

> **实现状态：** 已完成（分支 `feature/thorn-canvas-reach`，2026-10-13）。Thorn 的 Reach 改为画布的比例而不是 em 的比例，文字排版时不计它的刺，字体文件会裁剪超出字体存储范围的字形，而不是把它们排除。详见 EXPERIMENTAL_PLAN 第 4.8 节和 PRD 的字体导出边界。

1. **按画布计量的 Reach：** Reach 是画布对角线的比例（0–100%，读数为 "% canvas"，默认 10%），所以 100% 时一根刺能横跨整个画布；每根刺仍然伸出它的 35–100%（由种子决定）。
   - Thorn 打开时，应用把以 em 计的对角线交给它（`src/geometry/thorn.ts` 中的 `canvasDiagonalEm`：画布的宽和高构成的对角线除以字号，精确到 0.01 em），所以只有这时改变字号或画布才会重新计算字母；PNG 的倍数不计入。一根刺最长 256 em（`THORN_LIMITS.maxReachEm`），而且只有刺尖变长：根部、底部和竖条仍以 em 计。
   - 滑块是三次方的（`src/state/sliderScales.ts` 中的 `THORN_REACH`：滑块位置的立方，所以正中是 12.5%），所以短刺仍能细调；靠近 0 的地方每档增加画布的 0.01%，直到立方增长得更快为止（约 0.28% 以内），所以没有哪一档会取整为 0，每按一次方向键距离都会变。读数在 1% 以下保留两位小数，10% 以下保留一位，以上取整（只有正好为 0 时才显示 0.0，这时不长刺）；它的 ⓘ 说明在当前字号和画布下 100% 相当于多少 em。状态栏和导出说明按同样的格式写作 "reach N% canvas (about M em)"。
2. **玻璃与排版：** Refraction 只盖住字母所在的竖条和两侧各一条，所以向左右伸出的刺的远端不会被折射。每个字形保留它在 Thorn 之前的框和凸包（`PolygonGlyph.layoutBox`、`layoutHull`）；锚定和 Free 摆放、Fit text 以及超出边缘的警告都按它们量字母（`SpecimenScene.body`；文字倾斜时凸包逐点倾斜，所以排版与关闭 Thorn 时完全相同），伸出画布边缘的刺和任何墨迹一样，在预览以及样张 SVG 和 PNG 中被截掉。开启 Thorn 时，字形靠宽为前进宽度、高为整行的矩形和一份看不见的原始轮廓副本接收点击和 Free 拖动，它画出的轮廓不接收任何点击，所以点到刺上会交给它后面的东西（另一个字母，或画布，在那里拖动就是平移）；没有 Thorn 时，字形和以前一样点选。
3. **合并：** 网格延伸到 ±2^22 个单元（原来是 2^19），足够每 em 4,096 单位时 256 em 长的刺；超出网格的字形会被报告为未合并。平均宽度很窄的轮廓只有在里面放不下一个直径 0.01 em 的圆时才会被略去（`OVERLAP_LIMITS.room`），所以带着很长很细的刺的字母、带一道细长裂缝的内孔都会保留，而发丝般细的细条仍会被略去。
4. **字体导出：** 每个字形都被放进一个边长 32,766 字体单位的正方形（`src/export/fitGlyph.ts`）；超出的部分被直线截掉，对话框在 "Trimmed to fit" 下列出这个字形。前进宽度超过 32,767 单位的字形会被排除并说明原因；校验还会检查 head 和 CFF 的边界框以及坐标限制。
5. **会话保存与声音：** 会话版本为 2；旧的以 em 计的 Reach 换算成它保存的画布上同样的比例（对角线最多按 256 em 计，与 Thorn 的算法相同；4 位小数；大于 0 的 Reach 至少是滑块的第一档 0.01%，所以原来打开的 Thorn 仍然打开），Reach 上的 Sound 映射行保留它们的 Depth。Thorn · Reach 沿三次方滑块移动，Flare 在 Reach 上的 Level 行从 30% 改为 50%。
6. **测试：** 快速测试新增五个文件，现在共 23 个（`tests/geometry/thorn.test.ts`、`tests/export/fitGlyph.test.ts`、`tests/specimen/layout.test.ts`、`tests/specimen/glyphTarget.test.ts`、`tests/state/thornReach.test.ts`），并为远处的合并、合并时保留的细长刺和裂缝、字体导出、会话保存和声音新增了用例。

阶段验收：
- 刺长是 Reach × 画布对角线的 35–100%，最长 256 em；刺伸到 256 em 而不是 30 em 时，点数增加不到 10%，也从不触发顶点预算。
- 无论文字是否倾斜，刺永远不会移动、缩放文字或触发警告；点到离开字母的刺上，也不会选中这个字母。
- 合并时，被又长又细的刺弄得平均宽度很窄的字母会保留下来。
- 两种测试字体的拉丁样本在 120 em 的对角线上以 Reach 100% 导出，没有字形被排除，回读时都在字体的限制之内。
- 以 em 计 Reach 保存的会话，在它保存的字号和画布上恢复出同样长度的刺。

# 阶段 H：逐字母的声音响应、Response 控件与视频录制

> **实现状态：** 已完成（分支 `feature/sound-visuals`，2026-10-14）。每个字母可以按自己的幅度回应声音，六个 Response 控件决定字母怎样回应声音，画布可以连同声音录成视频。Response 设置都在默认值时，Sound 的表现与之前完全相同。详见 PRD 第 11 节和 [SOUND_PLAN.zh.md](SOUND_PLAN.zh.md)。

1. **字母**（`src/sound/letters.ts`，纯函数）：文字中字形的每一处出现都是一个字母，按画布摆放它们的顺序计数（空格和缺失的字形也计数，但从不驱动）。每个字母有它在文字块中的横向位置（左端 0，右端 1），以及按前进宽度算出的它占整段文字的份额。
   - **Motion contrast：** 字母的权重来自它所在位置的一个稳定哈希和一个缓慢的波（6 s，每个字母错开一些），所以领头的字母每隔几秒就会换。100% 时权重从共享幅度的 1/3.6 到 3.6 倍，以 1 为中心均衡分布：画出的字母中大约 17% 平静、67% 共享、17% 强烈（Roboto 默认文字画出的 196 个字母中分别是 33、132 和 34 个）。Strength 决定整体幅度；Motion contrast 只负责把它拉开。
   - **Pitch reactive：** 近来旋律中的低音让左边的字母权重更大，高音让右边的字母权重更大，所以无论曲调在哪个音区，都会扫过整段文字。音高放在旋律音域里（`pitchPlace`），这个音域由 `features.ts` 记在每一帧中（`pitchLow`、`pitchHigh`；`SOUND_LIMITS.melodyRangeAttackMs` 150、`melodyRangeReleaseMs` 8000、`melodyRangeMinSt` 12）：一开始是围绕第一个稳定下来的音的一个八度，遇到更高或更低的新音时约 0.15 秒内扩展过去，约 8 秒内向最后一个音收拢，超过 8 秒没有音就重新开始，始终至少一个八度宽，并忽略距 Pitch 的 55–1760 Hz 刻度两端一个半音以内的音（和弦和鼓会读在那里）。旋律第一次上行时，每个新的最高音都落在最右端；音域听过一遍之后，每个音都有自己的位置。需要清楚的单个音。
   - **三个档位：** 权重被归到三个档位（平静、共享、强烈），档位在一个设置下固定，所以声音平稳时，字母只会换到已经算好的参数组上。两个控件合起来也保持在固定的界限之内。字母只有在权重明显越过边界后才离开它的档位（滞后），所以不会在两个档位之间来回闪。
   - **每个字母都是滑块值：** 档位把每个被驱动滑块相对于滑块自身位置的实时偏移按比例缩放，再截断、取整到档位；结果落在滑块自身那一档时，就正好是滑块的值。Pan 保持它的正负号。种子由所有字母共用，Strength 缩放它们的 Rate。
   - **已知限制：** 在档位很少的滑块上，只有共享值离开了滑块自身那一档之后，平静和强烈的字母才会拉开。
2. **画面上每个字母的闪烁限制**（`src/sound/live.ts`、`src/sound/flash.ts`）：
   - 一个滑块的折返量，取它的共享折返量和每个有字母正在显示或即将显示的档位的折返量中最大的那个。档位是共享值的单调映射，所以只在共享值折返时折返；让共享值停住，每个字母也就停住。
   - 字母在档位之间切换：它们的移动量按每个字母占文字的份额加权，从画面上的档位量起（`switchSwing`），也从最近 250 ms 内显示过的每一帧的档位量起（`LIVE_LIMITS.switchSpanMs`），取较大者，所以一次分几帧到达画面的换音只算一次变化；一次从额度中扣除的移动之后，这串记录重新开始。移动量达到滑道的 10% 或以上就是一次大变化，每个显示出来的帧最多从同一份额度中扣一次；额度用完时，每个字母保持画面上的档位。
   - Motion contrast 或 Pitch reactive 改变、文字变成不同数量的字母，或 Sound 停止时，档位重新开始。只改同一段文字的样式（字距、行高、对齐、倾斜）时，每个字母保留它的档位。
3. **每帧一个请求**（`src/geometry/protocol.ts`、`workerCore.ts`、`src/state/geometryClient.ts`）：
   - 一个计算请求带若干任务，每个任务是一个参数键和它的字形。实时帧先发共享值，覆盖画面上的每个字形，再发强烈和平静档位的字形，全部通过 `prefetchJobs()` 放在同一个请求里；全部到齐后才提交这一帧。
   - Worker 按顺序执行任务，每个任务的结果用它自己的键发送，心跳中写明键，最后只发一个 `done`。正在处理的请求如果已经覆盖每一个缺少的（键，字形）对，客户端就沿用它。
   - 实时结果按最近最少使用的顺序保留，最多 6 组参数（`LIVE_KEPT_KEYS`），所以下一帧计算时，画面上那一帧的档位仍然保留。只有请求的第一个任务会成为字形的替身形状，在其他设置计算时显示。
   - 画布按字母在文字中的位置查找它（`PolygonLookup(index, occurrence)`），样张 SVG 按多边形为路径建索引，所以预览显示每个字母自己的形状。所有字母都用共享值时，输出与之前逐字节相同。
4. **Response 控件**（`src/sound/types.ts`、`features.ts`、`mapping.ts`、`jumps.ts`、`mappingStore.ts`、`src/components/SoundControls.tsx`）：
   - Analysis 组改为 **Response**：Sensitivity（−24 到 +24 dB，档位 1）、Strength（0–400%，档位 5）、Motion contrast（0–100%，档位 1）、Release（20–1000 ms，档位 10；原名 Smoothing，起音时间仍然固定）、Pitch reactive（0–200%，档位 5）和 Melody tracking（0–200%，档位 5）。范围写在 `SOUND_LIMITS` 和 `RESPONSE_LIMITS` 里；默认值都是中性的（`NEUTRAL_RESPONSE`）。
   - Strength 乘到每个滑块映射的总和以及每个种子的 Rate 上（Rate 最多为 1）。0% 时 Sound 停止驱动，完全恢复滑块值和种子，Mappings 组显示 "Strength is 0%: the letters hold still."。
   - **Melody** 是 Tone 中的新特征，有自己的电平表，也能像其他特征一样映射：音高换到一个相差至少半个半音的新音、并在那里稍作停留时，产生一次脉冲。颤音、鼓声以及静音后滑进一个音都不产生脉冲，它按 Release 回落。Melody tracking 把它的值的一半 × Melody 加到每个滑块映射的特征上，Pan 的行、Melody 的行和种子除外。
   - 这六个值作为一个可选的 `sound` 块保存在会话中（会话版本仍是 2；没有这个块的会话按默认值读取），并像映射一样可以撤销：拖动一次算一步，把六个一起恢复的 Reset sound 也算一步。预设不改动它们。
5. **Freeze 与状态：** Freeze 写入共享值和其中被停住的值，它们已经算好，所以切换是立即的，之后每个字母都采用它们；它的说明会写明这一点。滑块上的标记、实时种子、状态栏和选中字形的统计都显示共享值；"Live · N fps" 统计完整的帧，包括所有档位。它是几何计算的速率，而不是读取声音的频率：声音每个动画帧读取一次，所以标签页被隐藏或被遮住时一帧也不读，字母不再跟随声音，直到标签页重新显示。Motion contrast 或 Pitch reactive 大于 0 时，太慢的提示也会建议调低它们。
6. **视频录制**（`src/export/videoFormat.ts`、`drawArtboard.ts`、`recorder.ts`、`src/sound/engine.ts` 中的音频分支、`src/components/RecordControls.tsx`、`RecordingCanvas.tsx`、`RecordingIndicator.tsx`、`Header.tsx`、`ExportDialog.tsx`）：
   - `videoFormat.ts`（纯函数，`VIDEO_LIMITS`）：要尝试的 MIME 类型（H.264 High，然后 Baseline，然后任意 H.264，然后浏览器自己的 MP4；VP9，然后 VP8，然后浏览器自己的 WebM），MP4 不行时退回 WebM；尺寸（画布的导出尺寸，最长边不超过 3840 px，面积不超过 3840 × 2160，边长为偶数）；码率（每像素 4.5 比特，2–12 Mbps，所以 10 分钟约 0.9 GB）；音频延迟（实时延迟加 37 ms，在 40–400 ms 之间，测到第一帧之前用 90 ms）；文件名；以及时钟。
   - `drawArtboard.ts`（纯函数）：按 SVG 导出的画法把场景画到画布上：总是先画纸色；每个字母各填充一次（nonzero），所以不同档位的字母各自显示自己的形状；倾斜画成错切；画布支持滤镜时，模糊通过第二个图层完成。`touchCanvas` 把一个像素复制到它自己上面，并裁剪到这个像素，所以静止的画布也照样产生帧。
   - `recorder.ts`：一个通过注入依赖工作的控制器，加上一个带 hook 的页面单例。一次录制先锁定尺寸和 MIME 类型，需要时启动来源（Whole file 会跳到 0 并关闭 Loop），然后等待声音和第一个画好的帧（30 s 后放弃）。之后它捕获画布（`captureStream` 和 `requestFrame`），并加入引擎延迟后的音轨。
   - 按 Stop、到达设定时长、声音停止、结束或切换、标签页被隐藏、画布尺寸改变或字体关闭、录制器出错（保存出错之前的内容），或到 10 分钟时，录制停止并保存。到达设定时长、或因文件暂停或结束而停止的录制，会多录音频延迟加 100 ms，让声音的结尾也进入文件；按 Stop、到达 10 分钟上限或麦克风停止后，多录 100 ms，留住最后一帧；标签页被隐藏、出错、画布或字体改变时立即停止。之后它恢复 Loop，只暂停由它自己启动的来源。
   - 引擎的音频分支：测量用的来源（听到的文件，或麦克风）经过一个延迟进入一个供录制使用的流；扬声器听到的不变。
   - 界面：Sound 标签页底部的 **Record** 组（Record 或 Stop、已录时长、Format、Length、Include audio、Use the preview look、尺寸一行、"Live · N fps"，以及上一次录制是怎样结束的）；Export 对话框中的 **Video**，它的 Record 会关闭对话框并开始录制；顶部栏依次显示 "Starting to record…"、带一个只有图标的 Stop 的 "Recording 0:12"，然后是 "Saving the video…"，结束后显示录制是怎样结束的，并带一个关闭按钮。录制期间 Freeze 不可用。录制用的画布放在屏幕之外，只在录制期间存在。录制期间离开页面会先询问。
