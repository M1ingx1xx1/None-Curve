# Experimental effects plan

**English** · [中文](EXPERIMENTAL_PLAN.zh.md)

**Status:** Phases 1–9 (Crumple, Ripple, Slipstream, more extreme ranges, folds, petals, Whorl, Thorn, and the rework of Crumple, Slipstream, and Thorn with the merge's exact redraw) built and verified; since then, a vertex budget per glyph and a sturdier, faster merge (section 4.10)  
**Scope:** A new **Experimental** tab beside **Geometry** in the tools panel, holding creative effects that can all be applied to the same letters at once.  
**Names:** Phase 9 renamed the effects: Noise became Crumple, Curl became Whorl, Wind became Slipstream, and Spikes became Thorn. This plan uses the new names throughout, also for the phases built under the old ones.

## 1. Goals

- One tab, **Experimental**, for all creative effects: Crumple, Ripple, Whorl, Slipstream, and Thorn. There is no separate tab per effect.
- The effects **stack**: any combination can be on at the same time, and the result is always a valid letter that exports.
- Each effect is built and shipped on its own, in this order: **Crumple → Ripple → Slipstream**, then **Whorl** (Phase 7), which runs between Ripple and Slipstream, and **Thorn** (Phase 8), which runs last. Phase 9 reworked Crumple, Slipstream, and Thorn (section 4.9).
- Random anchors (in the Geometry tab) is no longer experimental: its "Experimental" tag is removed.

## 2. Highest rule: no curves

None-Curve means no curves. That rule comes before every other choice in this plan, and it covers what the letters look like, not only the file format.

1. **Straight lines only in the data.** Every contour stays a closed polygon. SVG keeps using only `M` / `L` / `Z`, and the font export keeps checking that no glyph contains a curve command. Nothing changes here.
2. **No smooth sampling.** No effect may sample a smooth function (a sine wave, smooth noise) densely along the outline. Dense sampling would give straight lines on paper and a curve to the eye.
3. **Every effect is built from piecewise-linear warps of the plane.** The plane is cut into triangles, and each triangle is moved by its own linear map. A straight edge stays exactly straight inside a triangle and bends only where it crosses a triangle edge (a **crease**). New vertices are added only at creases. So an effect can only add corners; it can never round anything off. (Three parts are not warps: Slipstream's trails and cuts, section 4.3, and Thorn's tips, section 4.8. Each adds a few straight edges and nothing else, so they keep to the rule too.)
4. **Visible facets.** Every mesh has a minimum cell size, so the pieces between creases stay large enough to read as facets.
5. **Faint creases left out.** A crease that turns the outline by less than 3° reads as a wobble, not a corner, so it is left out (as long as the outline stays within 1% of the em of where it was; less where contours are close).
6. **Measured and enforced.** A **curve-like run** is five or more vertices in a row that all turn the same way by 0.5°–20°, between edges shorter than 4% of the em: that is how a polyline starts to look like a curve. Creases are removed until none is needed to make such a run. Runs that the input's own vertices already form are the input's shape (for example a finely flattened bowl) and are left alone; the input's vertices are never removed. Creases of earlier effects count as creases too, so a run that only several effects together form is broken up as well.
7. **Only where it fits.** If removing creases makes a contour touch itself or another, the creases along that one edge are restored and the rest is tidied again. Where two parts of an outline are a fraction of a unit apart (New York's hairline joins), a crease that cannot be removed without touching stays.

What this means for the effects: Ripple waves are zigzags (a triangle wave) on concentric polygons, not sine curves on circles. Crumple looks like folded or crumpled paper, not like a wobbly hand-drawn line.

## 3. Stacking

- **Fixed order, last in the pipeline.** Experimental effects run after the whole Geometry pipeline (after Distortion), always as Crumple → Ripple → Whorl → Slipstream → Thorn. Each takes the previous effect's result. The pipeline is still rebuilt from the original curves for every change, so turning an effect off simply removes it.
- **Valid by construction.** Up to 100%, each warp keeps every triangle the same way round (it never flips or flattens one), which makes it a one-to-one map of the plane. A one-to-one map cannot make an outline cross itself, push a counter out of its letter, or merge separate parts. Applying several such maps one after another is again one-to-one, so **any combination of effects within 100% is valid** and keeps every letter arranged as it was.
- **Folds beyond 100%.** Past their safe range, effects may fold the letter onto itself; the overlaps are then merged into one clean outline (section 4.5), so the result is still valid and exports, only no longer arranged like the original letter. Thorn's thorns may cross the letter at any setting, so whenever Thorn adds one the result is merged the same way (section 4.8), and Slipstream's cuts are cut out by the same merge (section 4.3).
- **Checked anyway.** After each effect, every contour is still checked for self-crossings and against the glyph's other contours, as every Geometry step does. All contours start as their exact images, which are valid together; each is then replaced by its tidied image (faint creases and curve-like runs removed) only if that is valid against the others. A crossing counts only where the input's edges neither crossed nor touched, because heavy Geometry settings can leave outlines lying on top of themselves; nor between two edges still exactly as the warp mapped them whose input edges are less than 0.05 units apart, which only rounding can cross (a strong Slipstream can squeeze a sharp spike that thin). If rounding ever breaks an exact image, that contour is retried at 1/2 down to 1/16 strength, and if nothing works the glyph is left as it was; the panel says so.
- **One seed.** The Experimental tab has one seed with **Next variant**. Each effect derives its own random numbers from it, so one control rerolls the whole look, and the same seed and settings always give the same letters.
- **Same letter, same shape.** Effects work in each glyph's own coordinates, so every copy of a letter looks the same. Font export needs this, because a font has one shape per character.
- **Vertex budget.** Creases add vertices. The panel shows how many each effect added, and the minimum cell sizes keep each effect in check: Ripple adds about 30 vertices per glyph at its defaults and about 100 at the shortest wavelength. Several dense effects together multiply, though, so each glyph also has a fixed budget: at most 6,000 vertices more than it brings into the Experimental effects after any effect, and 30,000 grid points more in any merge. A glyph over it is simplified, and merged afterwards (section 4.10). The defaults, every effect alone, and the Sound presets never reach it.

## 4. Effects

### 4.1 Crumple (Phase 1, reworked in Phase 9)

Crumples the letter like paper, at three scales: large folds tilt and kink whole strokes, medium ones bend a stroke end here and there, and small sharp creases gather in busy stretches between calm ones.

- **Meshes:** three square lattices, each turned by its own angle from the seed, each square split into two triangles along a diagonal also chosen by the seed, so the creases of different meshes do not line up.
  - **Large** (cells of 2.25 × Facet size): every point moves, so whole strokes tilt and kink as blocks; a long stem bends once or twice instead of zigzagging.
  - **Medium** (cells of one Facet size): a point moves only where it ranks first among its eight neighbours by a seeded hash, about one point in nine and never two in one triangle, so a stroke end or a joint bends here and there.
  - **Fine** (cells of 0.4 × Facet size, never below 5% of the em, so its creases stay about 2% of the em apart or more): every point moves, but only in busy stretches, giving small sharp corners along the edge.
- **Movement:** each moving point moves by a vector from the seed, turned by **Turn**; points in between move linearly with their triangle. The three movements add up: a sum of maps that are linear on each triangle is linear on each piece where the triangles overlap, so straight edges stay straight between creases, and the creases are those of the three meshes (on the medium and fine meshes, only where a corner nearby moves).
- **Busy and calm:** a coarse field from the seed (smooth value noise on a lattice of 3 × Facet size) decides where the medium and fine meshes act. It is read only at lattice points, so its smoothness never reaches the outline. Busy stretches alternate with calm ones, where only the large mesh bends the outline; in busy stretches the large mesh moves less, leaving room for the fine corners. **Detail** shares the crumpling between the scales: at 0 only the large mesh moves; higher values move strength to the medium and fine meshes and widen the busy stretches (about 45% of the area stays calm at Detail 50%, about 25% at 100%).
- **Why up to 100% is one-to-one:** on a triangle of a lattice with cell c whose corners move by m0, m1, and m2, the movement changes by (m1 − m0) / c and (m2 − m0) / c along the two legs, so its gradient is at most 2√2 · R / c when no corner moves more than R, and √2 · R / c when only one corner moves (the medium mesh). The gradients of the three meshes add up, and while the sum stays below 1 no piece of the combined mesh flips. The large mesh takes at most its share of a budget of 0.85 (all of it at Detail 0, 60% at Detail 100%); each medium and fine point then takes a share of what the coarser meshes leave on the triangles near it, measured from their actual moves, so the sum stays within 0.85 everywhere. Turn changes only where the points go, not how far, so this holds at any turn. Sampled across settings, the smallest Jacobian determinant was 0.27. Crumple never needs weakening up to 100%.
- **Same letter, same shape, no drift:** each glyph reads the meshes at its own offset, from the seed and its glyph index, so neighbouring letters such as l, i, and h crumple differently, while every copy of a letter gets the same shape. The middle of each glyph's ink box is held in place (the whole warp is shifted back by its movement), which changes no shape but keeps letters from drifting into each other at large facets.
- **Controls:** Use crumple, Amount (0–500%, default 70%; above 100% facets fold over each other, see section 4.5), Detail (0–100% in 5% steps, default 50%), Facet size (8–100% of the em, default 18%: the medium cell), Turn (0–345° in 15° steps, default 0°), and the shared seed. Statistics: largest move and creases added. The pipeline summary lists "crumple N%, detail N%, facets N% em, turn N°, seed S". Settings saved before Detail existed get 50%. Crumple's random numbers use channels 105–120.
- **Checked (Phase 9):** every Latin glyph of Arial (286), Georgia (286), and New York (282) at 10 settings (the defaults; Amount 100% at Detail 0, 50%, and 100%; Detail 100% at Facet size 8%; Facet size 100%; Detail 75% with Turn 135°; Amount 30% at Detail 100% and Facet size 12%; folds at Amount 250%; Amount 500% with Detail 100% and Facet size 8%), seeds 1, 7, and 42, alone and with Slipstream and Thorn at their defaults on dense and heavy Geometry settings: no new crossing, no export failure at 0 or 2 decimals, no glyph left without Crumple, and no fold within 100%. Crossings the fonts' own overlapping parts already have (Å, Ç, ogonek, New York's overlapping contours) stay as they were. Curve-like runs from Crumple's creases within 100%: none in Arial or Georgia, 0–6 per setting in New York, where `warp.ts` keeps creases next to a touching contour. Alone, no coordinate goes beyond 1.14 em. Time per glyph: about 0.6 ms at the defaults, 0.7–0.8 ms at Amount 100% with Detail 100%, up to about 1.9 ms at Facet size 8% with Amount 500%.
- **History:** Phase 1 built Crumple as a single lattice whose points all moved up to Amount × 30% of the facet size, one-to-one by the same reasoning (each triangle kept about 15% of its area). On straight stems that even lattice gave every letter the same regular zigzag, so Phase 9 replaced it with the three meshes above.
- **Difference from Distortion:** Distortion moves each contour along its own length, independently of the others. Crumple moves the plane, so a counter and the outline around it fold together, and the folds are straight creases.

### 4.2 Ripple (Phase 2)

Waves spreading from a point.

- **Mesh:** concentric regular polygons with a flat side at the bottom, around a centre given as a fraction of the glyph's ink box, with a ring every half wavelength measured across the sides. Rays through the polygon corners cut the rings into cells, each split into two triangles.
- **Movement:** every ring moves outward or inward as a whole, in turn, so it stays a regular polygon and the outline zigzags where it crosses the rings (a triangle wave). The amplitude can fade linearly toward the farthest point of the glyph.
- **Validity:** the warp is one-to-one as long as neighbouring rings never pass each other, that is, while the amplitude stays below half the ring spacing. It is capped at 45% of the spacing, so rings stay at least 10% of it apart (40% and 20% before Phase 4). The ring just outside the glyph stays put, and without petals everything beyond it is left alone (with petals, see section 4.6).
- **Controls:** Use ripple, Amount (0–400%, default 50%; above 100% rings pass each other, see section 4.5), Wavelength (8–200% of the em, default 30%), Sides (3–12, default 8), Center X and Y (−50% to 150% of the ink box, default the middle), Fade, Petals (0–300%, default 0%, see section 4.6). Ripple uses no randomness.
- **Measured:** on the Latin glyphs of Arial, New York, and Georgia, alone, on top of 9 Geometry settings, and stacked with Crumple: no new crossing, no weakened contour, and every glyph exports; 5 curve-like runs remain in New York, all where two parts of the outline are less than one unit apart. Across 19,440 random combinations of Geometry, Crumple, and Ripple settings, nothing crosses and every glyph exports. At its defaults Ripple adds about 30 vertices per glyph (about 100 at the shortest wavelength); With Crumple and Ripple both on, computing the geometry takes four to five times as long as Geometry alone (about 0.4 ms per glyph).
- **Found while testing:** a segment passing exactly through the centre crossed every ray at once and lost its creases; it is now split at the centre. And Ripple used to keep Crumple's creases as fixed vertices, so the two together could still form curve-like runs (69–93 per font); creases are now marked across effects.
- **Later:** one wave across a whole line of text. Each letter would then depend on its position, so the geometry cache, the worker, and export would all have to change. Not in Phase 2.

### 4.3 Slipstream (Phase 3, reworked in Phase 9)

Letters caught in a stream: bands across the stream slide past each other like slices, the stream draws the letters out, thin cuts run into them along the stream, and trails stream off their downwind side.

- **Mesh:** bands that run with the stream, one Gust size apart and anchored at the glyph origin (so with a level stream every letter on a line shares the same bands), cut into square cells, each split into two triangles along a diagonal chosen by the seed.
- **Slip, a shear:** every point moves along the stream by an offset that depends only on where it lies across the stream. Sway bands 2–6 Gust sizes wide (mostly 3–5) each slide by their own seeded share of Slip, from −½ to +½ of it; each band one Gust size wide adds a smaller jolt of its own (turbulence), none in 40% of the bands and up to ±15% of Slip in the rest, so a few large steps stand out among finer ones. The offset holds steady inside a band and changes linearly only across a thin zone at its edges, so the bands slide past each other like slices and their edges are straight creases.
- **Stretch:** every point also moves along the stream by Strength × its band's gust × its distance downwind of the glyph's upwind edge, so the edge facing the stream stays put and the letter is drawn out more the further downwind it reaches. Each band's gust is a random share of the full strength (from the seed), between 1 − Gustiness and 1. No point moves more than 4 em.
- **Why the warp cannot fold:** in stream coordinates (u along, v across) it maps (u, v) to (u + d(u, v), v), whose Jacobian determinant is 1 + ∂d/∂u. Slip depends on v alone, so it adds nothing to ∂d/∂u: a shear keeps every triangle the same way round at any amount. Up to 100% Gustiness the gusts are never negative and the stretch only grows downwind (∂d/∂u ≥ 0), so the determinant is at least 1 and the warp is one-to-one at any strength and slip, with no cap needed.
- **Trails** (not a warp), after the warp: thin streaks grow downwind out of the edges of the letter's outside contours that face away from the stream (outward normal within about 53° of it), at bases spread evenly along the outline. Each replaces its base by five points (base, shoulder, tip, shoulder, end): 2–5% of the em wide where it leaves the letter, narrowing to 30% of that a quarter of the way along, then running out thin, so it reads as a streak dragged off the letter rather than a thorn. Its length is a seeded 45–100% of 15% of the em + 50% × Strength (at most 2 em), turned up to 4° off the stream. A trail that would cross or come within 0.6% of the em of the letter or an earlier trail (so it survives rounding for export) is tried in up to 3 places, then left out: trails never need merging, and a letter can get fewer than asked.
- **Cuts** (not a warp), last, so they slice the trails too: long, thin wedges along the stream, on seeded lines that keep 6% of the letter's extent across the stream free at either side. Each enters from the side facing the stream or the side away from it, opening 3% of the em outside the first stroke it meets, widest there, and tapers to a sharp tip 35–85% of the way into that stroke (for 30% of the cuts, the second stroke); one in four goes right through the letter and on past it. Each is tried in up to 3 places. They are cut out exactly: the outline is first redrawn by the nonzero rule (section 4.5), so the ink winds once and everything else not at all; the wedges are then added clockwise, and the outline is redrawn around what still winds positively (the `'positive'` fill rule, section 4.9). That redraw also merges any folds so far, so the final merge is skipped unless Thorn adds a thorn or the vertex budget simplifies the glyph afterwards (section 4.10), and Thorn checks its warps again.
- **Still no curves:** slip and stretch are piecewise-linear, and trails and cuts are a few straight edges each; nothing is sampled or smoothed.
- **Controls:** Use slipstream, Direction (0° right, 90° up, in 15° steps), Strength (0–800%, default 15%), Slip (0–60% of the em in 1% steps, default 15%), Gust size (6–50% of the em, default 12%), Gustiness (0–200%, default 60%; above 100% some gusts blow backwards, see section 4.5), Cuts and Trails (0–8 per letter, default 2 each), and the shared seed. Slipstream acts when any of Strength, Slip, Cuts, or Trails is above 0. Statistics: largest move, creases added, and, while there are cuts or trails, Cuts and Trails. The pipeline summary lists "slipstream N% toward D°, slip N% em, gusts N% em, gustiness N%, C cuts, T trails, seed S". Settings saved without Slip, Cuts, or Trails read them as 0, which gives exactly the earlier Slipstream (2,562 glyphs compared: no difference). Slipstream's random numbers use channels 201–207, keyed by the glyph index.
- **Checked (Phase 9):** every Latin glyph of Arial, Georgia, and New York, at 8 or more settings (the defaults; the earlier look; Trails 8 with Strength 300%; Strength 800% with Slip 60%; Gustiness 200%; values beyond the sliders' ranges), seeds 1, 7, and 42, alone, on heavy and on dense Geometry, and with Crumple and Thorn at their defaults (122,976 glyph runs): no new crossing (the fonts' own overlapping parts give 1,170, counted apart), no export failure at 0 or 2 decimals, and no glyph left without Slipstream. At the defaults about 2 cuts and 2 trails per glyph; the farthest point lies 1.33 em out at the defaults, 5.3 em with Trails 8 at Strength 300%, and 7.1 em at Strength 800% with Slip 60% (the stretch itself). Curve-like runs: of the 1,107 glyph-and-seed cases whose plain Geometry glyph has none, the defaults add one to 39 (the earlier look: 32), bowing at most 2.3% of the em (earlier: 3.4%), where a crease lands inside the font's own flattened curve. Time per glyph: about 0.9 ms at the defaults, of which the two merges for the cuts take about half; about 8.5 ms on dense Geometry.
- **Found while testing (Phase 3):** a strong Slipstream can squeeze a sharp spike left by heavy Distortion so thin that rounding makes its two sides cross, although the warp keeps them apart. A crossing between two edges still exactly as the warp mapped them, whose input edges are less than 0.05 units apart, is now recognised as rounding instead of weakening the contour.
- **History:** Phase 3 built only the stretch, which drew the trailing side out into ragged streaks but left each letter whole. Phase 9 added Slip (misaligned slices inside the letter, with large swings over fine turbulence), Cuts, and Trails attached to the letter, and lowered the default Strength from 30% to 15%.
- **Later:** fragments blowing off the letters.

### 4.4 More extreme ranges (Phase 4)

The effects could go further than the first ranges allowed. Two levers, used where each is safe:

- **Higher maxima.** Crumple and Ripple were capped by their safety limits, so their maxima cannot simply grow:
  - **Crumple:** Amount now goes to 200%. Above 100%, the result is crumpled a second time on the same lattice by the rest (replaced in Phase 5 by folding, section 4.5). Two one-to-one warps in a row are one-to-one, and the same lattice deepens the same folds, so the pattern does not jump as the slider passes 100%. Facet size now goes to 100% of the em.
  - **Ripple:** a second pass does not add up (the rings have already moved, so the second push partly cancels), so the single-pass limit is raised instead, from 40% to 45% of the ring spacing: neighbouring rings come within 10% of the spacing, squeezing strokes into slivers. (48% was tried first: rings within 4% squeezed some New York strokes thinner than a font unit, and those glyphs could no longer be rounded for font export.) Wavelength now goes to 200% of the em, so the waves (and their amplitude) can be far larger.
  - **Slipstream** had no safety limit: Strength now goes to 300%.
- **Bigger steps.** Every slider moves in about 10–20 steps from end to end: Amount, Strength, Gustiness, Center, and Fade in 10% steps; Facet size, Wavelength, and Gust size in 2% of the em; Direction in 15°.
- **Checked:** the chained Crumple and the new Ripple limit keep every mesh triangle the same way round (exact images match densely sampled ones). On the Latin glyphs of Arial, New York, and Georgia at the new maxima, alone, on top of Geometry settings, and all three at once (63 font and setting combinations), and across 29,160 random combinations: no new crossing, no weakened contour, and every glyph exports; one curve-like run remains (New York ç, where the outline is under a unit from itself).
- **Found while testing:** at full strength, Ripple can squeeze an accent or a stroke end into a sliver thinner than a font unit, which rounding to whole units for font export cannot keep. Such a contour (narrower on average than one unit: twice its area over its perimeter) is now left out on its own, like a contour too small to show, instead of the glyph failing to export.

### 4.5 Folds: beyond the safe range (Phase 5)

Even at the Phase 4 maxima the letters stayed readable, because every effect stopped where the plane would fold over itself. Phase 5 lets the effects go past that point. The highest rule stays: **no curves**. What gives way is only the promise that every letter stays arranged like the original.

- **What folds.** Above 100%, each effect is allowed to flip its triangles:
  - **Crumple** (to 500%): every mesh point moves up to five times as far as at 100%, along the same directions, so the pattern grows without jumping. Facets flip over their neighbours.
  - **Ripple** (to 400%): rings move up to 1.8 ring spacings, overtaking their neighbours; the innermost can pass through the centre and turn inside out.
  - **Slipstream**: Gustiness goes to 200%. Above 100% some gusts are negative and blow backwards, pushing their bands back through the letter and tearing it. Strength goes to 800%.
- **Still no curves.** Folding changes nothing about the warp itself: it is still piecewise-linear, straight edges bend only at creases, and creases are tidied exactly as before (faint ones removed, curve-like runs broken).
- **Merging the overlaps.** A folded letter overlaps itself. Fonts fill outlines by the nonzero rule, so it still has a definite shape, but crossing outlines do not survive rounding for export, and font tools reject them. So, once any effect folds, every effect runs unchecked, and at the end the glyph is redrawn as the outline of exactly what the nonzero rule fills (`src/geometry/overlaps.ts`):
  1. **Snap rounding** on a grid of whole font units: every vertex and every place where outlines cross is rounded to the grid (a crossing within rounding error of a cell side is rounded exactly, section 4.10), and each edge is routed through every grid point whose cell it passes (each cell owns only its bottom-left corner, so an edge through a cell corner is routed once). Rounded edges then meet only at their ends, and all further arithmetic is exact. Should the rounding still join outlines wrongly, the merge tries a grid twice as fine, and failing that leaves the glyph as it was (section 4.10).
  2. Each region between edges gets its **winding number**; edges with ink on one side and none on the other are joined into contours. Where two inked regions touch at a single point, each keeps its own contour.
  3. Contours too small to show (under 4 square units, or under one unit wide on average) are left out.
  4. **Exact redraw** (Phase 9, section 4.9): each contour is drawn again through the input's own vertices and the exact places where input edges cross, dropping the grid detours, except where a vertex has to stay on the grid to keep the contours valid.
  5. **Run breaking:** in any curve-like run left that is not made of the input's own points, the corner that turns least is dropped where that moves the outline by at most one grid cell.
  The result has only straight edges; new vertices appear only where outlines crossed (and rounded ones where contours come within a grid cell). Outer contours run counter-clockwise and holes clockwise.
- **Within font limits.** Strong streams with backward gusts could stretch a wide glyph beyond 32,767 units, the largest step a font outline can store, which corrupted the written font. Slipstream now carries nothing further than 4 em; and font export leaves out (and names) any glyph that is still too wide, instead of writing a broken file.
- **Checked:**
  - Merging: 1,500 random self-crossing polygons give outlines that never cross, with exactly the same filled area away from the edges.
  - On the Latin glyphs of Arial, New York, and Georgia (16 settings each, from each effect alone at its maximum to all three at once, on top of Geometry settings): no crossing in any result and no export failure, at whole units and at two decimals.
  - Whole fonts written as OTF and read back with every effect at its maximum: Arial, New York, and Georgia pass for each effect alone; New York and Georgia pass with all three at once. Arial (2,692 glyphs) with all three at once exceeds the existing limit of 1,000,000 outline points in one file; the message suggests exporting only the characters in the text.
  - Within 100%, every result is identical to Phase 4.
  - Curve-like runs not formed by the input's own vertices: 0–9 per font at the maxima, almost all five vertices long, where a crossing extends four of the input's own vertices. Settings with a dense input (Anchor spacing 5) give more (48–109 per font), of the same kind.
  - The geometry takes about 0.5 ms per glyph for one folding effect and about 6 ms with all three at their maxima.

### 4.6 Petals (Phase 6)

Ripple's rings were always regular polygons. Petals bends every ring into a flower with one petal per side, so **Sides** sets the number of petals: 3 gives a trefoil, and so on up to 12.

- **Idea, and why not curves.** Flower-like ripples in other tools come from moving Bézier control points: the curves balloon into petals. None-Curve cannot use curves, so its petals are made of straight facets instead.
- **Mesh:** when Petals is above 0, each wedge between two polygon corners is cut by three more rays from the centre, through points evenly spaced along the side. Along each side the rays are: tip (the corner), shoulder, notch (the middle of the side), shoulder. Each petal tip points at a polygon corner; since the polygons sit on a flat side, with 5 sides one petal points straight up.
- **Movement:** each ray scales the rings along it (after the ripple has moved them) by its own factor: tips out by the full depth, shoulders out by 70% of it, notches in. At 100% the depth is 0.9: tips reach 90% further out, and notches keep 10% of their distance. Above 100% (to 300%, depth 2.7) tips and shoulders keep growing while the notches stay at 10%. Beyond the last ring the same scaling goes on, linear in each slice, so the plane stays continuous.
- **Validity:** corners only ever move along their own ray and stay on the same side of the centre (no ray's factor falls below 10%), so the rays keep their order and the rings keep their order along each ray. Petals is one-to-one at any depth: it never folds on its own and never needs the overlap merge. Folding (and the merge, section 4.5) still comes only from Ripple **Amount** above 100%.
- **Still no curves.** The warp is still piecewise-linear; the new rays are just more creases. Each petal has only three convex corners (shoulder, tip, shoulder) between concave notches, so petals never form a curve-like run, and creases are tidied as for every effect.
- **Controls:** Petals (0–300%, default 0%, in 10% steps), in the Ripple group between Fade and the statistics. Ripple counts as on when Use ripple is checked and either Amount or Petals is above 0; the pipeline summary lists "petals N%". Settings saved before Petals existed get 0. With Petals at 0 the mesh and every result are exactly as before (positions agree to within 1e-12 units, creases identical).
- **Checked:**
  - Mesh: exact images match densely sampled ones (within 3e-11 units), the map is continuous across every crease, and over 20,000 random points with Petals up to 300% and Amount up to 100% no triangle flips.
  - On the Latin glyphs of Arial, New York, and Georgia (13 settings each: Petals from 50% to 300%, with and without Amount, on top of Geometry settings, and stacked with Crumple and Slipstream): no new crossing, no weakened contour, no curve-like run that needs a crease, and every glyph exports. (One New York R reads as a new crossing to the audit, but it is the letter's own overlap, with a crease landing exactly on it.)
  - With Amount above 100% as well (and with every effect at its maximum): no crossing and no export failure; at most two curve-like runs per font not formed by the input's own vertices.
  - Whole fonts written as OTF and read back pass with Petals at 300%, alone and with Amount at 400%. With every effect at its maximum at once, all three fonts exceed the 1,000,000-point limit, and the message suggests exporting only the characters in the text.
  - Ripple with Petals adds about 0.3 ms per glyph to the geometry; every effect at its maximum at once takes about 20 ms per glyph.

### 4.7 Whorl (Phase 7)

Swirls each letter around the centre of its ink box.

- **Mesh:** the one Ripple uses: concentric regular polygons with **Sides** (3–12, default 8) and a flat side at the bottom (so with an even number of sides also a flat top), rays through the corners, each cell split into two triangles. The outermost of the **Rings** (2–12, default 6) lies half the ink box's height from the centre, so the top and bottom of the letter sit on it. (For a flat glyph such as a hyphen it lies at least 5% of the em out, so the glyph still turns.)
- **Movement:** instead of moving out and in, every ring turns as a whole about the centre, so it stays a regular polygon. Points in between move linearly with their triangle, so strokes bend only along straight creases and the swirl is built from straight pieces. **Pin top and bottom** picks one of two ways to turn:
  - **Pinned** (on, the default): the outermost ring and everything beyond it stay put, and the rings turn more toward the centre. The top and bottom of the letter stay where they are and the middle twists.
  - **Whole** (off): the centre stays put, the rings turn more toward the outside, and everything beyond the outermost ring turns with it as one piece. The top and bottom swing round too.
- **Validity:** neighbouring rings turn by the same step relative to each other. Turned too far, the triangles between them flip, and the further out the ring, the smaller the step that does it. At 100% the step is 90% of the largest that keeps every triangle the same way round, worked out for the Sides and Rings in use, with the cell diagonals laid along the swirl (whichever of the two diagonal directions lets the rings turn further). So up to 100% either way Whorl is one-to-one: no crossings, and counters stay inside. How far the swirl turns at 100% depends on Sides and Rings: from about 30° with 3 sides to well over a full turn with 12 sides and many rings. Above 100% either way, triangles flip, the letter folds, and the overlaps are merged (section 4.5); Whorl counts as folding when Amount is beyond ±100%.
- **Still no curves.** The warp is piecewise-linear: the creases are the ring sides, the rays, and the cell diagonals inside the rings. Beyond the outermost ring nothing creases (pinned: it is unchanged; whole: it turns rigidly as one piece). Creases are tidied as for every effect (faint ones removed, curve-like runs broken). Like Ripple and Slipstream, Whorl places itself by the ink box of what it receives.
- **Controls:** Use whorl, Amount (−400% to 400%, default 60%, in 10% steps; below 0% it turns clockwise), Pin top and bottom (default on), Rings (2–12, default 6), Sides (3–12, default 8). Whorl uses no randomness, so the shared seed does not affect it. Statistics as in the other groups (largest move, creases added); the pipeline summary lists "whorl N% (pinned|whole), R rings, S sides".
- **Checked:**
  - Mesh: exact images match densely sampled ones (within 1e-11 units), the map is continuous across every crease, and over 24,000 random points at up to ±100% (both modes, 3–12 sides, 2–12 rings) no triangle flips.
  - On the Latin glyphs of Arial, New York, and Georgia (12 settings each: ±30–100%, pinned and whole, 2–12 rings, 3–12 sides, on top of Geometry settings, and stacked with Crumple, Ripple, and Slipstream): no new crossing, no weakened contour, and every glyph exports. One curve-like run that needs a crease remains (New York č with very fine flattening, where the outline comes within 0.7 units of itself).
  - Beyond 100% (±200% to ±400%, both modes, 2–12 rings, 3–12 sides, and all four effects folding at once): no crossing and no export failure. Curve-like runs not formed by the input's own vertices appear only with the coarsest mesh at 300% (2 rings, 3 sides; 6–11 per font, every one five vertices long, where a crossing extends four of the input's own vertices) and at most 2 per font otherwise. Whole fonts written as OTF and read back pass at 100% with 12 rings and 12 sides, and at 400% whole.

### 4.8 Thorn (Phase 8, reworked in Phase 9)

A few anchors of each letter jump out into the canvas as long, straight thorns and pull the letter along: strokes lean and thin, and counters bend toward the thorn. Refraction can then show it all through fluted glass.

- **Which anchors:** only anchors on the outside of the letter, on contours that do not lie inside another contour, grow thorns, so counters never do (though they bend with a root, below). **Anchors** of them jump per letter, ranked by a hash of the shared seed and each anchor's position, so the same seed and outline always give the same thorns, every copy of a letter gets the same ones, and **Next variant** moves them. Driven by Sound (Beat → Seed), they jump somewhere new on every beat.
- **Direction and length:** each picked anchor jumps away from the ink, along the mean of its two edges' outward normals, turned by a seeded angle of up to **Spread** × 90° to either side, by a seeded 35–100% of **Reach**, and with a seeded lean.
- **1. Root** (a warp): a star mesh with 8 sides around the anchor (a flat side facing the thorn): the anchor in the middle, an inner ring at 35% of the root's radius (**Root** × 60% of the em), and an outer ring at the radius that stays put. The anchor moves out half its thorn's length, at most 75% of the radius; the inner ring follows 60% of that move on the thorn's side and 15% on the far side, is drawn in toward the thorn's axis by 35% of the move, and one seeded side follows up to 50% more than the other. Everything inside the outer ring moves with it, other contours included, so strokes tilt and thin, and a counter (the o's) or the far side of a stem bends toward the thorn too.
- **Why each root is valid:** every mesh triangle must keep at least 20% of its original signed area; while one would not, the pull is halved, up to 6 times, so each pull is one-to-one. Later thorns centre their mesh where earlier pulls moved their anchor, and all pulls run as one warp, their composition, through the shared warp (validation, retries at weaker strengths, tidying, crease marks); anchors are protected from tidying. When the warp has dropped an anchor because it sat on the tip of a hair-thin spike, the thorn grows from the nearest vertex within 4% of the em.
- **2. Tip** (not a warp): the anchor jumps the rest of its length, a sharp straight thorn. Its base reaches along the outline on either side by **Width** × the root's inner ring or the anchor's shorter edge, whichever is longer (at least 2% of it: a thin needle). Neighbouring thorns share a base point midway between them, so no filled web triangles form between them. The result is a wide root narrowing to a sharp tip. At Root 0% there is no root, and the thorns are only added on, as before Phase 9.
- **3. Refraction** (a warp, optional): the letter as seen through fluted glass. Vertical strips **Flute width** wide, from the glyph origin, each show their part of the letter magnified about their middle (by up to 30% at Refraction 100%), slid sideways, and lifted or dropped by up to 35% of the strip's width (seeded per strip), with the seams between strips (30% of a strip) squeezed into steep breaks and the lift ramping across them. x moves by a rising piecewise-linear function and y by a shift that depends on x alone, so the map is one-to-one at any strength.
- **Tidying and merge:** a pass over the creases removes the weakest one from any curve-like run of creases. A thorn may cross the letter or another thorn at any setting, so whenever a thorn is added the outlines are merged into one clean outline at the end, exactly as when an effect folds (section 4.5), and the letters still export.
- **Still no curves:** the root and the glass are piecewise-linear, and each tip is two straight edges from its base to its point; nothing is sampled or smoothed.
- **Controls:** Use thorn, Anchors (1–12, default 3), Reach (0–200% of the em, default 60%), Root (0–100%, default 50%), Spread (0–100%, default 50%), Width (0–100%, default 30%), Refraction (0–100%, default 0%, off), Reach, Root, Spread, Width and Refraction in 5% steps, Flute width (4–30% of the em in 1% steps, default 10%; greyed out while Refraction is 0%), and the shared seed. Statistics: Thorns (how many jumped), Roots (how many pulled the letter), and Longest (font units), with warnings when contours use a weaker root or refraction or a glyph is left without them; while Thorn is on, the intro also shows Crossings merged and Slivers dropped. The pipeline summary lists "thorn ×N, reach N% em, root N%, spread N%, width N%, refraction N% (flutes N% em), seed S". Settings saved before Phase 9 get Root 50% and Flute width 10% with Refraction off, so their look changes and Width now means how far the base reaches (Root 0% gives the earlier look back); settings saved before Thorn existed have it off. Thorn's random numbers use their own channels (0x5a1–0x5a6).
- **Checked (Phase 9):** every Latin glyph of Arial, Georgia, and New York, seeds 1, 7, and 42 (2,562 glyph runs per row), at 11 settings (the defaults; Root 0%; Root 100% with Reach 100%; every slider at its maximum with Width 2%, and with Width 100%; Anchors 1 with Reach 5% and Root 100%; Refraction 100% with flutes of 4% and 30%; a strong mix with Refraction 50%; values beyond the sliders' ranges; settings saved before Phase 9), alone, on dense and on heavy Geometry, and with Crumple and Slipstream: no export failure at 0 or 2 decimals, no glyph left without its effect, and every glyph with thorns. One crossing showed at the maximum setting on heavy Geometry (New York â, seed 7), a 1-unit loop left by the merge's snap rounding; the merge fix of section 4.9 removed it, and every audit now has none. The farthest point lies at most 3.7 em from the origin. Time per glyph: about 0.7 ms at the defaults (Thorn off: 0.12 ms), 5.3–6.5 ms on dense Geometry, and up to about 17 ms with every slider at its maximum on dense Geometry, mostly the root warp running over many vertices. Curve-like runs that creases make: 75 in 2,562 glyph runs at the defaults alone, mostly where the root squeezes the font's own flattened curves; at the extremes up to 405 alone and 2,329 on dense Geometry, most shorter than 5% of the em.
- **History:** Phase 8 built Thorn (then Spikes) as the tip alone: two new anchors on the jumping anchor's edges, Width × its shorter edge away, kept the rest of each edge in place, and the letter around the spike stayed untouched. Phase 9 added the root, which makes the letter respond, and Refraction.

### 4.9 Rework (Phase 9)

- **Why:** the first versions of three effects did not look as intended. Crumple's single even lattice gave every straight stem the same regular zigzag; Slipstream only stretched, with no misalignment inside the letter, no cuts or trails, and no large swings over fine turbulence; and Thorn's spikes were only added on, leaving the letter around them untouched.
- **Rename:** Noise → Crumple, Curl → Whorl, Wind → Slipstream, Spikes → Thorn, in the code (`experimental.crumple`, `.ripple`, `.whorl`, `.slipstream`, `.thorn`), the labels ("Use crumple", …, the statistic "Thorns"), and the Sound tab ("Turned off Crumple and Ripple."). Distortion's Noise amplitude and Noise frequency keep their names. The rename alone changed no result: 14,518 glyph and setting pairs compared, with no difference.
- **Crumple, Slipstream, and Thorn:** sections 4.1, 4.3, and 4.8.
- **The `'positive'` fill rule** (`overlaps.ts`): beside the nonzero rule fonts use, the merge can keep only what the outlines wind around counter-clockwise on balance, so clockwise contours added to a glyph whose ink winds exactly once cut holes into it. Slipstream's cuts use it; every other caller keeps the nonzero rule.
- **The merge's exact redraw** (`overlaps.ts`, so all three places that merge get it): snap rounding had moved every point a little, and a run of short edges then read as a wobbly curve.
  1. After the grid merge, each contour is redrawn through the input's own vertices and the exact places where input edges cross, and the grid detours are dropped.
  2. Validation, up to 8 rounds: a vertex goes back to the grid if it makes a contour cross or touch itself or another, turn inside out, nest differently than on the grid, or come within one grid cell of the point after next (rounding to whole units would join those two and fold the contour up). If the rounds run out, the last valid state is used, and the grid result is the final fallback.
  3. Run breaking: in each remaining run not made of the input's own points, the corner that turns least is dropped when that moves the outline by at most one cell, under the same checks.
  4. A segment passing exactly through a cell corner was routed into all four cells, a zigzag that crossed itself (New York â); each cell now owns only its bottom-left corner.
- **Measured** on Arial, Georgia, and New York, all Latin glyphs, seeds 1 and 7, 6 settings, each alone and on dense and heavy Geometry (30,744 glyph runs):

  | | Before | After |
  |---|---|---|
  | Run vertices that merges add | 36,539 in 5,731 glyph runs | 498 in 129 |
  | Run vertices the effects add, against the effect off | 32,200 in 4,937 | 4,904 in 841 |
  | Crossings | 1 | 0 |
  | Export failures | 0 | 0 |

  Effect audits, run vertices before and after: Crumple (96 rows) 108,454 → 14,499; Thorn (36 rows) 12,146 → 3,669; Slipstream 87.5 → 35.7 per 1,000 glyphs. Merging takes longer: 3.85 → 4.56 ms per glyph on average over all settings, Slipstream on dense Geometry 6.27 → 8.49 ms, all three effects on dense Geometry 13.44 → 17.57 ms. Merged outputs now keep the input's exact vertices (on dense Arial about 1,455 points per glyph instead of 637), so Ripple and Whorl beyond 100%, which go through the merge, changed too; within 100%, and with no effect on, nothing changed.
- **Sound:** seven new targets (Crumple Detail; Slipstream Slip, Cuts, and Trails; Thorn Root, Refraction, and Flute width, which needs Refraction above 0%), and the Flare and Gale presets retuned for the new effects (SOUND_PLAN §6–7).
- **Left open:** a few merge-added runs remain (498 vertices in 129 of 30,744 glyph runs, each about 1–3 units, where outlines cross and a vertex had to stay on the grid, such as Arial ţ, 8, and ò). The effects themselves make runs before any merge (about 4,900 vertices, mostly Crumple folds in Georgia and New York and Thorn's root in Georgia), where warps squeeze the font's own flattened curves; `warp.ts` deliberately keeps runs made of the input's own vertices, and changing that would also change Ripple and Whorl. Dense Geometry with merges costs 2–4 ms more per glyph at the heaviest settings. A long trail can reach into the next letter; outlines are per glyph, so this is only visual.

### 4.10 Vertex budget and a sturdier merge

- **Why:** dense effects multiply. Every warp adds a vertex wherever its mesh creases the outline, Thorn's refraction warps each strip of the letter again, and every merge adds one wherever outlines cross. With all five effects on at their densest, a letter of a hundred vertices became tens of thousands (up to 135,000), which took up to 14 s per glyph, and an unmerged one could hang export. Separately, the merge could join outlines wrongly where a crossing fell on a grid cell's side, and on Anchor spacing 1 under a folding effect it overflowed the stack.
- **The budget** (`src/geometry/budget.ts`, inside `applyExperimental`, so the canvas, the preview, and every export agree). After any effect a glyph may have at most 6,000 vertices more than it brought into the Experimental effects, and a merge at most 30,000 grid points (vertices and crossings) more (`EXPERIMENTAL_LIMITS.maxAddedVertices`, `maxMergePoints`). The limits are on top of the input, so dense Geometry is never cut, and they depend only on the glyph and the settings, never on time, so the same settings always give the same letters.
  1. **Simplifying:** after each effect, a glyph over the limit is simplified by Ramer–Douglas–Peucker with one tolerance shared by all its contours, starting at the warps' drift limit (0.01 em) and doubling, at most 12 times (about 40 em), until it fits. Contours no larger than the tolerance are left out (never all of them), and so are simple slivers thinner than it on average; triangles and contours that cross themselves are kept. Each contour keeps a subset of its own vertices, so every edge stays straight, and runs the simplification leaves looking like a curve are broken up (section 2). The simplified outlines may cross, so from then on the glyph is merged at the end.
  2. **Warps:** a warp that would make more than 16 times the vertex limit (a long tangle through a fine mesh) is left out of that glyph before its costly tidying, and the effect's group says so. Thorn's root and refraction warps get the same cap.
  3. **Merges:** every merge (the final one, and Slipstream's two for its cuts) gets the merge limit. It counts grid points before its costly steps and stops as soon as there are too many: 1–13 ms instead of 60–700 ms for a full merge. The glyph is then simplified more coarsely, each try with at most half the vertices of the one before, and merged again, until it fits. Only if even the coarsest simplification is too complex is it left unmerged (`tooComplex`), at that coarsest simplification: by the nonzero rule it fills the same, and with few vertices left it is still quick to draw and export. In the tests this last resort was reached only with synthetic input.
  4. **The first design** stopped simplifying at 0.16 em and left the glyph unmerged. But an unmerged glyph with every slider at its maximum crosses itself 200,000–850,000 times, and rounding it for export took more than 100 s per glyph. So the retries go on to the twelfth doubling, and at the maximum every glyph merges; exporting those takes 11–30 ms per glyph. Export rounding now also takes a contour that crosses itself more than 2,000 times as it rounds, checking only its direction, area, and place among the other contours (`src/export/quantize.ts`), so even an unmerged tangle of 100,000 crossings rounds in 0.5–1.2 s instead of not finishing in 300 s.
- **What reaches it:** the defaults, every effect alone (even at the ends of its sliders, also on Anchor spacing 1), and every Sound preset stay under the budget, and their results are byte-identical to before (147 audited configurations). Only several dense effects together reach it:
  - All five effects on at Amount 100% with every other slider at its densest end: tolerance 0.01–0.02 em, and the letters look as before with fewer vertices.
  - Every slider at its maximum: tolerance 0.64–2.56 em, and the letters turn into a few broad slabs of ink instead of thin wisps. This is accepted; keeping the thin look would need an exact merge of 200,000–850,000 crossings, 2–7 s and 15,000–54,000 vertices per glyph.
  - Measurements in earlier sections that stack several effects at their maxima were taken before the budget.
- **Shown:** the Experimental panel's merge statistics appear whenever the budget acted, with "Simplified: these settings make too many vertices or crossings, so the outline was reduced (tolerance N u).", or "Too complex to merge; lower the settings." when even the last resort is left unmerged. A warp left out reads "This glyph is left without <effect>: too complex." (for Thorn, "without roots or refraction"). The status bar shows "(simplified)" after the selected glyph's vertex count. The intro says that where several dense effects together would add too many vertices, the letter is simplified.
- **A sturdier merge** (`overlaps.ts`, so all three places that merge get it):
  1. **Exact rounding:** a crossing within rounding error (1e-6 of a grid unit) of a cell side could round into a cell one of its two edges does not pass, and the edges were then not joined there. Such a crossing is now rounded exactly, in integer arithmetic.
  2. **Broken-graph check:** should rounding still join outlines wrongly, a region is reached twice with different winding numbers. Which crossings fall on cell sides depends on the grid, so the merge then tries once more on a grid twice as fine. If that breaks down too, the glyph is left as it was (`failed`): its outlines still cross, but it fills the same, and the panel says "Overlaps could not be merged; the outline is left as it is."
  3. **No stack overflow:** joining the pieces (union-find) is iterative, with path halving and union by size, since a piece can have tens of thousands of vertices.
  4. **The limit** (above): over it the merge gives the glyph back with `tooComplex`, and the finer grid is not tried.
  5. **Faster searches:** the crossing searches (a contour against itself, two contours, and the merge's crossings) sweep along x, y, or a diagonal, whichever the segments are shortest along in total when that is less than half their length along x, and only with 64 segments or more; what they find is put back in the order of a sweep along x, so results are unchanged. Contours of 128 points or more get a strip index (`RingIndex`) for finding crossings between contours and for testing which lies inside which, and pairs of contours whose boxes are apart are skipped, also in export rounding.
- **Measured** (times on a shared machine, so differences under about 10% are noise):

  | | Before | After |
  |---|---|---|
  | All five effects at Amount 100%, densest sliders: median / slowest glyph (Arial; New York) | 1,128 / 2,001 ms; 625 / 990 ms | 477 / 707 ms; 459 / 525 ms |
  | Every slider at its maximum: median / slowest glyph (Arial; New York) | 6,237 / 13,761 ms; 5,798 / 10,781 ms | 383 / 585 ms; 416 / 443 ms |
  | Vertices out at the maximum, average (Arial) | 85,227 | 4,008 |
  | 680 synthetic crossings on cell corners and sides | 85 silently wrong | all right |
  | Anchor spacing 1 under six folding settings, 5 fonts (9,474 glyphs) | 135 stack overflows | no error, crossing, failure, or export failure |
  | Merge of an 8,002-point comb | stack overflow | 122 ms |
  | Self-crossings of a 40,000-point comb (along x; at 45°; at 30°) | 2,860; 719; 631 ms | 26; 24; 246 ms |
  | Crossings between two 20,000-point contours | 2,015 ms | 38 ms |
  | Captured heavy merges, total (Arial @, 85,000 vertices; New York Q, 55,000) | 12,365 ms (6,806; 2,045) | 3,113 ms (956; 464) |
  | Export rounding at 0 decimals: 3,000; 6,000; 20,000 contours | 4,146 ms; failed; failed | 15; 24; 57 ms |

  The 5-glyph sample was a, e, O, Q, and @; on 21 glyphs, the defaults take about 8 ms per glyph (34–36 ms at most). With exact rounding switched off, the finer grid caught and fixed all 85 broken corner cases. Outputs at ordinary settings are byte-identical to before (88,608 glyph hashes of Arial and New York, geometry and export at 0 and 2 decimals); the one intended change is a single vertex of one STIX Two Text glyph under strong Thorn on Anchor spacing 1, moved by the exact rounding. The page gives up on a glyph after 60 s without word from the geometry worker; with the budget the slowest glyph measured took 2.7 s (all effects at Amount 100% on Anchor spacing 1, on a busy machine).
- **Left open:** the budget bounds the cost tightly but the vertex count only roughly, since a merge adds a vertex at each crossing (up to 6,407 against a limit of about 6,100–6,180). Dense Geometry gets a proportionally larger budget. When the budget simplified a glyph before Thorn, Thorn picks its anchors from the simplified outline, so the thorns land elsewhere than they would without it. Merges on Anchor spacing 1 still drop up to 14.9% of the ink as slivers, as before. A comb at an angle none of the four sweeps fits gains less (631 → 246 ms).

## 5. Interface

- English-only labels, short, with explanations folded behind ⓘ buttons.
