# None-Curve

[English](README.md) · **中文**

一个把字体曲线转换成可编辑多边形的实验性网页工具。载入字体、输入文字，调整控制项时，每个字母都会实时由直线重新构成。你可以让轮廓变成折面、方形、对齐网格或带有粗糙感，然后把单个字形或整段文字导出为 SVG，把字形导出为 OpenType 字体，或者录下文字随声音变化的视频。一切都在浏览器中完成，字体和音频文件不会被上传。

**第一次使用、不懂代码？** 请阅读 **[用户指南](docs/USER_GUIDE.zh.md)**——它用通俗的语言解释了屏幕上的每个区域和每个控制项。

## 运行

- **在线：** `main` 分支部署后访问 `https://m1ingx1xx1.github.io/None-Curve/`（见[部署到 GitHub Pages](#部署到-github-pages)）。
- **本地：** 需要 Node.js 20.19 及以上（推荐 22）。

```bash
npm install       # 安装依赖
npm run dev       # 开发服务器：http://localhost:5173/
npm run build     # 类型检查（应用、测试和脚本）+ 生产构建，输出到 dist/
npm run preview   # 预览生产构建：http://localhost:4173/None-Curve/
npm test          # 快速测试（约 15 秒）；见下文“测试”
```

## 界面

```text
┌────────────────────────╥───────────────────────────────────────────────────┐
│ 功能区                 ║ 结果画布                                          │
│ 导入 · 字体信息        ║ 只显示输入的文字                                  │
│ 几何参数（可滚动）     ║                                                   │
╞════════════════════════╩═════╦═════════════════════╦═══════════════════════╡
│ 排版 / 字形 / 颜色           ║ 文字输入            ║ 预览 + 模糊/反色      │
└──────────────────────────────╨─────────────────────╨───────────────────────┘
```

双线是拖动手柄。每个手柄只移动两侧区域之间的分界线，两侧加起来的大小始终不变：上下两行始终正好填满标题栏和状态栏之间的窗口高度（页面不会滚动）；功能区和画布平分上面一行的宽度；下面一行的排版 / 字形 / 颜色标签页、文字输入和预览加起来始终等于这一行的宽度（最小宽度依次为 260、180、200 像素）。每个手柄就是那条 1 像素的分隔线本身（和标题栏、状态栏的边线一样用低调的边框色），另有 9 像素宽的隐形拖动区域。可以拖动手柄，或让手柄获得焦点后用方向键调整（Home / End 跳到两端）；双击恢复默认。每个区域都保留最小尺寸，分隔比例会记在浏览器里。上下两行各自独立调整，所以它们的竖向分界线不一定对齐。

- **顶部栏：** 文件状态和 **Export…**。撤销和重做没有按钮，只用键盘快捷键（见[保存与撤销](#保存与撤销)）。录制视频期间，这里显示 “Recording 0:12” 和一个 Stop 按钮，录完后显示这次录制的结果（见[视频](#视频)）。
- **左上——功能区：** 最上方是 **Import** 和字体信息，下面是 **Geometry（几何）**、**Experimental（实验）** 和 **Sound（声音）** 三个标签页。**Geometry** 按流水线顺序排列全部几何参数（展平、方形化、锚点、网格与角度、扰动），最后是随机锚点；**Experimental** 放在它之后运行、可以同时打开的效果（Crumple、Ripple、Whorl、Slipstream、Thorn）；**Sound** 播放本地音频文件或通过麦克风收音，显示实时电平表，并通过映射让声音移动另外两个标签页的滑块，或让它们的种子跳变，还能录制视频；被驱动的滑块保留自己的值，并用一条细标记显示实时值；被驱动的种子输入框保留自己的种子，并在旁边显示实时种子（见[声音](#声音)）。浏览器会记住当前选中的标签页。参数区的统计数字针对当前选中的字形。当前不起作用的控件会变灰：随机锚点开启时整个曲线展平组变灰；随机程度为 0% 时随机种子变灰。各项说明默认收起在标签旁的 ⓘ 按钮后面（点击展开，因此键盘也能用；收起时文字仍作为控件的读屏描述）；面板内容上方的 **Show all explanations** 可以一次展开全部（包括排版和颜色标签页里的说明），并会记在浏览器里。警告、统计数字以及“为什么这个控件变灰”的说明始终显示。
- **右上——结果画布：** 显示画布（画板）及其上输入框里的文字，使用当前字体、全部参数、排版设置和颜色。画布下方的 **Canvas size** 可以展开或收起画布尺寸抽屉（见[画布尺寸](#画布尺寸)），展开状态会被记住。它的轮廓视图与图层开关（Original / Flattened / Compare、Fill、Skeleton、Vertices、Metrics）以及缩放与平移都只影响画布，只有 **Fill** 例外：关闭时，预览以及 SVG、PNG 和视频导出也只画轮廓（见[仅轮廓](#仅轮廓关闭-fill)）；预览始终显示导出结果（见[文字预览](#文字预览)）。每个字形的点击范围是它的字列（字宽 × 上伸到下伸）加上字母本身，所以小字也很容易点中；宽度为零的附加符号（比如组合重音）没有字列，只有字母本身。没有 Thorn 时，字母本身就是当前视图里画出的轮廓。开启 Thorn（Experimental）时，它是字母原始轮廓的一份看不见的副本，按 Curve flattening 展平成直线段，而画出的轮廓（包括刺、Ripple 的花瓣和 Slipstream 的拖尾）从不接收指针：在刺上点击或拖动，都交给它后面的东西，比如另一个字母、开启 Free 位置时的整块文字，或空白画布（在那里拖动就是平移）。所以点离开字母的刺，不会选中这个字母。点击字形即可选中它（统计数字随之切换），并把它在文中的每一处都换成高亮色（鼠标悬停时也一样）。高亮色由文字颜色和背景颜色计算得出：在背景上仍然易读的颜色中（对比度至少等于文字本身的对比度，最高要求 4.5 : 1，最低不低于 3 : 1），选出在色相和色度上与文字颜色差别最大的一个（OKLab），偏向鲜艳的颜色，避免亮度往背景方向褪，并且色相与配色的色相相差不超过 40°（文字本身已经很鲜艳、40° 内拉不开差别时放宽到 90°；先取文字的色相，文字无色时取背景的，都无色时取橙色）。米色纸上的黑字会高亮为朱红；彩色文字会高亮为相邻色相中更鲜艳的颜色。点击画布空白处（拖动结束时不算）或按 Esc 取消高亮；统计数字仍显示最后选中的字形，Geometry 面板顶部的 **Statistics** 一行会写明是哪个字形（字符和编码）。预览从不显示高亮。
- **左下——文字工具：** 三个标签页（会记在浏览器里，可用方向键切换；始终保持加载，切换时不会丢失局部状态）：**Typography（排版）**——文字在画布上如何排布（见[排版](#排版)）；**Glyphs（字形）**——见下条；**Color（颜色）**——文字与背景的颜色。
- **Glyphs 标签页：** 可搜索的字符网格，列出字体映射的所有字符，用作插入器：点击字符会把它插入到文字输入框的光标处（有选中文字时替换选中部分），并选中该字形。输入框从未获得焦点时，字符追加到末尾。没有对应字符的字形（连字、替代字形）和控制字符无法输入，因此不列出。字形列表窄于 280 像素时，格子会缩小并只显示字符本身；超过这个宽度时重新显示 Unicode 编码（编码始终保留在每个格子的悬停提示里）。
- **右下——输入与预览：** 左边是紧凑的多行文字输入（Text 标题右边的大小写开关 **AA** / **Aa** / **aa**、示例文本菜单、Clear、字符数、字偶距状态、缺字提示）；右边是缩小显示的 SVG 导出结果本身（裁到画布边缘；见[文字预览](#文字预览)），带独立的 **Blur（模糊）** 滑块（0–12 像素，每档 0.1）和 **Invert（反色）** 按钮（交换文字与背景的颜色）。除非勾选 **Export the preview look**，模糊和反色只作用于这个视图，相当于“眯眼看整体字形”。两部分之间有一个拖动手柄，可以移动分界线（默认 40 / 60）。
- **状态栏：** 字体状态、选中的字形和当前视图（其中有选中字形的顶点数；实验效果的顶点预算简化过这个字形时，后面跟着 “(simplified)”，见[翻折](#实验效果crumpleripplewhorlslipstream-与-thorn)）；Sound 驱动字母期间显示 **Live · N fps**（实时帧率）；麦克风收音期间显示 **Microphone on**（在任何标签页都能看到），麦克风自己停止时（被拔出或权限被收回）显示 **No microphone**；最右端是 **Reset all**（全部重置，一个画着回转箭头的图标按钮；见[保存与撤销](#保存与撤销)）和一个小小的界面亮色 / 暗色切换。每次打开都先按系统设置（`prefers-color-scheme`），系统设置改变时也会跟随；在这里的选择只在本次访问有效，不会保存。主题色是 CSS `light-dark()` 值，由 `<html data-theme>` 上的 `color-scheme` 切换。画布在两种主题下都使用颜色设置里的配色。
- **滑块与数字框：** 每个滑块都带一个数字框，按标签所示的单位（%、°、% em、u、px、ms、dB）显示当前值：在 Geometry、Experimental 和 Sound 标签页里位于滑块的标题行，在 Typography 和 Canvas size 里位于滑块旁边，预览的 Blur 也有一个。每个数字框的宽度刚好放下它最宽的值（`widestChars`，即 `styles.css` 中的 `--chars` 宽度），没有上下小箭头，用方向键可以按档位调整。输入的值在按回车或离开数字框时生效（按 Escape 恢复原值），并限制在滑块的范围内、取整到它的档位（`src/components/` 中的 `SliderNumber` 和 `NumberField`）。档位都很细（NOCUR-63）：比例 1%，尺寸为 em 的 1%，角度 1°，距离 1 个字体单位（Anchor reduction 和 Noise frequency 为 0.1），计数为 1；要精确设定某个值就用数字框。Tolerance 和 Thorn 的 Reach 保留各自的对数和立方滑块；它们的数字框直接输入值本身（字体单位，精确到 0.01，并按滑块的方式取整；画布的百分比，精确到 0.01%）。
- 只面向桌面浏览器：没有手机或窄屏布局。窗口变窄时布局不变：各区域先缩到各自的最小尺寸，再窄就按比例一起缩小。

### 画布

- 轮廓视图：**Original**（字体原始曲线）、**Flattened**（最终多边形）、**Compare**（最终多边形，叠加原始曲线虚线）。当前视图显示在画布角落和状态栏。
- 图层：**Fill**（关闭后显示描边；预览以及 SVG、PNG 和视频导出都跟随它，字体文件始终是实心的）、**Skeleton**（原始曲线上锚点为方块、曲线外控制点为空心圆，以及控制柄；TrueType 的隐含节点也显示为锚点）、**Vertices**（最终多边形顶点，绿色圆点）、**Metrics**（上伸线、大写高度、x 高度、基线、下伸线、字宽）。
- 用鼠标滚轮或 `+` / `−` 缩放，拖拽或方向键（画布获得焦点时）平移，`0` 或 **Fit** 复位。右下角的预览始终适配全文，不能交互。
- 在画布上，所有图层都作用于文字中的每个字形；预览不显示任何图层。只绘制可见范围内的字形；刺伸进可见范围的字形也算在内，所以平移时长刺不会忽隐忽现；每个 em 在屏幕上不小于 48 像素时才显示骨架点和顶点，否则画布提示放大，长文本因此仍可辨认。度量线的文字标签只标在第一条可见行上。

### 画布尺寸

文字排在一个固定像素尺寸的画布（画板）上；缩放 100% 时完整显示整个画布。背景色铺满整个视图。画板以外（工作区）比背景色暗 7%（深色背景则亮 6%），并铺有屏幕网格（每 24 像素一格），浅色背景上用黑色、深色背景上用白色，不透明度取到与背景的对比度为 1.3 : 1——无论文字是什么颜色，每种配色下的可见度都一样（`src/specimen/color.ts` 中的 `gridLineColor`；Grid & angles 的吸附网格为 1.5 : 1）；画板以内和导出效果完全一样。只有在需要对齐时，网格才会淡入到画板内：拖动文字时（Free 位置），或缩放到 200% 及以上时。一条带柔和阴影的 1.5 像素外框（目前设为透明，只留阴影）标出导出区域，并让它从周围的背景上浮起——外框用界面的薄荷绿（#adfce7；在背景上更显眼时用 #0f7a5c），而不是文字颜色，所以不会被误认为文字的一部分；阴影在浅色背景上是深色投影，在深色背景上是浅色光晕（`src/styles.css` 中的 `.artboard-frame`）；度量线也用文字颜色绘制。透明背景显示为棋盘格，由背景色和叠了文字颜色的背景色组成，因此文字依然清晰。画布下方的抽屉包含：

- **W** / **H**：画布宽和高，100–4000 像素，每档 1（滑块或数字框；数字框在按回车或离开时生效，并限制在范围内）。
- 画幅比例 **1:1**、**4:3**、**16:9**、**4:5**、**3:2**、**3:4**：保持宽度、按比例设定高度（若超出范围则改为保持高度）；与当前尺寸相符的比例会高亮。**Swap** 交换宽和高。
- **1×–4×**：导出倍数。PNG 的尺寸为宽 × 倍数、高 × 倍数，排版不变，倍数越高越清晰。
- 开启 Thorn 时，**W** 和 **H** 还决定刺按 em 计能伸多远（Reach 是画布对角线的比例，见[实验效果](#实验效果crumpleripplewhorlslipstream-与-thorn)），所以改变它们会重新计算字母；导出倍数不会。

超出画布边缘的文字在画布上仍可见并给出提示（“The text runs past the canvas edge and will be cut off in the preview and in exports. Try Typography → Fit text.”）；预览和导出会裁到画布边缘。这条提示量的是不带 Thorn 刺尖的字母（`src/specimen/artboard.ts` 中的 `textOverflows`）：刺本来就可以伸出画布，在工作区上照样显示，在预览和 SVG、PNG 导出中则在画布边缘被裁掉，不会给出提示。声音驱动字母时，这条提示量的是滑块值下的字母，也就是决定文字块位置的那些字母（`useGeometry` 给出的 `placement`；见[排版](#排版)），而不是实时字母：声音把某个实时字母扭得比滑块值更远时，它可能伸出画布边缘而没有提示，在预览和视频中就会被裁掉（画布上仍完整显示）。

### 排版

`src/specimen/artboard.ts` 与 `src/specimen/scene.ts`。这些设置改变排版和 SVG/PNG 导出，不改变字形几何，也不影响字体文件，只有一个例外：开启 Thorn 时，**Size**（和画布尺寸一样）决定刺按 em 计能伸多远，因为 Reach 是画布的比例（见[实验效果](#实验效果crumpleripplewhorlslipstream-与-thorn)），所以改变字号会重新计算字母。

- **Size（字号）**（4–1000 像素，默认 48）：每个 em 在画布上的像素数；改变画布尺寸不会改变字号。**Fit text** 设为能让轮廓的范围（含倾斜）在两个方向上都放进边距内的最大整数像素字号。
- **边距**：位置锚点和 Fit text 在轮廓的范围与画布四边之间固定保留 25 个画布像素，与字号无关（`src/specimen/artboard.ts` 中的 `EDGE_MARGIN_PX`），没有对应的控件。
- **排版不计 Thorn 的刺。** Fit text、位置锚点、Free 和超出画布的提示，量的都是每个字母在 Thorn 之前的样子：Thorn 的根部、刺尖和折射之前的墨迹范围（`PolygonGlyph.layoutBox`），文字倾斜时再加上同一个字母的凸包（`PolygonGlyph.layoutHull`），逐点倾斜，所以无论倾斜多少，文字的位置、Fit text 和超出提示都与关闭 Thorn 时完全相同（只有字形没有凸包时，才退而用范围框倾斜后的四角，它们伸得更远）。它们汇总为 `src/specimen/scene.ts` 中的 `SpecimenScene.body`，所以刺从不移动、缩小或挡住文字，也可以伸出画布边缘。本节中的“轮廓的范围”都指这个范围；没有 Thorn 时就是轮廓本身的范围。
- **声音不移动文字。** 声音驱动字母时，文字块的位置由滑块值下的字母（滑块场景）决定，而不是由实时字母决定（`src/specimen/artboard.ts` 中的 `placementScene`，由 `src/state/useDerivedGeometry.ts` 中的 `useGeometry` 使用），实时字母就画在这个位置上。两者的行和笔位相同（都来自步进宽度），不同的只有在轮廓上量出的范围。所以无论效果、种子、预设或 Response 设置把实时轮廓变成什么样，文字块都停在没有声音时的位置。滑块值下的字母通常在平常编辑时就已算好；声音驱动期间滑块、文字、字体或排版有变化时，还缺的字形要等这些设置停下 200 ms（`SLIDER_SCENE_DELAY_MS`）后才去计算，所以拖动滑块只请求一次，而不是每帧一次。结果到来之前，文字块保持同一段排好的文字上一次按滑块值得到的位置；没有这样的位置时，由实时字母决定（与以前相同）。超出画布的提示也量滑块值下的字母（见[画布尺寸](#画布尺寸)），所以比它们扭得更远的实时字母可能伸出画布边缘，在预览和视频中被裁掉。视频把实时字母画在同一个位置，所以视频里的文字块同样不动。Freeze 会把实时值写进滑块，所以那时文字块可能移动一次。没有声音时一切不变。
- **Tracking（字间距）**（−200–1000，单位千分之一 em，每档 1）：在字宽和字偶距之外加在字形之间，不加在每行最后一个字之后。
- **Line height（行距）**（0.5–3 倍）：字体行距（上伸 − 下伸 + 行间隙）的倍数。
- **Slant（倾斜）**（−30°–30°）：绕每个字形自己的基线做错切（x′ = x + tan(倾斜) · y），正值向右倾。
- **Align（对齐）** Left / Center / Right（图标按钮）：整块文字内部行与行之间的对齐。
- **Position（位置）**：整块文字在画布上的位置。九个锚点（3 × 3 网格：四角、四边中点、正中）按轮廓的范围（含倾斜；不是行框，所以字身两侧的留白和上伸空间不会留下空隙）把文字贴到左边距、水平居中或贴到右边距，以及贴到上边距、垂直居中或贴到下边距——字母离画布的边和角 25 像素。点锚点时也会按它所在的列设置 **Align**（左列靠左、中列居中、右列靠右），之后仍可单独更改 Align。默认是左侧、垂直居中。选中的锚点（以及开启时的 Free）会以主色薄荷绿发光。**Free（自由）** 时可以按住字母的范围或任一字形的点击范围在画布上拖动文字（从别处开始的拖动，比如从远离这两者的 Thorn 刺尖上开始的，仍是平移视图）；位置记为画布在轮廓范围旁边和上方留出的空间的比例，所以文字到画布边缘就停住，改变字号或画布尺寸后也仍在画布内。点 Free 会先把文字放回默认位置和对齐（左侧、垂直居中），然后就可以拖动；再点一次会重新回到默认位置。
- **大小写**（Text 标题右边的 **AA** / **Aa** / **aa**）：**All caps**（全大写）、**Title case**（每个单词首字母大写、其余小写）或 **Lower**（全小写）；再点一次已选中的按钮即恢复原样。输入的文字本身从不改变；画布、预览、导出以及字体文件的 “Specimen characters” 都使用转换后的文字。
- **Reset typography** 恢复默认值（48 px、0、1、0°、左对齐、位置为左侧垂直居中），保留大小写设置。

### 颜色

十二个预设（Charcoal——默认，浅底深字——以及 Off White、Kryptonite、Plum、Glowing Cyan、Acid Lime、Ember、Moonlit Purple、Chrome Pink、Cherry、Atomic Blue、Forest Moss），**Random**（随机生成一组易读的配色，对比度 ≥ 4.5 : 1），**Swap**（交换），以及自定义 **Text**（文字）与 **Background**（背景）颜色：取色器加十六进制输入框（`#rgb` 或 `#rrggbb`）。面板会显示对比度，低于 3 : 1 时给出警告。**Transparent background** 让 SVG 和 PNG 导出不含背景；背景色仍保留，供 Swap、Invert 和棋盘格使用。画布上的悬停和选中使用由文字颜色和背景颜色计算出的高亮色（见上文的结果画布）。

### 文字预览

输入的文字使用共享几何缓存中的最终多边形排布，因此画布、预览和导出结果始终一致。

- 每个字形按字宽推进，并在字体带有字偶距数据时应用字偶距（GPOS `kern` 特性或旧版 `kern` 表，经 fontkit 排版）。连字关闭，每个字符保持自己的字形。没有字偶距数据的字体会明确标注。
- 行高 = （上伸 − 下伸 + 字体行距）× **Line height**。空格只推进不绘制。缺字在画布上以虚线框标出，并在文字面板中列出。
- 最多显示 1000 个字符。同一组参数下，每个不同的字形只处理一次（缓存键：字体、字形和全部几何参数）。
- **预览**（右下；`src/components/ExportedArtboard.tsx`）画的就是 SVG 导出本身：画框、背景、模糊滤镜、分组变换和字形路径都与 `specimenToSvg` 写出的完全相同，全部来自 `src/export/svg.ts` 中的 `specimenPaths()`。它显示按导出的 **Coordinate precision** 取整后的直边轮廓：实心，或在 **Fill** 关闭时像导出那样只描边（见[仅轮廓](#仅轮廓关闭-fill)），从不跟随 Original / Compare、Skeleton、Vertices、Metrics、吸附网格或缺字虚线框（这些只在画布上显示）；缺字和文件里一样只留空。透明背景显示为棋盘格。按这个精度取整失败时，预览显示 “Export would fail: …” 和原因。声音驱动字母期间，预览显示实时帧；字母按不同幅度反应时（Motion contrast、Pitch reactive），每个字母显示自己的形状（路径按多边形而不是按字形编号生成）；SVG、PNG 和字体导出仍然使用滑块值，只有视频会录下实时帧（见[视频](#视频)）。取整后的轮廓按多边形缓存，预览延后更新（`useDeferredValue`），所以画布优先。

### 保存与撤销

`src/state/persist.ts`、`src/state/history.ts` 与 `src/state/reset.ts`。

- **在两次访问之间保存**在 `localStorage` 里（键名 `none-curve:session`，带版本号；约 2 KB），每次改动后半秒、以及页面被隐藏或关闭时写入：所有设置（Geometry、Experimental、Typography、Color 和 Canvas size）、画布视图的轮廓和图层按钮（不含缩放和平移）、文字（最多 10,000 个字符）、预览的 Blur 和 Invert、导出精度、声音映射、Sound 标签页的 Response 分组（Sensitivity、Strength、Motion contrast、Release、Pitch reactive 和 Melody tracking；在它们出现之前保存的记录读作默认值）、选中的字形（只在同一字体族和样式中恢复），以及字体。Google 字体会在页面打开时重新下载；本地文件无法重新打开，所以画布会写出它的名字（“Last font: X. Import it again to continue.”）。读取时，每个值都会对照默认值检查，所以损坏的或旧版本的记录不会让应用出错（旧的效果名和特征名会改成新名字）。当前版本是 2：版本 1 记录里的 Thorn **Reach**（em 的比例）会按该记录保存的字号和画布，换算成同样长度在画布对角线中所占的比例（对角线最多按 256 em 计，与 Thorn 的算法相同），最多 100%，保留 4 位小数；大于 0 的 Reach 换算后不会低于滑块的第一档（0.01%），所以原来长着刺的 Thorn 仍然长刺（`src/state/persist.ts` 中的 `fromV1`）；作用在 Thorn · Reach 上的声音映射保留原来的 Depth。Thorn 用到的“画布对角线有多少 em”由设置算出，从不保存。
- **不保存：** Drive letters、音频文件或麦克风、声音的实时值、视频录制选项（Format、Length、Include audio、Use the preview look）、打开的对话框，以及亮色 / 暗色主题。（各区域的分隔比例、选中的标签页和 Show all explanations 本来就各自记在浏览器里。）清除网站数据即可从头开始。保存只针对当前浏览器：同时开着两个标签页时，最后保存的那个为准；Safari 在 7 天没有访问后可能会清掉它。
- **崩溃保护：** 第一次画出恢复的设置时，会写入一个标记（`none-curve:restoring`）。如果下次启动时标记还在，说明上次访问在绘制时关闭了（可能是崩溃），这次设置和视图就从默认值开始，画布显示 “The last visit closed while drawing, so its settings were not restored.”；文字、映射和字体照常恢复。
- **撤销与重做：** Mac 上用 ⌘Z 和 ⇧⌘Z；其他系统用 Ctrl+Z，以及 Ctrl+Shift+Z 或 Ctrl+Y（只能用键盘，没有按钮）。所有设置、文字、声音映射和 Sound 标签页的 Response 分组共用一份历史。拖动一次滑块是一步（Response 的滑块也一样）；连续打字在停顿一秒之前算一步；Clear、示例文本和插入的字形各算一步，预设的 Load、Freeze、**Reset sound**、导入配置文件，以及选择目标连同它打开的设置也各算一步。声音的实时帧从不成为撤销步骤。不能撤销的：画布视图、缩放和平移、字形选择、预览的 Blur 和 Invert、导出精度、导入字体、Drive letters，以及视频录制选项。在文字输入框和其他文本框里使用的是输入框自己的撤销；对话框打开时快捷键不起作用。最多 100 步；历史不会在两次访问之间保存，**Reset all** 会把它清空。
- **Reset all**（全部重置；状态栏里紧挨在亮色 / 暗色切换左边的图标按钮）：不经确认，让编辑器回到刚打开时的样子。字体关闭（正在进行的导入会被放弃），选中的字形也随之消失；上次访问的字体也会被忘掉，下次打开时不会再重新打开它。文字变回示例文本（第一个示例 Lorem ipsum）。所有设置（Geometry、包括种子在内的 Experimental、Typography、Color 和 Canvas size）、Sound 映射（全部移除）和 Response 组恢复为默认值，Drive letters 也重新打开（系统要求减少动态效果时为关闭）。画布视图回到起点：**Flattened** 轮廓，图层和刚打开时一样（Fill 打开，Skeleton、Vertices 和 Metrics 关闭），缩放 100%（完整显示整个画布），没有平移。正在播放的声音文件暂停，麦克风停止收音；已载入的声音文件仍然保留。预览的 Blur 和 Invert 以及导出精度（2）恢复为默认值，关于配置导入或上次访问的提示也会清除。界面主题、各区域的分隔比例和选中的标签页保持不变。它不能撤销：历史所管的部分回到 `START_SNAPSHOT`，同时历史被清空（`src/state/reset.ts` 中的 `resetHistory`，它调用 `UndoHistory.startOver`），所以之后没有可撤销或重做的内容；reducer 的 `resetAll` 动作返回 `initialState`，`src/App.tsx` 中的 `resetAll` 负责历史之外的部分。没有可重置的内容时（`isAtStart`：没有字体、文字是示例文本，所有设置、视图、Sound 的值、Drive letters、Blur、Invert 和导出精度都在起点）按钮不可用，提示文字为 “Everything is as the editor first opens”；否则提示文字为 “Reset all: closes the font and puts the text and every setting back to the start. Cannot be undone.”

### 性能

- **几何 Worker**（`src/geometry/geometry.worker.ts`、`src/state/geometryClient.ts`）：几何流水线在 Web Worker 中运行，Worker 自己打开一份字体，页面从不需要等它。先算选中的字形（统计数字），再按阅读顺序算文字中的字形；结果约每 40 毫秒分批返回，并合并显示（每 50 毫秒最多重绘一次）。新的参数会在字形之间打断旧的计算。新形状到达之前，画布继续显示该字形之前的形状，画布角标显示 “Updating N…”（声音驱动字母时，实时帧一帧接一帧替换，不显示角标；此时角标只计还没有任何形状的字形）。最近四组参数的结果会保留，退回之前的设置时立即可见（声音驱动的实时帧单独保存，所以一首歌不会把它们挤掉；见[声音](#声音)）。字形只在 Worker 中计算，从不在页面上计算（Worker 的逻辑在 `src/geometry/workerCore.ts`）。每个请求都有编号，并且一定以“完成”或“失败”作答；Worker 在每个字形之前发一次心跳；退回到结果仍保留着的设置时，正在进行的请求立即取消。忙碌的 Worker 连续 60 秒没有任何消息，就视为卡住（流水线自己的单字形预算会把最慢的字形控制在几秒内，所以只有故障才会走到这一步）：它正在算的字形标记为失败（“Took longer than 60 s; try lighter settings”；导出时以这个原因略去它），并重启 Worker、重新发送字体；60 秒内重启超过 3 次时，几何计算停止，直到载入另一款字体。新的设置已经不需要某个算了 750 毫秒的字形时，立即换一个新 Worker，而不是等它算完（最多每 2 秒一次，声音的实时帧从不这样做）。Worker 无法启动、打不开字体、一再失败或一再没有响应时，字形计算失败，画布显示提示：“The geometry worker could not open this font (…).”、“The geometry worker could not start. Reload the page to try again.”、“The geometry worker kept failing. Reload the page to try again.” 或 “The geometry worker stopped responding. Reload the page to try again.”。SVG 和 PNG 导出使用 Worker 已有的结果，缺少的再请它补算；字体文件则在导出自己的 Worker 中生成（见[导出](#导出)）。
- **文字排版**拆成两步：排字（`shapeSpecimen`，只在文字或排版设置变化时重算）和放置多边形（`placePolygons`，结果到达时重算）。路径字符串和倾斜后的范围按多边形缓存，画布上每个字形都是记忆化组件，所以重复出现的字母只生成一次轮廓，没有变化的字形不会重绘。
- **Free 位置拖动**只用 SVG 变换移动文字，松手时才提交一次位置，拖动过程中页面不重新渲染。
- **相交检测**（`src/geometry/crossings.ts`）：每个步骤对每个轮廓、每次重试都要检测。现在按 x 排序扫描线段，只比较包围盒重叠的线段对；交点数一超过原有数量就停止；每个轮廓自身的交点数只算一次。15 000 个点的轮廓（Anchor spacing 1）检测只需几毫秒，而不是几秒。线段达到 64 条时，如果沿 y 方向或某条对角线方向的线段总长不到沿 x 方向的一半，就改为沿那个方向扫描（`SegmentSweep`），所以并排的长边（梳子形、Slipstream 的条纹）不会两两比较；找到的结果再按 x 方向扫描的顺序排好。在重叠合并中（`src/geometry/overlaps.ts`），有 128 个点以上的轮廓会建立一个按水平条带划分的索引（`RingIndex`），供轮廓之间的检查和“是否在内部”的判断使用。两个轮廓之间的检查（`src/geometry/contourLayout.ts`）先比较包围盒，只看重叠区域内的线段；包围盒互不相交的轮廓对直接跳过；每对轮廓原来的位置关系，每一步只算一次。
- **打包：** React 单独放在一个代码块里（`vite.config.ts`），只改应用的部署不会让它的缓存失效；Experimental 和 Sound 两个面板在第一次打开各自的标签页时才加载。
- **几何缓存**：每款字体超过 4000 个字形或 1 000 000 个多边形点时，丢弃最久未用的条目，密集设置不会耗尽内存。声音驱动的实时帧使用另一个更小的缓存（每款字体 600 个字形或 200 000 个点），所以从不挤掉这里的条目。
- 实测（生产构建，1000 个字符，Inter）：拖动 Tolerance 滑块每一步占用页面约 10 毫秒（原约 90 毫秒），Random anchors 密度 100 约 9 毫秒（原 260–690 毫秒）；间距 1 + 网格 50 + 15° + 扭曲时，“@” 需要 48 毫秒（原 2.8 秒）；间距 1 时计算并取整 Arial 全部 2691 个字形需 3 秒、常驻内存约 200 MB。

## 字体

### 本地文件

- 格式：`.ttf`、`.otf`（TrueType 与 CFF 轮廓）、`.woff`、`.woff2`，以及字体集合（`.ttc` / `.otc`，例如 macOS 的 Helvetica Neue、Avenir Next 或 Futura），按文件内容识别而不是扩展名。
- **字体集合：** 字体信息里的样式名会变成一个字面菜单（“Face”）。打开集合时显示最接近 Regular 的正体字面（字重 400、正常宽度；相同时取靠前的字面）。macOS 隐藏的系统字面（PostScript 名以点开头）不列出。选中的字面记在字体来源里，所以几何 Worker 打开的是同一个字面。换到同一文件的另一个字面时，画布的缩放和平移保持不变，新字面有当前选中的字符时也保持选中；其他导入会重置缩放和平移，并选一个默认字母。不支持用 WOFF 或 WOFF2 包装的字体集合。
- 通过 **Import** 选择文件，或直接拖到画布上（拖进来的 `.json` 文件按[配置文件](#配置文件)读取）。文件只在浏览器内读取，不会上传。上限 50 MB，字体集合也一样（Apple Color Emoji 的 `.ttc` 超过这个大小）。
- 空文件、无法识别的文件和损坏的文件会给出不同的错误提示和 **Retry**；之前载入的字体保持显示。

### Google Fonts

CSS 预览字体拿不到轮廓数据，因此应用会下载真实的字体文件：

1. `GET https://fonts.googleapis.com/css2?family=<Family>:ital,wght@0,100;…;1,900`——官方 CSS2 接口，无需 API key。只返回实际存在的样式，每个字符子集一条 `@font-face`，允许跨域。
2. `GET https://fonts.gstatic.com/s/<family>/<version>/<file>.woff2`，取所选字重、样式和子集对应的文件。
3. 用 fontkit 解析 WOFF2。解析成功后字体才可用。

限制：

- **目录：** 完整的可搜索目录需要 Google Fonts Developer API key，静态网站无法保密。对话框提供15 个精选字体（无衬线：Google Sans、Noto Sans、Archivo、Inter、DM Sans；衬线：EB Garamond、Baskervville、Bodoni Moda、DM Serif Display；粗衬线：Slabo 13px、Arvo；等宽：IBM Plex Mono、JetBrains Mono、Space Mono、DM Mono）、可输入与 fonts.google.com 完全一致的字体名称（区分大小写），也可粘贴 Google Fonts 链接。
- **字符子集：** Google 按子集（latin、latin-ext、cyrillic 等）拆分文件，一次只加载一个子集。
- **可变字体：** 当多个字重共用一个文件时识别为可变字体。仍然可以选择任何字重：所选字重会单独向 Google 请求，Google 会返回为该字重生成的静态文件（样式名和 OS/2 字重都正确）。如果 Google 仍返回可变文件（例如 Roboto Flex 的 700），则在载入时应用字重：fontkit 无法对 WOFF2 文件应用变体，所以先把 WOFF2 重建为 TrueType（`src/font/woff2.ts`：重新编码解码后的字形表，不含 hinting，其他表原样复制），再按该字重生成实例；字体面板会注明所用的字重。其他轴（`opsz`、`wdth` 等）保持默认值。
- **彩色字体**（Nabla、Honk、Bungee Spice、各个 “Ink” 字族）：只读取它们的普通轮廓；fontkit 读不了 COLR 第 1 版，所以绕过它的彩色字形（COLR、sbix）。字形只有彩色图像的字体（Noto Color Emoji）可以载入，但会提示没有可编辑的轮廓。
- **fontkit 读不了排版表的字体**（Iosevka Charon）按每个字符一个字形、使用字宽排列，不做字偶距。
- 已用整个 Google Fonts 目录（1950 个字族）检查：每个字族都能载入，每个可变字族在第二个字重下也能载入，且轮廓与默认字重不同。
- **错误：** 未知字体名返回 HTTP 400 且不带 CORS 头，浏览器看来与断网相同。应用会再发一次 `no-cors` 请求，区分“Google 拒绝了这个名字”和“网络 / CORS / 拦截插件”。下载失败与解析失败分别提示，都可 **Retry**。

#### 粘贴 Google Fonts 链接

链接由 `src/font/googleUrl.ts` 解析，链接本身不会被请求——只从中读出字体名和样式，再走上面的下载流程。

| 链接 | 读取内容 |
|---|---|
| `https://fonts.google.com/specimen/Roboto` | 字体名（`+` 代表空格）。`categoryFilters`、`preview.script` 等参数会被忽略并列出。 |
| `https://fonts.googleapis.com/css2?family=Roboto:ital,wght@1,700` | 从第一组样式中读取字体名、字重和斜体。字重范围（`wght@300..700`）表示在对话框中选择字重。 |
| `https://fonts.googleapis.com/css?family=Lato:300italic` | 旧版接口：字体名和第一个样式（`400`、`700italic`、`300i`、`bold`）。 |

- 只接受 `https://` 开头、域名为 `fonts.google.com` 或 `fonts.googleapis.com` 的链接。其他网站、仿冒域名、`http://`、带账号密码或端口的链接以及其他路径都会被拒绝并说明原因。
- 链接包含多个字体或样式时只用第一个，对话框会说明。`display`、`subset`、`text` 和追踪参数会被忽略并列出。
- `wght` 和 `ital` 以外的轴（如 `opsz`、`wdth`）无法应用；对话框会说明，这些轴保持默认值。
- 请求的样式不存在时按默认规则（最接近 400）回退，并写明实际加载的样式。

## 几何流水线

```text
原始曲线（只读）→ 展平（或随机锚点）→ 方形化 → 锚点间距 → 锚点简化 → 网格吸附 → 角度锁定 → 顶点扰动 → 实验效果（Crumple → Ripple → Whorl → Slipstream → Thorn）→ 最终多边形
```

顺序固定（`src/geometry/pipeline.ts`）。每次参数变化都会从原始曲线重新运行整条流水线，不会累积误差；关闭某一步就精确回到它之前的结果。所有距离都以字体单位计算，与画布缩放无关。扰动和实验效果最后执行，因此会让顶点离开吸附网格和锁定角度。

每一步都会逐个检查轮廓：至少三个不同的点、方向不变（字腔仍是洞）、面积不为零、自相交不增加。同时还要检查它和同一字形其他轮廓的位置关系是否不变（`src/geometry/contourLayout.ts`）：原本分开的轮廓仍然分开，字腔仍在外轮廓里面，没有轮廓跑进另一个轮廓。否则字腔被推出字母后，会被填成字母旁边的一块实心。各步骤逐个修改轮廓，每个新轮廓都和其他轮廓当时的状态比较，所以整个字形最终也是合格的。展平本身则与原始曲线的极细展平结果比较（见下文）。

在放弃之前，各步骤会逐级退让：方形化使用仍然安全的最大比例（并比极限略微回退，给后续步骤留出余地）；网格吸附和角度锁定会在逐步简化的轮廓副本上重试，角度锁定最后还会改用阶梯（把不在允许方向上的边拆成两段允许方向的边，不移动任何顶点）；扰动先只在相交处附近降低幅度，再整体降低。只有所有尝试都失败的轮廓才保持上一步的形状；面板会分别报告被减弱、被简化和保持不变的轮廓，以及原因。

在 Arial、New York、Georgia 的拉丁字形上实测，轮廓之间互相穿过或跑出彼此的字形比例：角度锁定 90° 从 13–25% 降到 0，随机锚点密度 1 从 16–18% 降到 0，网格 200 从 25–31% 降到 0，扰动 200 从 4–18% 降到 0，合并曲线且每条 1 段从 0–5% 降到 0。在四款字体上随机测试 6480 组参数组合，没有任何字形新增相交（无论是轮廓自身还是两个轮廓之间）。

### 曲线展平

每段二次和三次曲线都被替换为直线段（`src/geometry/flatten.ts`），结果只包含 `M`、`L`、`Z`。

- **Adaptive（自适应容差）**——递归中点细分（de Casteljau）。当子曲线到弦的最大偏差上界不超过容差时，变成一条直线（二次曲线取控制点距离的一半，三次曲线取较大控制点距离的 ¾）。范围 0.1–500 字体单位，滑块为对数刻度。不合并时每段字体曲线至少保留一条边，所以容差超过约 100 后几乎没有变化（Roboto 前 400 个字形在 100 和 500 时都是 11,219 个顶点）；想要更粗犷的形状请打开 **Merge joined curves**。安全上限：递归深度 12、最小子曲线长度 0.01；达到上限的曲线会被报告。
- **Fixed segments（固定线段数）**——每段曲线按 `t = i/N` 取点，正好变成 N 条边（1–32）。直线段保持一条边。任何边偏离曲线超过 em 的 1% 时显示警告。
- **Merge joined curves（合并相连曲线）**（两种模式都可用，默认关闭，合并相关设置两种模式共用；`src/geometry/curveRuns.ts`）——字体中一条看得见的曲线往往由多段 Bézier 组成（Roboto 的 O 每个轮廓有 16 段），所以单靠逐段设置仍然平滑。合并会把平滑相接的曲线段视为一条曲线：固定模式下按弧长均匀分成 N 条边；自适应模式下对整条曲线做简化（在曲线的密集采样上用 Ramer–Douglas–Peucker），保证每个采样点到对应边的距离不超过容差，闭合整圈至少 3 条边。顶点都落在曲线上。实测 Roboto 前 400 个字形（自适应）：容差 500 合并后 6,365 个顶点，不合并为 11,219 个；`o` 从 36 个顶点降到 12 个（Inter 从 24 降到 8）。
  - **Break merged curves at（断开位置）：** **Corners & extremes**（默认）——在尖角、直线段，以及曲线的水平 / 垂直极值点断开（极值点按解析方式求出，即使位于某段曲线中间），圆形字碗因此分成四段四分之一弧。**Corners only**——只在尖角和直线段断开，整圈平滑的轮廓变成一条曲线，至少使用 3 条边。
  - **Merge through straight lines（穿过直线合并）**（默认关闭）：与相邻部分平滑相接的直线段也并入合并曲线，例如 n、m、u 的竖笔流进弧线，或某些字体里 O 的直边，它们会和曲线一起重新取点。开启后，“极值点断开”只在两段曲线之间生效（竖笔正好在弧线的极值点处相接）。单独剩下的直线保持原样。字形变化很大，竖笔的端点可能被削掉。
  - **Corner angle（尖角阈值）**（1–90°，默认 15°）：转角超过该值的连接点一定断开。合并后的曲线也会在轮廓起点断开。不开启“穿过直线合并”时，它只影响曲线与曲线之间的连接点，而大多数字体里这些连接点本来就是平滑的（Roboto 的 6206 个中有 6200 个转角小于 1°），所以几乎没有变化。开启后，它决定哪些涉及直线的连接点会被合并：从 15° 调到 90°，Roboto 前 400 个字形中有 365 个发生变化。
  - Roboto `a` 实测：38 段曲线合并成 12 条；N = 4 / 3 / 2 / 1 时分别为 57 / 45 / 33 / 21 个顶点（不合并时 N = 1 也有 47 个）。
  - 合并后不合格的轮廓会改用不合并的结果，面板会说明。合并时不显示“偏离 1% em”的警告。

- **校验**：结果会与一份极细的展平结果（容差 1/5000 em，代表原始曲线）比较。如果某条边横穿了比容差还细的笔画，使轮廓在原始曲线没有相交的地方与自身或另一个轮廓相交，就只把相关的曲线重新展平：每轮自适应模式容差缩小到 1/4、固定模式边数加倍，最多 6 轮；面板会显示被加细的曲线数量。New York 的 U、Ù、Ú、Û、Ü 以及 6、9 在默认设置下原本会自交，现在不会了。
- 没有面积的轮廓（少于三个点，或所有点在一条直线上）会被去掉，面板会注明。

轮廓保持起点、顺序和方向；字宽和左右边距保留。没有轮廓的字形（如空格）得到空多边形。

### 方形化

展平只是近似原曲线，所以 O 仍然是圆的。**Squaring（方形化）**（`src/geometry/squaring.ts`）会有意把圆形轮廓推向它的包围矩形。

- 每个轮廓按自己的包围盒归一化，每个点从盒子中心沿径向移向盒子边缘。100% 时点落在盒子上，圆、椭圆、超椭圆都变成带尖角的包围矩形。**Amount**（0–100%，预设 Off / Soft / Square）线性过渡。
- 字腔用自己的包围盒，变成同心的小矩形，因此四边中点处的笔画粗细不变（Roboto 的 O 在 100% 时左侧笔画仍为 191，底部仍为 163）。
- **Applies to: Round contours**（默认）只方形化接近包围盒内切椭圆的轮廓（按边长加权的平均偏差 ≤ 0.06 时完全方形化，≥ 0.16 时不处理）；竖笔、三角形、S 形曲线以及 B / D 形轮廓保持不变。**All contours** 会把所有轮廓推向包围盒。
- 紧接在展平之后执行，之后的锚点简化可以去掉直边上的共线点（方形 O 简化后只剩 4 个角加起点）。
- 100% 时，Roboto、Inter、Andale Mono 的 O、o、0 外轮廓和字腔的“面积 ÷ 包围盒面积”都达到 1.00（圆约为 0.79）。

### 锚点间距与简化

`src/geometry/anchors.ts`。设为 0 即关闭；**Reset anchors** 同时关闭两者。

- **Anchor spacing（锚点间距）**（0–200 字体单位）：把每条边（包括回到起点的闭合边）等分成不超过目标长度的小段。新点落在原有边上，形状不变。单个字形超过 50,000 个顶点时跳过并提示。
- **Anchor reduction（锚点简化）**（0–100 字体单位）：对每个闭合轮廓做 Ramer–Douglas–Peucker 简化，在起点（始终保留）和离起点最远的顶点处分成两段。数值越大删除的点越多，可能抹掉小细节。字体中原本就自相交的轮廓会保留已有交叉，但不会增加。
- 间距插入的点与原边共线，两者同时开启时简化会把它们再次删除，面板会提示。简化阈值是绝对的字体单位。

### 网格吸附与角度锁定

`src/geometry/constraints.ts`。**Reset grid & angles** 恢复默认值（都关闭，网格 10，45°）。

- **Snap to grid（网格吸附）**（网格大小 0–200 字体单位，0 为关闭）：每个坐标变为 `round(v / g) × g`，网格以字形原点为基准，正好一半时朝字形包围盒的中心取整，左右对称的字母吸附后仍然对称。落到同一点的相邻顶点会合并。画布上会画出网格仅供参考（比 4 像素更密时不画）。
- **Angle lock（角度锁定）**（90°、45°、30° 或 15° 的倍数，从水平方向逆时针计）：每条边转到最近的允许方向（等距时取逆时针方向），再只调整边长——用按边长加权的最小二乘让轮廓重新闭合。每条边只保留沿新方向的那部分长度，所以锁定会让曲线缩小（90° 下 O 的宽和高各缩约 30%）；因此结果会对齐到原轮廓的包围盒，而不是固定起点：90° 时宽和高分别缩放（只有横竖边，角度不变），其他角度用一个保持包围盒面积的等比缩放，水平居中、底边不动，字母仍坐在基线上。锁定使形状变化过大时不采用——有顶点移动超过轮廓包围盒对角线的 20%，或面积变化超过 30%（例如 S 的开口被挤没）；重试时最多简化对角线的 4%。一个字形整体锁定或整体用阶梯：只要有一个轮廓不采用，或者各轮廓分别锁定会让字形散开（Roboto 的 V 由两条重叠的腿组成，分别锁定后会变成两根分开的竖条），这个字形的所有轮廓都改用阶梯。阶梯保留每个顶点；长于 1/40 em 的斜边先切开，长斜线就变成贴着原线的细密台阶；台阶的拐角朝远离笔画的一侧（外轮廓朝外，字腔朝字腔内）；相邻两级台阶在内凹的尖角处会相交时，把其中一级翻到另一侧。台阶也相交时，该轮廓才保持原样。以前 Arial 的 Z 在 90° 下会向左滑约 800 单位压到前一个字母上，X 会掉到基线以下 512 单位；现在两者的包围盒都不变。在可打印 ASCII 上，Arial 90° 的最大顶点位移从 1024 降到 290 单位；未能锁定的轮廓数：Arial 90° 从 15 降到 0，45° 从 8 降到 0，30° 从 2 降到 0；New York 90° 从 24 降到 20（它的发丝线只有几个单位粗），45° 从 8 变为 11、30° 从 4 变为 5，因为以前放过的重叠现在会被拦下。“Largest move” 量的是每个原始顶点到新轮廓线的距离。
- 先吸附、后锁角；锁角会改变边长，部分顶点因此离开网格，面板会提示。

### 顶点扰动

`src/geometry/distortion.ts`。**Reset distortion** 恢复默认值（幅度为 0，少数锚点模式关闭），但保留当前种子。

- **Noise amplitude（噪声幅度）**（0–200 字体单位）：顶点最多移动的距离；0 为关闭。
- **Noise frequency（噪声频率）**（0.5–50）：每 1000 字体单位轮廓长度上的起伏个数，按弧长采样，并在每个轮廓上首尾连续，不会出现接缝。
- **Normal bias（法线偏向）**（0–100%）：0% 让顶点沿轮廓滑动，100% 让顶点垂直于轮廓进出。
- **Seed（种子）**（0–999,999）和 **Next variant**（种子加 1）。不使用 `Math.random`、时间或渲染次数；同样的字形、参数和种子总是得到同样的形状。
- 边保护只限制一条边的两端沿这条边互相靠近的距离（最多为边长的一半），因此边不会塌缩或反向；垂直于轮廓的移动不受限制。先缩短沿轮廓方向的移动，只有不够时（例如很紧的弯道内侧）才缩短垂直方向的移动。以前对所有相对移动都加限制，轮廓越密扭曲越弱，因为密集轮廓上相邻顶点离得很近。
- 扭曲后的轮廓与自身或另一个轮廓相交时（密集轮廓的内凹拐角、细笔画、靠近外轮廓的字腔），只在相交处附近把幅度减半，并在两侧各一个幅度的轮廓长度内平滑过渡，最多 12 次；轮廓其余部分保持全幅度。仍不够时，整个轮廓以 1/2 到 1/16 的幅度重试，仍不行就不扰动。
- 在 Arial 的 32 个字母和数字上实测，幅度 40 时顶点移动距离的中位数在 Anchor spacing 关闭 / 10 / 1 下分别为 18 / 18 / 16 单位（以前为 18 / 6.5 / 0），幅度 200 时为 67 / 46 / 25（以前为 22 / 0.3 / 0）。
- **少数锚点**（few anchors；设置中的 `sparse`；`pickMovers` 和 `SPARSE_LIMITS`）：一个没有自己控件的模式。只有 Sound 标签页的 **Flicker** 预设会打开它；**Reset distortion** 或载入另一个预设会关闭它；它也不是 Sound 的目标。每个字母只有少数几个锚点移动，其余顶点完全不动，所以字形得以保持。
  - **锁定的：** 拐角（轮廓转向超过 30°；恰好 30° 的转角不算拐角，Angle lock 常会造出这种转角）、x 和 y 方向的极值点（一段水平或竖直的平直段是顶边、底边或侧边时整段都算，是台阶时不算）、零长度边上的顶点，以及顶点少于 8 个的轮廓上的所有顶点。
  - **候选：** 其余每个顶点，以及任何有 3 个或更多顶点的轮廓上、长度至少为 em 的 10% 的每条直边的中点，小轮廓也包括在内（4 个顶点的 I、i 或连字符）。被选中的中点作为新顶点插入，和其他移动点一样移动，这条边的两端保持不动，所以只由拐角和极值点组成的字母（l、H、T）也会动。如果插入中点会碰到它所在轮廓的另一条边（轮廓沿这条边折返，网格吸附可能留下这种情况），就跳过这个中点。
  - **挑选：** 候选按种子、轮廓和位置的哈希排序，排在前面的移动：字母顶点数的 6%，四舍五入，1 到 5 个；一个轮廓上最多 2 个，沿轮廓相隔超过 4 个顶点（中点算作位于所在边两端的正中间）。换一个种子就换一组，所以 Beat → Distortion · Seed 让每个节拍换另外几个锚点移动。
  - **移动：** 噪声与上面相同，但每个移动点垂直于轮廓的分量和沿轮廓的分量，都各自至少提高到它们所占幅度份额的 60%（按 Normal bias 的比例；噪声为 0 处方向由种子决定），所以每次跳动都看得见。边保护和上面的修复仍可能降低它。
  - 打开时，面板显示说明 “Only a few anchors move (set by the Flicker preset in the Sound tab). Reset distortion moves every anchor again.”（只有少数锚点移动，由 Sound 标签页的 Flicker 预设设置；Reset distortion 让所有锚点重新移动），统计里多一项 **Anchors moved**（实际移动的顶点数，包括插入的中点），状态栏的描述写作 “distortion N u, few anchors, …”。关闭时，或旧设置里没有这一项时，结果与以前完全相同。
  - 在 Arial、Georgia 和 New York 的拉丁字形上检查过。在默认 Geometry 下（Noise amplitude 2 和 120，Normal bias 90%，种子 1–10），每个字形都至少有一个锚点移动；在所有测试中，锁定的顶点从未移动，没有字母的移动点超过它的个数，也没有轮廓超过 2 个。每种字体在 48 种 Geometry 设置 × 4 个种子下：没有布局损坏，也没有导出失败，平均每个字形移动 2.8 / 3.3 / 3.2 个锚点（Arial / Georgia / New York）。已知的不足：New York 的极细笔画上（# 和 $），被选中的中点无法越过 6 单位宽的横杠而不交叉，所以在某些种子下这个轮廓会退回不扰动（默认 Geometry 下约占字形运行的 0.2%）；锚点非常密时（Anchor spacing 5），每条边都短于 em 的 10%，所以少数矩形字形（I、l、i、连字符、句号、=）没有候选，保持不动。

### 随机锚点

`src/geometry/randomAnchors.ts`。位于 Geometry 标签页最底部，默认关闭。开启后，锚点不再按展平的规则间距放置，而是放在**原始曲线**上按弧长随机选取的位置；每个锚点都直接在原始 Bézier 曲线上求值，因此严格落在字形轮廓上。之后照常经过方形化、锚点、网格和扰动。由于展平的结果被替换，开启期间整个曲线展平组会变灰（它的设置只会作用于退回的轮廓）。

- **Density（密度）**（1–100）：每 1000 字体单位轮廓长度大约放多少个锚点；每个轮廓至少保留 3 个。
- **Randomness（随机程度）**（0–100%）：分层抽样。每个锚点各占一小段轮廓；0% 放在这段的正中，100% 可落在这段内任意位置。锚点之间不会交换顺序，所以轮廓不会折回。
- **Keep sharp corners（保留尖角）**（默认开启）：原始轮廓上转角大于 30° 的连接点固定保留为锚点，每两个尖角之间的部分各自取样。
- **Seed（种子）**（0–999,999；随机程度为 0% 时种子不起作用，会变灰）：**Shuffle** 随机换一个新种子（只有这个按钮用到浏览器的随机数）；**Copy** 复制种子；**Previous** 列出本次会话里最近用过的 6 个种子，点一下即可回到它。种子也会显示在底部状态栏和导出对话框里。
- 可复现：随机数来自 (种子, 轮廓的形状, 尝试次数) 的哈希，因此同一字体、同一设置、同一种子总是得到同一个多边形。文本中重复出现的同一个字母形状相同，形状相同的不同字形（如拉丁 A 与希腊 Alpha）结果也相同；不同形状各自取样。
- 校验：如果某次取样让轮廓反向、塌缩、新增自相交，或与另一个轮廓相交、跑出另一个轮廓，会用派生种子重新取样（最多 4 次，结果依然确定）；都不合格时该轮廓改用展平的结果，面板会注明。
- **Reset random anchors** 恢复默认设置，但保留当前种子。

### 实验效果：Crumple、Ripple、Whorl、Slipstream 与 Thorn

`src/geometry/crumple.ts`、`src/geometry/ripple.ts`、`src/geometry/whorl.ts`、`src/geometry/slipstream.ts` 和 `src/geometry/thorn.ts`，基于共用的变形模块 `src/geometry/warp.ts`，由 `src/geometry/experimental.ts` 按固定顺序 Crumple → Ripple → Whorl → Slipstream → Thorn 调用。**Geometry** 旁边的 **Experimental** 标签页放的是在整条几何流水线之后运行、可以同时打开的效果（计划见 [docs/EXPERIMENTAL_PLAN.zh.md](docs/EXPERIMENTAL_PLAN.zh.md)）。整个标签页共用一个 **Seed** 和 **Next variant**，另有 **Reset experimental**（保留种子）。（重做 Crumple、Slipstream 和 Thorn 时，这些效果改了名：Noise 改为 Crumple，Curl 改为 Whorl，Wind 改为 Slipstream，Spikes 改为 Thorn。Crumple 后来又回到了 Noise 的单层格子，只保留了新名字。）

- **效果由分段线性变形构成。** Crumple、Ripple、Whorl 都是变形，Slipstream 的拉长和滑移、Thorn 的根部和折射也是。把平面切成三角形，每个三角形各自做线性变换，在三角形边界上连续。直边在三角形内部保持完全笔直，只在穿过三角形边（折痕）的地方转折，新顶点也只加在那里。任何效果都不沿轮廓采样平滑函数，所以字母只会多出棱角，不会多出曲线。Slipstream 的拖尾和切口、Thorn 的刺尖不是变形：它们各自只加几条直边，可能与轮廓交叉的地方会合并轮廓（见下）。
- **从构造上保证有效，所以效果可以叠加。** 在 100% 以内，三角形不会翻转或压扁，因此每个变形都是一一映射：它不可能让轮廓自交或与别的轮廓交叉，也不可能把字腔推出字母；多个变形接连作用也一样。每个效果之后仍会检查轮廓：先把所有轮廓换成精确映射（它们在一起一定合格），再逐个尝试换成整理后的版本，只有与其他轮廓仍然合格时才替换。只有输入里既不相交也不相接的边新产生交叉才算出错（很重的几何设置可能让轮廓自己叠在自己身上）；另外，两条边如果都还是精确映射的原样、对应的输入边相距不到 0.05 单位，它们之间的交叉也不算：一一映射不可能让它们交叉，但很强的 Slipstream 可能把重度扰动留下的尖刺挤得极细，以致浮点误差让它们交叉。如果未被改动的两条边在输入里相距更远却交叉了，那就是真正的错误，仍会被拒绝。万一浮点误差让精确映射出错，该轮廓依次改用 1/2 到 1/16 的强度；都不行时整个字形保持原样。
- **整理，确保看起来不像曲线。** 转角小于 3° 的折痕会被去掉（被去掉的折痕离替代它的边不超过 em 的 1%）。然后，凡是连续 5 个以上、朝同一方向转 0.5°–20°、相邻边都短于 em 的 4% 的顶点（折线开始看起来像曲线就是这样），就去掉其中转角最小的折痕，直到不再有需要折痕才凑成的这种段落。输入自身的顶点已经构成的段落保持不变；输入的顶点永远不会被删除。前面效果的折痕也算作折痕，所以后面的效果也可以删掉前面效果的折痕，几个效果合起来才凑成的段落同样会被拆开。如果整理让轮廓碰到自身或其他轮廓，就把出问题的那条边所替代的折痕全部恢复，其余部分重新整理（最多 8 次），之后再尝试更严格的偏差上限。输入里宽度小于 0.01 单位的零宽细针（很重的几何设置可能留下）会先被去掉。
- **Crumple**（默认关闭；`src/geometry/crumple.ts`）把字母像纸一样揉皱。网格是方形格子，格子边长为 **Facet size**（em 的 8–100%，默认 18%），按种子旋转一个角度，每个方格沿种子选定的对角线分成两个三角形。每个格点按种子移动一个随机向量，最大为 **Amount** × Facet size 的 30%，格点之间的点随所在三角形线性移动。**Turn**（0–359°，每档 1°，默认 0°）把所有移动转同一个角度，折痕不变，折的方向变了（180° 就是反方向）。移动不超过格子的 30% 时，任何三角形都不会翻转（至少保留约 15% 的面积），与 Turn 无关，所以 Crumple 永远不需要减弱。**Amount** 的范围是 0–500%（默认 70%）：超过 100% 时格点沿同样的方向移得更远，刻面会互相翻折（见下面的“翻折”）。格子固定在字形坐标里，同一个字母的每次出现形状相同，导出的字体与画布一致。它的随机数来自自己的哈希通道（101–104）。这正是它最初以 Noise 之名做出时的格子。改名为 Crumple 的那次重做在字母上铺了三层不同尺度的网格，并加了 **Detail** 滑块；NOCUR-60 恢复了单层格子，保留了新名字。Amount 在 100% 以内时，输出与 Noise 逐字节相同（对比了 18 组设置）；超过 100% 时只因较新的重叠合并而略有不同（约 1 个字体单位），所以下面最初做出它时的检查依然成立。带 Detail 值的已保存设置载入时忽略该值，作用在 Crumple · Detail 上的 Sound 映射会被删去。
- **Ripple**（默认关闭；`src/geometry/ripple.ts`）从一个点向外发出多边形波纹。网格是一组同心正多边形，边数为 **Sides**（3–12，默认 8），底边水平，中心位于 **Center X / Center Y**（字形墨迹框的比例，−50% 到 150%，默认正中），沿垂直于边的方向每半个 **Wavelength**（em 的 8–200%，默认 30%）一圈。穿过多边形顶点的射线把各圈切成单元，每个单元再分成两个三角形。每一圈整体交替向外、向内移动，最大为 **Amount**（0–400%，默认 50%）× 圈距的 45%，所以每圈变形后仍是正多边形，轮廓在穿过各圈的地方形成锯齿（三角波，而不是正弦波）。**Fade** 让振幅随离中心的距离线性减小，到墨迹框最远的角时降到 (1 − Fade)。在 100% 以内相邻两圈永远不会交错（至少相距圈距的 10%），所以没有三角形会翻转；超过 100% 时各圈会互相越过并翻折；字形外面紧挨着的那一圈保持不动，没有 Petals 时再往外完全不变。**Petals**（0–300%，默认 0%）把每一圈弯成一朵花，每条边一片花瓣：从中心再发出三条射线把每条边均匀切开（顶点处是花瓣尖，然后是肩、边中点的凹口、肩），每条射线把它上面已经起伏过的各圈按 1 + 各自份额 × 深度缩放，份额依次为 1 / 0.7 / −1 / 0.7。100% 时深度为 0.9（花瓣尖向外多伸出 90%，凹口保留原距离的 10%）；超过 100% 时花瓣尖和肩继续变大，凹口永远不低于 10%。顶点只沿自己的射线移动，并始终留在中心的同一侧，所以任何深度下 Petals 都是一一映射，自己永远不会翻折；最后一圈之外仍按同样的方式缩放，在每个切片内线性变化，所以平面保持连续。**Reverse**（默认关闭）把外和内对调：每一圈都朝相反方向移动（第一圈改为向内，幅度不变），花瓣份额取反（−1 / −0.7 / 1 / −0.7），所以顶点和肩被拉向中心（顶点至少保留原距离的 10%，肩保留 37%），每条边的中点则按完整深度向外推：花瓣尖落在边的中点。各条射线的缩放都仍为正数，所以反向的 Petals 同样是一一映射。Reverse 出现之前保存的设置读作关闭。Ripple 没有随机性。
- **Whorl**（默认关闭；`src/geometry/whorl.ts`）让每个字母绕它墨迹框的中心旋转成漩涡。网格与 Ripple 相同：边数为 **Sides**（3–12，默认 8）的同心正多边形，底边水平，穿过顶点的射线把各圈切成单元，每个单元分成两个三角形；**Rings**（2–12，默认 6）中最外面一圈离中心半个墨迹框高度（至少 em 的 5%），所以字母的顶和底落在这一圈上。各圈不再向外、向内移动，而是整体绕中心旋转，所以转完仍是正多边形，轮廓只在各圈的边、射线和各圈内的单元对角线处转折。勾选 **Pin top and bottom**（默认）时，最外面一圈以及它之外的一切保持不动，越靠近中心的圈转得越多；不勾选时，中心保持不动，越靠外的圈转得越多，最外面一圈之外的一切作为一整块刚性地跟着它转。相邻两圈之间的相对转角都相同。**Amount** 为 100%（范围 −400% 到 400%，默认 60%；低于 0% 时顺时针转）时，这个转角是“保持每个三角形朝向不变”的最大值的 90%，按当前的 Sides 和 Rings 计算，单元对角线顺着漩涡布置（两种对角线方向中让各圈能转得更远的那一种），所以正反方向在 100% 以内 Whorl 都是一一映射。此时整个漩涡转过的角度从 3 条边时约 30° 到 12 条边、圈数多时远超一整圈。正反方向超过 100% 时，三角形翻转，字母翻折（见“翻折”）。Whorl 没有随机性。在 Arial、New York、Georgia 的拉丁字形上各用 12 组设置检查（±30–100%，固定上下和整体旋转，叠加在几何设置之上，以及与其他效果叠加）：没有新增交叉，没有轮廓被减弱，所有字形都能导出。
- **Slipstream**（默认关闭；`src/geometry/slipstream.ts`）让字母处在一股流向 **Direction**（0–359°，每档 1°，0° 向右，90° 向上；默认 0°）的气流里。它的变形让每个点沿气流方向移动两部分距离。**Slip**（em 的 0–60%，默认 15%）是一种剪切，偏移量只取决于点在垂直于气流方向上的位置：宽 2–6 个 **Gust size**（多为 3–5 个）的摆动条带各自按种子滑动 Slip 的一部分，范围为 −½ 到 +½ 个 Slip；每个宽一个 Gust size 的条带还会再加一点自己的抖动（40% 的条带没有，其余最多 ±15% 的 Slip），所以少数大台阶夹在较细的台阶之间。偏移量在条带内部保持不变，只在条带边缘很窄的一段里变化，所以笔画断成一片片沿笔直折痕互相错开的切片。在气流坐标里（u 沿气流，v 垂直于气流），剪切把 (u, v) 映射到 (u + d(v), v)，雅可比行列式等于 1，所以无论滑多少都不会让字母翻折。**拉长**让每个点移动 **Strength**（0–800%，默认 15%）× 所在条带的阵风 × 它在字形迎风边下风方向上的距离（按墨迹框计算），所以迎风边保持不动，越往下风方向，轮廓被拉得越远；每个条带的阵风是全强度的一个份额，由种子决定，介于 1 − **Gustiness**（0–200%，默认 60%）和 1 之间，任何点的移动都不超过 4 em。条带沿气流方向排列，间距一个 **Gust size**（em 的 6–50%，默认 12%），以字形原点为基准，所以气流水平时同一行的字母共用相同的条带；条带再切成方格，每个方格沿种子选定的对角线分开。Gustiness 不超过 100% 时阵风从不为负，拉长只会顺着下风方向增大，所以雅可比行列式至少为 1，任何强度下变形都是一一映射。超过 100% 时部分阵风反向吹，把字母撕开（见“翻折”）。变形之后是 **Trails**（拖尾，每个字母 0–8 条，默认 2）：从字母外轮廓上背向气流的边（外法线与气流方向夹角约 53° 以内）沿下风方向拖出的细条，起点沿轮廓均匀分布。每条拖尾用五个点替换它的起点一段（起点、肩、尖、肩、终点）：离开字母处宽 em 的 2–5%，在四分之一长度处收窄到这个宽度的 30%，之后细细地拖出去；长度为（em 的 15% + 50% × Strength）的 45–100%，由种子决定，最多 2 em，并偏离气流方向最多 4°。拖尾若会与字母或之前的拖尾交叉、或离它们不到 em 的 0.6%，就最多换 3 个位置尝试，仍不行就不画，所以拖尾永远不需要合并。最后是 **Cuts**（切口，每个字母 0–8 道，默认 2），放在最后，所以拖尾也会被切开：沿气流方向、位于种子所选直线上的细长楔形，从迎风一侧或背风一侧切入，入口最宽，逐渐收成尖头，尖头落在遇到的第一道笔画（30% 的切口是第二道）深度的 35–85% 处；四分之一的切口直接贯穿字母。切口是精确切出的：先按非零规则重画轮廓，使墨迹的环绕数正好为 1、其余处为 0，再把楔形按顺时针方向加入，然后围绕环绕数仍为正的区域重画轮廓（`overlaps.ts` 新增的 `'positive'` 填充规则）。这次重画也会合并此前的翻折，所以除非 Thorn 加了刺，最后的合并就省掉。所有随机选择都由种子经 Slipstream 自己的哈希通道（201–207）给出，并以字形编号区分。没有 Slip、Cuts 或 Trails 的旧设置把它们读作 0，结果与原来的 Slipstream 完全相同。统计：**Max move**、**Creases**，有切口或拖尾时还有 **Cuts** 和 **Trails**。在 Arial、Georgia、New York 的拉丁字形上检查（8 组以上设置 × 3 个种子，单独使用、叠加在很重和密集的几何设置之上，以及与 Crumple、Thorn 一起：共 122,976 次字形运算）：没有新增交叉，保留 0 位和 2 位小数导出都没有失败，没有字形因此不加 Slipstream。默认设置下每个字形约 0.9 ms，大部分花在为切口做的两次合并上；在密集的几何设置上约 8.5 ms。
- **Thorn**（默认关闭；**Use thorn**；`src/geometry/thorn.ts`）最后运行：每个字母有几个锚点跳进画布，长成又长又直的刺，并带动周围的字母。只有字母外侧的锚点会长刺（不在任何其他轮廓内部、或位于偶数个其他轮廓内部的锚点；轮廓互相重叠时，比如很多可变字体的实例，取在其他轮廓之外的锚点，锚点足够多时还要与自己的轮廓所穿过的轮廓保持至少 0.1 em 的距离），方向背离墨迹：垂直于从锚点沿轮廓向两侧各 0.06 em 范围内的轮廓走向（`THORN_WINDOW`，每侧最多为轮廓的四分之一），而不只看锚点本身，再向任意一侧偏转最多 **Spread**（0–100%，默认 50%）× 90°，0% 就是垂直于轮廓向外。**Anchors**（1–12，默认 3）是每个字母跳出的锚点数，**Reach**（画布对角线的 0–100%，默认 10%，读数写作 “% canvas”，1% 以下保留两位小数，10% 以下保留一位，以上取整，只有正好为 0 时才显示 0.0，这时不长刺）是跳出的距离：每个锚点跳出其中由种子决定的 35–100%，所以开到 100% 时一根刺可以横穿整个画布。这个滑块是立方曲线：距离等于滑块位置的立方，位置每档 0.005，结果保留 4 位小数（画布的 0.01%），所以位置 0.5 是 12.5%，1 是 100%，短刺仍能细调。靠近 0 的地方，立方每档增加不到 0.01%，这时每档改为增加 0.01%（位置到约 0.14、距离到约 0.28% 为止），所以每一档都是不同的距离，方向键也总能移动滑块（`src/state/sliderScales.ts` 中的 `THORN_REACH`、`reachFromSlider` 和 `reachToSlider`）。它的数字框直接输入距离本身，单位是画布的百分比，精确到 0.01%。换成 em，距离是 Reach × 画布对角线 ÷ 字号（都以像素计，精确到 0.01 em；`canvasDiagonalEm`），对角线最多按 256 em 计（`THORN_LIMITS.maxReachEm`，一个安全上限，保证每次合并都在精确网格之内）。所以改变字号或画布尺寸（导出倍数不算）会改变刺按 em 计的长度，让它们在画布中所占的比例保持不变；开启 Thorn 时，这样的改动会重新计算字母，关闭时则不改变任何几何。默认画布（1200 × 800 像素）在 48 像素字号下对角线约 30 em，所以默认的 10% 约为 3 em；Reach 的 ⓘ 说明会写出在当前字号和画布下 100% 是多少 em。变长的只是刺尖：根部的拉动、底部宽度和竖条宽度仍按 em 计。状态栏、Export 对话框和 SVG 的说明里写作 “reach N% canvas (about M em)”，两个数都按滑块读数的方式取舍（`reachReadout`）。每根刺分三步长成。(1) **Root**（根部，0–100%，默认 50%；100% 时半径为 em 的 60%）：锚点周围一个 8 边星形网格上的分段线性变形，网格由锚点、半径 35% 处的内圈和半径处保持不动的外圈组成。锚点向外移动刺长的一半（最多为半径的 75%）；内圈在刺这一侧跟着移动其中的 60%，在另一侧只移动 15%，同时向刺的轴线收拢，并向种子选定的一侧多拉一些。外圈以内的一切都随之移动，包括其他轮廓，所以笔画会倾斜、变细，像 `o` **刺尖**：锚点跳完剩下的距离，成为一根尖而直的刺。**Width**（0–100%，默认 30%）决定刺的底部沿轮廓向两侧延伸多远，取根部内圈与锚点较短一条边中较长者的一部分（至少 2%：一根细针；Root 0%、Width 100% 时锚点把两条边整条带走）。相邻的刺共用中点作为底部端点，所以它们之间不会形成填满的蹼：结果是宽阔的根部收成尖锐的刺尖。(3) **Refraction**（折射，0–100%，默认 0%，即关闭）让字母像隔着竖条纹玻璃一样显示：竖条宽 **Flute width**（em 的 4–30%，默认 10%；Refraction 为 0% 时变灰），每一条显示字母上对应的部分，以条带中线为中心放大最多 30%，并向侧面滑动、上移或下移最多条宽的 35%，条与条之间的接缝（条宽的 30%）被压成陡峭的断口。x 按一个递增的分段线性函数移动，y 的偏移只取决于 x，所以任何强度下玻璃都是一一映射。玻璃只罩住字母本身：刺尖长出之前的墨迹范围，再加两侧各一条；此外的玻璃是平的，每个点都留在原处，所以向左或向右伸出这个范围的刺尖保持锐利：不会被折射，无论伸多远也不会多出点来（在这些竖条里向上或向下伸的刺仍会被折射）。之后一遍整理去掉根部造成的每段“像曲线”段落里最弱的折痕。哪些锚点跳、往哪个方向、跳多远、根部向哪边偏，以及竖条怎样滑动和升降，都来自共用的 **Seed** 和各锚点在字形参考轮廓上位置的哈希（Thorn 自己的通道），所以同一个种子得到同样的刺，**Next variant** 会让它们换位置。**稳定的锚点**（`thorn.ts` 中的 `ThornAnchors`）：参考轮廓是顶点扰动和其他实验效果之前的字母（流水线把它传给 `applyExperimental`）。锚点在参考轮廓上按哈希排序，取其中前 **Anchors** 个外侧锚点，所以 Anchors 只在一个固定列表的末尾增减刺。之后每个选中的锚点都跟着 Distortion 和后面的每一步，找到它变成的那个顶点：变形会按顺序保留收到的每个顶点，并标记自己加上的折痕，所以选中的锚点移到未标记顶点中同一位置的那个顶点；遇到重画轮廓的步骤（顶点预算的简化、Slipstream 的拖尾和切口）之后，则移到字母外侧最近的顶点。刺从画出的轮廓上的这个顶点长出，方向取参考轮廓的方向（即上面范围两端给出的方向），并随各个变形一起转动，每个变形都按去掉 Distortion 对墨迹范围的移动来放置，所以 Distortion 的噪声从不转动它；如果某个变形把画出的轮廓在锚点处转得太多，使刺会指向字母内部，就把它镜像到外面。所以 Distortion 的滑块或 Crumple、Ripple 的 **Amount** 调动一档，或换一个 Distortion 种子，几乎每根刺都留在原来的锚点上、指向不变（`tests/geometry/thorn-anchors.test.ts`：在刺曾经乱跳时声音驱动的那组设置上，Noise amplitude、Crumple 的 Amount 或 Ripple 的 Amount 调动一档，或换一个 Distortion 种子后，至少 90% 的刺根部移动不超过 0.05 em、方向偏转不超过 10°，没有哪个字母的刺全部换掉；只改 Distortion 时，选中的锚点和方向完全不变）。Crumple、Ripple、Whorl 和 Slipstream 的其他滑块会改变变形本身，所以仍可能移动或转动刺（因此声音通过 Thorn 轮换送出它们；见[声音](#声音)）；换一个 Experimental 种子，或改动 Distortion 之前的几何步骤，会重新选择。同一个种子选出的刺与以前的版本不同，所以以前保存的作品在相同种子下会显示别的刺；Thorn 的滑块、范围和默认值没有变。由声音驱动时（Beat → Seed），刺每次只在少数几个字母上跳到新的地方（Thorn 轮换；见[声音](#声音)）。刺可能穿过字母或其他刺，所以只要加了刺，轮廓就会合并成一个干净的轮廓，与效果翻折时的合并相同（见“翻折”），字母仍然可以导出。**Reverse**（默认关闭，位于 Reach 下方）把每根刺掉转方向：沿向内的法线射进字母，锚点、偏转、长度、根部的偏向和刺底都不变，只把方向取反（所以根部会把字母往里拉）。刺会走完全部长度：在笔画内部刻出一道白色的缝，穿过字腔或从另一侧穿出的部分则由合并（非零环绕规则）显示为墨色的尖刺。Reverse 出现之前保存的设置读作关闭。**Burst**（爆裂，默认关闭，位于 Use thorn 下方）让字母改为“炸开”：没有锚点跳出，而是在每个轮廓（包括字怀）四周长出许多笔直的尖刺，尖刺之间的轮廓陷进笔画（`burstOutline`）。此时 **Anchors** 表示每个字母的尖刺数（4–80，默认 40，与刺的 1–12 分开保存，所以切换 Burst 时两者都保留），按露在外面的轮廓长度分给各个轮廓（轮廓重叠时，藏在另一个轮廓墨迹里的部分不长尖刺），沿轮廓均匀排开，每个位置再向前或向后挪动最多间距的 30%（由种子决定）。每根尖刺在轮廓上有一个刺底（**Width**：间距的 5–90%，但不超过到任一相邻尖刺距离的 48%，也不超过尖刺长度的一半；每一侧只延伸到轮廓转过 20° 之前，所以刺底不会切掉笔臂、横笔或拐角），两条笔直的侧边各在靠近刺底、向轴线收拢的“肩部”折一次，所以尖刺根部张开，尖端细如针。在字母外侧，尖刺背离墨迹，并按 **Spread** 偏向“从墨迹框中心射出”的方向、再随机偏转（与轮廓的夹角始终不小于约 15°）；伸进字怀（四面都被包住的白色）的尖刺不偏向（只随机偏转），最多伸到对面距离的 42%，所以始终留在字怀里。长度由种子决定：多数中等，约八分之一很长，并有一道绕轮廓的缓慢起伏把长刺聚在一起；最长为 Reach 长度的 30%（`BURST_REACH`），在初始画布上默认 10% 时约 0.9 em。**Dent**（凹陷，0–100%，默认 80%；Burst 关闭时变灰）把两个刺底之间的轮廓陷进笔画，中间三分之一最深，最多为该处笔画厚度的 60%（每个三等分点取其中由种子决定的 55–100%，且深度不超过这段间隙宽度的 1.5 倍）。凹陷保留轮廓的尖角，平缓的转折只在相对深度仍看得出时保留，另加自己的两个拐角，所以绝不会看起来像曲线，并从 0% 起平滑加深；0% 时尖刺之间的轮廓保持原样，尖刺很少时的长间隙也保留字母的形状。**Root** 变灰，不带动任何根部。**Reverse** 让每根尖刺朝墨迹里长，凹陷改为向外鼓出，位置、长度和刺底都不变；**Refraction** 仍在之后生效。尖刺与字母、尖刺与尖刺之间的交叉由合并清理，之后再去掉面积小于（em 的 1%）² 的轮廓：这些碎点小到看不见，导出取整时还可能塌掉（`withoutSpecks`）。统计中 **Thorns** 换成 **Spikes**，不显示 Roots。Burst 出现之前保存的设置读作关闭，尖刺数 40，Dent 80%。排版不理会刺尖：每个字形都带着它在 Thorn 之前的墨迹范围和凸包（`layoutBox`、`layoutHull`），Fit text、位置锚点、Free 和超出画布的提示都用它们，所以无论文字是否倾斜，它们的处理都与关闭 Thorn 时完全相同（见[排版](#排版)）。开启 Thorn 时，字形靠它的字列和一份看不见的原始轮廓副本（展平成直线段，和画布上画的一切一样）来点选；画出的刺不接收点击（见[界面](#界面)）。没有 Root 的旧设置取 50%（Root 0% 就是原来“只加上去”的样子），没有 Refraction 时保持关闭。统计：**Thorns**（跳出的锚点数）、**Roots**（带动了字母的根部数）和 **Longest**（最远的一跳，字体单位）；有轮廓需要更弱的根部或折射、或某个字形没能加上它们时会给出警告。以下是 Reach 还按 em 计（0–200%，默认 60%）、折射还覆盖整根刺时的测量：在 Arial、Georgia、New York 的全部拉丁字形上，用 3 个种子、11 组设置（从 Root 0% 到每个滑块都开到最大甚至超出范围），单独使用、叠加在密集和很重的几何设置之上，以及与 Crumple、Slipstream 一起检查：结果中没有任何交叉（合并改为精确重画之后，见下），保留 0 位和 2 位小数导出都没有失败，没有字形长不出刺；最远的点离字形原点约 3.7 em 以内。默认设置下每个字形约 0.7 ms，在密集的几何设置上 5–6.5 ms，所有滑块开到最大且几何设置密集时最多约 17 ms，主要是根部变形要处理大量顶点。
- **翻折**（`src/geometry/overlaps.ts`）：只要有一个效果超过 100%，字母就可能折到自己身上，所以各效果都不再检查轮廓，最后把字形重画成非零规则所填充区域的轮廓。只要 Thorn 加了刺，之后也会做同样的合并；Slipstream 的切口则用“正值”规则调用它（见上）。在整数字体单位的网格上做捕捉取整：每个顶点和每个交叉处都变成网格点，每条边绕经它穿过的每个网格单元的网格点（每个单元只拥有它左下角的那个点，所以正好穿过单元角点的边只绕经一次），于是取整后的边只在端点相交；然后计算每个区域的环绕数，把有墨与无墨之间的边连成轮廓（外轮廓逆时针，内孔顺时针；两个有墨区域只在一点相接时各自保留自己的轮廓）。面积不到 4 平方单位的轮廓会被略去；平均宽度（面积的两倍除以周长）不到一个单位的轮廓也会被略去，除非它里面放得下一个直径 0.01 em 的圆（`OVERLAP_LIMITS.room`，由 `hasRoom` 贴着每条边的中点试放）：发丝般细的细条无论多长都会被略去，而刺又长又细、以致平均宽度很窄的字母会保住它的主体，带一道细长裂缝的内孔也会保留。取整让每个点都移动了一点，会把一串短边变成一段转角很小的抖动，看起来像曲线，所以接着把每个轮廓**重新画过输入自己的顶点**和输入边精确的交叉点，去掉网格上的绕行。凡是精确点会让轮廓与自身或其他轮廓交叉或相接、内外翻转、嵌套关系与网格结果不同，或离再下一个点不到一个网格单元（取整到整数单位时这两个点会合并，让轮廓折起来）的地方，就把这个顶点放回网格点上；最多进行 8 轮，保留最后一个合格的状态，最终的后备是网格结果。最后，在剩下的、不是由输入自己的点构成的每段“像曲线”段落里，如果去掉转角最小的那个角最多让轮廓移动一个单元，就把它去掉，同样要通过上述检查。结果只有直边，新顶点只出现在轮廓交叉处（以及轮廓相距不到一个单元处取整后的点），并且一定能通过导出。离单元边不到取整误差的交叉点会精确取整，所以它一定落在两条边都经过的单元里。如果取整仍然把轮廓错误地连在一起，同一区域沿两条路径算出的环绕数会不同；这时合并会在细一倍的网格上再试一次，仍然失败的话，字形就保持不合并，而不是画成丢了墨的样子：它的轮廓仍然交叉，但各处填充的范围不变，也仍然能导出，面板会提示 “Overlaps could not be merged; the outline is left as it is.”。网格在离字形原点 ±2^22 个单元以内都是精确的（`OVERLAP_LIMITS.maxCoordinate`），足以容纳每 em 4096 单位下达到 256 em 上限的刺，在细一倍的网格上也一样；伸出这个范围的字形同样保持不合并，给出同样的提示。长刺合并起来也不慢：给一条边绕行时，只走网格中含有取整后顶点或交叉点的那些列（陡的边则是行），不必经过一根长刺穿过的成千上万个空列。合并时用不递归的方式（迭代的并查集）把各段连起来，所以有几万个点的轮廓（Anchor spacing 1）不会再让调用栈溢出。此时标签页说明区会显示合并了多少处交叉、略去了多少细条（**Crossings merged**、**Slivers dropped**），Thorn 打开、Slipstream 有切口或顶点预算（见下条）简化过字形时也会显示。在 Arial、Georgia、New York 的拉丁字形上实测（种子 1 和 7、6 组设置，单独使用以及叠加在密集和很重的几何设置之上：共 30,744 次字形运算）：合并新增的“像曲线”段落顶点从 36,539 个降到 498 个（分布在 129 次运算中，每段约 1–3 个单位），交叉从 1 处降到 0，导出失败仍为 0；合并耗时约增加 18%，输出的顶点也更多（在密集的 Arial 上每个字形约 1,455 个点，原来是 637 个）。刚引入翻折时，在每款字体上各用 16 组翻折设置实测：各效果开到最大时整套字体都能写成 OTF 并读回（Arial 三个翻折效果同时开时超过 1 000 000 个轮廓点的上限除外）；100% 以内的结果完全不变。
- **顶点预算**（`src/geometry/budget.ts`；`src/geometry/experimental.ts` 中 `EXPERIMENTAL_LIMITS` 的 `maxAddedVertices` 和 `maxMergePoints`）：密集的效果会相乘。每个变形在网格折到轮廓的地方都加一个顶点，Refraction 会把字母的每个竖条再变形一次，每次合并在轮廓交叉的地方也加一个顶点，所以几个效果叠在一起，可能把一个一百个顶点的字母变成十万个顶点，合并和绘制都要好几秒。因此每个字形都有一个预算，它只取决于字形和设置，与时间无关，所以画布、预览和导出始终一致：每个效果之后，顶点最多比进入 Experimental 时多 6,000 个；每次合并时，网格点（顶点和交叉点）最多多 30,000 个。超出顶点上限的字形会被简化到上限以内：每个轮廓都用同一个容差做 Ramer–Douglas–Peucker 简化，容差从 em 的 1% 开始翻倍（最多 12 次），直到字形放得下，并略去比容差小的轮廓（但不会全部略去）。每个轮廓保留的是原有顶点的一部分，所以边仍然是直的，简化留下的“像曲线”段落也会被打散；之后再合并轮廓。会产生超过上限 16 倍顶点的变形，在代价很高的整理步骤之前就不用到这个字形上。超出上限的合并会在代价很高的步骤之前停下，字形简化得更粗（顶点最多是上一次尝试的一半）后再合并；只有连最粗的简化也放不下时，字形才保持不合并，按那个程度简化。默认设置、任何单个效果（即使滑块都拉到头、叠在密集的几何设置上）以及声音预设都不会触发预算；只有几个密集效果一起才会，而所有滑块都拉到最大时，字母会变成几块宽宽的墨块。这时面板会提示 “Simplified: these settings make too many vertices or crossings, so the outline was reduced (tolerance N u).”；字形保持不合并时提示 “Too complex to merge; lower the settings.”；某个变形没用到字形上时提示 “This glyph is left without crumple: too complex.”（ripple、whorl 和 slipstream 同理；Thorn 为 “roots or refraction”）；状态栏在顶点数后面加上 “(simplified)”。
- 统计（每个效果分别显示）：最大移动距离和新增的折痕数（Slipstream 还有切口数和拖尾数；Thorn：跳出的锚点数（Burst 中为长出的尖刺数）、带动字母的根部数和最远的一跳）；有轮廓需要减弱、或某个字形没能加上该效果时会给出警告。
- 刚做出 Crumple、Ripple 和 Slipstream 时（Crumple 当时叫 Noise，用的就是它现在的单层格子；Slipstream 只有拉长），在 Arial、New York、Georgia 的拉丁字形上实测，每个效果单独使用、叠加在各组几何设置之上（细展平和粗展平、锚点间距 5、角度锁定、网格、扰动 80、随机锚点，以及一组很重的组合），以及三个效果同时使用（共 78 组字体与设置组合）：没有新增轮廓自交或轮廓间交叉，没有轮廓被减弱，所有字形都能导出。需要折痕才凑成的“像曲线”段落只在 New York 上出现（6 组组合，共 7 个字形），都在轮廓两部分相距不到一个单位的地方。默认设置下 Crumple 和 Ripple 每个字形各增加约 30 个顶点（Facet 最小时约 80 个，波长最短时约 100 个）。在三款字体上随机测试 19,440 组几何、Crumple、Ripple 与 Slipstream 设置组合，没有任何交叉，没有轮廓被减弱，所有字形都能导出。重做后的 Slipstream 和 Thorn 各有上面的检查。

## 导出

从顶部栏右上角打开 **Export…**（提示文字为 “Export SVG, PNG, a font file, a video or the config”）。没有载入字体时只提供配置文件。只有点击下载按钮才会下载；视频在一次录制结束时保存。SVG、PNG 和字体文件使用与画布相同、按滑块值算出的最终多边形；画布还没按滑块值算好的字形会先补算：SVG 和 PNG 在几何 Worker 中补算，字体文件在导出自己的 Worker 中补算。视频录下的是画布当前显示的样子，包括实时帧（见[视频](#视频)）。

### SVG 与 PNG

- **SVG — main view**（默认）和 **PNG — main view** 导出画布：画布尺寸、按排版设置放置的文字以及颜色设置。在颜色标签页勾选 **Transparent background** 后，导出不含背景（SVG，以及带透明通道的 PNG）；导出预览效果时同样适用。SVG 为宽 × 高像素；PNG 再乘以 **Canvas size** 的倍数，由同一个 SVG 渲染而成。如果文字里有字形还没算好（例如声音正在驱动画布时），几何 Worker 补算期间对话框显示 “Computing outlines…”（`geometryClient.ensure`），**Cancel** 可以停止这次导出。
- 勾选 **Export the preview look**（默认不勾选）则改为导出右下角预览的样子：预览的颜色（开启 **Invert** 时文字与背景互换）加实心背景，并带上 **Blur**。模糊会从预览像素换算成字体单位，再换算成画布像素，因此在任何分辨率下相对字母的大小都不变；SVG 中用作用在未变换分组上的 `feGaussianBlur` 滤镜实现。
- 每个字形是一条使用自身字体单位的路径（y 轴向上，轮廓坐标保持完整精度），通过 `translate(…) skewX(…) scale(1 −1)` 放置，外层分组把字体单位缩放为画布像素。路径只用 `M`、`L`、`Z`，填充规则为 `nonzero`（**Fill** 关闭时改为只描边、不填充，见下文），保留轮廓顺序和方向。字偶距、字间距和换行与画布一致。缺字留空并在 XML 注释中列出。
- **Coordinate precision（坐标精度）** 0–4 位小数。取整的检查和修复方式与字体文件相同（见下文）；如果修复后轮廓仍会退化、反转或自相交，导出会停止并要求提高精度。
- `<title>` / `<desc>` 中的文字会转义；文件名只保留英文字母、数字、`.`、`-`、`_`。

### 仅轮廓（关闭 Fill）

画布的 **Fill** 图层按钮也决定 SVG、PNG 和视频怎样画字母（`src/export/svg.ts` 中的 `SvgLook.outlineOnly` 和 `drawArtboard.ts` 中的 `VideoLook.outlineOnly`，都取自 `view.showFill`）；预览画的就是 SVG 导出，所以也跟随它。字体文件始终是实心的：字体没有描边。

- **Fill 开启**（默认）：和以前一样填充。SVG 与 Fill 影响导出之前逐字节相同，视频的绘制调用也完全相同（`tests/export/outlineExport.test.ts` 把两者都固定了下来）。
- **Fill 关闭**：只画轮廓。字形分组带 `fill="none"`、文字颜色的 `stroke`（导出预览效果时用预览的颜色）、`stroke-width`、`stroke-linejoin="miter"` 和 `stroke-miterlimit="4"`，并有一条 XML 注释写明 “Outlines only (Fill off)”；路径不变（只有 `M`、`L`、`Z`）。视频用同样的宽度、连接方式和斜接限制描出每个轮廓。
- **宽度：2 个画布像素**（`OUTLINE_STROKE_PX`）。画布在 Fill 关闭时，任何缩放下都用 1.5 个屏幕像素宽的线画轮廓；缩放 100 % 时，默认 1200 × 800 的画布（加上视图边距宽 1272 像素）放进桌面上约 950 像素宽的画布区域，此时 1.5 个屏幕像素正好是 2 个画布像素。它以字体单位写在字形分组上（2 × 每像素字体单位数，`outlineStrokeWidth`），由分组缩放为画布像素，所以 2× 的 PNG 线宽为 4 像素，视频则随画布一起拉伸。倾斜的文字会让描边随字母一起斜切，差别最多几个百分点。
- **连接方式：** 斜接（miter），让直线段相交处的角和画布上一样尖；限制为 4（SVG 和 CSS 的默认值，也就是画布自己的值；约 29°），针一样尖的刺（例如 Thorn 的刺尖）会被削平，而不是画成很长的尖角。每个轮廓都是闭合的，所以没有线帽。
- **Original 和 Compare** 是画布视图：导出始终使用最终多边形。Fill 关闭时，Compare 在画布上画出的多边形轮廓就是导出画的样子。
- 导出对话框会说明当前是哪种：“Fill is on: the letters are filled.”，或者一条提示 “Fill is off on the canvas: outlines only, 2 px strokes in the text colour with no fill.”；完成消息会加上 “, outlines only”，SVG 的摘要写 “stroked with no fill”。字体文件则写明 “Always filled”。

### 字体文件

- 格式：**OpenType CFF 轮廓（`.otf`）**，用 opentype.js 写入（fontkit 只能读取字体）。只在生成字体时加载。
- 字形范围：当前字形、输入文字中的字符，或字体中所有已映射字符（最多 5000 个字形、1 000 000 个轮廓点——Anchor spacing 1 这类很密的设置、或所有实验效果都开到最大时，导出整套字体会达到点数上限，生成会停止并给出提示），另加一个 `.notdef` 方框。**字形大小：** CFF 中每个坐标都在 ±32 767 以内，相邻两点之间在每个方向上最多相差 32 767 单位，所以每个字形都必须放进一个边长 32 766 字体单位的正方形（每 em 2048 单位时为 16 em，1000 单位时为 32.8 em；`src/export/fitGlyph.ts` 中的 `FONT_BOX_LIMITS`）。在每个方向上，跨度不超过 32 766 单位（且在 ±32 767 以内）的字形保持完整；更宽的字形，正方形在这个方向上取以 em 框为中心的 32 766 单位（横向以字宽的一半为中心，纵向以上伸和下伸的中点为中心），必要时移进字形的范围内，边缘取整数单位。超出正方形的轮廓部分（比如很长的 Thorn 刺尖）会在它的边缘被直线切掉，而不是整个字形被略去（每个轮廓沿正方形的各边裁剪；裁完没有面积的轮廓去掉），对话框会列出这些字形：“Trimmed to fit: a font stores each glyph within a square 32,766 font units across (N em for this font). Outline parts reaching further, such as long Thorn tips, were cut off at its edge in …. Only the font file is trimmed: the canvas, SVG and PNG are not.”。字宽超过 32 767 单位的字形会被略去并写明原因；裁切之后还会再检查一遍坐标限制。对话框会事先估计大小（“About N outline points.”，根据已经算好的字形，其余字形按它们的平均值估算），超过 1 000 000 个点的上限时给出警告，还有很多字形需要计算时提醒生成可能要几分钟。
- **在后台生成：** 字体在一个专用的 Worker 中生成，每次生成一个（`src/export/fontExport.worker.ts`、`src/export/fontExportClient.ts`），对话框显示进度。画布已经按当前设置算好的字形会直接交过去原样使用，所以文件里的轮廓就是画布上的轮廓；其余字形经过相同的流水线计算。**Cancel** 会立即停止这个 Worker。Worker 60 秒没有任何消息时会被停止，对话框显示 “The export stopped responding.”。无法启动 Worker 时，改在页面上生成，每个字形之间让出页面。
- 命名：字体族名和样式名（可打印 ASCII）。默认族名会加上 “Poly”（并去掉开头的 “.”，否则字体会从菜单里隐藏）。PostScript 名为 `Family-Style`，不含空格和保留字符，最多 63 个字符；唯一标识为 `1.000;None-Curve;<PostScript 名>`。如果原字体的 SIL OFL 版权或授权信息中声明了保留字体名（“Reserved Font Name”），而族名中包含它，对话框会提醒修改版必须改名。
- 保留：字符映射、字宽、轮廓顺序、字腔、units per em、上伸和下伸。左右边距以最终多边形为准。轮廓按 CFF 的方向写入（外轮廓逆时针；最大轮廓为顺时针的字形——如 TrueType 来源——整体反转）。
- **字偶距**（`src/font/kerning.ts`、`src/export/gpos.ts`）：按 fontkit 的规则从原字体读出画布所用的成对字偶距（每种文字默认语言的 GPOS `kern` 特性，只取成对调整查找，可变实例会加上变化增量；没有这个特性时用旧版 `kern` 表，带 `morx` 表的字体始终用旧版 `kern` 表），写成一个 GPOS 表，即 `kern` 特性下的成对调整查找，只保留导出字形之间的字偶对。子表格式与原字体相同，所以按类定义的字偶距仍按类保存，超过约 60 KB 时使用 Extension 查找。这个表添加到生成好的文件里（`src/export/sfnt.ts`），校验时会读回来，与原字体逐对比较。不包含：上下文字偶距（`kern` 特性中的 GPOS 类型 7 和 8）、特定语言的字偶距、Apple 按类定义的旧版 `kern` 子表（格式 2 和 3；只读取格式 0），以及附加符号定位（文件里没有 GDEF）。对可变实例，带变化增量的字偶距取整到整数单位，所以文件与画布每对最多相差 1 个单位。
- **行距**与画布一致：原字体 hhea 的上伸、下伸和行间隙，同时写成 OS/2 的排版度量（OS/2 版本 4），并设置 `USE_TYPO_METRICS`，所以各个平台上的应用排出的行距相同。Windows 上伸和下伸仍会加大，以包住超出它们的轮廓（Slipstream、Thorn），所以只有忽略 `USE_TYPO_METRICS` 的应用会把行距排得更大。
- 从原字体复制：OS/2 的字重和字宽等级、样式位（`fsSelection`，与 head 的 `macStyle` 保持一致，并加上 `USE_TYPO_METRICS`）、嵌入权限（`fsType`）、panose、字族分类、上下标与删除线参数、x 高度和大写高度；hhea 行距；post 的倾斜角、下划线位置和粗细、等宽标记。Windows 上伸和下伸沿用原字体，若新轮廓超出则相应加大（Windows 会裁掉超出部分）。复制的名称记录：版权、商标、厂商、设计师、厂商和设计师网址、授权及授权网址；描述中注明轮廓由 None-Curve 重建。原字体没有的条目直接省略，而不是写成空白。head 中的包围盒和 CFF 的 FontBBox 都是实际包围盒：所有字形的点的并集，包括 `.notdef`。写入库（opentype.js）无法设置的字段——hhea 行距、head `macStyle`、head 的包围盒（写入库会漏掉 `.notdef`，还把空字形算成伸到它的字宽处）、CFF FontBBox——会在生成的文件中直接改写，它写不了的表（GPOS）也在这里添加（`src/export/sfnt.ts`），然后重新计算校验和。
- 取整（`src/export/quantize.ts`）：每个轮廓先取整到整数单位，再去掉重复点、零长度边，以及位于前后两点连线上的点（包括往返的尖刺）。轮廓必须至少保留三个点、方向不变、面积不为零，且不能新增自交。只有在未取整的轮廓既没有自交、也没有两部分相距两个单位以内的地方出现的交叉，才算新增——原本就重叠（字体中很常见）或几乎相碰的轮廓，在整数单位下无法避免，差别也不到一个单位。取整造成的交叉先通过删除相关的一个顶点来修复；仍不行时，把轮廓极轻微地简化（0.5–2 个单位）后再取整。面积小于 4 平方单位、或平均宽度不到 1 个单位（面积的两倍除以周长——很强的实验效果可能把笔画挤成这样的细条）的轮廓若在取整后退化，只排除该轮廓本身。取整后的每个轮廓还要和字形的其他轮廓保持原来的位置关系：两个轮廓之间的新交叉，只有在两者原本就相距两个单位以内的地方才接受；会把轮廓推进另一个轮廓的修复不采用，改试下一种做法。轮廓是逐个取整的，所以如果某个轮廓让相邻轮廓没有余地取整，整个字形会按相反的轮廓顺序再取整一次。自交检查按 x 排序扫描线段，所以有数千个点的轮廓（Anchor spacing 1）也很快；每个轮廓只和包围盒离它不到两个取整步长的轮廓比较，未取整轮廓自身的交叉点放在网格单元里查找，所以有数千个轮廓的字形也很快。本来就自交超过 2,000 次的轮廓（实验效果的合并没有合并的一团乱线）只取整一次并原样保留：只检查它的方向、面积以及与其他轮廓的位置关系，因为那里的取整误差不到一个单位，而逐个检查它的大量交叉点要花好几分钟。在 New York 和 Arial 上测试：默认设置、Squaring 为 Square / All contours、Anchor spacing 1、Distortion 40 时都没有字形被排除（之前默认设置下 New York 有 42 个字形被排除，包括所有 “a”；Square / All 时为 26%）。
- 先点 **Build & verify**，再点 **Download .otf**。文件会用 fontkit 重新打开并逐字形比对（文件签名、族名、字形数、行距和 `USE_TYPO_METRICS`、每个映射、每个字宽、每个轮廓的每个点及方向、每个字形都在 ±32 767 以内且宽高不超过 32 766 单位、head 中的包围盒和 CFF 的 FontBBox，以及字偶距），再交给浏览器字体引擎加载（`FontFace`，OTS 校验）。文件带有字偶距时，结果中会写明。任一检查失败都不会提供下载。无法保存的字形会被排除，连同原因一起列出（最多写出 8 个，其余写作 “and N more”）：“Left out of the font file: …”。这里不适用任何精度设置：字体只能保存整数字体单位。
- 无论画布上的 **Fill** 是否开启，字体文件始终是实心的；对话框会写明这一点（“A font file is always filled”）。
- 不包含：TTF / WOFF / WOFF2 输出；上下文和特定语言的字偶距、连字、附加符号定位及其他 OpenType 排版特性（成对字偶距已包含，见上）；hinting；可变轴（可变字体导出画布上显示的实例）；只能通过排版特性访问的字形；U+FFFF 以上的字符；超出 32 766 单位正方形的轮廓部分（会被切掉，见上）。坐标取整到字体单位。

### 视频

代码在 `src/export/recorder.ts`、`src/export/videoFormat.ts` 和 `src/export/drawArtboard.ts`；控件在 `src/components/RecordControls.tsx`、`RecordingCanvas.tsx` 和 `RecordingIndicator.tsx`。视频实时录下画布随声音变化的样子，并带上声音本身。它是唯一保留实时样子的导出：SVG、PNG 和字体文件使用滑块值。

- **入口：** Export 对话框中的 **Video — live sound**，它的 **Record** 在同一次点击里关闭对话框并开始录制；以及 Sound 标签页底部的 **Record** 分组，里面有 Record / Stop、已录时间（“0:12”，定长录制时为 “0:12 / 0:30”）、“Live · N fps”、各个选项，以及上一次录制的结果。两处设置的是同一组选项（`RecordOptionsFields`）。录制期间，顶部栏先显示 “Starting to record…”，然后是带红点的 “Recording 0:12” 和一个只有图标的 Stop 按钮（“Stop recording”），最后是 “Saving the video…”；录完后显示这次录制的结果，直到你关掉它（只有图标的 “Dismiss” 按钮）或开始下一次录制。顶部栏也会向读屏软件播报开始和结束。录制期间再次打开对话框，它有自己的 Stop。录制期间 Freeze 不可用（“Freeze is off while recording.”）。
- **选项**（只在本次访问有效：不保存、不能撤销，录制期间锁定）：
  - **Format**（格式）：MP4（默认）或 WebM。浏览器写不了的格式会变灰，例如 “MP4 (not supported in this browser)”。
  - **Length**（时长）：Until stopped（默认）、5 s、10 s、15 s、30 s、60 s 或 Whole file；最长 10 分钟。使用文件时，从当前的 Position 开始录。Whole file（只在载入了音频文件时可选）从头到尾播放整个文件，录制期间关闭 Loop，录完再恢复。
  - **Include audio**（包含声音，默认打开）：使用麦克风时，它的声音会进入文件（仍然从不回放）。
  - **Use the preview look**（使用预览的样子，默认关闭）：关闭时按画布的 Color 设置录制；打开时录制右下角预览的样子，即它的颜色（Invert 时互换）和 Blur，文件名以 `-video-preview` 结尾。
  - 选项下方一行写出这次录制的尺寸、帧率和格式，例如 “1200 × 800 px · up to 30 fps · MP4”。
- **Record** 在以下情况变灰，并把原因作为提示：浏览器不能录制（“This browser cannot record video.”）、没有字体（“Load a font to record.”）、选了 File 但没有文件（“Choose an audio file first.”），以及声音正在打开时（“Opening the sound…”）。文件或麦克风没在运行时，它会（在同一次点击里）开始播放文件或开始收音；录完后，只有当初是它开始的，才会暂停文件或停止收音。Drive letters 关闭、Strength 为 0%，或没有任何打开的映射有 Depth 时，显示 “Sound is not moving the letters: the video will be still.”。
- **尺寸与质量：** 画布尺寸乘以 **Canvas size** 的倍数，与 PNG 相同；长边超过 3840 px 或面积超过 3840 × 2160 px 时按比例缩小（尺寸那一行会加上 “ (scaled down to the 4K limit)”），每条边取偶数。每画出一个实时帧就是一个视频帧，所以视频的帧率就是实时帧率，最高 30 fps（没有帧率选项）。视频码率：每像素 4.5 比特，限制在 2–12 Mbps（12 Mbps 时 10 分钟约 0.9 GB，保存之前都放在内存里）；音频 128 kbps。视频没有透明度：背景色总会画上，打开 **Transparent background** 时会有提示说明。
- **格式**（`videoFormat.ts`）：MP4 依次尝试 H.264 High（`avc1.640028`）、Baseline（`avc1.42E01E`）、任意 H.264，最后是浏览器自己的 MP4，音频为 AAC（`mp4a.40.2`）；WebM 依次尝试 VP9、VP8，最后是浏览器自己的 WebM，音频为 Opus。录制器拒绝的类型会换下一个。不能写 MP4 的浏览器保存为 WebM，并提示 “MP4 isn't supported in this browser: saved as WebM.”。
- **绘制**（`drawArtboard.ts`，纯函数式，用记录调用的假绘图对象测试）：一个隐藏的画布（`RecordingCanvas`，只在录制期间存在，挂在页面上但看不见）画出画布当前显示的场景，包括实时形状、每个字母自己的层级和它所在 Thorn 轮换组的刺，位置取滑块值下的字母给文字块的位置（见[排版](#排版)），所以视频里的文字块和画布上一样静止。它使用 SVG 导出的排布（分组变换，每个字形的位置、倾斜和翻转，nonzero 填充规则，只有直线段；**Fill** 关闭时改为像 SVG 那样描出每个轮廓，见[仅轮廓](#仅轮廓关闭-fill)），每个多边形的路径只生成一次（`Path2D`）。使用预览的样子时，模糊通过字形单独的一层画上，和 SVG 对字形分组做模糊一样；不支持画布 `filter` 的浏览器录制时不带模糊，并提示 “Blur isn't available for video in this browser: recorded without it.”。
- **采集**（`recorder.ts` 中的 `RecordingController`；时钟、计时器、声音引擎、浏览器检查和录制器都由外部注入，所以测试可以用假的对象运行它）：一次录制最多等 30 秒，等声音开始、第一帧画好。然后用 `captureStream(0)` 采集画布，每画一次就是一个视频帧（`requestFrame`；不支持时用 `captureStream(30)`），交给每秒交出一次数据的 `MediaRecorder`。画布只有变化时才产生一帧，所以在第一帧、至少每秒一帧，以及最后一帧时，会“碰”一下静止的画布：把一个像素画回它自己（只限于这个像素），算作变化，但看起来没有不同。录制结束时文件只保存一次，例如 “Saved Roboto-Regular-video.mp4: 0:05, 1200 × 800 px.”（文件名为 `Family-Style-video.mp4` 或 `.webm`）。
- **文件里的声音：** 声音引擎的录音分支（`engine.ts` 中的 `startRecordingAudio`）把正在运行的来源（听到的文件声音，或麦克风）经过一个延迟送进一个 MediaStream 目标。这条支路不接扬声器，所以你听到的声音不变。延迟让声音和字母对齐：实时延迟（从测得一帧声音到它的字母交给 React 的平滑耗时；`live.ts` 中的 `liveLatencyMs`）加 37 ms（分析窗口的一半加一个显示帧），限制在 40–400 ms；还没有实时帧时为 90 ms；在录制开始时设定一次。
- **录制结束于：** 到达设定的时长或 10 分钟上限（“Stopped at the 10-minute limit.”）；声音暂停、停止、切换或结束（“The sound stopped, so the recording ended.”）；标签页被隐藏（“Recording stopped because the tab was hidden.”）；画布尺寸或倍数改变（“Recording stopped because the canvas size changed.”）；字体被关闭；你按下 Stop；或录制器出错（“Recording failed: …”，保留已录下的部分）。录制会多延续一点，让最后一帧进入文件：按 Stop、到达上限或麦克风停止后再继续 100 ms；时长用完、文件暂停或播完时再继续音频延迟加 100 ms，让还在延迟中的声音结尾也进入文件。标签页被隐藏、出错、画布或字体改变时立即停止。什么都没录到时不保存（“Nothing was recorded.”）。录制期间关闭页面会先询问。录制期间的其他改动，例如编辑文字，会按画布显示的样子录下来。
- **实测**（Chromium 浏览器、Roboto、测试音轨）：1200 × 800 的 5 秒录制保存为 WebM（`video/webm`，266 KB，4.92 秒）和 MP4（398 KB，4.97 秒），帧都正确；Export 对话框的 Record、MP4 → WebM 的退回和标签页被隐藏时的停止都如上所述；录制期间没有长任务。视频的流畅程度取决于实时帧率：连续 2 秒低于 8 fps 时，Record 分组提示 “Too slow for a smooth video: try fewer effects or a shorter text.”。WebM 文件不带时长。音频延迟是估计值。其他浏览器尚未测试。

### 配置文件

`src/state/persist.ts` 中的 `serializeConfig` 和 `parseConfig`；对话框里的 **Config — settings (.json)** 和 **Import → Config file**。

- **Download config** 保存 `none-curve-Family-config.json`（没有字体时为 `none-curve-config.json`）：内容就是[在两次访问之间保存](#保存与撤销)的那份会话，键名和版本号都相同，另外加上 `"app": "none-curve"` 和 `"kind": "config"`，并带缩进。里面是滑块自己的值（从不包含声音的实时值），不写 Thorn 由设置算出的画布对角线，文字和存储时一样最多 10,000 个字符。对话框会写出这个文件将要求的字体。保存不需要字体。
- **Import → Config file**（或拖到画布上的 `.json` 文件）按读取已保存会话的方式读取：从旧版本迁移，并逐项检查，所以损坏的值变回默认值，不认识的键被丢弃。不是 JSON 的文件（“The file is not valid JSON.”）、没有标记的文件、或大于 1 MB 的文件会被拒绝，菜单下方显示 “Config not imported”，什么都不改变。新版本保存的文件尽量读取能识别的部分，提示里会说明。
- **应用的内容：** 设置、文字、声音映射和 Response 分组作为一个撤销步骤；画布视图的轮廓和图层按钮、预览的 Blur 和 Invert、导出精度也会应用，但和其他地方一样不能撤销。字体：Google Fonts 的字体会重新下载（已经打开时不重复下载）；本地文件无法重新打开，所以提示里会写出文件名（“Its font is the local file X: import it to see the config as it was saved.”）。当前字体（或之后载入的下一个字体）是同一字体族和样式时，恢复选中的字形。菜单下方的提示在点它的 × 按钮（Dismiss）、下一次导入字体或按下 **Reset all** 时消失。

## 声音

代码在 `src/sound/`，显示在 **Sound** 标签页（`src/components/SoundControls.tsx`）；计划见 [docs/SOUND_PLAN.zh.md](docs/SOUND_PLAN.zh.md)。第 1 阶段负责播放或收音、测量并显示电平表。第 2 阶段在文件播放或麦克风收音期间，让特征移动 Geometry 和 Experimental 标签页的滑块。第 3 阶段已完成一部分：三个种子成为随声音跳变的目标，每个锚点都会落到新的位置；Beat 成为映射可以跟随的特征；选择目标时会打开它需要的设置；十个预设可以设好字母并填好映射。第 4 阶段的 Pitch 和立体声 Pan 也已完成（最初测量的 20 个特征合并成了 10 个；随 Response 分组加入的 Melody 让特征变成 11 个）。**Response** 分组调节声音移动字母的幅度，并能让每个字母按自己的幅度反应；**Record** 分组录制视频（见[视频](#视频)）。第 3 阶段还剩 Step 映射（Allowed directions、Sides、Rings）。

- **来源：** **File**（文件，默认：Choose file、Play / Pause、Loop、Position）和 **Microphone**（麦克风：Start listening / Stop listening；选中它只会显示这两个按钮并暂停文件，只有点 Start listening 才会打开麦克风）。没有 Off 这个来源：文件用 Pause 停下，麦克风用 Stop listening 停下，选 File 会释放麦克风。麦克风收音期间，标签页显示 **Listening**，状态栏显示 **Microphone on**。
- **电平表**（**Levels** 分组）：每个特征一行紧凑的电平表（名称、条形、数字），分在五个小标题下：**Loudness**、**Bands**、**Tone**、**Rhythm** 和 **Stereo**，每组都有一个 ⓘ，用通俗的话解释组里的电平表。数字的显示方式：Level 用 dB，Pitch 用 Hz，Pan 显示偏向哪一侧（“L 40”、“R 40”，离中间不到 5% 时显示 “C”），其他特征都用百分比；没有读数时显示 “—”。Pan 的条形从中间向左或向右填充。**Beat** 是脉冲条：每次起音跳到满格，再按 **Release** 回落；它取代了原来的指示灯。**Melody**（在 Tone 中，位于 Pitch 之后）也是脉冲，每个新音一次。每个条形都是 `role="meter"`（Pan 为 −100 到 100），读屏读出的值与显示的一致（“40 percent left”、“Centre”、“No reading”）。电平表由每帧回调直接写入 DOM，不为每一帧设置 React 状态：条形每帧更新，数字每秒最多更新约 10 次，读屏的值每秒最多 4 次。条形的变化不带过渡，所以开启 `prefers-reduced-motion` 时看起来也一样。
- **Mappings**（映射，位于 Levels 和 Response 之间）：
  - **Drive letters**（驱动字母；一个开关：带 `role="switch"` 的复选框，画成跟随主题配色的小滑轨和圆钮）：只有它打开、并且文件正在播放或麦克风正在收音时，声音才会移动字母。默认打开；如果系统要求减少动态效果（`prefers-reduced-motion`），它默认关闭，标签页会显示 “Off because your system asks for reduced motion.”（这句提示也是开关的描述）。访问期间才开启减少动态效果时，它也会自动关闭；关闭减少动态效果时，开关保持原样。**Strength** 为 0% 时，开关下方提示 “Strength is 0%: the letters hold still.”。
  - **Preset**（预设）和 **Load**（载入）（`presets.ts` 中的 `PRESETS` 和 `presetSettings`）：现成的起点，带一个 ⓘ，说明 Load 会恢复哪些默认值，并给每个预设一行说明。在列表里选择只是选中（默认选中 Flicker），所以用键盘在列表中移动不会替换任何东西。**Load**：
    1. 把 Geometry 和 Experimental 的每个分组（Curve flattening、Random anchors、Squaring、Anchors、Grid & angles、Distortion，以及各个 Experimental 效果）恢复为默认值，保留三个种子；Typography、Color、画布，以及 Sound 标签页的来源、Drive letters 和 Response 分组都不动；
    2. 设好预设的起始值（只设与默认值不同的部分），每个改变了的分组一次参数更新；
    3. 用预设的各行替换所有映射，并清除之前各行的提示；
    4. 在 Preset 一行下方显示一个状态行：先是 “Loaded Flicker.”，然后对关闭了的 Experimental 效果显示 “Turned off Crumple and Ripple.”，关闭了 Random anchors 时显示 “Turned off Random anchors.”，预设没有设置的其他设置有恢复为默认值的，显示 “Other Geometry and Experimental settings back to defaults (seeds kept).”。它一直保留到下一次 Load，或在列表里选了另一个预设为止。

    Load 只算一步撤销，撤销后会恢复之前的设置和映射（见[保存与撤销](#保存与撤销)）。所以无论之前设了什么，预设总是从同样的字母开始，它的各行也不需要再打开任何设置；万一某一行仍然需要，就像手动选择该目标时一样，按行的顺序打开，并显示该行的提示。手动选择目标仍然只会打开它所需的设置（见下文），不会恢复任何默认值。各预设如下，括号里是 Depth（种子上是 Rate），然后是起始值：
    - **Flicker：** Level → Distortion · Noise amplitude（+90%），Beat → Distortion · Noise amplitude（+30%），Beat → Distortion · Seed（Rate 100%）。起始：少数锚点模式打开（见[顶点扰动](#顶点扰动)），Noise amplitude 2，Normal bias 90%。很小的幅度让 Distortion 保持打开，所以安静时 Seed 那一行也起作用。
    - **Scatter：** Level → Random anchors · Randomness（+90%），Level → Random anchors · Density（−9%），Beat → Random anchors · Seed（Rate 50%）。起始：Use random anchors 打开，Density 10，Randomness 5%。
    - **Pixel：** Bass → Grid & angles · Grid size（+70%），Treble → Anchors · Anchor reduction（+40%）。起始：Snap to grid 打开。
    - **Low poly：** Level → Curve flattening · Tolerance（+70%），Brightness → Anchors · Anchor reduction（+40%）。起始：Merge joined curves 打开，所以较大的 Tolerance 能作用到整个碗形。
    - **Block：** Swell → Squaring · Amount（+90%），Beat → Squaring · Amount（+30%）。起始：全部默认。
    - **Jitter：** Treble → Distortion · Noise amplitude（+60%），Brightness → Distortion · Noise frequency（+30%）。起始：Noise amplitude 2（让 Noise frequency 那一行在安静时也起作用），Noise frequency 20。
    - **Facet：** Level → Curve flattening · Segments per curve（−15%），Beat → Curve flattening · Segments per curve（−5%），Pitch → Curve flattening · Segments per curve（+20%）。起始：Mode 为 Fixed segments，Merge joined curves 打开，Segments per curve 6。
    - **Bloom：** Beat → Ripple · Amount（+10%），Bass → Ripple · Petals（+5%：低音起来后花瓣到 10%，因为 20% 已经很难辨认）。起始：Use ripple 打开，Amount 30%。
    - **Flare：** Beat → Seed（Rate 100%），Level → Thorn · Reach（+50%：满响度时推到立方滑块的一半，即画布对角线的八分之一，默认画布上约 3.8 em），Beat → Thorn · Anchors（+15%）。起始：Use thorn 打开，Anchors 1，Reach 0%（安静时没有刺，也没有根部的拉动），Root 25%（较浅的根部让笔画保持可读）。开启 Thorn 时，这三行都通过 Thorn 轮换送到字母，每次只有少数几个字母（见下面的“Thorn 轮换”），所以一拍不再让每个字母的刺同时重新选择或成倍增加。
    - **Gale：** Level → Slipstream · Slip（+50%），Beat → Slipstream · Cuts（+40%），Activity → Slipstream · Trails（+35%）。起始：Use slipstream 打开，Strength 0%，Slip 0，Cuts 0，Trails 0：安静时什么都不流动；也没有拉长，因为拉长会把字母推到相邻字母上。
  - 最多 8 行（`MAPPING_LIMITS.maxMappings`），每行有 **Feature**（特征：11 个特征，按电平表的分组排列）、**Target**（目标，分为 Geometry / Experimental 两组，名称为“分组 · 标签”，例如 “Distortion · Noise amplitude”；Experimental 标签页的种子只叫 “Seed”）、**Depth**（深度，−100% 到 +100%，每档 1%，带数字框）、开关（“Use mapping 1”、“Use mapping 2”……）和删除按钮（“Remove mapping 1”……；删除后键盘焦点移到下一行的删除按钮，没有下一行时移到上一行的，都没有时移到 Add mapping）。目标是种子时，Depth 滑块改称 **Rate**（频率，0–100%，每档 1%，有自己的 ⓘ；见下面的“种子”），某行改选种子时，负的 Depth 会变成正值。**Add mapping** 添加 Level → Distortion · Noise amplitude，Depth 为 +50%（这个目标已被使用时，改为还没有任何一行使用、并且已经起作用的第一个目标，没有的话取还没被使用的第一个目标），并像选择目标时一样打开它需要的设置；已有 8 行时不再添加（仍可获得焦点，用 `aria-disabled`），标签页显示 “Up to 8 mappings.”。映射会和设置一起保存在浏览器里，下次打开时恢复，对映射的每次改动都可以撤销；Drive letters 不保存（见[保存与撤销](#保存与撤销)）。
  - **打开目标需要的设置：** 选择一个在当前设置下不起作用的目标时，会自动改好它需要的设置（打开它所在的步骤或效果、设置 Mode，或者为 Curve flattening 的滑块关闭 Random anchors），并在该行下方说明，例如 “Turned on Ripple.”、“Set Noise amplitude to 40.” 或 “Turned off Random anchors. Set Mode to Adaptive.”（规则见下表）。这条提示是一个状态行，一直保留到该行的目标再次改变或该行被删除。把某行换到别的目标、或删除该行，都不会关闭任何设置。用键盘在 Target 列表中移动时（方向键，或在收起的列表上打字），只有按回车或焦点离开列表时才会打开设置，所以途经的目标不会改变任何设置；用鼠标选择时立即生效。
  - 只要某行的目标当前不起作用（例如之后又关掉了它需要的设置），行下方就改为说明原因（说明见下表；这句说明也是 Target 下拉框的描述）。旁边的 **Enable** 按钮（“Enable, mapping 1”……）做出与选择该目标时相同的改动，显示提示，并把键盘焦点交给该行的 Target。在此之前，这一行不移动任何值。
- **目标**（`mapping.ts` 中的 `TARGETS`），按面板顺序共 44 个：两个标签页里的每个连续滑块，范围、档位和刻度都与该滑块完全相同（控件和目标从同一张表读取，即 `src/state/sliderScales.ts` 中的 `SLIDER_RANGES`、`TOLERANCE`（对数）和 `THORN_REACH`（立方），所以两者不会不一致；作用在 Thorn · Reach 上的映射移动的是立方滑块的滑块位置，所以实时值也沿同一条曲线变化）；以及三个种子，取种子输入框自己范围内的整数（0–999,999）。旧设置里没有的字段按面板显示的值读取（Thorn 的 Root 50%、Flute width 10%、Burst anchors 40 和 Dent 80%，Crumple 的 Turn、Ripple 的 Petals、Slipstream 的 Slip、Cuts 和 Trails 以及 Thorn 的 Refraction 为 0）。
  - Geometry：Curve flattening 的 Tolerance、Segments per curve 和 Corner angle；Squaring 的 Amount；Anchors 的 Anchor spacing 和 Anchor reduction；Grid & angles 的 Grid size；Distortion 的 Noise amplitude、Noise frequency、Normal bias 和 **Seed**；Random anchors 的 Density、Randomness 和 **Seed**。
  - Experimental：Crumple 的 Amount、Facet size 和 Turn；Ripple 的 Amount、Wavelength、Sides、Center X、Center Y、Fade 和 Petals；Whorl 的 Amount、Rings 和 Sides；Slipstream 的 Direction、Strength、Slip、Gust size、Gustiness、Cuts 和 Trails；Thorn 的 Anchors、Reach、Root、Spread、Width、Refraction、Flute width、Burst anchors（Burst 中的 Anchors）和 Dent；以及共用的 **Seed**。
  - 不是目标的：开关和选项（Mode、Break merged curves at、Applies to、Allowed directions），以及 Distortion 的少数锚点模式。播放期间声音从不打开或关闭任何步骤；只有选择目标、Add mapping 或 Enable 会打开设置，而且只打开一次；Load 则恢复默认设置并设好预设自己的值（见上文）。

- **调制**（`modulate`，纯函数）：对于每个滑块目标，只要至少有一个映射是打开的、Depth 不为 0、并且目标所在的步骤或效果是开着的，实时位置 = 滑块位置（沿显示出来的滑块，0–1）+ 这些映射的 Depth × 特征之和，截断到 0–1，再换算回数值并取整到滑块的档位。位置沿滑块计算，所以对数刻度的 Tolerance 是沿滑块均匀移动，而不是按字体单位均匀移动。同一目标上的多个映射先相加，再乘以 **Strength**，然后截断。**Melody tracking** 大于 0 时，每个滑块映射的特征先加上 0.5 × Melody tracking × Melody 脉冲（最多到 1；不包括 Pan，也不包括 Melody 本身的映射；`RESPONSE_LIMITS.melodyBoost`）。Pan 是唯一的双向特征（−1 到 1）：Depth 为正时，声音偏左让滑块向下，偏右让滑块向上；其他特征都在 0–1 之间。没有任何作用时（没有映射、全部关闭、Depth 为 0、所有特征为 0、没有种子前进，或所有目标都不起作用），直接返回滑块值本身（同一个对象），所以字母会完全恢复。因此每个实时帧都是滑块和种子输入框能调出来的一组参数（没有新几何，帧与帧之间不做补间）；字母按不同幅度反应或显示 Thorn 轮换时，屏幕上的每个字母也是如此（见下面的“字母”和“Thorn 轮换”）。Response 分组为默认值时（Strength 100%，其余三个为 0），得到的值与这个分组出现之前的声音逐位相同（`tests/sound/neutral.test.ts`）。
- **种子**（跳变目标；`jumps.ts` 中的 `JumpTracker`，纯函数式）：映射到种子时不参与上面的求和，而是每跳变一次，种子就前进 1（超过 999,999 后回到 0），所以每个锚点（Distortion、Random anchors）或每处翻折、阵风、滑移、切口、拖尾、刺和玻璃竖条（Experimental）都会落到新的位置（开启 Thorn 时，Experimental 种子和 Random anchors 的种子通过 Thorn 轮换送到字母，每次只有少数几个字母；见下文）；在 Distortion 的少数锚点模式下（Flicker），改为每个字母换一组新的少数几个锚点移动。该行的 **Rate** 乘以 **Strength** 决定跳变的频率（仍最多 100%）；Depth 的正负不起作用。Melody tracking 不加强种子。
  - 跟随 **Beat** 时，种子按起音计数：Rate 100% 每次起音前进一次，50% 每隔一次，25% 每四次。
  - 跟随其他特征时，每秒最多跳变 4.8 × Rate × 特征值次（Pan 偏向哪一侧都算）。两帧间隔超过 100 ms 时按 100 ms 计算，所以卡顿之后不会一下子放出一串跳变。
  - **闪烁限制：** 一个跳变帧算一次大变化，从被驱动的滑块共用的同一份闪烁额度中扣除（见下面的“闪烁限制”）：所有种子和滑块加起来，任意 1.25 秒内最多 6 次大变化，也就是每秒 3 次闪烁（同一帧里一起跳变的种子只算一次，同一帧的跳变和滑块折返也只算一次）。超出限制的跳变直接跳过，不会推迟，所以被驱动的滑块很忙时，种子跳得少一些。
  - 只有声音能够驱动字母、并且种子的目标起作用时才计算跳变。暂停、停止或关闭 Drive letters 时，每个种子都回到它输入框里的值（完全恢复），再次播放时从这个值开始；闪烁计数窗口会保留，回到原值也算一次，所以快速暂停再播放不会放出第二串跳变。不再被驱动的种子（映射关闭、被删除或换了目标）在下一帧回到输入框里的值。
  - 种子被驱动期间，它的输入框旁边会出现一个小的实时数字（`src/components/LiveSeed.tsx`，悬停提示为 “Live seed”，对读屏软件隐藏，每秒最多更新约 15 次），Distortion 和 Random anchors 的统计数字也显示实时种子。输入框本身保留自己的值。
- **字母**（`letters.ts`，纯函数式；**Motion contrast** 或 **Pitch reactive** 大于 0 时启用）：每个字母，即文字中一个字形的一次出现（按 `placePolygons` 的方式计数：先按行，再按字形；空格和缺字也计入），每帧得到一个权重，并据此落在三个层级之一，层级随设置固定：quiet（弱）、shared（共享）和 strong（强）。共享层级就是上面的实时值，也就是标记、实时种子、统计数字和 Freeze 使用的值。处在弱或强层级的字母显示共享值，只是每个被驱动滑块相对于滑块值的偏移乘以该层级的倍数，再截断并取整到滑块的档位，所以屏幕上的每个字母仍然是滑块和种子输入框能调出来的结果，没有 Thorn 时一帧最多需要三组参数。层级从不缩放 Thorn 的滑块；开启 Thorn 时，所有 Thorn 轮换目标都不缩放，取所在轮换组的值（见下面的“Thorn 轮换”；`levelPosition`），所以强层级的字母不再得到成倍的 Reach。每个层级的种子都相同（开启 Thorn 时，Experimental 种子和 Random anchors 的种子取自每个字母所在的轮换组）。字母必须越过层级边界一段距离才会换层级（滞回），所以靠近边界的字母不会来回闪。编辑文字后，在下一帧到来之前所有字母都显示共享层级；同一段文字只是排版改变（字间距、行距、对齐、倾斜）时，字母保持原来的层级。已知限制：在受层级缩放、档位很少的滑块上（例如关闭 Thorn 时的 Ripple · Sides、Whorl · Rings 和 Sides，或 Curve flattening · Segments per curve），只有共享值离开滑块值自己所在的那一档之后，字母之间才会拉开差别。
  - **Motion contrast**（0–100%）：每个字母的倍数由它自己固定的一份和一条缓慢的波（6 秒）混合而成，波在字母之间错开，所以领头的字母每隔几秒就会换。倍数均匀分布在 1 的两侧，100% 时在 1/3.6 到 3.6 之间（3.6 的设置值次方），所以 100% 时约 17% 的字母在弱层级、67% 在共享层级、17% 在强层级。Strength 决定整体幅度，Motion contrast 决定差别。
  - **Pitch reactive**（0–200%）：近来旋律中的低音让左边的字母动得更多，高音让右边的字母动得更多，所以无论曲调在哪个音区，都会扫过整段文字。每个字母的权重是围绕音高在文字块中横向位置的一个钟形，这个位置就是音高在旋律音域中所处的位置（`pitchPlace`，取自帧里的 `pitchLow` 和 `pitchHigh`；见下文 `features.ts` 中的 Pitch）。音域一开始是围绕第一个稳定下来的音的一个八度，遇到更高或更低的新音时约 0.15 秒内扩展过去，约 8 秒内向最后一个音收拢；超过 8 秒没有音之后，下一个音让它重新开始。它始终至少一个八度宽，所以平稳的人声不会随每次晃动扫过整段文字；距 Pitch 的 55–1760 Hz 刻度两端一个半音以内的音会被忽略（和弦或鼓会读在那里）。旋律第一次上行时，音域随每个新音扩展，所以每个新的最高音都落在最右端；音域听过一遍之后，每个音都有自己的位置。它需要清晰的单个音，例如人声或一件乐器。已知限制：在 200% 时，快速的八度跳进偶尔会被闪烁限制拦下（C4 和 C5 交替、每秒 2 个音时，11 次跳进中有 10 次到位，100% 时 11 次全部到位）。
- **Thorn 轮换**（`types.ts` 中的 `THORN_TURNS`；`letters.ts` 中的 `isTurnTarget`、`turnGroups`、`ThornTurns` 和 `turnSets`；`live.ts` 中的调度器）：声音驱动字母且实时值中 Thorn 打开时，决定刺长在哪里、指向哪里的那些设置每次只送到少数几个字母，所以声音不会同时改变每个字母的刺。
  - **哪些设置轮换**（轮换目标，`isTurnTarget`）：Thorn 的滑块（Anchors、Reach、Root、Spread、Width、Refraction、Flute width、Burst anchors、Dent），Experimental **Seed**（Crumple 和 Slipstream 共用它，所以它们也按轮换换种子），Distortion 之前的每个几何目标（Curve flattening、Squaring、Anchor spacing 和 Anchor reduction、Grid size，以及 Random anchors 和它的种子：Thorn 在它们做出的字母上选锚点），以及 Crumple、Ripple、Whorl 和 Slipstream 的每个滑块，但 Crumple 和 Ripple 的 **Amount** 除外。Distortion 的四个目标（Noise amplitude、Noise frequency、Normal bias 和它的 Seed）以及这两个 Amount 保持连续、共享（其中的滑块仍像以前一样受层级缩放）：刺在它们的变动中保持锚点和方向（见[实验效果](#实验效果crumpleripplewhorlslipstream-与-thorn)中的 Thorn）。开启 Thorn 时，层级（Motion contrast、Pitch reactive）从不缩放轮换目标。
  - **分组**（`turnGroups`）：要画的字母（按 `letterSlots` 的计数）分成 5 个轮换组，每组由完整的字形编号组成，所以一个字形的所有出现一起轮换，一个组也不需要额外的几何计算。N 个要画的字母中，每组最多 ceil(N / 5) 个；字形按出现次数从多到少（次数相同时按字形编号的哈希排序）放进剩余空间最多的组，所以一个组的字母散布在整段文字中，而不是按阅读顺序排列；只有整个放不进任何组的字形才按出现拆开。字母少于 5 个时，有些组是空的。同一段字母只是排版改变时保持原来的分组。
  - **轮换**（`ThornTurns`）：每个字母显示它所在的组上一次轮到时取得的轮换状态，其余的值取它所在层级的值（`turnSets`）。上一次轮换显示到屏幕上、并且过了 250 ms（`THORN_TURNS.gapMs`）之后，按顺序轮到的下一个组如果自己的状态与实时轮换状态不同，就取得实时状态：种子或刺数不同、某个滑块相差至少半个闪烁摆幅（滑块行程的 5%），或某个滑块被声音放回了它自己的值。只要另有组的状态不同，状态没有不同或没有字母的组就放弃这次轮换（这次轮换什么都不改，只过去 250 ms）。所以每 250 ms 最多约五分之一字母的刺发生变化，每个字母的刺最多每 1.25 秒（5 × 250 ms）变化一次，与文字长短无关。
  - **闪烁限制：** 大的轮换（该组在文字中所占份额乘以它的轮换目标滑块移动的距离，新种子算一整个行程，达到滑块行程的 10%）和字母在层级之间切换一样，从同一份闪烁预算中扣；预算拒绝的轮换会等待（该组保持原状态），在下一次更新时再请求，从不丢弃。
  - **重新开始：** 声音开始驱动字母、Thorn 被打开、文字的字母改变（编辑文字，或换了会改变字形的字体或大小写；只改同一段文字的样式时保留分组）时，所有组立即取得实时状态，不算轮换，也不扣预算。添加或删除映射不会重新开始：它带来的变化按轮换送达。用手移动一个声音没有驱动的轮换目标时，所有组立即跟上，与没有声音时一样。
  - 标记、实时种子、状态和 Freeze 都使用共享实时值，而不是某个组的值。每个字母显示的仍是普通的、在范围内的滑块值和种子（它所在组的轮换状态加上它所在层级的其他值），所以仍然是滑块和种子输入框能调出来的结果；输出仍然只有 `M`/`L`/`Z`。一个实时帧的字母现在最多显示 15 组参数（3 个层级 × 5 个组）。这一帧的一次请求只为显示某组参数的字母的字形计算该组，并且总会带上共享的那组，用于显示它的字母的字形和选中的字形（以便统计；`FrameJob.within`）：最多 16 组。
  - 关闭 Thorn 时没有轮换：调度器的请求、提交和 Freeze 与以前完全相同（`tests/sound/neutral.test.ts` 固定了除 Flare 外的所有预设，Flare 的起始设置打开了 Thorn；`tests/sound/turns.test.ts` 测试轮换和 Flare）。
  - **实测**（Node，端到端，EB Garamond 187 像素，“Hello / This is / Ming”，中性的 Response，一组类似 Flare 的效果，与改动前的 develop 对比）：字母的刺每秒变化 7.2 次，以前是 283.9 次（算上 Distortion 和两个 Amount 在内的所有形状变化：7.4 次，以前是 299.7 次）；任意 250 ms 内刺发生变化的字母最多 3 个，以前是 15 个；同一个字母两次刺变化之间最短间隔 1331 ms，以前是 33 ms；文字块移动 0 像素；几何计算每秒占用 135 ms，以前是 340 ms；没有曲线。在真实浏览器中（无头 Chrome，Roboto，“Hello / This is / Ming”，15 个字母，Thorn 3 个锚点，加上 Crumple、Ripple 和 Distortion，映射为 Beat → Seed、Level → Thorn · Reach、Beat → Thorn · Anchors 和 Level → Distortion · Noise amplitude，42 秒的测试音轨）：8 秒内文字块只有 1 个位置，每 250 ms 最多 3 个字母变化，同一个字母两次变化之间最短 1533 ms，每秒 7.9 次变化，没有曲线，Live 30 fps。
- **实时调度**（`useLiveFrame` 和 `useLiveLetters`，各在 `App.tsx` 中调用一次）：已载入字体、文件正在播放或麦克风正在收音、Drive letters 打开、Strength 大于 0%，并且有映射作用在一个起作用的目标（滑块或种子）上时，声音就在驱动字母。没有载入字体时声音只是等待：什么都不动，标记保持隐藏，种子也不跳变。每个测量帧先让被驱动的种子前进（如果有跳变），再进行调制，但只有当新的实时参数和上一次发出的不同、当前没有几何请求在处理、并且距上一次至少 33 ms 时，才会把它交给几何计算。所以帧率随计算量变化，上限 30 fps。调度器先请几何 Worker 在一个请求里算好一个实时帧的字形（`geometryClient.prefetchJobs`）：先是画布上显示的字形的共享参数，再是强层级和弱层级字母所用字形的参数（有 Thorn 轮换时，共享参数只用于显示它的字母的字形和选中的字形，其余每组参数各用于它的字母的字形）。全部到齐后才把这一帧交给 React，每秒最多 30 次，所以每个实时帧只渲染一次、完整显示，不会混有两帧。画布上的吸附网格跟随实时的 Grid size，预览显示实时帧，状态栏的 View 一行描述的是当前显示的参数。SVG、PNG 和字体导出仍然使用滑块值（视频录下实时帧），Typography 中的 **Fit text** 和 **Free** 以及拖动自由位置的文字也一样：它们测量的是滑块值下的字母（`useDerivedGeometry.ts` 中的 `loadSliderScene`；声音驱动期间，滑块值需要的字形先在几何 Worker 中算好），所以实时帧不会影响文字的位置；声音驱动期间，文字块本身的位置也由滑块值下的字母决定，所以声音从不移动它（见[排版](#排版)）。声音停止驱动时（暂停、停止收音、Drive letters 关闭、Strength 为 0%、没有映射起作用，或字体被移除），画布立即回到滑块值和种子输入框里的值，标记和实时种子也随之消失。
- **闪烁限制**（`flash.ts` 中的 `FlashBudget` 和 `FLASH_LIMITS`，`live.ts` 中的 `FlashLimiter`）：所有被驱动的滑块和所有被驱动的种子（见上文）共用一份大变化额度，所以无论有多少个映射，声音每秒最多造成 3 次闪烁：任意 1.25 秒内最多 6 次大变化（边沿），稍晚到达屏幕的帧也守这个限制。被驱动滑块往回走的量加起来达到一个滑块滑道的 10% 或以上时，这一帧就算一次大变化：可以是一个滑块往回折返这么多，也可以是几个较小的折返加在一起。折返按显示出来的滑块位置（取整到档位之后）计算；同一测量帧里的大变化只算一次，声音停止驱动时的精确恢复算一次。额度用完时，正在往回走的滑块保持上一个值，直到额度空出来；其他滑块照常通过。保持的值都是滑块片刻之前给出的值，标记和 Freeze 使用的也是屏幕上的这些值。这个限制对屏幕上的每个字母都成立：字母按不同幅度反应时，一个滑块往回走的量取共享值和字母所显示的每个层级中最大的那个（保持共享值就保持了每个层级）；字母从一个层级换到另一个层级本身也算一次变化，从同一份额度中扣除，大小为每个换层级的字母在文字中所占的份额乘以它前后两个层级的滑块相差多少（达到一个滑块滑道的 10% 就算一次大变化）。这个变化既从屏幕上的层级算起，也从最近 250 ms 内显示过的每一帧的层级算起（`LIVE_LIMITS.switchSpanMs`），取较大者，所以一次换音分几帧到达屏幕时（音高经过平滑），只算它看起来的那一次变化；一次扣除了额度的变化之后，从显示它的那一帧起重新计算。额度用完时，每个字母保持它正在显示的层级。大的 Thorn 轮换也从同一份额度中扣，额度用完时就等待（见上面的“Thorn 轮换”）。
- **实时缓存：** 实时请求带有 `live: true`（`protocol.ts`）。一个计算请求带有一组 `jobs`，每个 job 是一组参数和它的字形；Worker 按顺序计算，每个 job 的结果用它自己的键发回，心跳消息写明键和字形，整个请求以一条 `done` 结束。Worker 把实时结果放进每款字体单独的、更小的缓存（600 个字形或 200 000 个点；`cache.ts` 中的 `glyphGeometry(…, live)`），页面保留屏幕上的一帧和正在计算的一帧的实时参数结果：最近四次实时请求中最多那次所需组数的两倍，至少 6 组（帧最多三个层级时），最多 32 组（`LIVE_KEPT_KEYS`；有 Thorn 轮换时一帧最多请求 16 组：字母能显示的 15 组，即三个层级乘五个组，再加共享的那组），最久没被请求的先丢（`geometryClient.ts`），所以一首歌从不挤掉正常编辑时的结果。只有共享参数的结果会在新结果算好之前代替字形显示。
- **实时值标记**（`src/components/LiveMarker.tsx`）：每个目标滑块都包在一个 `.live-slider` 里；声音驱动它时，轨道上一条细细的强调色竖线显示实时位置，并与滑块按钮应在的位置对齐。标记每秒最多更新约 15 次，对读屏软件隐藏。滑块本身保留自己的值。（种子则显示实时数字，见上面的“种子”。）
- **帧率：** 声音驱动字母期间，标签页和状态栏（在 **Microphone on** 之前）显示 “Live · N fps”，N 是几何计算每秒能跟上的实时结果数（1000 ms ÷ 从发出一帧到它最后一个结果的平滑耗时，包括所有层级，最多 30），所以实时值不变时它也保持稳定。它是几何计算的速率，而不是读取声音的频率（声音每个动画帧读取一次，见下文 `engine.ts`）。连续 2 秒低于 8 fps 时，标签页提示 “Too slow to follow the sound: try fewer effects or a shorter text.”（Motion contrast 或 Pitch reactive 大于 0 时提示 “Too slow to follow the sound: try fewer effects, a shorter text, or less Motion contrast and Pitch reactive.”）。
- **Freeze**（冻结；声音驱动字母时可用；其他时候以及录制视频期间用 `aria-disabled` 变灰，仍保留键盘焦点）：把屏幕上的共享实时值（标记所显示的值）写入滑块、把实时种子写入种子输入框（每个改变了的参数组更新一次，合起来算一步撤销），并让声音暂停（暂停文件或停止收音），所以冻结的样子会留在屏幕上，可以导出。反应更强或更弱的字母，以及所在 Thorn 轮换组还显示较早刺设置的字母，都改用共享值；它们的形状通常已经算好，所以切换是即时的；但有轮换组显示其他刺设置时，一帧只为显示共享值的字母的字形计算共享值，所以其他字形要到那时才计算。如果按下时共享实时值正好和滑块一致（例如两次鼓点之间），它只会暂停声音。SVG、PNG 和字体导出始终使用滑块值；声音驱动字母期间，Export 对话框会说明这一点，并指向 Freeze。视频则录下实时的样子（见[视频](#视频)）。
- **Response**（响应，位于 Mappings 之后的分组；`types.ts` 中的 `ResponseSettings` 和 `RESPONSE_LIMITS`）：六个滑块，各带一个 ⓘ，随会话保存，能像其他滑块一样撤销，预设不会改动它们：
  - **Sensitivity**（灵敏度，−24 到 +24 dB，每档 1，默认 0）：测量前加到输入上。
  - **Strength**（强度，0–400%，每档 1%，默认 100%）：把每个映射移动字母的幅度乘以这个倍数（滑块的和与种子的 Rate，见上文）。0% 时字母保持不动（声音停止驱动）；高于 100% 时，闪烁限制会更常压住往回的动作。
  - **Motion contrast**（动作对比，0–100%，每档 1%，默认 0）：让每个字母按自己的幅度反应（见上面的“字母”）。开启 Thorn 时，它不改变 Thorn 轮换目标（见上面的“Thorn 轮换”）。可能降低帧率。
  - **Release**（释放，20–1000 ms，每档 1 ms，默认 150 ms；原来叫 Smoothing）：声音过后读数回落得有多慢；读数上升总是立即的。Beat 和 Melody 脉冲回落的快慢也由它决定。
  - **Pitch reactive**（随音高反应，0–200%，每档 1%，默认 0）：近来旋律中的低音让左边的字母动得更多，高音让右边的字母动得更多（见上面的“字母”）；开启 Thorn 时，它和 Motion contrast 一样不改变 Thorn 轮换目标。它的 ⓘ 写着 “The low notes of the melody move the letters on the left more, its high notes those on the right, so a tune sweeps across the text. Follows the range of the last few seconds of notes. Needs a clear note, such as a voice or one instrument. Can lower the frame rate.”（旋律的低音让左边的字母动得更多，高音让右边的字母动得更多，所以一段曲调会扫过整段文字。跟随最近几秒内音符的音域。需要清晰的音，例如人声或一件乐器。可能降低帧率。）
  - **Melody tracking**（旋律跟随，0–200%，每档 1%，默认 0）：旋律每换到一个新音就加一些动作，即使响度不变；做法是把 Melody 脉冲加到每个滑块映射的特征上（见上面的“调制”）。
  - **Reset sound** 用一步撤销把六个值都恢复为默认值；它们都是默认值时按钮变灰。
- **Record**（录制，位于 Response 之后的分组）：见[视频](#视频)。
- **测试音轨：** `test-audio/sound-test.wav`（42 秒，16 位立体声，44.1 kHz，完全由程序合成）不提交到仓库：`npm run test-track`（`scripts/make-test-track.ts`，渲染 `scripts/test-track.ts`）会生成它，git 会忽略它；`npm run test-track -- out.wav` 写到别的位置。渲染结果是确定的，有一个测试会检查它的校验和。它的每一段对应一种读数。先是居中、左右声道相同的部分：只有底鼓（0–4 秒）、底鼓加踩镲（4–8 秒）、底鼓加一个渐强的和弦（8–12 秒）、静音（12–15.5 秒）、逐渐变弱的完整混音（15.5–21.5 秒）、只有每秒 16 下的踩镲（21.5–26 秒）。然后是每半秒一个音的单音旋律，A2 → A5 再回来（26–32 秒，用于 Pitch）；每半秒在最左和最右之间切换的踩镲，下面是居中的轻柔低音（32–38 秒，用于 Pan，它在约 ±0.5 之间摆动）；以及左右声道互不相关、逐渐减弱的宽声场噪声（38–42 秒；Pan 在这里保持居中）。

模块：

- `types.ts`：共用类型（包含所有特征、音高置信度和旋律音域的 `FeatureFrame`、`StereoSamples`）、`SOUND_LIMITS`（下面的测量参数和文件大小上限；分析器的 dB 范围和播放进度的更新频率在 `engine.ts` 中设定）、`SILENT_FRAME` 和初始状态；Response 分组的值：`FeatureSettings`（Sensitivity 和 Release，属于声音引擎）、带 `RESPONSE_LIMITS`、`NEUTRAL_RESPONSE` 和 `clampResponse` 的 `ResponseSettings`（Strength、Motion contrast、Pitch reactive、Melody tracking），以及 `SoundSettings`，即保存和撤销的全部六个值；`THORN_TURNS`（`groups: 5`、`gapMs: 250`；见上面的“Thorn 轮换”）。
- `features.ts`：`FeatureExtractor`，纯函数式（不依赖 DOM 和 Web Audio），所以可以用合成信号测试。每一帧接收分析器的频谱（fftSize / 2 个频点，单位 dBFS；第 k 个频点的中心频率是 k × 采样率 / fftSize）、时域采样（各声道混合后的），以及左右声道各自的采样；除了返回的那一帧，不分配任何内存。
  - **Level（响度）：** 去掉均值（直流偏移）后采样 RMS 的 20 log10，加上 Sensitivity；−60 dB 读作 0，0 dB 读作 1。加上 Sensitivity 后低于 −60 dB 的帧算作静音：所有连续特征回落到 0（Activity 的速度部分随起音移出时间窗口而回落），也不触发起音。
  - **Swell（缓变响度）：** 用自己的时间常数平滑的 Level，上升 300 ms、下降 2 秒，不受 Release 影响。
  - **频带：** **Bass**（20–250 Hz）、**Mids**（250–2000 Hz）、**Treble**（2000 Hz 到奈奎斯特频率）：中心频率落在该频带内的频点的能量（线性幅度的平方和），换算成 dB 并加上 Sensitivity。每个频带各自记录一个滑动最大值：遇到更大的值立即跟上，否则能量每 3 秒减半。频带在最大值处读作 1，在最大值以下 40 dB 处或 −68 dB 处（取较高者）读作 0。−68 dB 是换算到频带上的静音阈值：经 Blackman 窗处理的频谱里，频带能量比 RMS 电平低约 8 dB。所以即使另一个频带很响，低于静音阈值的底噪也读作 0。（早先版本的六个窄频带已去掉；这三个就是原来的 Low、Mid 和 High。）
  - **Brightness（亮度）：** 频谱质心（20 Hz 到 20 kHz 频点按幅度加权的平均频率，所以高采样率下的超声底噪不计入），按对数刻度，100 Hz → 0，8 kHz → 1。
  - **Pitch（音高）：** 在降采样到最多 24 kHz（每段取平均）的采样上用 YIN 求基频：在 1/1760 秒到 1/55 秒之间，取第一个累积均值归一化差值低于 0.15 的延迟，继续走到它的局部最小值，再用抛物线插值细化。55 Hz 读作 0，1760 Hz 读作 1，按对数刻度（5 个八度）。找不到这样的延迟的帧（无音高：噪声、鼓）保持上一个音；静音时归 0。它双向都以 30 ms 跟随，静音时按释放时间回落到 0。与它一起给出的还有**音高置信度**（0–1）：Pitch 有多确定，音很轻或不清楚时较低，无音高或静音时为 0。它不是映射可以跟随的特征；Melody 和 Pitch reactive 会用到它。与它一起给出的还有**旋律音域**（`pitchLow` 到 `pitchHigh`，在 Pitch 的 0–1 上；`followRange` 和 `melodyRange`），Pitch reactive 就把音高放在这个音域里：从 Melody 近来稳定下来的最低音到最高音。新的最低或最高音以 150 ms 的时间常数（`melodyRangeAttackMs`）把它撑开，两端则以 8 秒（`melodyRangeReleaseMs`）向正在听到的音（两个音之间则是上一个音）收拢；距上一个音超过 8 秒的第一个音让它重新开始，成为围绕这个音的一个八度。它在所含的音周围至少一个八度宽（`melodyRangeMinSt`，12 个半音），并保持在 0–1 之内。重新开始后仍在稳定中的音（滑进来的音）、Melody 离开其稳定音的那些帧（鼓击、八度误判、颤音），以及距刻度两端一个半音以内的音都不计入（和弦或完整混音会以很高的置信度读在 55 Hz 附近）。听到第一个音之前它读作 0 和 1（Pitch 的全部），它同样不是映射可以跟随的特征。
  - **Melody（旋律）：** 每个新音一次脉冲。音高离已经稳定下来的音至少半个半音、并在那里保持 70 ms 时，Melody 跳到这次移动的大小（2 个半音时为满）乘以音高置信度，之后按释放时间回落。持续的音、5 到 7 Hz 下最多约 ±80 音分的颤音、噪声、持续音下的八度误判或鼓点，以及静音后的第一个音（包括滑进这个音的短暂滑音）都不产生脉冲。已知限制：幅度大而慢的颤音仍可能产生几次脉冲，短于约 200 ms 的音可能漏掉。
  - **Release（释放）：** 每个连续特征用一阶滤波器跟随目标值，a = 1 − exp(−dt / τ)，上升时 τ 为 10 ms，下降时为 Release；Swell 和 Pitch 有自己的时间常数（见上），Pan 上升和下降都按 Release。重置后的第一帧直接取目标值。
  - **Beat（节拍）：** 两个基于频谱通量的起音检测器。频谱通量是压缩幅度 ln(1 + 1000 g m) 的上升量之和，其中 g = 10^(Sensitivity / 20)：一个检测器算 20 Hz 以上的频点（全频带），另一个只算 20–150 Hz（底鼓检测器），因为宽频声音下底鼓可能淹没在全频带通量里。检测器的通量超过最近一秒的中位数 × 1.5（底鼓检测器为 × 3，因为它的频点很少，稳定的噪声也会让它跳动）再加一个很小的固定下限（`fluxFloor`、`kickFluxFloor`），同时超过它上一次起音通量的一半（以 120 ms 的时间常数衰减，所以军鼓、拍手或混响的噪声尾巴不会再次触发），距它上一次起音至少 100 ms，当前帧不是静音，并且已经积累了至少 250 ms 的历史（所以重置后不会立刻触发）时，就触发一次。此外还必须通过一道能量门（`onsetRiseDb`、`onsetRiseWindowMs`、`onsetRiseBandsHz`、`onsetRiseResetDb`）：从 20 Hz 起每个倍频程频带的能量（加上 Sensitivity 后的 dB，不低于静音阈值）与该频带最近 100 ms 内的最大值比较，只有检测器所听的某个频带比它高出至少 2 dB 时，检测器才会触发（底鼓检测器听起点低于 150 Hz 的频带，全频带检测器听所有频带）。频带一旦比之前的记录低了 12 dB，那些记录就不再算数，所以声音在两次敲击之间消失后，和第一次一样响的第二次敲击仍然算数。没有这道门时，泛音丰富的持续低音（锯齿波或嗡嗡的贝斯）因为通量与帧率形成拍频，会让 Beat 每秒触发 5–11 次；现在它不再产生节拍，而它上面的底鼓和踩镲照样能检测到。已知的限制：被同一倍频程里更响的声音盖住的敲击（比低音音符小 12 dB 的底鼓）会漏掉。每次底鼓也会触发全频带检测器（仍受它的 100 ms 间隔限制），所以两个检测器都听到的一次敲击只算一次起音（帧里的 `onset`，种子按它计数）。起音每秒最多判断约 60 次（在刷新率更高的屏幕上，与大约 1/60 秒前的频谱比较），所以在任何刷新率下这些下限的含义都相同。两帧间隔超过 500 ms（标签页被隐藏过）时，起音历史重新开始，但平滑和频带最大值保留。特征 **Beat** 是脉冲：任一检测器触发的那一帧为 1，之后按释放时间指数回落；它取两个检测器脉冲中较大的一个，因为离上一次起音不到 100 ms 的底鼓不算新的起音，但仍会让它自己的脉冲重新开始。
  - **Activity（活跃度）：** 声音有多忙，取两个读数中较大的一个，一起平滑。**Change（变化）：** 最近一次判断起音时的全频带通量比全频带检测器最近一秒的中位数高出多少，与最近这种高出量的最大值相比（这个滑动最大值像频带的最大值一样每 3 秒减半），但比较的基准从不低于 `fluxFloor`，也不低于这一帧压缩后频谱的四分之一（通量所比较的那些压缩幅度之和）；静音时它回落到 0。中位数去掉了持续噪声始终带有的通量，四分之一的下限让持续声音自身的抖动无论持续多久都保持很低：持续的声音接近 0，纯音和噪声都一样（110 Hz 锯齿波、和弦、白噪声或粉红噪声持续 25 秒都低于 0.15；55 Hz 锯齿波的嗡声与帧率形成拍频，约为 0.28）；安静之后的起音很高；响亮噪声之上的起音只显示一点。**Pace（速度）：** 最近 2 秒内的起音数，换算成每秒次数，再除以 8（每秒 8 次读作 1）。Activity 取较大者而不是平均值，因为平均会把范围减半、永远到不了 1：一次敲击立刻读得很高，快速的节拍让它在两次敲击之间也保持在高位（测试音轨上只有底鼓时约 0.38，加上踩镲时 0.91–1）。
  - **Pan（声像）：** 左右声道 RMS（去掉直流偏移）的 (R − L) / (R + L)，从 −1（左）到 +1（右）。静音时、或没有两个声道时读作 0。文件按立体声测量；麦克风通常是单声道，所以读作居中。（早先版本的立体声宽度已去掉。）
- `engine.ts`：`SoundEngine`，以及页面上唯一的实例 `getSoundEngine()`。
  - 一个 `AudioContext`，在第一次需要它的用户操作中创建（选择文件或来源、Play、Start listening），由 Play 和 Start listening 恢复运行，没有播放也没有收音 2 秒后暂停。来源先接到一个 20 Hz 高通滤波器，去掉被测量信号里的直流偏移（不影响播放）。之后，一个 `AnalyserNode` 接收各声道混合后的声音（44.1 和 48 kHz 下 FFT 大小 2048，88.2 和 96 kHz 下加倍，使分析窗口保持约 43 ms；本身不做平滑；−100 到 0 dB）；另有一条立体声支路为 Pan 测量：一个按扬声器规则输出正好两个声道的增益节点（单声道变成完全相同的左右声道，多于两个声道时混合成两个）、一个声道分离器，以及左右各一个分析器（FFT 大小相同，不做平滑）。每次切换来源或换新文件时重置特征提取器。
  - **读取一帧：** 三个分析器是先后读取的，音频线程可能在两次读取之间渲染（在 Chrome 中最多每 300 帧有一次），让其中一块数据稍稍落后，单声道来源在这一帧就可能偏向一侧。所以每一帧都会检查混合后的采样是否等于左右采样的平均值，不一致就重读，最多 3 次；都不一致时，Pan 使用上一次一致的左右采样。多于两个声道的来源永远不会一致（分析器按别的权重混合），所以保持一帧之后，直接使用读到的采样。
  - **文件：** 在代码中创建（不放进页面）的 `HTMLAudioElement` 播放一个对象 URL（`URL.createObjectURL`），经 `MediaElementAudioSourceNode` 送入测量支路和扬声器。超过 512 MB 的文件和空文件（0 字节）不读取，直接拒绝。播放进度通过 `timeupdate` 更新（每秒约 4 次），从不逐帧更新。
  - **麦克风：** 调用 `getUserMedia`，关闭回声消除、降噪和自动增益，只接到测量支路，从不接到扬声器，所以不会产生回授。只有点 Start listening 才会打开，选择来源时从不打开。需要安全页面（https 或 localhost）。Stop listening、切换来源、设备被拔出以及关闭页面（`pagehide`）都会停止所有音轨。
  - **录音分支**（`startRecordingAudio`、`stopRecordingAudio`）：录制视频时，正在运行的来源（听到的文件声音，或麦克风）还会经过一个 `DelayNode`（延迟限制在 40–400 ms，每次录制设定一次）送进一个 `MediaStreamAudioDestinationNode`，它的音轨就是视频的声音。这条支路不接扬声器，所以你听到的声音不变。同一时间只有一条分支；录制结束时由录制器断开，换新文件、释放它所接的麦克风以及 `dispose` 也会断开它。
  - 文件播放或麦克风收音期间，每个动画帧都测量特征；停止时发出一帧静音，让电平表归零。这些帧来自 `requestAnimationFrame`，所以标签页被隐藏或被遮住时没有帧，字母不再跟随声音，直到标签页重新显示（录像在标签页被隐藏时本来就会停止）。连续 3 秒没有声音时，状态会报告（“No sound detected.”）。
  - 错误类型：`unsupported`、`decode`、`empty`、`too-large`、`permission`、`no-device`、`device-busy`、`mic-connect`（麦克风已打开，但浏览器无法把它接到分析器上）、`mic-ended`（收音时麦克风停止了：被拔出或权限被收回）和 `insecure`，在标签页中各有各的提示。麦克风被占用或打开过程被中止（`NotReadableError`、`AbortError`）时算作 `device-busy`；打开麦克风时其他意外的错误算作 `unsupported`。
- `useSound.ts`：`useSoundEngine`（操作）、`useSoundState`（`useSyncExternalStore`；只在状态变化时重新渲染，不逐帧渲染）和 `useSoundFrames`（每测量一帧调用一次的回调）。
- `mapping.ts`：`FEATURES`（每个特征带有名称、分组，以及它是否双向、在种子上是否按起音计数）、`FEATURE_GROUPS`、`featureById` 和 `featureValue`；`TARGETS` 和 `targetById`（每个目标带有类型 `slider` 或 `jump`、范围、档位、`get` / `set`、`toSlider` / `fromSlider`、`inactive`，即它当前不起作用的原因，以及 `activate`，即让它起作用的改动和提示）；`applyPatches`、`seedAfter`、`Mapping` 和 `modulate`（它应用 Strength 和 Melody tracking；Motion contrast 和 Pitch reactive 按字母起作用，从不在这里）。纯函数式：不依赖 React、DOM 和 Web Audio。
- `jumps.ts`：`JUMP_LIMITS` 和 `JumpTracker`：根据测量帧计算被驱动种子的跳变次数（每个 Rate 乘以 Strength），每个跳变帧都从共用的闪烁额度中扣除。纯函数式：不依赖 React、DOM 和 Web Audio。
- `letters.ts`：按自己的幅度反应的字母（见上面的“字母”）：`letterSlots`（排好的文字里的字母，带每个字母在文字块中的横向位置和它在文字中所占的份额）、`contrastGain`、`pitchPlace`（音高在旋律音域中所处的位置，左 0 右 1）、Pitch reactive 的权重（围绕这个位置的钟形）、`letterLevels`（一个设置下的三个层级，两个控件都为 0 时为 null）、`assignLevels`（带滞回）、`levelPosition` 和 `levelSets`（每个层级的滑块值）、`switchSwing`（字母换层级造成的变化有多大）、Thorn 轮换（见上面的“Thorn 轮换”：`isThornTarget` 和 `isTurnTarget`、`turnGroups`、带 `thornState` 和 `withThornState` 的 `ThornState`、`thornDiffers`、`turnSwing`（一次轮换有多大）、`ThornTurns` 和 `turnSets`），以及 `buildLetterFrame`、`lettersOn` 和 `levelKeyAt`（每个字母显示哪组参数）。纯函数式：不依赖 React、DOM 和 Web Audio。
- `flash.ts`：`FLASH_LIMITS` 和 `FlashBudget`，即被驱动的滑块（`FlashLimiter`）和种子（`JumpTracker`）共用的那一份闪烁额度。纯函数式：不依赖 React、DOM 和 Web Audio。
- `mappingStore.ts`：映射列表、响应值（Strength、Motion contrast、Pitch reactive、Melody tracking）和 Drive letters，放在 React 状态之外的一个小 store 里，用 `useMappingState` 读取（页面打开期间跟随 `prefers-reduced-motion` 的变化；`replace` 载入预设的各行，不动响应值；`restore` 放回保存的或撤销后的映射；`setResponse` 截断取值，每次拖动滑块记录一步撤销；`restoreResponse` 放回保存的或撤销后的值）；`MAPPING_LIMITS`。
- `src/state/sliderScales.ts`（不在 `src/sound/` 里）：`SLIDER_RANGES`（每个线性滑块的范围和档位，按目标 id 索引）、`sliderRange`、`TOLERANCE` 和它的对数刻度换算，以及 `THORN_REACH` 和 Thorn 的 Reach 的立方换算（`reachToSlider`、`reachFromSlider`、`roundReach`、`reachPercent`、`reachReadout`），控件和 `mapping.ts` 都从这里读取。
- `presets.ts`：`PRESETS`，每个预设带有名称、它的 ⓘ 里显示的一行说明、起始值和它的映射；以及 `presetSettings`，给出 Load 之后的结果：设置（Geometry 和 Experimental 的每个分组恢复默认、保留种子，再设上起始值）、改变了的分组，以及提示。纯函数式：不依赖 React 和 DOM。
- `live.ts`：`LiveScheduler`（帧调度、种子的跳变、字母的层级、Thorn 轮换，以及从测量帧到提交的延迟，可通过注入依赖测试）和 `FlashLimiter`（带 `LevelSpread`，即字母所显示的层级）；`useLiveFrame`（页面上的调度器：给画布的实时参数和字母的层级）、`useLiveLetters`（把当前显示的文字的字母告诉调度器）、`liveLatencyMs`（用于视频的音频延迟）、`useLivePosition`（单个目标的标记；只在取整后的位置变化时重新渲染）、`useLiveSeed`（单个种子的实时值，供 `LiveSeed` 使用）、`useLiveStatus`（driving、fps、slow、differs；只在其中之一变化时重新渲染）、`useLiveDriving`（只有 driving）和 `freezeLive`。
- **隐私：** 不联网。文件通过对象 URL 在浏览器中读取，从不上传；麦克风的声音被测量，从不回放，而且只在收音期间打开麦克风。只有在打开 **Include audio** 录制视频时，它才会被录进视频，而这个文件保存在你的电脑上，从不上传。
