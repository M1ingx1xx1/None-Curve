# None-Curve

**English** · [中文](README.zh.md)

An experimental web app for turning font curves into editable polygon shapes. Load a font, type some text, and watch every letter rebuilt from straight lines as you adjust the controls. Make outlines faceted, square, snapped to a grid, or roughened, then export a glyph or your text as SVG, or the glyphs as an OpenType font, or record a video of the text moving with a sound. Everything runs in your browser; fonts and audio are never uploaded.

**New here and not a developer?** Read the **[User Guide](docs/USER_GUIDE.md)** — it explains every part of the screen and every control in plain language.

## Running the app

- **Online:** `https://m1ingx1xx1.github.io/None-Curve/` once the `main` branch is deployed (see [Deploy to GitHub Pages](#deploy-to-github-pages)).
- **Locally:** requires Node.js 20.19 or newer (22 recommended).

```bash
npm install       # install dependencies
npm run dev       # development server: http://localhost:5173/
npm run build     # type check (app, tests, and scripts) + production build into dist/
npm run preview   # preview the production build: http://localhost:4173/None-Curve/
npm test          # fast test suite (about 15 s); see Tests below
```

## Interface

```text
┌────────────────────────╥───────────────────────────────────────────────────┐
│ Tools                  ║ Result canvas                                     │
│ Import · font info     ║ shows only the input text                         │
│ Geometry (scroll)      ║                                                   │
╞════════════════════════╩═════╦═════════════════════╦═══════════════════════╡
│ Typography / Glyphs / Color  ║ Text input          ║ Preview + Blur/Invert │
└──────────────────────────────╨─────────────────────╨───────────────────────┘
```

Double lines are drag handles. Each one only moves the border between its two neighbours, so they always add up to the same size: the top and bottom rows always fill the window between the header and the status bar (no page scrolling), the tools and the canvas share the top row's width, and in the bottom row the Typography / Glyphs / Color tabs, the text input, and the preview always add up to the row's width (minimum widths 260, 180, and 200 px). Every handle is the 1 px divider itself (in the quiet border colour, like the header and status bar edges), with an invisible 9 px grab area. Drag a handle, or focus it and use the arrow keys (Home / End jump to the limits); double-click resets it. Every area keeps a minimum size, and the splits are remembered in the browser. The top and bottom rows are split independently, so their column borders need not line up.

- **Header:** the file status and **Export…**. Undo and redo have no buttons; they are keyboard shortcuts (see [Saving and undo](#saving-and-undo)). While a video records, it shows "Recording 0:12" with a Stop button, and afterwards how the take ended (see [Video](#video)).
- **Top left — tools:** **Import** and the font information come first, then the **Geometry**, **Experimental**, and **Sound** tabs. **Geometry** holds every geometry parameter (flattening, squaring, anchors, grid & angles, distortion) in pipeline order, then Random anchors; **Experimental** holds effects that run after it and can be on together (Crumple, Ripple, Whorl, Slipstream, Thorn); **Sound** plays a local audio file or listens to the microphone, shows live meters, and moves the sliders of the other two tabs with the sound through mappings, or makes their seeds jump, and records a video; a driven slider keeps its own value and shows a thin marker at its live value, and a driven seed field keeps its own seed and shows the live seed beside it (see [Sound](#sound)). The chosen tab is remembered in the browser. Parameter statistics refer to the selected glyph. Controls that currently have no effect are greyed out: all of Curve flattening while Random anchors are on, and the random seed at 0 % randomness. Explanations are folded behind an ⓘ button next to each label (click to open, so it also works with the keyboard; the text stays the control's screen-reader description while folded); **Show all explanations** above the panel's content opens them all (the Typography and Color tabs included) and is remembered in the browser. Warnings, statistics, and notes about why a control is disabled are always shown.
- **Top right — result canvas:** shows the canvas (artboard) with the text from the input, set with the current font, all parameters, the Typography settings, and the colours. Below it, **Canvas size** opens and closes a drawer with the canvas size (see [Canvas size](#canvas-size)); the drawer's state is remembered. Its outline and layer controls (Original / Flattened / Compare, Fill, Skeleton, Vertices, Metrics), zoom, and pan apply to the canvas only, except **Fill**: off, the preview and the SVG, PNG, and video exports draw outlines only too (see [Outlines only](#outlines-only-fill-off)); the preview always shows the export (see [Text preview](#text-preview)). Each glyph's click target is its column (advance width by ascender to descender) plus the letter itself, so small text is easy to hit; a zero-width mark (such as a combining accent) has no column, only the letter. Without Thorn, the letter is the outline drawn in the current view. With Thorn (Experimental) on, it is an invisible copy of the letter's original outline, flattened into straight segments as Curve flattening draws it, and the drawn outline (thorns, Ripple's petals, and Slipstream's trails included) never catches the pointer: a click or drag on a thorn goes to whatever lies behind it, such as another letter, the text block with Free position, or the empty canvas, where a drag pans. So clicking a thorn away from its letter does not select that letter. Clicking a glyph selects it (the statistics follow it) and recolours every copy of it (hovering does the same) with a highlight colour computed from the text and background colours: among colours that stay readable on the background (at least the text's own contrast, up to 4.5 : 1, and never below 3 : 1), the one that differs most from the text colour in hue and chroma (OKLab), preferring vivid colours, penalising lightness that fades toward the background, and staying within 40° of the palette's hue (90° when a text that is already vivid leaves too little room; the text's hue, otherwise the background's, otherwise orange). Black on cream paper highlights in vermilion; a coloured text gets a vivid neighbouring hue. Clicking empty canvas (not the end of a drag) or pressing Escape clears the highlight; the statistics keep showing the last selected glyph, which the **Statistics** line at the top of the Geometry panel names (character and code point). The preview never shows the highlight.
- **Bottom left — text tools:** three tabs (remembered in the browser; arrow keys move between them; all stay loaded, so switching keeps local state): **Typography** — how the text is set on the canvas (see [Typography](#typography)); **Glyphs** — see below; **Color** — the text and background colours.
- **Glyphs tab:** a searchable grid of every character the font maps, used as an inserter: clicking a character inserts it into the text at the cursor (replacing selected text) and selects that glyph. Before the text box has been focused, characters are appended. Glyphs without a character (ligatures, alternates) and control characters are not listed, since they cannot be typed. When the glyph list is narrower than 280 px, the cells shrink and show only the character; the code point labels return above that width (the code point stays in each cell's tooltip).
- **Bottom right — input and preview:** a compact multi-line text input (letter case toggles **AA** / **Aa** / **aa** right of the Text title, sample texts in a menu, Clear, character count, kerning status, missing characters); then the SVG export itself, drawn small (cut to the canvas edges; see [Text preview](#text-preview)), with its own **Blur** slider (0–12 px in steps of 0.1) and an **Invert** button that swaps the text and background colours. Blur and Invert only affect this view unless **Export the preview look** is ticked — a squint test for the overall shape. A handle between the two parts moves the border (default 40 / 60).
- **Status bar:** the font status, the selected glyph, and the current view (with the selected glyph's vertex count, followed by "(simplified)" when the Experimental vertex budget simplified it; see [Folds](#experimental-crumple-ripple-whorl-slipstream-and-thorn)); while Sound drives the letters, **Live · N fps** (the live frame rate); while the microphone is listening, **Microphone on** (visible from every tab), and **No microphone** if it stopped on its own (unplugged or access withdrawn); at its right end, **Reset all** (an icon button with a turning arrow; see [Saving and undo](#saving-and-undo)) and a small light / dark switch for the interface. Every visit starts with the system setting (`prefers-color-scheme`) and follows it when it changes; a choice there lasts for the visit and is not stored. The theme tokens are CSS `light-dark()` values, switched by `color-scheme` on `<html data-theme>`. The canvas keeps the Color settings in both themes.
- **Sliders and number boxes:** every slider has a number box showing its value in the unit its label gives (%, °, % em, u, px, ms, dB): in the slider's head on the Geometry, Experimental, and Sound tabs, beside it in Typography and Canvas size, and next to the preview's Blur. Typing a value commits it on Enter or when you leave the box (Escape puts the old one back), clamped to the slider's range and rounded to its step (`SliderNumber` and `NumberField` in `src/components/`). The steps are fine (NOCUR-63): 1 % for shares, 1 % of the em for sizes, 1° for angles, 1 font unit for distances (0.1 for Anchor reduction and Noise frequency), 1 for counts; the box is the way to set a value exactly. Tolerance and Thorn's Reach keep their logarithmic and cubic sliders; their boxes take the value itself (font units in hundredths, rounded as the slider rounds; % of the canvas to 0.01 %).
- Desktop browsers only: there is no phone or narrow-screen layout. A narrow window keeps the same layout: the panes shrink to their minimum sizes, and below that all shrink alike.

### Canvas

- Outline view: **Original** (font curves), **Flattened** (final polygon), **Compare** (final polygon with the original curves overlaid as a dashed line). The current view is shown in the canvas corner and the status bar.
- Layers: **Fill** (off = outline stroke; the preview and the SVG, PNG, and video exports follow it, the font file is always filled), **Skeleton** (original on-curve anchors as squares, off-curve controls as hollow circles, and handles; TrueType's implied on-curve points appear as anchors), **Vertices** (final polygon vertices as green dots), and **Metrics** (ascender, cap height, x-height, baseline, descender, advance width).
- Zoom with the mouse wheel or `+` / `−`, pan by dragging or with the arrow keys (canvas focused), `0` or **Fit** to reset. The preview (bottom right) is always fitted and is not interactive.
- All layers apply to every glyph of the text on the canvas; the preview shows none of them. Only glyphs inside the visible area are drawn; a glyph whose thorns reach into view counts as inside, so long thorns do not pop in and out while panning. Skeleton points and vertices appear once an em is at least 48 px on screen; below that the canvas asks you to zoom in, so long texts stay readable. Metric labels are drawn on the first visible line only.

### Canvas size

The text is set on a canvas (artboard) of a fixed pixel size; zoom 1 fits the whole canvas. The background colour fills the whole view. Outside the artboard (the pasteboard) it is 7 % darker (6 % lighter on a dark background) and carries a screen grid (every 24 px) in black on light backgrounds and white on dark ones, at the opacity that gives a contrast of 1.3 : 1 with the background — the same visibility in every palette, whatever the text colour (`gridLineColor` in `src/specimen/color.ts`; the snap grid of Grid & angles uses 1.5 : 1); inside, the artboard looks exactly like the export. The grid fades in inside the artboard only while it helps: while dragging the text (Free position) or at 200 % zoom and above. A soft shadow lifts the artboard off the pasteboard — dark on light backgrounds, a light glow on dark ones; its 1.5 px outline (interface mint, never the text colour) is currently transparent (`.pasteboard`, `.artboard-grid`, and `.artboard-frame` in `src/styles.css`); the metric guides are drawn in the text colour too. A transparent background shows as a checkerboard of the background colour and the same tinted with the text colour, so the text stays readable. The drawer below the canvas holds:

- **W** / **H**: canvas width and height, 100–4000 px in steps of 1 (slider or number box; the box commits on Enter or when you leave it, clamped to the range).
- Aspect presets **1:1**, **4:3**, **16:9**, **4:5**, **3:2**, **3:4** keep the width and set the height (or keep the height if that would exceed the range); the matching preset is highlighted. **Swap** exchanges width and height.
- **1×–4×**: export multiplier. A PNG is width × multiplier by height × multiplier pixels with the same layout, so higher multipliers are sharper.
- With Thorn on, **W** and **H** also set how far the thorns reach in em (Reach is a share of the canvas diagonal; see [Experimental](#experimental-crumple-ripple-whorl-slipstream-and-thorn)), so changing them recomputes the letters; the multiplier does not.

Text that runs past the canvas edge stays visible on the canvas with a warning ("The text runs past the canvas edge and will be cut off in the preview and in exports. Try Typography → Fit text."); the preview and the exports are cut to the canvas. The warning measures the letters without their Thorn tips (`textOverflows` in `src/specimen/artboard.ts`): thorns may reach past the canvas on purpose, show on the pasteboard, and are cut off at the canvas edge in the preview and in SVG and PNG exports without a warning. While Sound drives the letters, the warning measures the letters at the slider values, the ones that place the block (`placement` from `useGeometry`; see [Typography](#typography)), not the live ones: a live letter that the sound warps further than the sliders do can run past the canvas edge without a warning, and is then cut off in the preview and in a video (the canvas still shows it in full).

### Typography

`src/specimen/artboard.ts` and `src/specimen/scene.ts`. These settings change the layout and the SVG/PNG export, not the glyph geometry or the font file, with one exception: with Thorn on, **Size** (like the canvas size) sets how far the thorns reach in em, since Reach is a share of the canvas (see [Experimental](#experimental-crumple-ripple-whorl-slipstream-and-thorn)), so changing it recomputes the letters.

- **Size** (4–1000 px, default 48): the em in canvas pixels; changing the canvas size does not change it. **Fit text** sets the largest whole-pixel size at which the outlines' box, slant included, fits inside the margin on both axes.
- **Margin**: the position anchors and Fit text keep 25 canvas pixels between the outlines' box and every canvas edge, whatever the font size (`EDGE_MARGIN_PX` in `src/specimen/artboard.ts`). There is no control for it.
- **Thorns do not count for layout.** Fit text, the position anchors, Free, and the overflow warning measure each letter as it was before Thorn: its ink box before Thorn's roots, tips, and refraction (`PolygonGlyph.layoutBox`) and, for slanted text, the convex hull of that same letter (`PolygonGlyph.layoutHull`) slanted point by point, so at any slant the text is placed, fitted, and flagged exactly as with Thorn off (the box's slanted corners, which reach further, stand in only where a glyph has no hull). They are collected as `SpecimenScene.body` in `src/specimen/scene.ts`, so thorns never move, shrink, or block the text and may run past the canvas edge. Everywhere in this section, "the outlines' box" means this box; without Thorn it is the outlines' own.
- **Sound does not move the text.** While Sound drives the letters, the block is placed by the letters at the slider values (the slider scene), not by the live ones (`placementScene` in `src/specimen/artboard.ts`, used by `useGeometry` in `src/state/useDerivedGeometry.ts`), and the live letters are drawn at that place. Both have the same lines and pens (they come from the advances); only the box measured on the outlines differs. So the block stays exactly where it is without Sound, whatever the effects, seeds, presets, or Response settings do to the live outlines. The slider letters are usually kept from normal editing; when the sliders, text, font, or typography change while Sound drives, the glyphs still missing are asked for once those have rested 200 ms (`SLIDER_SCENE_DELAY_MS`), so a dragged slider asks once, not on every frame. Until they arrive, the block keeps the slider-based place it last had for the same shaped text; with none, the live letters place it (as before). The overflow warning measures the slider letters too (see [Canvas size](#canvas-size)), so a live letter warped further than they are can run past the canvas edge and is cut off in the preview and in a video. A video draws the live letters at the same place, so the block is still in videos too. Freeze writes the live values into the sliders, so the block may move once then. Without Sound nothing changes.
- **Tracking** (−200–1000 thousandths of an em, in steps of 1): added between glyphs on top of advances and kerning, not after a line's last glyph.
- **Line height** (0.5–3 ×): multiple of the font's line spacing (ascender − descender + line gap).
- **Slant** (−30°–30°): a skew around each glyph's own baseline (x′ = x + tan(slant) · y); positive leans right.
- **Align** Left / Center / Right (icon buttons): aligns the lines with each other inside the block.
- **Position**: where the block sits on the canvas. Nine anchors (a 3 × 3 grid: corners, edge middles, centre) place the outlines' box (slant included; not the line box, so side bearings and ascender space do not leave a gap) against the left margin, centred, or against the right margin, and against the top margin, centred, or against the bottom margin — the letters sit 25 px from the edges and corners. An anchor also sets **Align** to its column (left column left, middle column centre, right column right); Align can still be changed afterwards. The default is left, vertically centred. The chosen anchor (and Free when on) glows in the primary mint. **Free** lets you drag the text on the canvas by the letters' box or by any glyph's click target (drags that start elsewhere, such as on a Thorn tip away from both, still pan); the position is stored as a share of the room the canvas leaves beside and above the outlines' box, so the text stops at the canvas edges and stays inside when its size or the canvas changes. Pressing Free puts the text back at the default position and alignment (left, vertically centred) and then lets you drag it; pressing it again resets it there.
- **Letter case** (**AA** / **Aa** / **aa**, right of the Text title): **All caps**, **Title case** (first letter of every word upper case, the rest lower case), or **Lower**; press the active one again for the text as typed. The typed text is never changed; the canvas, the preview, the exports, and the font file's "Specimen characters" use the converted text.
- **Reset typography** restores the defaults (48 px, 0, 1, 0°, left-aligned, positioned left and vertically centred) and keeps the letter case.

### Color

Twelve presets (Charcoal — the default, dark text on paper — Off White, Kryptonite, Plum, Glowing Cyan, Acid Lime, Ember, Moonlit Purple, Chrome Pink, Cherry, Atomic Blue, Forest Moss), **Random** (a random readable pair, contrast ≥ 4.5 : 1), **Swap**, and custom **Text** and **Background** colours with a colour picker and a hex box (`#rgb` or `#rrggbb`). The contrast ratio is shown, with a warning below 3 : 1. **Transparent background** leaves the background out of SVG and PNG exports; the background colour is kept for Swap, Invert, and the checkerboard. Hover and selection on the canvas use a highlight colour computed from the text and background colours (see the result canvas above).

### Text preview

The input text is set with the final polygons from a shared geometry cache, so the canvas, the preview, and the exports always agree.

- Each glyph advances by its advance width plus kerning when the font has it (GPOS `kern` feature or a legacy `kern` table, applied through fontkit's layout). Ligatures are off so every character keeps its own glyph. Fonts without kerning data are labeled as such.
- Line height is ascender − descender + the font's line gap, times **Line height**. Spaces advance without drawing. Missing characters are drawn as dashed boxes on the canvas and listed in the text panel.
- Up to 1000 characters are shown. Each distinct glyph is processed once per parameter set (cache key: font, glyph, and all geometry parameters).
- **The preview** (bottom right; `src/components/ExportedArtboard.tsx`) draws the SVG export itself: the same frame, background, blur filter, group transform, and glyph paths that `specimenToSvg` writes, all from `specimenPaths()` in `src/export/svg.ts`. It shows straight-edged outlines rounded at the export's **Coordinate precision**, filled, or with **Fill** off stroked as the exports stroke them (see [Outlines only](#outlines-only-fill-off)), and never follows Original / Compare, Skeleton, Vertices, Metrics, the snap grid, or the missing-character boxes (those are canvas only); missing characters are blank advances, as in the file. A transparent background shows as a checkerboard. When rounding at that precision fails, the preview reads "Export would fail: …" with the reason. While Sound drives the letters it shows the live frame, each letter in its own shape when letters react by different amounts (Motion contrast, Pitch reactive; paths are built per polygon, not per glyph id); SVG, PNG, and font exports still use the slider values, and only a video records the live frame (see [Video](#video)). Rounded outlines are cached per polygon, and the preview is deferred (`useDeferredValue`), so the canvas keeps priority.

### Saving and undo

`src/state/persist.ts`, `src/state/history.ts`, and `src/state/reset.ts`.

- **Saved between visits** in `localStorage` (key `none-curve:session`, with a version number; about 2 KB), half a second after each change and when the page is hidden or closed: every setting (Geometry, Experimental, Typography, Color, and Canvas size), the canvas view's outline and layer buttons (not zoom or pan), the text (up to 10,000 characters), the preview's Blur and Invert, the export precision, the Sound mappings, the Sound tab's Response group (Sensitivity, Strength, Motion contrast, Release, Pitch reactive, and Melody tracking; an entry saved before they existed reads the defaults), the selected glyph (restored only in the same family and style), and the font. A Google font is downloaded again when the page opens; a local file cannot be reopened, so the canvas names it ("Last font: X. Import it again to continue."). On reading, every value is checked against the defaults, so a damaged or older entry never breaks the app (older effect and feature names are renamed). The current version is 2: a version 1 entry's Thorn **Reach** (a share of the em) becomes the same length as a share of the canvas diagonal, measured on that entry's saved text size and canvas with the diagonal counted as at most 256 em (as Thorn counts it), at most 100 % and rounded to 4 decimals; a Reach above 0 never drops below the slider's first step (0.01 %), so Thorn that grew thorns still does (`fromV1` in `src/state/persist.ts`); the entry's Sound rows on Thorn · Reach keep their depth. The canvas diagonal in em that Thorn reads is worked out from the settings and never saved.
- **Not saved:** Drive letters, the audio file or microphone, live Sound values, the video recording options (Format, Length, Include audio, Use the preview look), open dialogs, and the light / dark theme. (The pane splits, the chosen tabs, and Show all explanations were already remembered on their own.) Clearing the site's data starts fresh. Saving is per browser: with two tabs open, the last one to save wins, and Safari may clear it after 7 days without a visit.
- **Crash guard:** while the restored settings are first drawn, a mark (`none-curve:restoring`) is set. If it is still there on the next start, that visit closed while drawing (it may have crashed), so the settings and the view start at their defaults and the canvas says "The last visit closed while drawing, so its settings were not restored."; the text, mappings, and font are restored as usual.
- **Undo and redo:** ⌘Z and ⇧⌘Z on a Mac; Ctrl+Z, and Ctrl+Shift+Z or Ctrl+Y, elsewhere (keyboard only; there are no buttons). One history covers every setting, the text, the Sound mappings, and the Sound tab's Response group. A slider drag is one step (the Response sliders' too); typing is one step until a pause of a second; Clear, a sample text, and an inserted glyph are one step each, and so are preset Load, Freeze, **Reset sound**, importing a config file, and picking a target together with what it switched on. Live Sound frames are never undo steps. Not undone: the canvas view, zoom and pan, the glyph selection, the preview's Blur and Invert, the export precision, font imports, Drive letters, and the video recording options. In the text box and other text fields the field's own undo applies, and the shortcuts are ignored while a dialog is open. Up to 100 steps; the history is not saved between visits, and **Reset all** clears it.
- **Reset all** (the icon button just left of the light / dark switch in the status bar): puts the editor back to how it first opens, without asking. The font closes (an import in progress is dropped), and the selected glyph with it; the last visit's font is forgotten too, so the next visit does not reopen it. The text becomes the sample text again (the first sample, Lorem ipsum). Every setting (Geometry, Experimental with its seeds, Typography, Color, and Canvas size), the Sound mappings (none are left), and the Response group go back to their defaults, and Drive letters is on again (off when the system asks for reduced motion). The canvas view goes back to its start: the **Flattened** outline, the layers as at first open (Fill on; Skeleton, Vertices, and Metrics off), zoom 1 (the whole canvas in view), and no pan. A playing sound file pauses and the microphone stops listening; a loaded sound file stays loaded. The preview's Blur and Invert and the export precision (2) go back to their defaults, and the notices about a config import or the last visit are cleared. The interface theme, the pane splits, and the chosen tabs stay. It cannot be undone: the history's part goes back to `START_SNAPSHOT` and the history is cleared (`resetHistory` in `src/state/reset.ts`, which calls `UndoHistory.startOver`), so afterwards there is nothing to undo or redo; the reducer's `resetAll` action returns `initialState`, and `resetAll` in `src/App.tsx` does the parts outside the history. The button is disabled, with the tooltip "Everything is as the editor first opens", when there is nothing to reset (`isAtStart`): no font, the sample text, and every setting, the view, the Sound values, Drive letters, Blur, Invert, and the precision at their start. Otherwise its tooltip is "Reset all: closes the font and puts the text and every setting back to the start. Cannot be undone."

### Performance

- **Geometry worker** (`src/geometry/geometry.worker.ts`, `src/state/geometryClient.ts`): the pipeline runs in a Web Worker that opens its own copy of the font, so the page never waits on it. The selected glyph is computed first (its statistics), then the text's glyphs in reading order; results come back in batches every ~40 ms and are shown together (one re-render per 50 ms). A newer parameter set stops the older one between glyphs. Until a glyph's new shape arrives the canvas keeps its previous one, and the canvas badge shows "Updating N…" (while Sound drives the letters, live frames replace one another without the badge, which then counts only glyphs that have no shape yet). Results for the last four parameter sets are kept, so stepping back is instant (live sound frames are kept apart, so a song does not push these out; see [Sound](#sound)). Glyphs are computed only in the worker, never on the page (`src/geometry/workerCore.ts` holds the worker's logic). Every request has an id and ends with an answer, done or failed; the worker sends a heartbeat before each glyph; and going back to settings whose results are kept cancels the running request at once. A busy worker that stays silent for 60 s is stuck (the pipeline's own per-glyph budget keeps the slowest glyph to a few seconds, so only a fault gets there): the glyph it was on is marked failed ("Took longer than 60 s; try lighter settings"; exports leave it out with that reason), and the worker is restarted with the font sent again; after more than 3 restarts within 60 s, geometry stops until another font is loaded. When new settings no longer need a glyph that has already run for 750 ms, the worker is replaced at once instead of finishing it (at most once every 2 s, and never for a live Sound frame). If the worker cannot start, cannot open the font, or keeps failing or going silent, the glyphs fail and the canvas shows an alert: "The geometry worker could not open this font (…).", "The geometry worker could not start. Reload the page to try again.", "The geometry worker kept failing. Reload the page to try again.", or "The geometry worker stopped responding. Reload the page to try again." SVG and PNG exports use the worker's results and ask it for what is missing; a font file is built in a worker of its own (see [Export](#export)).
- **Text layout** is split into shaping (`shapeSpecimen`, rerun only for text or typography changes) and placing polygons (`placePolygons`, rerun as results arrive). Path strings and slanted extents are cached per polygon, and each glyph on the canvas is a memoised component, so a text that repeats a letter builds its outline once and unchanged glyphs are not drawn again.
- **Free position drag** moves the text with an SVG transform only; the position is committed once, on release, so dragging never re-renders the page.
- **Crossing checks** (`src/geometry/crossings.ts`), run by every step for every contour and retry, sweep segments sorted by x and compare only pairs whose boxes overlap, stop as soon as the count exceeds the original's, and count each contour's own crossings once. A 15 000-point contour (Anchor spacing 1) is checked in milliseconds instead of seconds. From 64 segments on, the sweep runs along y or a diagonal instead when the segments are less than half as long in total that way (`SegmentSweep`), so long edges side by side (a comb, Slipstream's streaks) are not compared pair by pair; what it finds is put back in x order. In the merge of overlaps (`src/geometry/overlaps.ts`), contours of 128 points or more get an index of horizontal strips (`RingIndex`) for the checks between contours and the inside tests. Checks between two contours (`src/geometry/contourLayout.ts`) first compare bounding boxes and only look at segments inside the overlap; pairs whose boxes are apart are skipped at once, and each pair's original arrangement is worked out once per step.
- **Bundle:** React sits in a chunk of its own (`vite.config.ts`), which stays cached across deploys that change only the app, and the Experimental and Sound panels load the first time their tab is opened.
- **Geometry cache**: least recently used entries are dropped beyond 4000 glyphs or 1 000 000 polygon points per font, so dense settings cannot fill memory. Live sound frames use a second, smaller cache (600 glyphs or 200 000 points per font), so they never evict these.
- Measured (production build, 1000 characters, Inter): each Tolerance slider step costs ~10 ms of page time (was ~90 ms), Random anchors at density 100 ~9 ms (was 260–690 ms); spacing 1 + grid 50 + 15° + distortion takes 48 ms for "@" (was 2.8 s); computing and rounding all 2691 Arial glyphs at spacing 1 takes 3 s with ~200 MB live memory.

## Fonts

### Local files

- Formats: `.ttf`, `.otf` (TrueType and CFF outlines), `.woff`, `.woff2`, and font collections (`.ttc` / `.otc`, such as macOS's Helvetica Neue, Avenir Next, or Futura), detected from the file's bytes rather than its extension.
- **Collections:** the style name in the font summary becomes a menu of the faces ("Face"). A collection opens on the upright face closest to Regular (weight 400, normal width; the earlier face wins a tie). macOS's hidden system faces (PostScript names starting with a dot) are not listed. The chosen face is part of the font's source, so the geometry worker opens the same one. Picking another face of the same file keeps the canvas zoom and pan, and the selected character when the new face has it; any other import resets zoom and pan and picks a default letter. Collections wrapped in WOFF or WOFF2 are not supported.
- Choose a file from **Import** or drop it on the canvas (a dropped `.json` file is read as a [config file](#config-file)). Files are read in the browser and never uploaded. Limit: 50 MB, collections included (Apple Color Emoji's `.ttc` is larger).
- Empty, unrecognized, and damaged files show distinct errors with **Retry**; the previously loaded font stays visible.

### Google Fonts

A CSS preview of a family has no outline data, so the app downloads the actual font file:

1. `GET https://fonts.googleapis.com/css2?family=<Family>:ital,wght@0,100;…;1,900` — the official CSS2 API, no API key. It returns only the styles that exist, one `@font-face` per subset. CORS is allowed.
2. `GET https://fonts.gstatic.com/s/<family>/<version>/<file>.woff2` for the chosen weight, style, and subset.
3. Parse the WOFF2 with fontkit. Only after this succeeds does the font become available.

Limits:

- **Catalog:** the full searchable catalog needs the Google Fonts Developer API key, which cannot be kept secret in a static build. The dialog offers a curated list of 15 families — Sans: Google Sans, Noto Sans, Archivo, Inter, DM Sans; Serif: EB Garamond, Baskervville, Bodoni Moda, DM Serif Display; Slab: Slabo 13px, Arvo; Mono: IBM Plex Mono, JetBrains Mono, Space Mono, DM Mono — any family name typed exactly as on fonts.google.com (case-sensitive), or a pasted Google Fonts URL.
- **Subsets:** Google splits families into per-subset files (latin, latin-ext, cyrillic, …). One subset is loaded at a time.
- **Variable fonts:** detected when several weights share one file. Every weight can still be chosen: the chosen weight is requested on its own, and Google then serves a static file made for that weight (correct style name and OS/2 weight). When Google still serves the variable file (Roboto Flex at 700, for example), the weight is applied on load: fontkit cannot vary WOFF2 files, so the WOFF2 is rebuilt as TrueType (`src/font/woff2.ts`: the decoded glyph table is re-encoded without hinting, every other table is copied) and instanced at that weight; the font panel then names the weight used. Other axes (`opsz`, `wdth`, …) stay at their defaults.
- **Colour fonts** (Nabla, Honk, Bungee Spice, the "Ink" families): only their plain outlines are read; fontkit's colour glyphs (COLR, sbix) are bypassed because it cannot read COLR version 1. A font whose glyphs are colour images only (Noto Color Emoji) loads with a warning that there is nothing to edit.
- **Fonts whose layout tables fontkit cannot read** (Iosevka Charon) are set one glyph per character with their advance widths, without kerning.
- Checked against the whole Google Fonts catalogue (1950 families): every family loads, and every variable family loads at a second weight with outlines that differ from the default.
- **Errors:** unknown families return HTTP 400 without CORS headers, which looks like a network error to the browser. A follow-up `no-cors` request tells "Google rejected the name" apart from "network / CORS / content blocker". Download and parsing errors are reported separately, all with **Retry**.

#### Pasting a Google Fonts URL

The URL is parsed by `src/font/googleUrl.ts` and never fetched itself — only the family and style are read and passed to the flow above.

| URL | What is read |
|---|---|
| `https://fonts.google.com/specimen/Roboto` | Family (`+` = space). Parameters such as `categoryFilters` or `preview.script` are ignored and listed. |
| `https://fonts.googleapis.com/css2?family=Roboto:ital,wght@1,700` | Family, weight, and italic from the first style tuple. A weight range (`wght@300..700`) leaves the weight to choose in the dialog. |
| `https://fonts.googleapis.com/css?family=Lato:300italic` | Legacy API: family and first style (`400`, `700italic`, `300i`, `bold`). |

- Only `https://` URLs on `fonts.google.com` and `fonts.googleapis.com` are accepted. Other hosts, look-alike domains, `http://`, credentials, ports, and other paths are rejected with an explanation.
- With several families or styles, the first is used and the dialog says so. `display`, `subset`, `text`, and tracking parameters are ignored and listed.
- Axes other than `wght` and `ital` (for example `opsz`, `wdth`) cannot be applied; the dialog says so, and they stay at their defaults.
- Missing styles fall back to the default rule (closest to 400), and the dialog names the style that will actually load.

## Geometry pipeline

```text
Original curves (frozen) → Flatten (or Random anchors) → Squaring → Anchor spacing → Anchor reduction → Grid snapping → Angle lock → Vertex distortion → Experimental (Crumple → Ripple → Whorl → Slipstream → Thorn) → final polygon
```

The order is fixed (`src/geometry/pipeline.ts`). Every parameter change reruns the whole pipeline from the original curves, so nothing accumulates, and turning a step off restores exactly the result of the steps before it. All distances are in font units and do not depend on canvas zoom. Distortion and the Experimental effects run last, so they move vertices off the snapping grid and off locked angles.

Every step validates each contour: it must keep at least three distinct points, its winding direction (so counters stay holes), non-zero area, and no more self-crossings than before. It must also sit against the glyph's other contours as before (`src/geometry/contourLayout.ts`): contours that were apart stay apart, a counter stays inside its outer contour, and nothing moves into another contour. Without this, a counter pushed out of its letter is filled as a solid shape beside it. Steps change contours one at a time and check each new contour against the others as they are at that moment, so the finished glyph is valid as a whole. Flattening itself is checked against a much finer flattening of the original curves (see below).

Before giving up, steps degrade gracefully: squaring uses the largest safe share of the amount (backed off slightly from the limit so later steps still have room), grid snapping and angle lock retry on progressively simplified copies of the contour and, for angle lock, finally as stair steps (each off-angle edge split into two allowed directions, no vertex moved), and distortion lowers the amplitude where the contour crosses, then overall. Only a contour for which every attempt fails keeps its previous shape; the panel reports reduced, simplified, and unchanged contours, and why.

Measured on the Latin glyphs of Arial, New York, and Georgia, the share of glyphs whose contours crossed each other or left one another went from 13–25 % to 0 with Angle lock 90°, 16–18 % to 0 with Random anchors at density 1, 25–31 % to 0 with Grid 200, 4–18 % to 0 with Distortion 200, and 0–5 % to 0 with Merge joined curves at 1 segment. Across 6480 random parameter combinations on four fonts, no glyph has a new crossing, within a contour or between two.

### Curve flattening

Every quadratic and cubic segment is replaced by straight edges (`src/geometry/flatten.ts`); the result uses only `M`, `L`, and `Z`.

- **Adaptive (tolerance)** — recursive midpoint subdivision (de Casteljau). A sub-curve becomes one edge once an upper bound on its distance from the chord is within the tolerance (half the control point's distance for a quadratic, ¾ of the larger control distance for a cubic). Range 0.1–500 font units on a logarithmic slider. Without merging every font curve keeps at least one edge, so raising the tolerance beyond about 100 changes little (Roboto: 11,219 vertices at both 100 and 500 over the first 400 glyphs); turn on **Merge joined curves** for coarser shapes. Safety limits: recursion depth 12 and a 0.01-unit minimum sub-curve length; curves that hit a limit are reported.
- **Fixed segments** — each curve is sampled at `t = i/N` and becomes exactly N edges (1–32). Straight segments stay single edges. A warning appears if an edge strays more than 1 % of the em from its curve.
- **Merge joined curves** (both modes, off by default; the merge settings are shared; `src/geometry/curveRuns.ts`) — fonts build one visible curve from several Bézier segments (a Roboto O has 16 per contour), so per-curve settings alone stay smooth. Merging joins segments that meet smoothly into one curve. In fixed mode it is sampled with N edges spaced evenly by arc length; in adaptive mode it is simplified as a whole (Ramer–Douglas–Peucker on dense samples of the curve) so that no sample is farther than the tolerance from its edge, with at least 3 edges for a closed loop. Vertices stay on the curve. Roboto, first 400 glyphs, adaptive: 6,365 vertices at tolerance 500 with merging, against 11,219 without; the `o` goes from 36 to 12 vertices (Inter: 24 to 8).
  - **Break merged curves at:** **Corners & extremes** (default) — corners, straight segments, and the curve's horizontal/vertical extremes (found analytically, even inside a segment), so a round bowl splits into quarter arcs. **Corners only** — a fully smooth loop becomes one curve and uses at least 3 edges.
  - **Merge through straight lines** (off by default): straight segments that meet a neighbour smoothly also join the merged curve, so stems that flow into arches (n, m, u) or the straight sides of some O shapes are resampled with the curve. With this on, the extremes rule applies only between curves (a stem meets an arch exactly at its extreme). A straight segment left alone stays a line. Letters change a lot — stems can lose their ends.
  - **Corner angle** (1–90°, default 15°): a joint turning more than this always breaks. Merged curves also break at the contour start. Without merging through lines it only affects curve-to-curve joints, which in most fonts are already smooth (in Roboto 6200 of 6206 turn less than 1°), so it rarely changes anything. With merging through lines it decides which line joints merge: going from 15° to 90° changes 365 of the first 400 Roboto glyphs.
  - Measured on Roboto `a`: 38 segments merge into 12 curves; N = 4 / 3 / 2 / 1 gives 57 / 45 / 33 / 21 vertices (47 without merging at N = 1).
  - If a merged contour fails validation, it uses the unmerged result and the panel reports it. The 1 %-of-em warning is suppressed while merging.

- **Validation.** The result is compared with a much finer flattening that stands in for the original curves (tolerance 1/5000 em). Where an edge cuts across a stroke thinner than the tolerance, so the outline crosses itself or another contour where the original does not, only the curves involved are flattened again, each round with a quarter of the tolerance (adaptive) or twice the edges (fixed), up to 6 rounds; the panel counts the curves flattened more finely. New York's U, Ù, Ú, Û, Ü and its 6 and 9 crossed themselves at the default settings; they no longer do.
- Contours with no area (fewer than three points, or all points on a line) are left out and reported.

Contours keep their start point, order, and direction; advance widths and side bearings are kept. Glyphs without contours (such as a space) give an empty polygon.

### Squaring

Flattening only approximates curves, so an O stays round. **Squaring** (`src/geometry/squaring.ts`) deliberately reshapes round contours toward their bounding rectangle.

- Each contour is normalized to its own bounding box, and every point moves radially from the box centre toward the box edge. At 100 % it lands on the box, so a circle, ellipse, or superellipse becomes its bounding rectangle with sharp corners. **Amount** (0–100 %, presets Off / Soft / Square) blends linearly.
- A counter uses its own box and becomes a smaller concentric rectangle, so stroke thickness at the side midpoints is unchanged (Roboto O: left stem 191 units, bottom 163 units at 100 %).
- **Applies to: Round contours** (default) squares only contours close to the ellipse that fills their box (edge-weighted mean deviation ≤ 0.06 fully, ≥ 0.16 not at all); stems, triangles, S-curves, and B/D shapes stay as they are. **All contours** pushes every contour toward its box.
- Runs right after flattening, so anchor reduction can then drop the collinear points on the straight sides (a squared O reduces to 4 corners plus its start point).
- At 100 % the O, o, and 0 of Roboto, Inter, and Andale Mono — outer contour and counter — reach an area-to-box ratio of 1.00 (a circle is about 0.79).

### Anchor spacing and reduction

`src/geometry/anchors.ts`. 0 turns either step off; **Reset anchors** turns both off.

- **Anchor spacing** (0–200 font units): every edge, including the closing edge, is split into equal parts no longer than the target. New points lie on the existing edges, so the shape is unchanged. Skipped (with a warning) above 50,000 vertices per glyph.
- **Anchor reduction** (0–100 font units): Ramer–Douglas–Peucker on each closed contour, split at its start point (always kept) and at the vertex farthest from it. Larger values remove more points and can erase small details. Fonts that already contain self-crossing contours keep those crossings but gain none.
- Because spacing points are collinear with their edge, reduction removes them again when both are on; the panel warns about this. Reduction thresholds are absolute font units.

### Grid snapping and angle lock

`src/geometry/constraints.ts`. **Reset grid & angles** restores the defaults (both off, grid 10 u, 45°).

- **Snap to grid** (grid size 0–200 font units; 0 = off): each coordinate becomes `round(v / g) × g`, with the grid anchored at the glyph origin; exact halves round toward the centre of the glyph's bounding box, so a symmetric letter stays symmetric. Neighbours landing on the same point are merged. The canvas draws the grid for reference only (not when denser than 4 px).
- **Angle lock** (multiples of 90°, 45°, 30°, or 15°, counter-clockwise from horizontal): each edge turns to the nearest allowed direction (ties go counter-clockwise), then only edge lengths are adjusted — a length-weighted least-squares change that makes the contour close again. Each edge keeps only the part of its length along its new direction, so locking shrinks curves (at 90° an O loses about 30 % of its width and height); the result is therefore fitted to the original's bounding box instead of pinning the start vertex: at 90° width and height are scaled separately (every edge is horizontal or vertical, so angles are kept), otherwise one scale keeps the box's area, the contour is centred sideways and keeps its bottom, so letters stay on the baseline. Locking is rejected when it changes the shape too much — a vertex moves more than 20 % of the contour's bounding-box diagonal, or the area changes by more than 30 % (an S whose openings close up) — and retries simplify the contour by at most 4 % of that diagonal. A glyph is locked or stepped as a whole: if any contour is rejected, or locking every contour on its own would pull the glyph apart (Roboto builds a V from two overlapping legs; locked separately they become two bars), every contour gets stair steps. Stairs keep every vertex; off-angle edges longer than 1/40 em are first split, so a long diagonal becomes a fine staircase that follows it; corners go away from the ink (outward on outer contours, into counters); and where two neighbouring steps would cross at a sharp inner turn, one is flipped. Only if those cross too does a contour keep its previous shape. Before, Arial's Z at 90° slid about 800 units left onto the previous letter and its X dropped 512 units below the baseline; both now keep their bounding box. On printable ASCII, the largest vertex move at 90° went from 1024 to 290 units in Arial, and contours left unlocked went from 15 to 0 (Arial 90°), 8 to 0 (Arial 45°), 2 to 0 (Arial 30°), and 24 to 20 (New York 90°, whose hairlines are only a few units thick); New York went from 8 to 11 at 45° and 4 to 5 at 30°, because overlaps that used to pass are now caught. "Largest move" measures each original vertex's distance to the new outline.
- Snapping runs first; angle lock then changes edge lengths, so some vertices leave the grid. The panel warns about this.

### Vertex distortion

`src/geometry/distortion.ts`. **Reset distortion** restores the defaults (amplitude 0, few anchors off) but keeps the current seed.

- **Noise amplitude** (0–200 font units): the largest distance a vertex can move; 0 is off.
- **Noise frequency** (0.5–50): noise features per 1000 font units of outline length, sampled by arc length and periodic around each contour, so there is no seam.
- **Normal bias** (0–100 %): 0 % slides vertices along the outline, 100 % pushes them across it.
- **Seed** (0–999,999) and **Next variant** (seed + 1). No `Math.random`, time, or render count is involved; the same glyph, parameters, and seed always give the same shape.
- Edge protection limits only how far the two ends of an edge may move toward each other along it (at most half its length), so no edge collapses or reverses; movement across the outline is not limited. Along-the-outline movement is shortened first, movement across it only where that is not enough (the inside of a tight curve). Limiting all relative movement, as before, made the distortion weaker the denser the outline, because neighbouring vertices of a dense outline are close together.
- Where a distorted contour crosses itself or another contour (dense outlines at inner corners, thin strokes, counters near their outer contour), the amplitude is halved around the crossing, fading out over one amplitude of outline on each side, up to 12 times; the rest of the contour keeps the full amplitude. If that is not enough, the whole contour is retried at 1/2 down to 1/16 of the amplitude, then left undistorted.
- Measured on 32 Arial letters and digits, the median vertex movement at amplitude 40 is now 18 / 18 / 16 units with Anchor spacing off / 10 / 1 (before: 18 / 6.5 / 0), and at amplitude 200 it is 67 / 46 / 25 (before: 22 / 0.3 / 0).
- **Few anchors** (`sparse` in the settings; `pickMovers` and `SPARSE_LIMITS`): a mode with no control of its own. Only the Sound tab's **Flicker** preset turns it on; **Reset distortion**, or loading another preset, turns it off; it is not a Sound target. Only a few anchors of each letter move, and every other vertex stays exactly in place, so the letter keeps its shape.
  - **Locked:** corners (the outline turns by more than 30°; exactly 30°, which Angle lock often makes, is not a corner), the extremes in x and y (a flat run counts whole when it is a top, bottom, or side, not when it is a step), vertices on a zero-length edge, and every vertex of a contour with fewer than 8 vertices.
  - **Candidates:** every other vertex, and the midpoint of every straight edge at least 10 % of the em long, on any contour of 3 or more vertices, small ones included (the 4-vertex I, i, or hyphen). A picked midpoint is inserted as a new vertex and moves like any other mover, while the edge's ends stay put, so letters made only of corners and extremes (l, H, T) move too. A midpoint is skipped where inserting it would touch another edge of its contour (an outline that runs back along the edge, as grid snapping can leave).
  - **Picking:** the candidates are ranked by a hash of the seed, the contour, and their position, and the first ones move: 6 % of the letter's vertices, rounded, from 1 to 5, at most 2 on one contour, and more than 4 vertices apart along it (a midpoint counts as halfway between its edge's ends). A new seed picks a new set, so Beat → Distortion · Seed moves other anchors on every beat.
  - **Movement:** the same noise as above, but each mover's part across the outline and its part along it are each raised to at least 60 % of their share of the amplitude (in the Normal bias proportions; a seeded direction where the noise is 0), so every jump shows. Edge protection and the repairs above can still lower it.
  - While it is on, the panel shows the note "Only a few anchors move (set by the Flicker preset in the Sound tab). Reset distortion moves every anchor again." and the statistic **Anchors moved** (the vertices that actually moved, inserted midpoints included), and the status bar's description reads "distortion N u, few anchors, …". Off, or missing in older settings, the result is exactly as before.
  - Checked on the Latin glyphs of Arial, Georgia, and New York. At the default Geometry (Noise amplitude 2 and 120, Normal bias 90 %, seeds 1–10), every glyph moves at least one anchor, and in every test run no locked vertex moved, no letter had more movers than its count, and no contour more than 2. At 48 Geometry settings × 4 seeds per font: no broken layout and no export failure, with 2.8 / 3.3 / 3.2 anchors moved per glyph on average (Arial / Georgia / New York). Known gaps: on New York's hairline strokes (# and $), a picked midpoint cannot move across a 6-unit bar without crossing, so that contour falls back at some seeds (about 0.2 % of glyph runs at the default Geometry); with very dense anchors (Anchor spacing 5) every edge is shorter than 10 % of the em, so a few rectangle shapes (I, l, i, hyphen, period, =) have no candidate and stay still.

### Random anchors

`src/geometry/randomAnchors.ts`. The last group in the Geometry tab, off by default. When on, anchors are placed at random arc-length positions on the **original curves** instead of Flatten's regular sampling; each anchor is evaluated on the source Bézier, so it lies exactly on the glyph outline. The result then goes through Squaring, Anchors, Grid, and Distortion as usual. Because Flatten's polygon is replaced, the whole Curve flattening group is greyed out while this is on (its settings would only shape contours that fall back).

- **Density** (1–100): about how many anchors per 1000 font units of outline; every contour keeps at least 3.
- **Randomness** (0–100 %): stratified sampling. Each anchor has its own stretch of outline; 0 % puts it in the middle, 100 % anywhere inside it. Anchors never change order, so the outline cannot fold back.
- **Keep sharp corners** (on by default): source joints that turn by more than 30° stay as fixed anchors, and each stretch between two corners is sampled on its own.
- **Seed** (0–999,999; greyed out at 0 % randomness, where it has no effect): **Shuffle** picks a new seed (only the button uses the browser's random generator); **Copy** copies it; **Previous** lists the last six seeds of this session so you can go back. The seed also appears in the status bar and the export dialog.
- Reproducible: the random numbers come from a hash of (seed, the contour's outline, attempt), so the same font, settings, and seed always give the same polygon. Repeated letters in the text look identical, and so do different glyphs that share an outline (Latin A and Greek Alpha); different outlines get different draws.
- Validation: a draw that reverses a contour, collapses it, adds self-crossings, or crosses or leaves another contour is redrawn with a derived seed (up to 4 draws, still deterministic); if none is valid, that contour uses Flatten's result and the panel says so.
- **Reset random anchors** restores the defaults but keeps the current seed.

### Experimental: Crumple, Ripple, Whorl, Slipstream, and Thorn

`src/geometry/crumple.ts`, `src/geometry/ripple.ts`, `src/geometry/whorl.ts`, `src/geometry/slipstream.ts`, and `src/geometry/thorn.ts`, on the shared warp in `src/geometry/warp.ts`, run by `src/geometry/experimental.ts` in the fixed order Crumple → Ripple → Whorl → Slipstream → Thorn. The **Experimental** tab, beside **Geometry**, holds effects that run after the whole Geometry pipeline and can all be on together (plan: [docs/EXPERIMENTAL_PLAN.md](docs/EXPERIMENTAL_PLAN.md)). The tab has one **Seed** with **Next variant**, shared by every effect, and **Reset experimental** (keeps the seed). (The effects were renamed in the rework of Crumple, Slipstream, and Thorn: Noise became Crumple, Curl Whorl, Wind Slipstream, and Spikes Thorn. Crumple has since gone back to Noise's single lattice and kept only the new name.)

- **The effects are built from piecewise-linear warps.** Crumple, Ripple, and Whorl are warps, and so are Slipstream's stretch and slip and Thorn's roots and refraction. The plane is cut into triangles and each moves by its own linear map, continuously across their edges. A straight edge stays exactly straight inside a triangle and bends only where it crosses a triangle edge (a crease); new vertices go only there. No effect samples a smooth function along the outline, so the letters gain corners, never curves. Slipstream's trails and cuts and Thorn's tips are not warps: they add a few straight edges each, and the outline is merged where they may cross it (below).
- **Valid by construction, so effects stack.** Up to 100%, no triangle flips or flattens, which makes every warp one-to-one: it cannot make an outline cross itself or another contour, or push a counter out of its letter, and neither can several warps in a row. Contours are still checked after each effect. All contours start as their exact images (valid together); each is then replaced by its tidied image if that is valid against the others. A crossing counts only where the input's edges neither crossed nor touched (heavy Geometry settings can leave outlines lying on top of themselves), and not between two edges still exactly as the warp mapped them whose input edges lie less than 0.05 units apart: a one-to-one warp cannot make those cross, but a strong Slipstream can squeeze a sharp spike that heavy Distortion leaves so thin that rounding does. A crossing between untouched edges that lie further apart in the input would be a real fault and is still rejected. If rounding ever breaks an exact image, that contour is retried at 1/2 down to 1/16 strength; if nothing works the glyph is left as it was.
- **Tidying, so nothing reads as a curve.** Creases that turn the outline by less than 3° are left out (each left-out crease stays within 1 % of the em of the edge that replaces it). Then, in every run of five or more vertices that all turn the same way by 0.5°–20° between edges shorter than 4 % of the em (how a polyline starts to look like a curve), the weakest crease is removed until no such run needs a crease to exist. Runs the input's own vertices already form are left alone; the input's vertices are never removed. Creases of earlier effects count as creases too, so a later effect can also remove an earlier one's, and a run that only several effects together form is broken up as well. If tidying makes a contour touch itself or another, every crease the offending edge replaced is restored and the rest is tidied again (up to 8 times), then tighter drift limits are tried. Zero-width needles in the input (thinner than 0.01 units; heavy Geometry settings can leave them) are dropped first.
- **Crumple** (off by default; `src/geometry/crumple.ts`) crumples the letters like paper. The mesh is a square lattice with cells of **Facet size** (8–100 % of the em, default 18 %), turned by an angle from the seed, each square split along a diagonal chosen by the seed. Every lattice point moves by a random vector from the seed, up to **Amount** × 30 % of the facet size, and points in between move linearly with their triangle. **Turn** (0–359° in 1° steps, default 0°) turns every movement by the same angle, so the folds go another way over the same creases (180°: the opposite way). Below 30 % of the cell no triangle can flip (each keeps about 15 % of its area or more), whatever the turn, so Crumple never needs weakening. **Amount** runs from 0 to 500 % (default 70 %): above 100 % the points move further along the same directions, and facets fold over each other (see Folds below). The lattice is fixed in glyph coordinates, so every copy of a letter has the same shape and fonts export as shown. Its random numbers come from its own hash channels (101–104). This is the lattice it was first built with, as Noise. The rework that renamed it to Crumple laid three meshes of different scales over the letter, with a **Detail** slider; NOCUR-60 brought the single lattice back and kept the name. Up to 100 % its output is identical, byte for byte, to Noise's (18 settings compared); above 100 % it differs only through the newer overlap merge (about 1 font unit), so the checks below, made when it was first built, still hold. Saved settings with a Detail value load without it, and a Sound mapping on Crumple · Detail is dropped.
- **Ripple** (off by default; `src/geometry/ripple.ts`) sends polygonal waves out from a point. The mesh is a set of concentric regular polygons with **Sides** (3–12, default 8) sides and a flat side at the bottom, centred at **Center X / Center Y** (a share of the glyph's ink box, −50 % to 150 %, default the middle), one ring every half **Wavelength** (8–200 % of the em, default 30 %) measured across the sides. Rays through the polygon corners cut the rings into cells, each split into two triangles. Every ring moves out or in as a whole, in turn, by up to **Amount** (0–400 %, default 50 %) × 45 % of the ring spacing, so it stays a regular polygon and the outline zigzags where it crosses the rings (a triangle wave, not a sine). **Fade** lowers the amplitude linearly with distance from the centre, down to (1 − Fade) at the farthest corner of the ink box. Up to 100 % rings never pass each other (neighbours stay at least 10 % of the spacing apart), so no triangle flips; above it they overtake each other and fold; the ring just outside the glyph stays put and, without Petals, everything beyond it is left alone. **Petals** (0–300 %, default 0 %) bends every ring into a flower with one petal per side: three more rays from the centre cut each side evenly (tip at the corner, shoulder, notch at the middle, shoulder), and each ray scales the rippled rings along it by 1 + its share of the depth, with shares 1 / 0.7 / −1 / 0.7. The depth is 0.9 at 100 % (tips reach 90 % further out, notches keep 10 % of their distance); above it tips and shoulders keep growing while notches never go below 10 %. Corners only move along their own ray and stay on the same side of the centre, so Petals is one-to-one at any depth and never folds on its own; beyond the last ring the same scaling continues, linear in each slice, so the plane stays continuous. **Reverse** (off by default) swaps out and in: every ring moves the other way (the first ring in instead of out, by as much), and the petal shares are negated (−1 / −0.7 / 1 / −0.7), so the corners and shoulders are pulled in (corners keep at least 10 % of their distance, shoulders 37 %) and the middle of each side is pushed out by the full depth: the petal tips sit mid-side. Every scale stays positive, so reversed Petals is one-to-one too. Settings saved before Reverse existed read it as off. Ripple uses no randomness.
- **Whorl** (off by default; `src/geometry/whorl.ts`) swirls each letter around the centre of its ink box. The mesh is Ripple's: concentric regular polygons with **Sides** (3–12, default 8) sides and a flat side at the bottom, rays through the corners, each cell split into two triangles; the outermost of the **Rings** (2–12, default 6) lies half the ink box's height from the centre (at least 5 % of the em), so the letter's top and bottom sit on it. Instead of moving out and in, every ring turns as a whole about the centre, so it stays a regular polygon, and the outline bends only at ring sides, rays, and cell diagonals inside the rings. With **Pin top and bottom** on (the default), the outermost ring and everything beyond it stay put and the rings turn more toward the centre; off, the centre stays put, the rings turn more toward the outside, and everything beyond the outermost ring turns with it as one rigid piece. Neighbouring rings turn by the same step relative to each other. At **Amount** 100 % (−400 % to 400 %, default 60 %; below 0 % it turns clockwise) the step is 90 % of the largest that keeps every triangle the same way round, worked out for the Sides and Rings in use with the cell diagonals laid along the swirl (whichever diagonal direction lets the rings turn further), so up to 100 % either way Whorl is one-to-one. The whole swirl then turns from about 30° with 3 sides to well over a full turn with 12 sides and many rings. Beyond 100 % either way, triangles flip and the letter folds (see Folds). Whorl uses no randomness. Checked on the Latin glyphs of Arial, New York, and Georgia at 12 settings each (±30–100 %, pinned and whole, on Geometry settings, and with the other effects): no new crossing, no weakened contour, and every glyph exports.
- **Slipstream** (off by default; `src/geometry/slipstream.ts`) catches the letters in a stream flowing toward **Direction** (0–359° in 1° steps, 0° right, 90° up; default 0°). Its warp moves every point along the stream by two amounts. **Slip** (0–60 % of the em, default 15 %) is a shear, an offset that depends only on where the point lies across the stream: sway bands 2–6 **Gust size**s wide (mostly 3–5) each slide by a seeded share of Slip, from −½ to +½ of it, and every band one Gust size wide adds a smaller jolt of its own (none in 40 % of the bands, up to ±15 % of Slip in the rest), so a few large steps stand out among finer ones. The offset holds steady inside a band and changes only across a thin zone at its edges, so strokes break into slices that slide past each other along straight creases. In stream coordinates (u along, v across) a shear maps (u, v) to (u + d(v), v), whose Jacobian determinant is 1, so slipping never folds the letter, at any amount. The **stretch** moves each point by **Strength** (0–800 %, default 15 %) × its band's gust × its distance downwind of the glyph's upwind edge (from the ink box), so that edge stays put and the outline is drawn out more the further downwind it lies; each band's gust is a share of the full strength from the seed, between 1 − **Gustiness** (0–200 %, default 60 %) and 1, and no point moves more than 4 em. The bands run with the stream, one **Gust size** apart (6–50 % of the em, default 12 %), anchored at the glyph origin, so with a level stream every letter on a line shares the same bands; they are cut into square cells, each split along a diagonal chosen by the seed. Up to 100 % Gustiness, gusts are never negative and the stretch only grows downwind, so the determinant stays at least 1 and the warp is one-to-one at any strength. Above 100 % some gusts blow backwards and tear the letter (see Folds). After the warp come **Trails** (0–8 per letter, default 2): thin streaks dragged downwind out of the edges of the letter's outside that face away from the stream (outward normal within about 53° of it), at bases spread evenly along the outline. Each replaces its base by five points (base, shoulder, tip, shoulder, end): 2–5 % of the em wide where it leaves the letter, narrowing to 30 % of that a quarter of the way along, then running out thin, a seeded 45–100 % of 15 % of the em + 50 % × Strength long (at most 2 em), and turned up to 4° off the stream. A trail that would cross or come within 0.6 % of the em of the letter or an earlier trail is tried in up to 3 places, then left out, so trails never need merging. Last come **Cuts** (0–8 per letter, default 2), so they slice the trails too: long, thin wedges along the stream on seeded lines, entering from the side facing the stream or the side away from it, widest where they enter and tapering to a sharp tip 35–85 % of the way into the first stroke they meet (for 30 % of them, the second); one in four goes right through the letter. They are cut out exactly: the outline is first redrawn by the nonzero rule, so the ink winds once and everything else not at all, then the wedges are added clockwise and the outline is redrawn around what still winds positively (the `'positive'` fill rule of `overlaps.ts`). That redraw also merges any folds so far, so the final merge is then skipped unless Thorn adds a thorn. Every random choice comes from the seed through Slipstream's own hash channels (201–207), keyed by the glyph index. Older saved settings without Slip, Cuts, or Trails read them as 0, which gives exactly the earlier Slipstream. Statistics: **Max move**, **Creases**, and, while there are cuts or trails, **Cuts** and **Trails**. Checked on the Latin glyphs of Arial, Georgia, and New York (8 or more settings × 3 seeds, alone, on heavy and dense Geometry settings, and with Crumple and Thorn: 122,976 glyph runs): no new crossing, no export failure at 0 or 2 decimals, and no glyph left without Slipstream. A glyph takes about 0.9 ms at the defaults, most of it the two merges for the cuts, and about 8.5 ms on dense Geometry.
- **Thorn** (off by default; **Use thorn**; `src/geometry/thorn.ts`) runs last: a few anchors of each letter jump out into the canvas as long, straight thorns and pull the letter around them along. Only anchors on the letter's outside grow thorns (anchors inside no other contour, or inside an even number of them; where contours overlap, as in many variable fonts' instances, the anchors outside the others, kept at least 0.1 em from the contours their own crosses where enough are), each away from the ink: square to the outline's direction over 0.06 em either way along it from the anchor (`THORN_WINDOW`, at most a quarter of the contour each way), rather than at the anchor alone, turned to either side by up to **Spread** (0–100 %, default 50 %) × 90°, so 0 % is straight out from the outline. **Anchors** (1–12, default 3) is how many anchors of each letter jump, and **Reach** (0–100 % of the canvas diagonal, default 10 %, read out as "% canvas" with two decimals below 1 %, one below 10 %, and whole numbers above, and as 0.0 only at exactly 0, where no thorns grow) how far: each goes a seeded 35–100 % of it, so at 100 % a thorn can cross the whole canvas. The slider is cubic: the reach is the cube of the thumb's position, which moves in steps of 0.005, rounded to 4 decimals (0.01 % of the canvas), so 0.5 gives 12.5 % and 1 gives 100 %, and short thorns keep fine steps. Near 0, where the cube grows by less than 0.01 % a step, each step adds 0.01 % instead (positions up to about 0.14, reaches up to about 0.28 %), so every step is a reach of its own and the arrow keys always move it (`THORN_REACH`, `reachFromSlider`, and `reachToSlider` in `src/state/sliderScales.ts`). Its number box takes the reach itself, in % of the canvas to 0.01 %. In em, the reach is Reach × the canvas diagonal over the text size (both in pixels, to 0.01 em; `canvasDiagonalEm`), with the diagonal counted as at most 256 em (`THORN_LIMITS.maxReachEm`, a safety cap that keeps every merge on its exact grid). So changing the text size or the canvas size (not the PNG multiplier) changes how far the thorns reach in em, keeping the same share of the canvas, and while Thorn is on such a change recomputes the letters; with Thorn off it changes no geometry. On the default canvas (1200 × 800 px) at 48 px the diagonal is about 30 em, so the default 10 % is about 3 em; Reach's ⓘ explanation says what 100 % is in em at the current text size and canvas. Only the tips get longer: the root's pull, the base width, and the flutes stay measured in em. The status bar, the Export dialog, and the SVG's description name it as "reach N% canvas (about M em)", both numbers rounded as the slider reads (`reachReadout`). Each thorn grows in three steps. (1) **Root** (0–100 %, default 50 %; 100 % is a radius of 60 % of the em): a piecewise-linear warp on a star mesh with 8 sides around the anchor, made of the anchor, an inner ring at 35 % of the radius, and an outer ring at the radius that stays put. The anchor moves out half its thorn's length (at most 75 % of the radius); the inner ring follows 60 % of that on the thorn's side and 15 % on the far side, is drawn in toward the thorn's axis, and is pulled further on one seeded side. Everything inside the outer ring moves with it, other contours included, so strokes lean and thin, and a counter such as the `o`'s, or the far side of a stem, bends toward the thorn. Every mesh triangle must keep at least 20 % of its signed area; while one does not, the pull is halved, up to 6 times, so each pull is one-to-one. Later thorns centre their mesh where earlier pulls moved their anchor, and all pulls run as one warp, their composition, through the shared warp (checks, retries, tidying, crease marks). At 0 % there is no root and the thorns are only added on. (2) **Tip**: the anchor jumps the rest of its length, a sharp straight thorn. **Width** (0–100 %, default 30 %) sets how far its base reaches along the outline on either side, as a share of the root's inner ring or of the anchor's shorter edge, whichever is longer (at least 2 %: a thin needle; at Root 0 % and Width 100 % the anchor pulls its whole edges along). Neighbouring thorns share a base point midway, so no filled webs form between them: the result is a wide root narrowing to a sharp tip. (3) **Refraction** (0–100 %, default 0 %, off) shows the letter through fluted glass: vertical strips **Flute width** wide (4–30 % of the em, default 10 %; greyed out while Refraction is 0 %), each showing its part of the letter magnified up to 30 % about its middle, slid sideways and lifted or dropped by up to 35 % of the strip's width, with the seams between strips (30 % of a strip) squeezed into steep breaks. x moves by a rising piecewise-linear function and y by a shift that depends on x alone, so the glass is one-to-one at any strength. The glass covers only the letter: its ink box before the tips grow, plus one strip either side; beyond that it is plain and leaves every point where it is, so thorn tips that reach past it to the left or right stay sharp: they are not refracted and gain no points however far they reach (a thorn running up or down within those strips is still refracted). A tidying pass then removes the weakest crease of any curve-like run the roots made. Which anchors jump, which way, how far, which way their roots lean, and how the strips slide and lift all come from a hash of the shared **Seed** and each anchor's place on the glyph's reference outline (Thorn's own channels), so the same seed gives the same thorns and **Next variant** moves them. **Stable anchors** (`ThornAnchors` in `thorn.ts`): the reference outline is the letter before Vertex distortion and the other Experimental effects (the pipeline hands it to `applyExperimental`). The anchors are ranked there by the hash, and the first **Anchors** of them on the outside are picked, so Anchors adds or removes thorns at the end of a fixed list. Each pick is then followed through Distortion and every later step to the vertex it became: a warp keeps every vertex it receives, in order, and marks the creases it adds, so a pick moves to the vertex at its place among the unmarked ones; after a step that redraws the outline (the vertex budget's simplification, Slipstream's trails and cuts) it moves to the nearest vertex on the letter's outside. The thorn starts on that vertex of the drawn outline, and its direction is the reference outline's (the window's ends above), carried through the warps as each is placed without Distortion's move of the ink box, so Distortion's noise never turns it; where a warp has turned the drawn outline so far that the thorn would point into the letter, it is mirrored out. So a step of Distortion's sliders or of Crumple's or Ripple's **Amount**, or a new Distortion seed, keeps nearly every thorn on its anchor and pointing the same way (`tests/geometry/thorn-anchors.test.ts`: on the settings Sound drove when the thorns jumped about, at least 90 % of the thorns keep their root within 0.05 em and their direction within 10° through one step of Noise amplitude, Crumple's Amount, or Ripple's Amount or a new Distortion seed, and no letter loses all of them; Distortion alone changes no pick or direction). The other sliders of Crumple, Ripple, Whorl, and Slipstream change the warps themselves, so they can still move or turn thorns (which is why Sound hands them on by Thorn turns; see [Sound](#sound)); a new Experimental seed, or a change of the Geometry steps before Distortion, picks again. The picks for a given seed differ from earlier versions, so work saved before shows other thorns at the same seed; Thorn's sliders, ranges, and defaults are unchanged. Driven by Sound (Beat → Seed) the thorns jump somewhere new a few letters at a time (Thorn turns; see [Sound](#sound)). A thorn may cross the letter or another thorn, so whenever a thorn is added the outlines are merged into one clean outline, the same merge as when an effect folds (see Folds), and the letters still export. **Reverse** (off by default, below Reach) turns every thorn round: it shoots into the letter along the inward normal, with the same anchors, turns, lengths, root leans, and bases, only each direction negated (so its root pulls the letter in with it). It keeps going for its whole length: inside a stroke it carves a white slit, and where it crosses a counter or comes out past the far side the merge (nonzero winding) shows it as an ink spike. Settings saved before Reverse existed read it as off. **Burst** (off by default, below Use thorn) makes the letters explode instead: no anchor jumps; many straight spikes grow all round every contour, counters included, and the outline between them sinks into the strokes (`burstOutline`). **Anchors** then counts spikes per letter (4–80, default 40, saved apart from the thorns' 1–12, so switching Burst keeps both), shared out over the contours by the length of outline that shows (outline hidden in another contour's ink, where contours overlap, grows none) and spaced evenly along it, every place moved by up to 30 % of the spacing either way (seeded). Each spike has a base on the outline (**Width**: 5–90 % of the spacing, but at most 48 % of the way to either neighbour and half the spike's length) and two straight flanks, each bent once at a shoulder drawn in toward the axis, so it flares at its foot and tapers to a needle. On the letter's outside a spike points away from the ink, leaning toward pointing from the middle of the ink box and turned at random, both by **Spread** (never closer than about 15° to the outline); into a counter (white closed in on every side) it does not lean (it only turns) and stops at most 42 % of the way across, so it stays inside. Lengths are seeded: mostly medium, about one in eight long, with a slow wave round the contour that gathers the long ones; the longest is 30 % of Reach's length (`BURST_REACH`), about 0.9 em at the default 10 % on the starting canvas. **Dent** (0–100 %, default 80 %; greyed out unless Burst is on) sinks the outline between two bases into the stroke, deepest midway, by up to 60 % of the stroke's thickness there (each point a seeded 55–100 % of that, and never deeper than 1.5 times the gap is wide), redrawn with at most three corners so it never reads as a curve; at 0 % the outline between spikes stays as it was. **Root** is greyed out and no roots are pulled. **Reverse** turns every spike into the ink and pushes the dents out of it instead, with the same places, lengths, and bases; **Refraction** still applies after. The merge cleans up where spikes cross the letter and each other, and then leaves out any contour smaller than (1 % of the em)², specks too small to see that rounding for export could collapse (`withoutSpecks`). Statistics read **Spikes** in place of Thorns, without Roots. Settings saved before Burst existed read it as off, with 40 spikes and Dent 80 %. Layout ignores the tips: each glyph carries its ink box and convex hull from before Thorn (`layoutBox`, `layoutHull`), which Fit text, the position anchors, Free, and the overflow warning use, so they treat the text, slanted or not, exactly as with Thorn off (see [Typography](#typography)). While Thorn is on, a glyph is clicked by its column and an invisible copy of its original outline, flattened (straight segments, like everything the canvas draws); the drawn thorns take no clicks (see [Interface](#interface)). Older saved settings without Root get 50 % (Root 0 % gives the earlier add-on look), and without Refraction it stays off. Statistics: **Thorns** (how many anchors jumped), **Roots** (how many roots pulled the letter), and **Longest** (the longest jump, in font units), with a warning when a contour needed a weaker root or refraction, or a glyph was left without them. Measured while Reach was still a share of the em (0–200 %, default 60 %) and refraction covered whole thorns: checked on all Latin glyphs of Arial, Georgia, and New York at 3 seeds and 11 settings (from Root 0 % to every slider at its maximum and beyond), alone, on dense and heavy Geometry settings, and with Crumple and Slipstream: no crossing in any result (after the merge's exact redraw, below), no export failure at 0 or 2 decimals, and no glyph left without thorns; the farthest point lies within about 3.7 em of the glyph's origin. A glyph takes about 0.7 ms at the defaults, 5–6.5 ms on dense Geometry, and up to about 17 ms with every slider at its maximum on dense Geometry, mostly the root warp running over many vertices.
- **Folds** (`src/geometry/overlaps.ts`): once any effect goes beyond 100 %, the letters may fold onto themselves, so no effect checks its contours, and at the end the glyph is redrawn as the outline of exactly what the nonzero rule fills. The same merge runs after Thorn whenever a thorn is added, and Slipstream's cuts use it with the positive rule (above). Snap rounding on a grid of whole font units turns every vertex and every crossing into a grid point and routes each edge through every grid point whose cell it passes (each cell owns only its bottom-left corner, so an edge through a cell corner is routed once), so rounded edges meet only at their ends; each region then gets its winding number, and the edges between ink and no ink are joined into contours (outer ones counter-clockwise, holes clockwise; where two inked regions touch at a point, each keeps its own contour). Contours under 4 square units are dropped, and so are contours under one unit wide on average (twice the area over the perimeter) unless a disk 0.01 em across fits inside them (`OVERLAP_LIMITS.room`, tried against the middle of each edge by `hasRoom`): a hair-thin sliver, however long, is dropped, while a letter whose thorns are so long and thin that it is narrow on average keeps its body, and a hole with a long thin crack is kept too. Rounding moved every point a little, which would turn a run of short edges into a wobble of small turns that reads as a curve, so each contour is then **drawn again through the input's own vertices** and the exact places where input edges cross, and the grid detours are dropped. A vertex goes back to its grid point wherever the exact one would make a contour cross or touch itself or another, turn inside out, nest differently than on the grid, or come within one grid cell of the point after next (rounding to whole units would join those two and fold the contour up); this runs for up to 8 rounds, keeping the last valid state, with the grid result as the final fallback. Last, in each remaining curve-like run not made of the input's own points, the corner that turns least is dropped where that moves the outline by at most one cell, under the same checks. Only straight edges come out, with new vertices only where outlines crossed (and rounded ones where contours come within a grid cell), and the result always passes export. A crossing that lies within rounding error of a cell side is rounded exactly, so it lands in a cell that both its edges pass. Should rounding still join outlines wrongly, two ways round give a region different winding numbers; the merge is then tried once more on a grid twice as fine, and if that breaks down too, the glyph is left unmerged instead of being drawn with lost ink: its outlines still cross, but it fills the same everywhere and still exports, and the panel says "Overlaps could not be merged; the outline is left as it is." The grid is exact up to ±2^22 cells from the glyph's origin (`OVERLAP_LIMITS.maxCoordinate`), far enough for thorns at the 256 em cap at 4096 units per em, on the finer grid too; a glyph that reaches beyond it is left unmerged the same way, with the same warning. Long thorns stay fast to merge: routing an edge visits only the strips of the grid (columns, or rows for steep edges) that hold a rounded vertex or crossing, not the thousands of empty ones a long thorn passes. The merge joins its pieces without recursion (an iterative union-find), so outlines of tens of thousands of points (Anchor spacing 1) no longer overflow the stack. The intro of the tab then shows how many crossings were merged and slivers dropped (**Crossings merged**, **Slivers dropped**), and does so whenever Thorn is on, Slipstream cuts, or the vertex budget (below) simplified the glyph. Measured on the Latin glyphs of Arial, Georgia, and New York (seeds 1 and 7, 6 settings, alone and on dense and heavy Geometry: 30,744 glyph runs): the vertices of curve-like runs that merges add fell from 36,539 to 498 (in 129 glyph runs, each run about 1–3 units), crossings from 1 to 0, and export failures stayed at 0; merging takes about 18 % longer, and outputs keep more vertices (on dense Arial about 1,455 points per glyph instead of 637). Measured when folds were introduced, at 16 folding settings per font: whole fonts at the maxima write and read back as OTF (except Arial with all three folding effects at once, which exceeds the 1,000,000-point limit), and every result within 100 % is unchanged.
- **Vertex budget** (`src/geometry/budget.ts`; `maxAddedVertices` and `maxMergePoints` in `EXPERIMENTAL_LIMITS`, `src/geometry/experimental.ts`): dense effects multiply. Every warp adds a vertex wherever its mesh creases the outline, Refraction warps each strip of the letter again, and every merge adds one wherever outlines cross, so together they could turn a letter of a hundred vertices into a hundred thousand, which takes seconds to merge and draw. Each glyph therefore has a budget, which depends only on the glyph and the settings, never on time, so the canvas, the preview, and the exports agree: after any effect, at most 6,000 vertices more than the glyph brought into the Experimental tab, and in a merge, at most 30,000 grid points (vertices and crossings) more. A glyph over the vertex limit is simplified to fit: every contour by Ramer–Douglas–Peucker with one shared tolerance that starts at 1 % of the em and doubles (up to 12 times) until the glyph fits, leaving out contours smaller than the tolerance (never all of them). Each contour keeps a subset of its vertices, so edges stay straight, and curve-like runs the simplification leaves are broken up; the outlines are merged afterwards. A warp that would make more than 16 times the limit is left out of that glyph before its costly tidying. A merge over its limit stops before its costly steps, and the glyph is simplified more coarsely, to at most half the vertices of the try before, and merged again; only if even the coarsest simplification does not fit is the glyph left unmerged, simplified that far. The defaults, every single effect (even at the ends of its sliders, on dense Geometry), and the Sound presets never reach the budget; only several dense effects together do, and with every slider at its maximum the letters turn into a few broad slabs of ink. The panel then warns "Simplified: these settings make too many vertices or crossings, so the outline was reduced (tolerance N u).", "Too complex to merge; lower the settings." for a glyph left unmerged, or "This glyph is left without crumple: too complex." (likewise ripple, whorl, and slipstream; for Thorn, "roots or refraction") for a warp left out, and the status bar adds "(simplified)" after the vertex count.
- Statistics, per effect: largest move and the number of creases added (Slipstream also its cuts and trails; Thorn: how many jumped (in Burst, how many spikes grew), how many roots pulled, and the longest jump); a warning if a contour needed a weaker effect or a glyph was left without it.
- Measured when Crumple, Ripple, and Slipstream were first built (Crumple, then called Noise, with the same single lattice it has now; Slipstream as the stretch alone), on the Latin glyphs of Arial, New York, and Georgia, each effect alone, on top of Geometry settings (fine and coarse flattening, Anchor spacing 5, angle lock, grid, Distortion 80, Random anchors, and a heavy combination), and all three together (78 font and setting combinations): no new crossing within or between contours, no contour weakened, and every glyph exports. Curve-like runs that need a crease remained only in New York (7 glyphs across 6 combinations), all where two parts of the outline are less than one unit apart. At their defaults Crumple and Ripple each add about 30 vertices per glyph (about 80 at the smallest facet, 100 at the shortest wavelength). Across 19,440 random combinations of Geometry, Crumple, Ripple, and Slipstream settings on the three fonts, nothing crossed, no contour was weakened, and every glyph exported. The reworked Slipstream and Thorn have their own checks above.

## Export

Open **Export…** from the top-right corner of the header (its tooltip: "Export SVG, PNG, a font file, a video or the config"). Without a font it offers only the config. Nothing is downloaded until you press a download button; a video is saved when its take ends. SVG, PNG, and the font file use the same final polygons as the canvas at the slider values; glyphs the canvas has not computed yet for the slider values are computed first, in the geometry worker for SVG and PNG and in the export's own worker for a font file. A video records the canvas as it is shown, live frames included (see [Video](#video)).

### SVG and PNG

- **SVG — main view** (default) and **PNG — main view** export the canvas: its size, the text placed by the Typography settings, and the Color settings. With **Transparent background** on (Color tab) the background is left out, for SVG and for PNG with transparency; this applies to the preview look too. The SVG is width × height px; the PNG is that times the **Canvas size** multiplier, rendered from the same SVG. If some glyphs of the text are not computed yet (for example while Sound drives the canvas), the dialog shows "Computing outlines…" while the geometry worker computes them (`geometryClient.ensure`), and **Cancel** stops the export.
- **Export the preview look** (checkbox, off by default) exports the bottom-right preview instead: its colours (swapped when **Invert** is on) on a solid background, with its **Blur**. The blur is converted from preview pixels to font units and then to canvas pixels, so it keeps its size relative to the letters at any resolution; in SVG it is an `feGaussianBlur` filter on an untransformed group.
- Each glyph is one path in its own font units (y up, so outline coordinates keep full precision), placed with `translate(…) skewX(…) scale(1 −1)` inside a group that scales font units to canvas pixels. Paths use only `M`, `L`, and `Z` with `fill-rule="nonzero"` (with **Fill** off, stroked with no fill instead; see below); contour order and direction are kept. Kerning, tracking, and line breaks match the canvas. Missing characters are blank advances, named in an XML comment.
- **Coordinate precision** 0–4 decimal places. Rounding is checked and repaired as for the font file (below); if a contour would still collapse, flip, or cross itself, the export stops and asks for a higher precision.
- Text in `<title>` / `<desc>` is XML-escaped; file names use only ASCII letters, digits, `.`, `-`, and `_`.

### Outlines only (Fill off)

The canvas's **Fill** layer button also decides how the SVG, the PNG, and the video draw the letters (`SvgLook.outlineOnly` in `src/export/svg.ts`, `VideoLook.outlineOnly` in `drawArtboard.ts`, both from `view.showFill`); the preview follows it too, since it draws the SVG export. The font file is always filled: a font has no strokes.

- **Fill on** (the default): filled as before. The SVG is byte for byte what it was before Fill reached the exports, and the video draws the same calls (`tests/export/outlineExport.test.ts` pins both).
- **Fill off**: outlines only. The glyph group gets `fill="none"`, `stroke` in the text colour (the preview look's when that is exported), `stroke-width`, `stroke-linejoin="miter"`, and `stroke-miterlimit="4"`, and an XML comment says "Outlines only (Fill off)"; the paths are unchanged (`M`, `L`, and `Z` only). The video strokes each outline with the same width, join, and limit.
- **Width: 2 canvas px** (`OUTLINE_STROKE_PX`). The canvas draws Fill-off outlines 1.5 screen px wide at any zoom; at 100 % the default 1200 × 800 canvas (1272 px wide with its view margin) fits a desktop canvas area about 950 px wide, where 1.5 screen px is 2 canvas px. It is written in font units on the glyph group (2 × font units per pixel, `outlineStrokeWidth`), which the group scales to canvas pixels, so a 2× PNG has 4 px lines and a video stretches them with the canvas. Slanted text skews the stroke with the letter, by a few percent at most.
- **Joins:** miter, so corners stay sharp, as straight segments meet on the canvas; the limit 4 (the SVG and CSS default, so the canvas's own; about 29°) bevels needle-sharp spikes such as Thorn tips instead of drawing very long points. Every contour is closed, so there are no caps.
- **Original and Compare** are canvas views: exports always use the final polygon. With Fill off, Compare's polygon outline on the canvas is what the exports draw.
- The Export dialog says which applies: "Fill is on: the letters are filled." or a notice "Fill is off on the canvas: outlines only, 2 px strokes in the text colour with no fill."; the done message adds ", outlines only", and the SVG summary reads "stroked with no fill". For the font file it says "Always filled".

### Font file

- Format: **OpenType with CFF outlines (`.otf`)**, written with opentype.js (fontkit can only read fonts). Loaded only when you build a font.
- Glyph set: the current glyph, the characters in the text, or all mapped characters (up to 5000 glyphs and 1,000,000 outline points — very dense settings such as Anchor spacing 1, or every Experimental effect at its maximum, reach the point limit with a whole font, and the build stops with a message), plus a `.notdef` box. **Glyph size:** CFF stores every coordinate within ±32,767 and every step from point to point as at most 32,767 units along either axis, so each glyph must fit in a square 32,766 font units across (16 em at 2048 units per em, 32.8 em at 1000; `FONT_BOX_LIMITS` in `src/export/fitGlyph.ts`). Along each axis a glyph that spans at most 32,766 units (within ±32,767) is kept whole; for a wider one the square's side is the 32,766 units centred on the em box (half the advance across, halfway between ascender and descender up), moved inside the glyph's extent as far as needed, with whole-unit edges. Outline parts beyond it, such as long Thorn tips, are cut off with straight cuts at its edge instead of the glyph being left out (each contour is clipped against the square's sides; contours left without area are dropped), and the dialog names those glyphs: "Trimmed to fit: a font stores each glyph within a square 32,766 font units across (N em for this font). Outline parts reaching further, such as long Thorn tips, were cut off at its edge in …. Only the font file is trimmed: the canvas, SVG and PNG are not." A glyph whose advance width is above 32,767 units is left out with that reason, and the coordinate limits are checked again after the cut. The dialog estimates the size up front ("About N outline points.", from the glyphs computed so far and their mean for the rest), warns when that is over the 1,000,000-point limit, and warns that the build may take minutes when many glyphs still need computing.
- **In the background:** the font is built in a worker of its own, one per build (`src/export/fontExport.worker.ts`, `src/export/fontExportClient.ts`), with progress in the dialog. The glyphs the canvas already computed for these settings are handed over and used as they are, so the file has the canvas's outlines; the rest go through the same pipeline. **Cancel** stops the worker at once. A worker that sends nothing for 60 s is stopped and the dialog says "The export stopped responding." Where a worker cannot start, the build runs on the page, yielding between glyphs.
- Naming: family and style (printable ASCII). The default family adds "Poly" (and drops a leading ".", which hides a font from menus). The PostScript name is `Family-Style` without spaces or reserved characters, at most 63 characters; the unique ID is `1.000;None-Curve;<PostScript name>`. If the source's SIL OFL copyright or license reserves a font name ("Reserved Font Name") and the family name contains it, the dialog warns that a modified version must be renamed.
- Kept: character mapping, advance widths, contour order, counters, units per em, ascender, and descender. Side bearings follow the final polygon. Contours are written in the CFF direction (outer contours counter-clockwise; a glyph whose largest contour runs clockwise, as in TrueType sources, is reversed as a whole).
- **Kerning** (`src/font/kerning.ts`, `src/export/gpos.ts`): the pair kerning the canvas applies is read from the source by fontkit's rules (the GPOS `kern` feature of each script's default language, pair adjustment lookups only, with variation deltas applied for a variable instance; the legacy `kern` table where that feature is missing, and always for fonts with a `morx` table) and written as a GPOS table, pair adjustment lookups under the `kern` feature, keeping only pairs between exported glyphs. The source's subtable formats are mirrored, so class kerning stays class-based, with Extension lookups above about 60 KB. The table is added to the finished file (`src/export/sfnt.ts`), and verification reads it back and compares it with the source pair by pair. Not carried: contextual kerning (GPOS types 7 and 8 in the `kern` feature), language-specific kerning, Apple's class-based legacy `kern` subtables (formats 2 and 3; only format 0 is read), and mark positioning (the file has no GDEF). For a variable instance, kerning values with variation deltas are rounded to whole units, so the file can differ from the canvas by up to 1 unit per pair.
- **Line spacing** is the canvas's: the source's hhea ascender, descender, and line gap, also written as the OS/2 typographic metrics (OS/2 version 4) with `USE_TYPO_METRICS` set, so applications on every platform space lines alike. The Windows ascent and descent still grow to cover outlines that reach past them (Slipstream, Thorn), so only applications that ignore `USE_TYPO_METRICS` space lines further apart.
- Copied from the source: OS/2 weight and width class, style bits (`fsSelection`, kept consistent with head `macStyle`, with `USE_TYPO_METRICS` added), embedding permissions (`fsType`), panose, family class, sub- and superscript and strikeout metrics, x-height and cap height; the hhea line gap; the post italic angle, underline position and thickness, and fixed pitch. The Windows ascent and descent are the source's, raised if the new outlines reach further (Windows clips outside them). Name records copied: copyright, trademark, manufacturer, designer, vendor and designer URLs, license, and license URL; the description says the outlines were rebuilt with None-Curve. Entries the source lacks are left out instead of written as blanks. The bounding box in head and the CFF FontBBox are the real one: the union of every glyph's points, `.notdef` included. Fields the writer (opentype.js) cannot set — hhea line gap, head `macStyle`, head's bounding box (the writer leaves `.notdef` out and counts an empty glyph as reaching its advance), CFF FontBBox — are patched into the finished file, and tables it cannot write (GPOS) are added (`src/export/sfnt.ts`); the file is then re-checksummed.
- Rounding (`src/export/quantize.ts`): each contour is rounded to whole units, then repeated points, zero-length edges, and points on a straight line between their neighbours (including back-and-forth spikes) are removed. It must keep at least three points, its direction, and non-zero area, and gain no new self-crossings. A crossing counts as new only where the unrounded contour neither crossed itself nor ran within two units of itself — outlines that already overlap (common in fonts), or whose parts nearly touch, cannot avoid that at whole units, and the difference is below one unit. Rounding crossings are first repaired by removing one of the vertices involved; failing that, the contour is simplified very slightly (0.5–2 units) and rounded again. A collapsed contour smaller than 4 square units, or narrower on average than one unit (twice its area over its perimeter — a sliver that strong Experimental effects can squeeze out of a stroke), is left out on its own. Each rounded contour must also sit against the glyph's other contours as before; a new crossing between two contours is accepted only where both already ran within two units of each other, and a repair that would push a contour into another is passed over for the next attempt. Contours are rounded one after another, so if one leaves a neighbour no room, the glyph is rounded again in the reverse contour order. Crossing checks sweep segments sorted by x, so contours with thousands of points (Anchor spacing 1) stay fast; each contour is checked only against the contours whose boxes come within two steps of it, and an unrounded contour's own crossings are looked up in a grid of cells, so glyphs with thousands of contours stay fast too. A contour that already crosses itself more than 2,000 times (a tangle the Experimental merge left unmerged) is rounded once and kept as it is: only its direction, its area, and its place among the other contours are checked, since rounding noise there is below one unit and checking each of its many crossings took minutes. Measured on New York and Arial, no glyph is left out at the default settings, with Squaring at Square / All contours, with Anchor spacing 1, or with Distortion 40 (before: 42 New York glyphs at the defaults, including every "a", and 26 % with Square / All).
- **Build & verify**, then **Download .otf**. The file is reopened with fontkit and compared glyph by glyph (signature, family name, glyph count, line spacing and `USE_TYPO_METRICS`, every mapping, every advance, every contour point and direction, each glyph within ±32,767 and at most 32,766 units across, the bounding box in head and the CFF FontBBox, and the kerning), then loaded through the browser's font engine (`FontFace`, OTS sanitizer). The result names the kerning when the file carries it. If any check fails, no download is offered. Glyphs that cannot be stored are left out and listed with their reasons (at most 8 named, then "and N more"): "Left out of the font file: …". No precision setting applies: a font stores whole font units.
- Always filled, whatever **Fill** shows on the canvas; the dialog says so ("A font file is always filled").
- Not included: TTF / WOFF / WOFF2 output; contextual and language-specific kerning, ligatures, mark positioning, and other OpenType layout features (pair kerning is included, above); hinting; variation axes (a variable font exports the instance shown on the canvas); glyphs reachable only through layout features; characters above U+FFFF; outline parts beyond the 32,766-unit square (cut off, above). Coordinates are rounded to whole font units.

### Video

`src/export/recorder.ts`, `src/export/videoFormat.ts`, and `src/export/drawArtboard.ts`; the controls are in `src/components/RecordControls.tsx`, `RecordingCanvas.tsx`, and `RecordingIndicator.tsx`. A video records the canvas as it moves with the sound, in real time, with the sound itself. It is the one export that keeps the live look: SVG, PNG, and the font file use the slider values.

- **Where:** **Video — live sound** in the Export dialog, whose **Record** closes the dialog and starts the take in the same click; and the **Record** group at the bottom of the Sound tab, with Record / Stop, the time recorded ("0:12", or "0:12 / 0:30" for a timed take), "Live · N fps", the options, and how the last take ended. Both set the same options (`RecordOptionsFields`). During a take the header shows "Starting to record…", then "Recording 0:12" with a red dot and an icon-only Stop button ("Stop recording"), then "Saving the video…"; afterwards it shows how the take ended until you dismiss it (an icon-only "Dismiss" button) or start the next take. The header also announces the start and the end to screen readers. Opened again during a take, the dialog has its own Stop. Freeze is off while recording ("Freeze is off while recording.").
- **Options** (per visit: not saved, not undone, locked during a take):
  - **Format:** MP4 (default) or WebM. A format the browser cannot write is greyed out, such as "MP4 (not supported in this browser)".
  - **Length:** Until stopped (default), 5 s, 10 s, 15 s, 30 s, 60 s, or Whole file; at most 10 minutes. With a file, a take starts at the current Position. Whole file (only with an audio file loaded) plays the file from its start to its end with Loop off for the take, then gives Loop back.
  - **Include audio** (on by default): with the microphone, its sound goes into the file (it is still never played back).
  - **Use the preview look** (off by default): off records the canvas in its Color settings; on records the bottom-right preview's look, its colours (swapped with Invert) and its Blur, and the file name ends in `-video-preview`.
  - A line under them gives the size, the frame rate, and the format the take will write, such as "1200 × 800 px · up to 30 fps · MP4".
- **Record** is greyed out, with the reason as its hint, when the browser cannot record ("This browser cannot record video."), without a font ("Load a font to record."), with File chosen but no file ("Choose an audio file first."), and while the sound opens ("Opening the sound…"). It starts the file or the microphone if it is not running (inside the click), and at the end pauses the file or stops listening only if it started it. "Sound is not moving the letters: the video will be still." shows when Drive letters is off, Strength is 0 %, or no enabled mapping has a Depth.
- **Size and quality:** the canvas times its **Canvas size** multiplier, as for PNG, scaled down to fit 3840 px on the long side and 3840 × 2160 px in area (the size line then adds " (scaled down to the 4K limit)"), each side an even number. Each drawn live frame is one video frame, so the video runs at the live frame rate, up to 30 fps (there is no frame-rate option). Video bitrate: 4.5 bits per pixel, kept within 2–12 Mbps (12 Mbps is about 0.9 GB in 10 minutes, held in memory until the take is saved); audio 128 kbps. Videos have no transparency: the background colour is always painted, and with **Transparent background** on, a note says so.
- **Formats** (`videoFormat.ts`): MP4 tries H.264 High (`avc1.640028`), then Baseline (`avc1.42E01E`), then any H.264, then the browser's own MP4, with AAC audio (`mp4a.40.2`); WebM tries VP9, then VP8, then the browser's own WebM, with Opus audio. A type the recorder refuses falls through to the next. A browser that cannot write MP4 saves WebM and says "MP4 isn't supported in this browser: saved as WebM."
- **Drawing** (`drawArtboard.ts`, pure, tested with a fake painter): a hidden canvas (`RecordingCanvas`, present only during a take, attached to the page but out of sight) draws the scene the canvas shows, live shapes, every letter's own level, and its Thorn turn group's thorns included, at the place the slider letters give the block (see [Typography](#typography)), so the block holds as still in a video as on the canvas. It uses the SVG export's placement (the group transform, each glyph's position, slant, and flip, the nonzero fill rule, straight segments only; with **Fill** off it strokes each outline as the SVG does, see [Outlines only](#outlines-only-fill-off)) and builds each polygon's path once (`Path2D`). With the preview look, the blur is drawn over the glyphs through a layer of their own, as the SVG blurs their group; a browser without the canvas `filter` records without blur and says "Blur isn't available for video in this browser: recorded without it."
- **Capture** (`RecordingController` in `recorder.ts`, with its clock, timers, engine, browser checks, and recorder injected, so the tests run it with fakes): a take waits up to 30 s for the sound and the first drawn frame. It then captures the canvas with `captureStream(0)`, one video frame per drawing (`requestFrame`; `captureStream(30)` where that is missing), into a `MediaRecorder` that hands over its data every second. A canvas gives a frame only when it has changed, so for the first frame, for a frame at least every second, and for the last frame a still canvas is touched: one pixel is drawn onto itself (clipped), which counts as a change without looking different. When the take ends, the file is saved once, for example "Saved Roboto-Regular-video.mp4: 0:05, 1200 × 800 px." (file names `Family-Style-video.mp4` or `.webm`).
- **Sound in the file:** the engine's recording tap (`startRecordingAudio` in `engine.ts`) sends the running source (the file as heard, or the microphone) through a delay into a MediaStream destination. That branch reaches no speaker, so what you hear does not change. The delay lines the sound up with the letters: the live latency (the smoothed time from a measured sound frame to its letters reaching React; `liveLatencyMs` in `live.ts`) plus 37 ms (half the analysis window and one display frame), kept within 40–400 ms, or 90 ms before any live frame; it is set once, at the start of the take.
- **A take ends** at its length or at the 10-minute cap ("Stopped at the 10-minute limit."), when the sound pauses, stops, switches, or ends ("The sound stopped, so the recording ended."), when the tab is hidden ("Recording stopped because the tab was hidden."), when the canvas size or multiplier changes ("Recording stopped because the canvas size changed."), when the font is closed, when you press Stop, or after a recorder error ("Recording failed: …", keeping what was recorded). A take runs on a little, so its last frame is in the file: 100 ms after Stop, the cap, or the microphone stopping, and the audio's delay plus 100 ms when its length runs out or the file pauses or ends, so the end of the delayed sound is in it too. A hidden tab, an error, or a canvas or font change stops it at once. A take that recorded nothing saves nothing ("Nothing was recorded."). Closing the page during a take asks first. Other changes during a take, such as editing the text, are recorded as the canvas shows them.
- **Measured** (a Chromium browser, Roboto, the test track): 5 s takes at 1200 × 800 saved as WebM (`video/webm`, 266 KB, 4.92 s) and as MP4 (398 KB, 4.97 s) with the right frames; the Export dialog's Record, the MP4 → WebM fallback, and the stop on a hidden tab work as described; no long tasks while recording. The video is as smooth as the live frame rate: below 8 fps for 2 s the Record group warns "Too slow for a smooth video: try fewer effects or a shorter text." WebM files carry no duration. The audio's delay is an estimate. Other browsers are untested.

### Config file

`serializeConfig` and `parseConfig` in `src/state/persist.ts`; the dialog's **Config — settings (.json)** and **Import → Config file**.

- **Download config** saves `none-curve-Family-config.json` (`none-curve-config.json` without a font): the session that is [saved between visits](#saving-and-undo), the same keys and the same version, with `"app": "none-curve"` and `"kind": "config"` added, indented. The values are the sliders' own (live Sound values are never in it), Thorn's derived canvas diagonal is left out, and the text is capped at 10,000 characters as in storage. The dialog names the font the file will ask for. Saving needs no font.
- **Import → Config file** (or a `.json` file dropped on the canvas) reads the file as a saved session is read: migrated from older versions and checked leaf by leaf, so a damaged value becomes its default and unknown keys are dropped. A file that is not JSON ("The file is not valid JSON."), lacks the marker, or is larger than 1 MB is refused under the menu ("Config not imported") and nothing changes. A file from a newer version is read as far as it fits, and the notice says so.
- **Applied:** the settings, the text, the Sound mappings, and the Response group as one undo step; the canvas view's outline and layer buttons, the preview's Blur and Invert, and the export precision too, but those are never undone (as elsewhere). The font: a Google Fonts face is downloaded unless it is already open; a local file cannot be reopened, so the notice names it ("Its font is the local file X: import it to see the config as it was saved."). The selected glyph is restored when the font open (or the next one loaded) is the same family and style. The notice under the menu clears with its × button (Dismiss), the next font import, or **Reset all**.

## Sound

`src/sound/`, shown in the **Sound** tab (`src/components/SoundControls.tsx`); plan: [docs/SOUND_PLAN.md](docs/SOUND_PLAN.md). Phase 1 plays or listens, measures, and shows meters. Phase 2 lets the features move the sliders of the Geometry and Experimental tabs while a file plays or the microphone listens. Phase 3 is built in part: the three seeds are targets that jump with the sound, so every anchor lands somewhere new; Beat is a feature that a mapping can follow; picking a target switches on what it needs; and ten presets set the letters up and fill in the mappings. Phase 4's Pitch and stereo Pan are built too (the 20 features first measured were merged into 10; Melody, added with the Response group, makes 11). The **Response** group scales how far the sound moves the letters and can make each letter react by its own amount, and the **Record** group records a video (see [Video](#video)). Step mappings (Allowed directions, Sides, Rings) are still to come in phase 3.

- **Sources:** **File** (the default: Choose file, Play / Pause, Loop, Position) and **Microphone** (Start listening / Stop listening; choosing it only shows these and pauses the file, and the microphone opens only when you press Start listening). There is no Off source: Pause stops a file and Stop listening the microphone, and choosing File releases the microphone. While the microphone listens, the tab shows **Listening** and the status bar **Microphone on**.
- **Meters** (the **Levels** group): one compact line per feature (label, bar, number) under five small group headings, **Loudness**, **Bands**, **Tone**, **Rhythm**, and **Stereo**, each with an ⓘ that explains its meters in plain words. The numbers show Level in dB, Pitch in Hz, Pan as the side it leans to ("L 40", "R 40", or "C" within 5 % of the centre), and every other feature in percent; "—" with nothing to read. Pan's bar fills from the centre, to the left or to the right. **Beat** is a pulse bar that jumps to full on each onset and falls back with **Release**; it replaces the earlier lights. **Melody** (in Tone, after Pitch) is a pulse too, on each new note. Each bar is a `role="meter"` (Pan −100 to 100) whose spoken value says the same ("40 percent left", "Centre", "No reading"). The meters are written to the DOM from a per-frame callback, with no React state per frame: the bars every frame, the numbers at most about 10 times a second, the spoken values at most 4 times. The bars move without transitions, so they look the same with `prefers-reduced-motion`.
- **Mappings** (between Levels and Response):
  - **Drive letters** (an on/off switch: a checkbox with `role="switch"`, drawn as a small track and knob in the theme's colours): sound moves the letters only while this is on and a file plays or the microphone listens. It is on at the start, unless the system asks for reduced motion (`prefers-reduced-motion`): then it starts off and the tab says "Off because your system asks for reduced motion." (the note is also the switch's description). Turning reduced motion on during the visit switches it off too; turning it off leaves the switch as it is. With **Strength** at 0 % a note under it says "Strength is 0%: the letters hold still."
  - **Preset** and **Load** (`PRESETS` and `presetSettings` in `presets.ts`): ready-made set-ups to start from, with an ⓘ that says what Load resets and lists each preset with one line. Choosing in the list only selects (it starts on Flicker), so moving through it with the keyboard replaces nothing. **Load**:
    1. resets every Geometry and Experimental group (Curve flattening, Random anchors, Squaring, Anchors, Grid & angles, Distortion, and the Experimental effects) to its defaults, keeping the three seeds; Typography, Color, the canvas, and the Sound tab's source, Drive letters, and Response group are left alone;
    2. sets the preset's start values (only what differs from the defaults), as one parameter update per group that changed;
    3. replaces every mapping with the preset's rows, and clears the earlier row notices;
    4. shows a status line under the Preset row: "Loaded Flicker.", then "Turned off Crumple and Ripple." for the Experimental effects it turned off, "Turned off Random anchors." when it did, and "Other Geometry and Experimental settings back to defaults (seeds kept)." when any other setting the preset does not set went back to its default. It stays until the next Load or until another preset is chosen in the list.

    Load is a single undo step that brings back the earlier settings and mappings (see [Saving and undo](#saving-and-undo)). So a preset always starts from the same letters, whatever was set before, and its rows need nothing switched on; should one still need something, it is switched on as when its target is picked by hand, in row order, with the row's notice. Picking a target by hand still only switches on what it needs (below); it resets nothing. The presets, with Depth (or Rate, on a seed) in brackets, then the start values:
    - **Flicker:** Level → Distortion · Noise amplitude (+90 %), Beat → Distortion · Noise amplitude (+30 %), Beat → Distortion · Seed (Rate 100 %). Start: few anchors on (see [Vertex distortion](#vertex-distortion)), Noise amplitude 2, Normal bias 90 %. The tiny amplitude keeps Distortion on, so the Seed row acts while it is quiet.
    - **Scatter:** Level → Random anchors · Randomness (+90 %), Level → Random anchors · Density (−9 %), Beat → Random anchors · Seed (Rate 50 %). Start: Use random anchors on, Density 10, Randomness 5 %.
    - **Pixel:** Bass → Grid & angles · Grid size (+70 %), Treble → Anchors · Anchor reduction (+40 %). Start: Snap to grid on.
    - **Low poly:** Level → Curve flattening · Tolerance (+70 %), Brightness → Anchors · Anchor reduction (+40 %). Start: Merge joined curves on, so a large Tolerance reaches whole bowls.
    - **Block:** Swell → Squaring · Amount (+90 %), Beat → Squaring · Amount (+30 %). Start: the defaults.
    - **Jitter:** Treble → Distortion · Noise amplitude (+60 %), Brightness → Distortion · Noise frequency (+30 %). Start: Noise amplitude 2 (so the Noise frequency row acts while it is quiet), Noise frequency 20.
    - **Facet:** Level → Curve flattening · Segments per curve (−15 %), Beat → Curve flattening · Segments per curve (−5 %), Pitch → Curve flattening · Segments per curve (+20 %). Start: Mode Fixed segments, Merge joined curves on, Segments per curve 6.
    - **Bloom:** Beat → Ripple · Amount (+10 %), Bass → Ripple · Petals (+5 %: the petals go to 10 % once the bass is up, since 20 % is hard to read). Start: Use ripple on, Amount 30 %.
    - **Flare:** Beat → Seed (Rate 100 %), Level → Thorn · Reach (+50 %: half the cubic slider at full level, an eighth of the canvas diagonal, about 3.8 em on the default canvas), Beat → Thorn · Anchors (+15 %). Start: Use thorn on, Anchors 1, Reach 0 % (no thorns, and no root pull, while it is quiet), Root 25 % (a shallower root keeps the strokes readable). With Thorn on, all three rows reach the letters by Thorn turns, a few letters at a time (see Thorn turns below), so a beat no longer re-picks or multiplies every letter's thorns at once.
    - **Gale:** Level → Slipstream · Slip (+50 %), Beat → Slipstream · Cuts (+40 %), Activity → Slipstream · Trails (+35 %). Start: Use slipstream on, Strength 0 %, Slip 0, Cuts 0, Trails 0: nothing streams while it is quiet, and there is no stretch, which would push the letters into their neighbours.
  - Up to 8 rows (`MAPPING_LIMITS.maxMappings`), each with a **Feature** (the 11 features, grouped as the meters are), a **Target** (grouped Geometry / Experimental, named "Section · Label", such as "Distortion · Noise amplitude", or just "Seed" for the Experimental tab's seed), a **Depth** (−100 % to +100 % in steps of 1 %, with a number box), an on/off switch ("Use mapping 1", "Use mapping 2", …), and a remove button ("Remove mapping 1", …; it hands keyboard focus to the next row's remove button, else the previous one's, else Add mapping). On a seed the Depth slider reads **Rate** (0–100 % in steps of 1 %, with its own ⓘ; see Seeds below), and a negative Depth turns positive when the row switches to a seed. **Add mapping** adds Level → Distortion · Noise amplitude at +50 % (once that target is used, the first target no row uses yet that already acts, else the first unused one) and switches on what it needs, as picking a target does; with 8 rows it adds nothing (it stays focusable, `aria-disabled`) and the tab says "Up to 8 mappings." Mappings are saved in the browser with the settings and restored on the next visit, and every change to them can be undone; Drive letters is not saved (see [Saving and undo](#saving-and-undo)).
  - **Switching on what a target needs:** picking a target that does nothing with the current settings changes what it needs (switches its step or effect on, sets a Mode, or turns Random anchors off for the Curve flattening sliders) and says so under the row, for example "Turned on Ripple.", "Set Noise amplitude to 40.", or "Turned off Random anchors. Set Mode to Adaptive." (the rules are in the table below). The notice is a status line that stays until the row's target changes again or the row is removed. Switching a row to another target, or removing it, never switches anything off. With the keyboard, moving through the Target list (arrow keys, or typing on the closed list) switches things on only on Enter or when focus leaves the list, so the targets passed on the way change no setting; a pick with the mouse switches them on at once.
  - Whenever a row's target does nothing right now (for example, because its setting was turned off again later), a note under the row says why instead of the notice (the notes are in the table below; the note is also the Target select's description). An **Enable** button beside it ("Enable, mapping 1", …) makes the same changes as picking the target, shows the notice, and hands keyboard focus to the row's Target. Until then the row moves nothing.

- **Modulation** (`modulate`, pure): for each slider target with at least one enabled mapping whose Depth is not 0 and whose step or effect is on, the live position is the slider's position (0–1 along the slider as drawn) plus the sum of Depth × feature over those mappings, clamped to 0–1, then converted back to a value and rounded to the slider's step. Positions are measured along the slider, so the log-scaled Tolerance moves evenly along its slider, not evenly in font units. Mappings on one target add up, and **Strength** multiplies the sum, before clamping. With **Melody tracking** above 0, every slider mapping's feature first gains 0.5 × Melody tracking × the Melody pulse (capped at 1; not Pan, not a Melody row; `RESPONSE_LIMITS.melodyBoost`). Pan is the only two-sided feature (−1 to 1): at a positive Depth it moves a slider down for sound on the left and up for sound on the right; every other feature runs 0–1. When nothing contributes (no mapping, all off, Depth 0, every feature at 0, no seed moved on, or every target inactive), the slider values themselves are returned (the same object), so the letters go back exactly. Every live frame is therefore a parameter set the sliders and seed fields can produce (no new geometry, no tweening between frames), and so is every letter on screen when letters react by different amounts or show Thorn turns (see Letters and Thorn turns below). With the Response group at its defaults (Strength 100 %, the other three 0), the values are bit for bit those of Sound before the group existed (`tests/sound/neutral.test.ts`).
- **Seeds** (jump targets; `JumpTracker` in `jumps.ts`, pure): a mapping to a seed takes no part in the sum above. Instead the seed moves on by one on each jump (past 999,999 it wraps to 0), so every anchor (Distortion, Random anchors) or every fold, gust, slip, cut, trail, thorn, and flute (Experimental) lands somewhere new (while Thorn is on, the Experimental seed and the Random anchors seed reach the letters by Thorn turns, a few letters at a time; see below); with Distortion's few anchors (Flicker), a new few anchors of each letter move instead. The row's **Rate** sets how often, multiplied by **Strength** (still at most 100 %); the sign of Depth is ignored. Melody tracking does not boost seeds.
  - With **Beat**, the seed counts onsets: Rate 100 % moves on at every onset, 50 % at every other one, 25 % at every fourth.
  - With any other feature, it jumps at up to 4.8 times a second × Rate × the feature's value (Pan on either side). A gap of more than 100 ms between frames counts as 100 ms, so a stall releases no burst of jumps.
  - **Flash limit:** a jump frame is a large change taken from the one flash budget that the driven sliders share (see Flash limit below): at most 6 large changes in any 1.25 s from all seeds and sliders together, that is 3 flashes a second (seeds that jump in the same frame count once, and so do a frame's jumps and slider turns). A jump beyond it is skipped, not put off, so seeds jump less often while driven sliders are busy.
  - Jumps are counted only while Sound can drive the letters and the seed's target acts. Pausing, stopping, or turning Drive letters off returns every seed to its field's value (exact restore), and playing again starts from there; the flash window is kept, and the return counts in it, so a quick pause and play cannot let a second burst through. A seed no longer driven (its mapping off, removed, or moved to another target) goes back to its field's value on the next frame.
  - While a seed is driven, a small live number appears next to its field (`src/components/LiveSeed.tsx`, with the tooltip "Live seed", hidden from screen readers, updated at most about 15 times a second), and the Distortion and Random anchors statistics show the live seed. The field keeps its own value.
- **Letters** (`letters.ts`, pure; on while **Motion contrast** or **Pitch reactive** is above 0): each letter, one glyph occurrence of the text counted as `placePolygons` counts them (lines, then glyphs; spaces and missing glyphs included), gets a weight every frame and with it one of three levels, fixed per setting: quiet, shared, and strong. The shared level is the live values above, the ones the markers, the live seeds, the statistics, and Freeze use. A quiet or strong letter shows the shared values with every driven slider's offset from its slider value scaled by the level's gain, then clamped and rounded to the slider's step, so each letter on screen is still a result the sliders and seed fields could produce, and without Thorn a frame needs at most three parameter sets. Levels never scale Thorn's sliders, and while Thorn is on they leave every Thorn turn target unscaled, at its turn group's value (see Thorn turns below; `levelPosition`), so a strong letter no longer gets many times the reach. The seeds are the same at every level (while Thorn is on, the Experimental and Random anchors seeds come from each letter's turn group). A letter must pass a level's boundary by a margin to change level (hysteresis), so a letter near it does not flicker. After a text edit every letter shows the shared level until the next frame; the same text set differently (tracking, line height, alignment, slant) keeps its letters' levels. Known limit: on a slider with few steps that levels scale (such as Ripple · Sides, Whorl · Rings and Sides, or Curve flattening · Segments per curve, with Thorn off), letters spread apart only once the shared value has left the slider value's own step.
  - **Motion contrast** (0–100 %): each letter's gain mixes a stable share of its own with a slow wave (6 s), shifted from letter to letter, so which letters lead drifts every few seconds. The gains spread evenly around 1, between 1/3.6 and 3.6 at 100 % (3.6 to the power of the setting), so at 100 % about 17 % of the letters sit on the quiet level, 67 % on the shared level, and 17 % on the strong level. Strength sets the overall amount; Motion contrast the spread.
  - **Pitch reactive** (0–200 %): the low notes of the recent melody move the letters on the left more, its high notes those on the right, so a tune sweeps the whole text whatever its register. Each letter's weight is a bell around the pitch's place across the text block, which is where the pitch sits in the melody's range (`pitchPlace`, from the frame's `pitchLow` and `pitchHigh`; see Pitch under `features.ts` below). The range starts as an octave around the first settled note, widens to a new higher or lower note in about 0.15 s, closes in on the last note over about 8 s, and starts afresh with the first note after 8 s without one. It is always at least an octave wide, so a steady voice does not sweep the text with every wobble, and notes within a semitone of either end of Pitch's 55–1760 Hz scale are ignored (a chord or a drum reads there). On the first rise through a melody the range widens with each new note, so each new highest note sits at the right edge; once the range has been heard, each note gets its own place. It needs a clear single note, such as a voice or one instrument. Known limit: at 200 %, a fast octave leap can occasionally be held back by the flash limit (on C4 and C5 in turn, 2 notes a second, 10 of the 11 leaps land, against all 11 at 100 %).
- **Thorn turns** (`THORN_TURNS` in `types.ts`; `isTurnTarget`, `turnGroups`, `ThornTurns`, and `turnSets` in `letters.ts`; the scheduler in `live.ts`): while Sound drives the letters and Thorn is on in the live values, the settings that decide where the thorns sit and which way they point reach the letters a few at a time, so the sound does not change every letter's thorns at once.
  - **What goes by turns** (the turn targets, `isTurnTarget`): Thorn's sliders (Anchors, Reach, Root, Spread, Width, Refraction, Flute width, Burst anchors, Dent), the Experimental **Seed** (Crumple and Slipstream share it, so they re-seed by turns too), every Geometry target before Distortion (Curve flattening, Squaring, Anchor spacing and Anchor reduction, Grid size, and Random anchors with its seed: Thorn picks its anchors on the letter they make), and every slider of Crumple, Ripple, Whorl, and Slipstream except Crumple's and Ripple's **Amount**. Distortion's four targets (Noise amplitude, Noise frequency, Normal bias, and its Seed) and those two Amounts stay continuous and shared (the sliders among them scaled by levels as before): the thorns keep their anchors and directions through their moves (see Thorn under [Experimental](#experimental-crumple-ripple-whorl-slipstream-and-thorn)). Levels (Motion contrast, Pitch reactive) never scale the turn targets while Thorn is on.
  - **Groups** (`turnGroups`): the drawn letters (as `letterSlots` counts them) fall into 5 turn groups of whole glyph ids, so every occurrence of a glyph turns with the others and a group costs no extra geometry. Each group holds at most ceil(N / 5) of the N drawn letters; glyphs go largest first (ties in the order of a hash of the glyph id) to the group with the most room, so a group's letters lie all over the text rather than in reading order, and only a glyph that fits whole in no group is split by occurrence. With fewer than 5 letters, some groups hold none. The same letters set differently keep their groups.
  - **Turns** (`ThornTurns`): each letter shows the turn state its group took at its last turn, with its level's other values (`turnSets`). Once the last turn has reached the screen and 250 ms (`THORN_TURNS.gapMs`) have passed, the next group, round robin, takes the live turn state if it differs from its own: another seed or number of thorns, a slider at least half a flash swing (5 % of its travel) away, or a slider the sound has put back on its own value. While another group differs, a group whose state does not, or that holds no letter, gives its turn up (the turn passes 250 ms on with nothing changed). So the thorns of at most about a fifth of the letters change every 250 ms, and each letter's at most once every 1.25 s (5 × 250 ms), however long or short the text.
  - **Flash limit:** a large turn (the group's share of the text times how far its turn targets' sliders move, a new seed counting as a whole travel, at least 10 % of a slider's travel) takes from the one flash budget, like letters moving between levels; a turn the budget refuses waits (the group keeps its state) and is asked again on the next update, never dropped.
  - **Starting afresh:** every group takes the live state at once, with no turn and nothing charged, when Sound starts driving the letters, when Thorn is switched on, and when the letters of the text change (a text edit, or a font or text case that changes the glyphs; the same text restyled keeps its groups). A mapping added or removed starts nothing afresh: its changes come by turns. A turn target moved by hand that the sound does not drive reaches every group at once, as without Sound.
  - The markers, the live seeds, the status, and Freeze keep to the shared live values, not a group's. Every letter still shows ordinary in-range slider values and seeds (its group's turn state with its level's other values), so it is still a result the sliders and seed fields could produce; outputs stay `M`/`L`/`Z` only. The letters of a live frame can now show up to 15 parameter sets (3 levels × 5 groups). Its one request asks for each set only for the glyphs of the letters that show it, and always holds the shared set too, for its letters' glyphs and the selected glyph (for its statistics; `FrameJob.within`): up to 16 sets.
  - With Thorn off there are no turns: the scheduler's requests, commits, and Freeze are exactly as before (`tests/sound/neutral.test.ts` pins every preset but Flare, whose start turns Thorn on; `tests/sound/turns.test.ts` tests the turns and Flare).
  - **Measured** (Node, end to end, EB Garamond at 187 px, "Hello / This is / Ming", neutral Response, a Flare-like stack, against develop before this change): letters' thorns changed 7.2 times a second instead of 283.9 (every change of shape, Distortion and the two Amounts included: 7.4 instead of 299.7); at most 3 letters' thorns changed in any 250 ms instead of 15; the shortest time between two thorn changes of one letter was 1331 ms instead of 33; the block moved 0 px; the geometry computed for 135 ms a second instead of 340; no curves. In a real browser (headless Chrome, Roboto, "Hello / This is / Ming", 15 letters, Thorn with 3 anchors, Crumple, Ripple, and Distortion, the mappings Beat → Seed, Level → Thorn · Reach, Beat → Thorn · Anchors, and Level → Distortion · Noise amplitude, the 42 s test track): one block position over 8 s, at most 3 letters changed per 250 ms, a shortest gap of 1533 ms between two changes of one letter, 7.9 changes a second, no curves, and Live 30 fps.
- **Live scheduling** (`useLiveFrame` and `useLiveLetters`, each called once in `App.tsx`): Sound drives the letters while a font is loaded, a file plays or the microphone listens, Drive letters is on, Strength is above 0 %, and a mapping acts on an active target (a slider or a seed). With no font loaded, Sound waits: nothing moves, the markers stay hidden, and the seeds do not jump. Every measured frame first moves the driven seeds on (when they jump) and is then modulated, but a new live parameter set goes to the geometry only when it differs from the last one sent, no geometry request is in flight, and at least 33 ms have passed. So the frame rate follows the cost, capped at 30 fps. The scheduler asks the geometry worker for a live frame's glyphs first, in one request (`geometryClient.prefetchJobs`): the shared parameter set for the glyphs the canvas shows, then the strong and the quiet set for the glyphs of the letters on them (with Thorn turns, the shared set only for the glyphs of the letters that show it and the selected glyph, then every other set for the glyphs of its letters). It hands the frame to React only once they have all arrived, at most 30 times a second, so each live frame renders once, complete, and never mixes two frames. The snap grid on the canvas follows the live Grid size, the preview shows the live frame, and the status bar's View line describes the parameters shown. SVG, PNG, and font exports keep using the slider values (a video records the live frame), and so do **Fit text** and **Free** (Typography) and dragging free text, which measure the slider letters (`loadSliderScene` in `useDerivedGeometry.ts`; while Sound drives, glyphs the sliders need are computed in the geometry worker first), so a live frame never leaks into the text's position; the block's place itself comes from the slider letters while Sound drives, so Sound never moves it (see [Typography](#typography)). When Sound stops driving (paused, stopped listening, Drive letters off, Strength 0 %, no mapping acts, or the font is gone), the canvas goes straight back to the slider values and seed fields, and the markers and live seeds disappear.
- **Flash limit** (`FlashBudget` and `FLASH_LIMITS` in `flash.ts`, `FlashLimiter` in `live.ts`): one budget of large changes shared by every driven slider and every driven seed (above), so Sound makes at most 3 flashes a second however many mappings it has: at most 6 large changes (edges) in any 1.25 s, so frames that reach the screen a little later still keep to it. A frame is an edge when the driven sliders' moves back add up to 10 % or more of a slider's travel: one slider turning back that far, or several smaller turns together. Turns are counted on the slider positions as shown (after rounding to the step); edges of one measured frame count once, and the exact restore when Sound stops driving spends one edge. When the budget is spent, the sliders moving back keep their last values until it frees up; the others pass. Held values are values the slider produced a moment earlier, and the markers and Freeze use the same values as the screen. The limit holds for every letter on screen: while letters react by different amounts, a slider's move back counts as the largest among the shared value and every level that letters show (holding the shared value holds every level), and letters moving from one level to another are a change of their own from the same budget, measured as each moving letter's share of the text times how far its two levels' sliders lie apart (an edge from 10 % of a slider's travel). That move is measured from the levels on screen and from those of every frame shown within the last 250 ms (`LIVE_LIMITS.switchSpanMs`), whichever is larger, so a note change that reaches the screen over several frames (the pitch is smoothed) counts as the one change it shows as; after a move that took from the budget, the measuring starts afresh from the frame that shows it. When the budget is spent, every letter keeps the level it shows. A large Thorn turn takes from the same budget, and waits while it is spent (see Thorn turns above).
- **Live cache:** live requests carry `live: true` (`protocol.ts`). A compute request holds a list of `jobs`, each a parameter set with its glyphs; the worker runs them in order, sends each job's results under its own key, names the key and the glyph in its heartbeat, and ends the request with one `done`. The worker keeps live results in a second, smaller cache per font (600 glyphs or 200 000 points; `glyphGeometry(…, live)` in `cache.ts`), and the page keeps the results of the live parameter sets of the frame on screen and the one being computed: twice the most sets one of the last four live requests asked for, at least 6 (frames of up to three levels) and at most 32 (`LIVE_KEPT_KEYS`; with Thorn turns a frame can ask for up to 16 sets: the 15 its letters can show, three levels times five groups, and the shared set), dropping the least recently asked for first (`geometryClient.ts`), so a song never evicts the results of normal editing. Only the shared set's results stand in for a glyph while newer ones are computed.
- **Live markers** (`src/components/LiveMarker.tsx`): each target slider is wrapped in a `.live-slider` span; while Sound drives it, a thin accent line over the track shows its live position, lined up with where the thumb would be. Markers update at most about 15 times a second and are hidden from screen readers. The sliders keep their own values. (A seed shows its live number instead; see Seeds above.)
- **Frame rate:** while Sound drives the letters, the tab and the status bar (before **Microphone on**) show "Live · N fps", where N is how many live results per second the geometry keeps up with (1000 ms ÷ the smoothed time from sending a frame to its last result, every level included, at most 30), so it holds steady while the live values stay the same. It is the geometry rate, not how often the sound is read (every animation frame, see `engine.ts` below). Below 8 fps for 2 s, the tab warns "Too slow to follow the sound: try fewer effects or a shorter text." (with Motion contrast or Pitch reactive above 0: "Too slow to follow the sound: try fewer effects, a shorter text, or less Motion contrast and Pitch reactive.").
- **Freeze** (available while Sound drives the letters; `aria-disabled` otherwise, and while a video records, so it keeps keyboard focus): writes the shared live values on screen (the ones the markers show) into the sliders and the live seeds into the seed fields (one parameter update per changed group, one undo step together) and pauses the sound (pauses the file or stops listening), so the frozen look stays on screen and can be exported. Letters that reacted more or less, and letters whose Thorn turn group still shows earlier thorn settings, take the shared values. Their shape is usually already computed, so the switch is instant; but while a turn group shows other thorn settings, a frame computes the shared values only for the glyphs of the letters that show them, so the other glyphs are computed then. Pressed while the shared live values match the sliders (for example between two drum hits), it only pauses. SVG, PNG, and font exports always use the slider values; while Sound drives the letters, the Export dialog says so and points to Freeze. A video records the live look instead (see [Video](#video)).
- **Response** (the group after Mappings; `ResponseSettings` and `RESPONSE_LIMITS` in `types.ts`): six sliders, each with an ⓘ, saved with the session and undone like other sliders, and left alone by presets:
  - **Sensitivity** (−24 to +24 dB in steps of 1, default 0): added to the input before measuring.
  - **Strength** (0–400 % in steps of 1 %, default 100 %): multiplies how far every mapping moves the letters (the slider sums and the seeds' Rate, above). 0 % holds the letters still (Sound stops driving); above 100 % the flash limit holds moves back more often.
  - **Motion contrast** (0–100 % in steps of 1 %, default 0): lets each letter react by its own amount (see Letters above). While Thorn is on, it leaves the Thorn turn targets alone (see Thorn turns above). It can lower the frame rate.
  - **Release** (20–1000 ms in steps of 1 ms, default 150 ms; formerly Smoothing): how slowly the readings fall back after a sound; they rise at once. It also sets how fast the Beat and Melody pulses fall back.
  - **Pitch reactive** (0–200 % in steps of 1 %, default 0): the low notes of the recent melody move the letters on the left more, its high notes those on the right (see Letters above); while Thorn is on, it leaves the Thorn turn targets alone, as Motion contrast does. Its ⓘ reads "The low notes of the melody move the letters on the left more, its high notes those on the right, so a tune sweeps across the text. Follows the range of the last few seconds of notes. Needs a clear note, such as a voice or one instrument. Can lower the frame rate."
  - **Melody tracking** (0–200 % in steps of 1 %, default 0): adds movement each time the melody moves to a new note, even at a steady loudness, by adding the Melody pulse to every slider mapping's feature (see Modulation above).
  - **Reset sound** puts all six back to their defaults in one undo step; it is greyed out while all six are at their defaults.

Modules:

- `types.ts`: the shared types (`FeatureFrame` with every feature, the pitch confidence, and the melody's range, `StereoSamples`), `SOUND_LIMITS` (the measuring limits and the file size limit below; the analyser's dB range and the position update rate are set in `engine.ts`), `SILENT_FRAME`, and the initial state; the Response group's values: `FeatureSettings` (Sensitivity and Release, the engine's), `ResponseSettings` with `RESPONSE_LIMITS`, `NEUTRAL_RESPONSE`, and `clampResponse` (Strength, Motion contrast, Pitch reactive, Melody tracking), and `SoundSettings`, all six as saved and undone; `THORN_TURNS` (`groups: 5`, `gapMs: 250`; see Thorn turns above).
- `features.ts`: `FeatureExtractor`, pure (no DOM, no Web Audio), so it can be tested on synthetic signals. Each frame it takes the analyser's spectrum (fftSize / 2 bins in dBFS; bin k is centred at k × sample rate / fftSize), its time-domain samples (the channels mixed down), and the left and right channels' samples, and it allocates nothing but the frame it returns.
  - **Level:** 20 log10 of the RMS of the samples with their mean (DC offset) removed, plus Sensitivity; −60 dB reads 0 and 0 dB reads 1. Below −60 dB after Sensitivity the frame counts as silent: every continuous feature falls to 0 (Activity's pace as the onsets leave its window) and no onset fires.
  - **Swell:** Level, smoothed with its own time constants, 300 ms while rising and 2 s while falling, whatever Release says.
  - **Bands:** **Bass** (20–250 Hz), **Mids** (250–2000 Hz), and **Treble** (2000 Hz – Nyquist): the energy (sum of squared linear magnitudes) of the bins centred in the band, in dB plus Sensitivity. Each band keeps its own running maximum that follows a rise at once and otherwise halves in energy every 3 s. A band reads 1 at its maximum and 0 at 40 dB below it or at −68 dB, whichever is higher. −68 dB is the silence threshold in band terms, because the Blackman-windowed spectrum puts band energy about 8 dB under the RMS level. Hiss below the silence threshold therefore reads 0 even while another band is loud. (The six narrow bands of earlier versions are gone; these three are the former Low, Mid, and High.)
  - **Brightness:** the spectral centroid (magnitude-weighted mean frequency of the bins from 20 Hz to 20 kHz, so ultrasonic hiss at high sample rates does not count) on a log scale, 100 Hz → 0, 8 kHz → 1.
  - **Pitch:** the fundamental by YIN on the samples decimated to at most 24 kHz (the mean of each run): the first lag between 1/1760 s and 1/55 s whose cumulative-mean-normalised difference falls below 0.15, walked on to its local minimum and refined by a parabola. 55 Hz reads 0 and 1760 Hz reads 1, on a log scale (5 octaves). A frame with no such lag (unvoiced: noise, drums) holds the last note; silence sends it to 0. It follows with 30 ms both ways, and falls to 0 on silence with the release time. With it comes a **pitch confidence** (0–1): how sure Pitch is, low for a quiet or unclear note and 0 while unvoiced or silent. It is not a feature a mapping can follow; Melody and Pitch reactive use it. With it also comes the **melody's range** (`pitchLow` to `pitchHigh`, on Pitch's 0–1; `followRange` and `melodyRange`), where Pitch reactive places the pitch: from the lowest to the highest note Melody settled on lately. A new lowest or highest note widens it with a time constant of 150 ms (`melodyRangeAttackMs`), and both ends close in on the note heard (between notes, the last one) with 8 s (`melodyRangeReleaseMs`); the first note more than 8 s after the last starts it afresh, as an octave around that note. It is at least an octave wide around its notes (`melodyRangeMinSt`, 12 semitones), within 0–1. A note still settling after a fresh start (a slide into it), the frames Melody leaves its settled note at (a drum hit, an octave error, vibrato), and notes within a semitone of either end of the scale are left out (a chord or the full mix reads near 55 Hz with high confidence). It reads 0 and 1 (all of Pitch) until a note is heard, and it is not a feature a mapping can follow either.
  - **Melody:** a pulse on each new note. When the pitch moves at least half a semitone from the note it settled on and holds there for 70 ms, Melody jumps to the size of the move (full at 2 semitones) times the pitch confidence, then falls with the release time. A steady note, vibrato up to about ±80 cents at 5 to 7 Hz, noise, an octave error or a drum hit under a held note, and the first note after silence (a short slide into it included) give none. Known limits: wide, slow vibrato can still give a few pulses, and notes shorter than about 200 ms can be missed.
  - **Release:** each continuous feature follows its target with a one-pole filter, a = 1 − exp(−dt / τ), where τ is 10 ms while rising and Release while falling; Swell and Pitch have their own time constants (above), and Pan follows with Release both ways. The first frame after a reset jumps straight to the target.
  - **Beat:** two onset detectors on spectral flux, the sum of the rises of the compressed magnitudes ln(1 + 1000 g m), where g = 10^(Sensitivity / 20): one over the bins from 20 Hz up (full band), and one over 20–150 Hz only (the kick detector), because a bass drum can hide in the full-band flux under broadband sound. A detector fires when its flux exceeds the median of the last second × 1.5 (the kick detector: × 3, because its few bins make steady noise jumpy) plus a small fixed floor (`fluxFloor`, `kickFluxFloor`), and also exceeds half its last onset's flux, decaying with a 120 ms time constant (so the noisy tail of a snare, clap, or reverb does not fire again); at least 100 ms after its previous onset, in a frame that is not silent, and once at least 250 ms of history has built up (so none fires right after a reset). An energy gate (`onsetRiseDb`, `onsetRiseWindowMs`, `onsetRiseBandsHz`, `onsetRiseResetDb`) must also let it through: the energy of each octave band from 20 Hz (in dB after Sensitivity, never below the silence threshold) is compared with that band's loudest in the last 100 ms, and a detector fires only while a band it listens to has risen at least 2 dB above that (the kick detector listens to the bands that start below 150 Hz, the full-band detector to all). A band's earlier entries stop counting once it has fallen 12 dB below them, so a second hit as loud as the first still counts after the sound died away between them. Without the gate, a steady low note rich in harmonics (a sawtooth or buzzy bass) fired Beat 5–11 times a second, because its flux beats against the frame rate; it now gives no beats, while kicks and hats over it still do. Known limit: a hit masked by a louder sound in its own octave (a kick 12 dB under a bass note) is missed. Every kick also fires the full-band detector (within its 100 ms gap), so one hit heard by both gives one onset (`onset` in the frame, which seeds count). Onsets are judged at most about 60 times a second (on faster displays, against the spectrum of about 1/60 s earlier), so the floors mean the same at any display rate. A gap of more than 500 ms between frames (a hidden tab) restarts the onset history but keeps the smoothing and the band maxima. The feature **Beat** is a pulse: 1 on a frame where either detector fires, then falling exponentially with the release time; it is the larger of the two detectors' pulses, since a kick within 100 ms of an onset is no new onset but still restarts its own pulse.
  - **Activity:** how busy the sound is, the larger of two readings, smoothed together. **Change:** how far the full-band flux of the last judged frame rises above the full-band detector's median of the last second, against the largest such rise lately (a running maximum that halves every 3 s like the bands' maxima), but never against less than `fluxFloor` or a quarter of the frame's compressed spectrum (the sum of the compressed magnitudes the flux compares); in silence it falls to 0. The median takes out the flux that steady noise always has, and the quarter keeps a steady sound's own jitter low however long it lasts: near 0 on steady sound, tones and noise alike (under 0.15 over 25 s of a 110 Hz sawtooth, a chord, or white or pink noise; a 55 Hz sawtooth's buzz beats against the frame rate and reads about 0.28), and high on attacks after quiet; an onset over loud noise shows only a little. **Pace:** the onsets in the last 2 s, as onsets a second, ÷ 8 (8 a second read 1). Activity takes the larger, not the mean, which would halve the range and never reach 1: a hit reads high at once, and quick beats keep it up between hits (on the test track about 0.38 on the kick alone and 0.91–1 with hi-hats).
  - **Pan:** (R − L) / (R + L) of the left and right RMS (DC offset removed), from −1 (left) to +1 (right). It reads 0 in silence and without the two channels. A file is measured in stereo; a microphone is usually mono, so it reads centred. (The stereo width of earlier versions is gone.)
- `engine.ts`: `SoundEngine` and the page's single instance, `getSoundEngine()`.
  - One `AudioContext`, created inside the first user gesture that needs it (choosing a file or a source, Play, Start listening), resumed by Play and Start listening, and suspended after 2 s with nothing playing or listening. Sources feed a 20 Hz high-pass that removes DC offset from what is measured (not from playback). After it, one `AnalyserNode` hears the channels mixed down (FFT size 2048 at 44.1 and 48 kHz, doubled at 88.2 and 96 kHz so the window stays about 43 ms; no smoothing of its own; −100 to 0 dB), and a stereo branch gives Pan: a gain node that makes exactly two channels by the speaker rules (mono becomes identical left and right, more channels mix down), a channel splitter, and one more analyser for each side (same FFT size, no smoothing). The extractor is reset on every source change and new file.
  - **Reading a frame:** the three analysers are read one after another, and the audio thread can render in between (in Chrome up to one frame in 300), leaving one block a little behind, which could make a mono source lean to one side for that frame. So each frame checks that the mixed-down samples are the mean of the left and right ones and reads again, up to 3 times; when no read agrees, Pan uses the last left and right that did. A source of more than two channels never agrees (the analyser mixes it down by other weights), so after one held frame its reads are used as they are.
  - **File:** an `HTMLAudioElement` created in code (not in the page) plays an object URL (`URL.createObjectURL`) through a `MediaElementAudioSourceNode` into the measuring path and the speakers. Files over 512 MB, and empty (0-byte) files, are refused without being read. The position updates from `timeupdate` (about 4 times a second), never per frame.
  - **Microphone:** `getUserMedia` with echo cancellation, noise suppression, and automatic gain off, connected to the measuring path only, never to the speakers, so there is no feedback. It opens only from Start listening, never by choosing a source. It needs a secure page (https or localhost). Stop listening, switching source, an unplugged device, and closing the page (`pagehide`) stop every track.
  - **Recording tap** (`startRecordingAudio`, `stopRecordingAudio`): for a video, the running source (the file as heard, or the microphone) also feeds a `DelayNode` (its delay clamped to 40–400 ms and set once per take) into a `MediaStreamAudioDestinationNode`, whose track is the video's audio. The branch reaches no speaker, so what you hear does not change. One tap at a time; the recorder disconnects it at the end of a take, and a new file, releasing the microphone it taps, and `dispose` disconnect it too.
  - Features are measured every animation frame while a file plays or the microphone listens; when that stops, one silent frame resets the meters. The frames come from `requestAnimationFrame`, so while the tab is hidden or covered none come and the letters stop following the sound until the tab is shown again (a recording already stops when the tab is hidden). After 3 s without sound the state reports it ("No sound detected.").
  - Errors: `unsupported`, `decode`, `empty`, `too-large`, `permission`, `no-device`, `device-busy`, `mic-connect` (the microphone opened, but the browser could not connect it to the analyser), `mic-ended` (it stopped while listening: unplugged, or access withdrawn), and `insecure`, each with its own message in the tab. A microphone that is busy or whose opening was aborted (`NotReadableError`, `AbortError`) reads as `device-busy`; any other unexpected error from opening the microphone reads as `unsupported`.
- `useSound.ts`: `useSoundEngine` (actions), `useSoundState` (`useSyncExternalStore`; re-renders on state changes only, not per frame), and `useSoundFrames` (a callback for every measured frame).
- `mapping.ts`: `FEATURES` (each with its label, its group, and whether it is two-sided or counts onsets on a seed), `FEATURE_GROUPS`, `featureById`, and `featureValue`; `TARGETS` and `targetById` (each target with its kind, `slider` or `jump`, its range, step, `get` / `set`, `toSlider` / `fromSlider`, `inactive`, the reason it does nothing right now, and `activate`, the changes that make it act and their notice); `applyPatches`, `seedAfter`, `Mapping`, and `modulate` (which applies Strength and Melody tracking; Motion contrast and Pitch reactive act per letter, never here). Pure: no React, DOM, or Web Audio.
- `jumps.ts`: `JUMP_LIMITS` and `JumpTracker`, which counts the driven seeds' jumps from the measured frames (each Rate times Strength) and takes each jump frame from the shared flash budget. Pure: no React, DOM, or Web Audio.
- `letters.ts`: the letters that react by their own amounts (see Letters above): `letterSlots` (the letters of the shaped text, with where each sits across the text block and its share of the text), `contrastGain`, `pitchPlace` (where the pitch sits in the melody's range, 0 at the left to 1 at the right), the Pitch reactive weight (a bell around that place), `letterLevels` (the three levels of a setting, null when both controls are 0), `assignLevels` (with hysteresis), `levelPosition` and `levelSets` (each level's slider values), `switchSwing` (how large a change moving letters between levels is), the Thorn turns (see Thorn turns above: `isThornTarget` and `isTurnTarget`, `turnGroups`, `ThornState` with `thornState` and `withThornState`, `thornDiffers`, `turnSwing` (how large a turn is), `ThornTurns`, and `turnSets`), and `buildLetterFrame`, `lettersOn`, and `levelKeyAt` (which parameter set each letter shows). Pure: no React, DOM, or Web Audio.
- `flash.ts`: `FLASH_LIMITS` and `FlashBudget`, the one flash budget shared by the driven sliders (`FlashLimiter`) and seeds (`JumpTracker`). Pure: no React, DOM, or Web Audio.
- `mappingStore.ts`: the mappings, the response values (Strength, Motion contrast, Pitch reactive, Melody tracking), and Drive letters, a small store outside React state read with `useMappingState` (it follows `prefers-reduced-motion` while the page is open; `replace` loads a preset's rows and leaves the response alone; `restore` puts back saved or undone mappings; `setResponse` clamps and records one undo step per slider drag; `restoreResponse` puts back saved or undone values); `MAPPING_LIMITS`.
- `src/state/sliderScales.ts` (outside `src/sound/`): `SLIDER_RANGES` (the range and step of every linear slider, by its target id), `sliderRange`, `TOLERANCE` with its log-scale conversions, and `THORN_REACH` with the cubic conversions of Thorn's Reach (`reachToSlider`, `reachFromSlider`, `roundReach`, `reachPercent`, `reachReadout`), read by both the controls and `mapping.ts`.
- `presets.ts`: `PRESETS`, each with its name, the one line its ⓘ shows, its start values, and its mappings; and `presetSettings`, which gives what Load leaves: the settings (every Geometry and Experimental group reset, seeds kept, then the start values), the groups that changed, and the notice. Pure: no React or DOM.

## Roadmap: Sound

Phases 1, 2, and 4 are built, and phase 3 in part: the **Sound** tab plays a local audio file or listens to the microphone, shows live meters for 11 features in five groups (loudness, bands, tone with pitch and melody, rhythm with the beat pulse and activity, and stereo pan), and lets up to 8 mappings move the Geometry and Experimental sliders and make the three seeds jump, so the anchors jump to new places on the beat. Picking a target switches on what it needs, and ten presets set the letters up and fill in the mappings to start from. The Response group scales the movement and can make letters react by different amounts. Every letter on screen is an ordinary, valid, straight-edged result; **Freeze** keeps a moment for export, and video recording, once planned for later, is built: a take records the moving letters with their sound (see [Video](#video)).

Planned from phase 3, **not implemented yet**:
- **Step** event mappings: on each Beat, the next of a few choices, such as Allowed directions (the angle step), Sides, or Rings.
- Measuring the live SVG redraw in the browser.
