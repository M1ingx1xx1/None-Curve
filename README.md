# None-Curve

**English** · [中文](README.zh.md)

An experimental web app for turning font curves into editable polygon shapes. Load a font, type some text, and watch every letter rebuilt from straight lines as you adjust the controls. Make outlines faceted, square, snapped to a grid, or roughened, then export a glyph or your text as SVG, or the glyphs as an OpenType font. Everything runs in your browser; fonts and audio are never uploaded.

**New here and not a developer?** Read the **[User Guide](docs/USER_GUIDE.md)** — it explains every part of the screen and every control in plain language.

## Running the app

- **Online:** `https://m1ingx1xx1.github.io/None-Curve/` once the `main` branch is deployed (see [Deploy to GitHub Pages](#deploy-to-github-pages)).
- **Locally:** requires Node.js 20.19 or newer (22 recommended).

```bash
npm install       # install dependencies
npm run dev       # development server: http://localhost:5173/
npm run build     # type check + production build into dist/
npm run preview   # preview the production build: http://localhost:4173/None-Curve/
```

```text
╞════════════════════════╩═════╦═════════════════════╦═══════════════════════╡
│ Typography / Glyphs / Color  ║ Text input          ║ Preview + Blur/Invert │
└──────────────────────────────╨─────────────────────╨───────────────────────┘
```

Double lines are drag handles. Each one only moves the border between its two neighbours, so they always add up to the same size: the top and bottom rows always fill the window between the header and the status bar (no page scrolling), the tools and the canvas share the top row's width, and in the bottom row the Typography / Glyphs / Color tabs, the text input, and the preview always add up to the row's width (minimum widths 260, 180, and 200 px). Every handle is the 1 px divider itself (in the quiet border colour, like the header and status bar edges), with an invisible 9 px grab area. Drag a handle, or focus it and use the arrow keys (Home / End jump to the limits); double-click resets it. Every area keeps a minimum size, and the splits are remembered in the browser. The top and bottom rows are split independently, so their column borders need not line up.

- **Top left — tools:** **Import font** and the font information come first, then the **Geometry**, **Experimental**, and **Sound** tabs. **Geometry** holds every geometry parameter (flattening, squaring, anchors, grid & angles, distortion) in pipeline order, then Random anchors; **Experimental** holds effects that run after it and can be on together (Noise, Ripple, Curl, Wind, Spikes); **Sound** plays a local audio file or listens to the microphone, shows live meters, and moves the sliders of the other two tabs with the sound through mappings, or makes their seeds jump; a driven slider keeps its own value and shows a thin marker at its live value, and a driven seed field keeps its own seed and shows the live seed beside it (see [Sound](#sound)). The chosen tab is remembered in the browser. Parameter statistics refer to the selected glyph. Controls that currently have no effect are greyed out: all of Curve flattening while Random anchors are on, and the random seed at 0 % randomness. Explanations are folded behind an ⓘ button next to each label (click to open, so it also works with the keyboard; the text stays the control's screen-reader description while folded); **Show all explanations** above the panel's content opens them all (the Typography and Color tabs included) and is remembered in the browser. Warnings, statistics, and notes about why a control is disabled are always shown.
- **Top right — result canvas:** shows the canvas (artboard) with the text from the input, set with the current font, all parameters, the Typography settings, and the colours. Below it, **Canvas size** opens and closes a drawer with the canvas size (see [Canvas size](#canvas-size)); the drawer's state is remembered. Its outline and layer controls (Original / Flattened / Compare, Fill, Skeleton, Vertices, Metrics) also drive the preview; zoom and pan apply to the canvas only. Each glyph's click target is its box (advance width by ascender to descender), so small text is easy to hit. Clicking a glyph selects it (the statistics follow it) and recolours every copy of it (hovering does the same) with a highlight colour computed from the text and background colours: among colours that stay readable on the background (at least the text's own contrast, up to 4.5 : 1, and never below 3 : 1), the one that differs most from the text colour in hue and chroma (OKLab), preferring vivid colours, penalising lightness that fades toward the background, and staying within 40° of the palette's hue (90° when a text that is already vivid leaves too little room; the text's hue, otherwise the background's, otherwise orange). Black on cream paper highlights in vermilion; a coloured text gets a vivid neighbouring hue. Clicking empty canvas (not the end of a drag) or pressing Escape clears the highlight; the statistics keep showing the last selected glyph, which the **Statistics** line at the top of the Geometry panel names (character and code point). The preview never shows the highlight.
- **Bottom left — text tools:** three tabs (remembered in the browser; arrow keys move between them; all stay loaded, so switching keeps local state): **Typography** — how the text is set on the canvas (see [Typography](#typography)); **Glyphs** — see below; **Color** — the text and background colours.
- **Glyphs tab:** a searchable grid of every character the font maps, used as an inserter: clicking a character inserts it into the text at the cursor (replacing selected text) and selects that glyph. Before the text box has been focused, characters are appended. Glyphs without a character (ligatures, alternates) and control characters are not listed, since they cannot be typed. When the glyph list is narrower than 280 px, the cells shrink and show only the character; the code point labels return above that width (the code point stays in each cell's tooltip).
- **Bottom right — input and preview:** a compact multi-line text input (letter case toggles **AA** / **Aa** / **aa** right of the Text title, sample texts in a menu, Clear, character count, kerning status, missing characters); then a miniature of the canvas exactly as it is exported (cut to the canvas edges) with its own **Blur** slider (0–12 px) and an **Invert** button that swaps the text and background colours. Blur and Invert only affect this view unless **Export the preview look** is ticked — a squint test for the overall shape. A handle between the two parts moves the border (default 40 / 60).
- **Status bar:** the font status, the selected glyph, and the current view; while Sound drives the letters, **Live · N fps** (the live frame rate); while the microphone is listening, **Microphone on** (visible from every tab), and **No microphone** if it stopped on its own (unplugged or access withdrawn); at its right end, a small light / dark switch for the interface. Every visit starts with the system setting (`prefers-color-scheme`) and follows it when it changes; a choice there lasts for the visit and is not stored. The theme tokens are CSS `light-dark()` values, switched by `color-scheme` on `<html data-theme>`. The canvas keeps the Color settings in both themes.
- Desktop browsers only: there is no phone or narrow-screen layout. A narrow window keeps the same layout: the panes shrink to their minimum sizes, and below that all shrink alike.

### Canvas

- Outline view: **Original** (font curves), **Flattened** (final polygon), **Compare** (final polygon with the original curves overlaid as a dashed line). The current view is shown in the canvas corner and the status bar.
- Layers: **Fill** (off = outline stroke), **Skeleton** (original on-curve anchors as squares, off-curve controls as hollow circles, and handles; TrueType's implied on-curve points appear as anchors), **Vertices** (final polygon vertices as green dots), and **Metrics** (ascender, cap height, x-height, baseline, descender, advance width).
- Zoom with the mouse wheel or `+` / `−`, pan by dragging or with the arrow keys (canvas focused), `0` or **Fit** to reset. The preview (bottom right) is always fitted and is not interactive.
- All layers apply to every glyph of the text. Only glyphs inside the visible area are drawn. Skeleton points and vertices appear once an em is at least 48 px on screen; below that the canvas asks you to zoom in, so long texts stay readable. Metric labels are drawn on the first visible line only.

### Canvas size

The text is set on a canvas (artboard) of a fixed pixel size; zoom 1 fits the whole canvas. The background colour fills the whole view. Outside the artboard (the pasteboard) it is 7 % darker (6 % lighter on a dark background) and carries a screen grid (every 24 px) in black on light backgrounds and white on dark ones, at the opacity that gives a contrast of 1.3 : 1 with the background — the same visibility in every palette, whatever the text colour (`gridLineColor` in `src/specimen/color.ts`; the snap grid of Grid & angles uses 1.5 : 1); inside, the artboard looks exactly like the export. The grid fades in inside the artboard only while it helps: while dragging the text (Free position) or at 200 % zoom and above. A soft shadow lifts the artboard off the pasteboard — dark on light backgrounds, a light glow on dark ones; its 1.5 px outline (interface mint, never the text colour) is currently transparent (`.pasteboard`, `.artboard-grid`, and `.artboard-frame` in `src/styles.css`); the metric guides are drawn in the text colour too. A transparent background shows as a checkerboard of the background colour and the same tinted with the text colour, so the text stays readable. The drawer below the canvas holds:

- **W** / **H**: canvas width and height, 100–4000 px (slider or number box; the box commits on Enter or when you leave it, clamped to the range).
- Aspect presets **1:1**, **4:3**, **16:9**, **4:5**, **3:2**, **3:4** keep the width and set the height (or keep the height if that would exceed the range); the matching preset is highlighted. **Swap** exchanges width and height.
- **1×–4×**: export multiplier. A PNG is width × multiplier by height × multiplier pixels with the same layout, so higher multipliers are sharper.

Text that runs past the canvas edge stays visible on the canvas with a warning; the preview and the exports are cut to the canvas.

### Typography

`src/specimen/artboard.ts` and `src/specimen/scene.ts`. These settings change the layout and the SVG/PNG export, not the glyph geometry or the font file.

- **Size** (4–1000 px, default 48): the em in canvas pixels; changing the canvas size does not change it. **Fit text** sets the largest whole-pixel size at which the outlines, slant included, fit inside the margin on both axes.
- **Margin**: the position anchors and Fit text keep 25 canvas pixels between the outlines and every canvas edge, whatever the font size (`EDGE_MARGIN_PX` in `src/specimen/artboard.ts`). There is no control for it.
- **Tracking** (−200–1000 thousandths of an em): added between glyphs on top of advances and kerning, not after a line's last glyph.
- **Line height** (0.5–3 ×): multiple of the font's line spacing (ascender − descender + line gap).
- **Slant** (−30°–30°): a skew around each glyph's own baseline (x′ = x + tan(slant) · y); positive leans right.
- **Align** Left / Center / Right (icon buttons): aligns the lines with each other inside the block.
- **Position**: where the block sits on the canvas. Nine anchors (a 3 × 3 grid: corners, edge middles, centre) place the outlines' box (slant included; not the line box, so side bearings and ascender space do not leave a gap) against the left margin, centred, or against the right margin, and against the top margin, centred, or against the bottom margin — the letters sit 25 px from the edges and corners. An anchor also sets **Align** to its column (left column left, middle column centre, right column right); Align can still be changed afterwards. The default is left, vertically centred. The chosen anchor (and Free when on) glows in the primary mint. **Free** lets you drag the text on the canvas (drags that start elsewhere still pan); the position is stored as a share of the room the canvas leaves beside and above the outlines' box, so the text stops at the canvas edges and stays inside when its size or the canvas changes. Pressing Free puts the text back at the default position and alignment (left, vertically centred) and then lets you drag it; pressing it again resets it there.
- **Letter case** (**AA** / **Aa** / **aa**, right of the Text title): **All caps**, **Title case** (first letter of every word upper case, the rest lower case), or **Lower**; press the active one again for the text as typed. The typed text is never changed; the canvas, the preview, the exports, and the font file's "Specimen characters" use the converted text.
- **Reset typography** restores the defaults (4 %, 0, 1, 0°, left-aligned, positioned left and vertically centred) and keeps the letter case.

### Color

Twelve presets (Charcoal — the default, dark text on paper — Off White, Kryptonite, Plum, Glowing Cyan, Acid Lime, Ember, Moonlit Purple, Chrome Pink, Cherry, Atomic Blue, Forest Moss), **Random** (a random readable pair, contrast ≥ 4.5 : 1), **Swap**, and custom **Text** and **Background** colours with a colour picker and a hex box (`#rgb` or `#rrggbb`). The contrast ratio is shown, with a warning below 3 : 1. **Transparent background** leaves the background out of SVG and PNG exports; the background colour is kept for Swap, Invert, and the checkerboard. Hover and selection on the canvas use a highlight colour computed from the text and background colours (see the result canvas above).

### Text preview

The input text is set with the final polygons from a shared geometry cache, so the canvas, the preview, and the exports always agree.

- Each glyph advances by its advance width plus kerning when the font has it (GPOS `kern` feature or a legacy `kern` table, applied through fontkit's layout). Ligatures are off so every character keeps its own glyph. Fonts without kerning data are labeled as such.
- Line height is ascender − descender + the font's line gap, times **Line height**. Spaces advance without drawing. Missing characters are drawn as dashed boxes and listed.
- Up to 1000 characters are shown. Each distinct glyph is processed once per parameter set (cache key: font, glyph, and all geometry parameters).

### Performance

- **Geometry worker** (`src/geometry/geometry.worker.ts`, `src/state/geometryClient.ts`): the pipeline runs in a Web Worker that opens its own copy of the font, so the page never waits on it. The selected glyph is computed first (its statistics), then the text's glyphs in reading order; results come back in batches every ~40 ms and are shown together (one re-render per 50 ms). A newer parameter set stops the older one between glyphs. Until a glyph's new shape arrives the canvas keeps its previous one, and the canvas badge shows "Updating N…" (while Sound drives the letters, live frames replace one another without the badge, which then counts only glyphs that have no shape yet). Results for the last four parameter sets are kept, so stepping back is instant (live sound frames are kept apart, so a song does not push these out; see [Sound](#sound)). Without worker support, or if the worker cannot open the font, glyphs are computed on the page as before. Export uses the worker's results and computes only what is missing.
- **Text layout** is split into shaping (`shapeSpecimen`, rerun only for text or typography changes) and placing polygons (`placePolygons`, rerun as results arrive). Path strings and slanted extents are cached per polygon, and each glyph on the canvas is a memoised component, so a text that repeats a letter builds its outline once and unchanged glyphs are not drawn again.
- **Free position drag** moves the text with an SVG transform only; the position is committed once, on release, so dragging never re-renders the page.
- **Crossing checks** (`src/geometry/crossings.ts`), run by every step for every contour and retry, sweep segments sorted by x and compare only pairs whose boxes overlap, stop as soon as the count exceeds the original's, and count each contour's own crossings once. A 15 000-point contour (Anchor spacing 1) is checked in milliseconds instead of seconds. Checks between two contours (`src/geometry/contourLayout.ts`) first compare bounding boxes and only look at segments inside the overlap; each pair's original arrangement is worked out once per step.
- **Geometry cache**: least recently used entries are dropped beyond 4000 glyphs or 1 000 000 polygon points per font, so dense settings cannot fill memory. Live sound frames use a second, smaller cache (600 glyphs or 200 000 points per font), so they never evict these.
- Measured (production build, 1000 characters, Inter): each Tolerance slider step costs ~10 ms of page time (was ~90 ms), Random anchors at density 100 ~9 ms (was 260–690 ms); spacing 1 + grid 50 + 15° + distortion takes 48 ms for "@" (was 2.8 s); computing and rounding all 2691 Arial glyphs at spacing 1 takes 3 s with ~200 MB live memory.

## Fonts

### Local files

- Formats: `.ttf`, `.otf` (TrueType and CFF outlines), `.woff`, `.woff2`, detected from the file's bytes rather than its extension. Font collections (`.ttc` / `.otc`) are not supported.
- Choose a file from **Import font** or drop it on the canvas. Files are read in the browser and never uploaded. Limit: 50 MB.
- Empty, unrecognized, and damaged files show distinct errors with **Retry**; the previously loaded font stays visible.

### Google Fonts

A CSS preview of a family has no outline data, so the app downloads the actual font file:

1. `GET https://fonts.googleapis.com/css2?family=<Family>:ital,wght@0,100;…;1,900` — the official CSS2 API, no API key. It returns only the styles that exist, one `@font-face` per subset. CORS is allowed.
2. `GET https://fonts.gstatic.com/s/<family>/<version>/<file>.woff2` for the chosen weight, style, and subset.
3. Parse the WOFF2 with fontkit. Only after this succeeds does the font become available.

Limits:

- **Catalog:** the full searchable catalog needs the Google Fonts Developer API key, which cannot be kept secret in a static build. The dialog offers a curated list of 15 families — Sans: Google Sans, Noto Sans, Archivo, Inter, DM Sans; Serif: EB Garamond, Baskervville, Bodoni Moda, DM Serif Display; Slab: Slabo 13px, Arvo; Mono: IBM Plex Mono, JetBrains Mono, Space Mono, DM Mono — any family name typed exactly as on fonts.google.com (case-sensitive), or a pasted Google Fonts URL.
- **Subsets:** Google splits families into per-subset files (latin, latin-ext, cyrillic, …). One subset is loaded at a time.
- **Variable fonts:** detected when several weights share one file. Every weight can still be chosen: the chosen weight is requested on its own, and Google then serves a static file made for that weight (correct style name and OS/2 weight). When Google still serves the variable file (Roboto Flex at 700, for example), the weight is applied on load: fontkit cannot vary WOFF2 files, so the WOFF2 is rebuilt as TrueType (`src/font/woff2.ts`: the decoded glyph table is re-encoded without hinting, every other table is copied) and instanced at that weight; the font panel then names the weight used. Other axes (`opsz`, `wdth`, …) stay at their defaults.
- **Colour fonts** (Nabla, Honk, Bungee Spice, the "Ink" families): only their plain outlines are read; fontkit's colour glyphs (COLR, sbix) are bypassed because it cannot read COLR version 1. A font whose glyphs are colour images only (Noto Color Emoji) loads with a warning that there is nothing to edit.
- **Fonts whose layout tables fontkit cannot read** (Iosevka Charon) are set one glyph per character with their advance widths, without kerning.
- Checked against the whole Google Fonts catalogue (1950 families): every family loads, and every variable family loads at a second weight with outlines that differ from the default.
- **Errors:** unknown families return HTTP 400 without CORS headers, which looks like a network error to the browser. A follow-up `no-cors` request tells "Google rejected the name" apart from "network / CORS / content blocker". Download and parsing errors are reported separately, all with **Retry**.

#### Pasting a Google Fonts URL

The URL is parsed by `src/font/googleUrl.ts` and never fetched itself — only the family and style are read and passed to the flow above.

| URL | What is read |
|---|---|
| `https://fonts.google.com/specimen/Roboto` | Family (`+` = space). Parameters such as `categoryFilters` or `preview.script` are ignored and listed. |
| `https://fonts.googleapis.com/css2?family=Roboto:ital,wght@1,700` | Family, weight, and italic from the first style tuple. A weight range (`wght@300..700`) leaves the weight to choose in the dialog. |
| `https://fonts.googleapis.com/css?family=Lato:300italic` | Legacy API: family and first style (`400`, `700italic`, `300i`, `bold`). |

- Only `https://` URLs on `fonts.google.com` and `fonts.googleapis.com` are accepted. Other hosts, look-alike domains, `http://`, credentials, ports, and other paths are rejected with an explanation.
- With several families or styles, the first is used and the dialog says so. `display`, `subset`, `text`, and tracking parameters are ignored and listed.
- Axes other than `wght` and `ital` (for example `opsz`, `wdth`) cannot be applied; the dialog says so, and they stay at their defaults.
- Missing styles fall back to the default rule (closest to 400), and the dialog names the style that will actually load.

## Geometry pipeline

```text
Original curves (frozen) → Flatten (or Random anchors) → Squaring → Anchor spacing → Anchor reduction → Grid snapping → Angle lock → Vertex distortion → Experimental (Noise → Ripple → Curl → Wind → Spikes) → final polygon
```

The order is fixed (`src/geometry/pipeline.ts`). Every parameter change reruns the whole pipeline from the original curves, so nothing accumulates, and turning a step off restores exactly the result of the steps before it. All distances are in font units and do not depend on canvas zoom. Distortion and the Experimental effects run last, so they move vertices off the snapping grid and off locked angles.

Every step validates each contour: it must keep at least three distinct points, its winding direction (so counters stay holes), non-zero area, and no more self-crossings than before. It must also sit against the glyph's other contours as before (`src/geometry/contourLayout.ts`): contours that were apart stay apart, a counter stays inside its outer contour, and nothing moves into another contour. Without this, a counter pushed out of its letter is filled as a solid shape beside it. Steps change contours one at a time and check each new contour against the others as they are at that moment, so the finished glyph is valid as a whole. Flattening itself is checked against a much finer flattening of the original curves (see below).

Before giving up, steps degrade gracefully: squaring uses the largest safe share of the amount (backed off slightly from the limit so later steps still have room), grid snapping and angle lock retry on progressively simplified copies of the contour and, for angle lock, finally as stair steps (each off-angle edge split into two allowed directions, no vertex moved), and distortion lowers the amplitude where the contour crosses, then overall. Only a contour for which every attempt fails keeps its previous shape; the panel reports reduced, simplified, and unchanged contours, and why.

Measured on the Latin glyphs of Arial, New York, and Georgia, the share of glyphs whose contours crossed each other or left one another went from 13–25 % to 0 with Angle lock 90°, 16–18 % to 0 with Random anchors at density 1, 25–31 % to 0 with Grid 200, 4–18 % to 0 with Distortion 200, and 0–5 % to 0 with Merge joined curves at 1 segment. Across 6480 random parameter combinations on four fonts, no glyph has a new crossing, within a contour or between two.

### Curve flattening

Every quadratic and cubic segment is replaced by straight edges (`src/geometry/flatten.ts`); the result uses only `M`, `L`, and `Z`.

- **Adaptive (tolerance)** — recursive midpoint subdivision (de Casteljau). A sub-curve becomes one edge once an upper bound on its distance from the chord is within the tolerance (half the control point's distance for a quadratic, ¾ of the larger control distance for a cubic). Range 0.1–500 font units on a logarithmic slider. Without merging every font curve keeps at least one edge, so raising the tolerance beyond about 100 changes little (Roboto: 11,219 vertices at both 100 and 500 over the first 400 glyphs); turn on **Merge joined curves** for coarser shapes. Safety limits: recursion depth 12 and a 0.01-unit minimum sub-curve length; curves that hit a limit are reported.
- **Fixed segments** — each curve is sampled at `t = i/N` and becomes exactly N edges (1–32). Straight segments stay single edges. A warning appears if an edge strays more than 1 % of the em from its curve.
- **Merge joined curves** (both modes, off by default; the merge settings are shared; `src/geometry/curveRuns.ts`) — fonts build one visible curve from several Bézier segments (a Roboto O has 16 per contour), so per-curve settings alone stay smooth. Merging joins segments that meet smoothly into one curve. In fixed mode it is sampled with N edges spaced evenly by arc length; in adaptive mode it is simplified as a whole (Ramer–Douglas–Peucker on dense samples of the curve) so that no sample is farther than the tolerance from its edge, with at least 3 edges for a closed loop. Vertices stay on the curve. Roboto, first 400 glyphs, adaptive: 6,365 vertices at tolerance 500 with merging, against 11,219 without; the `o` goes from 36 to 12 vertices (Inter: 24 to 8).
  - **Break merged curves at:** **Corners & extremes** (default) — corners, straight segments, and the curve's horizontal/vertical extremes (found analytically, even inside a segment), so a round bowl splits into quarter arcs. **Corners only** — a fully smooth loop becomes one curve and uses at least 3 edges.
  - **Merge through straight lines** (off by default): straight segments that meet a neighbour smoothly also join the merged curve, so stems that flow into arches (n, m, u) or the straight sides of some O shapes are resampled with the curve. With this on, the extremes rule applies only between curves (a stem meets an arch exactly at its extreme). A straight segment left alone stays a line. Letters change a lot — stems can lose their ends.
  - **Corner angle** (1–90°, default 15°): a joint turning more than this always breaks. Merged curves also break at the contour start. Without merging through lines it only affects curve-to-curve joints, which in most fonts are already smooth (in Roboto 6200 of 6206 turn less than 1°), so it rarely changes anything. With merging through lines it decides which line joints merge: going from 15° to 90° changes 365 of the first 400 Roboto glyphs.
  - Measured on Roboto `a`: 38 segments merge into 12 curves; N = 4 / 3 / 2 / 1 gives 57 / 45 / 33 / 21 vertices (47 without merging at N = 1).
  - If a merged contour fails validation, it uses the unmerged result and the panel reports it. The 1 %-of-em warning is suppressed while merging.

- **Validation.** The result is compared with a much finer flattening that stands in for the original curves (tolerance 1/5000 em). Where an edge cuts across a stroke thinner than the tolerance, so the outline crosses itself or another contour where the original does not, only the curves involved are flattened again, each round with a quarter of the tolerance (adaptive) or twice the edges (fixed), up to 6 rounds; the panel counts the curves flattened more finely. New York's U, Ù, Ú, Û, Ü and its 6 and 9 crossed themselves at the default settings; they no longer do.
- Contours with no area (fewer than three points, or all points on a line) are left out and reported.

Contours keep their start point, order, and direction; advance widths and side bearings are kept. Glyphs without contours (such as a space) give an empty polygon.

### Squaring

Flattening only approximates curves, so an O stays round. **Squaring** (`src/geometry/squaring.ts`) deliberately reshapes round contours toward their bounding rectangle.

- Each contour is normalized to its own bounding box, and every point moves radially from the box centre toward the box edge. At 100 % it lands on the box, so a circle, ellipse, or superellipse becomes its bounding rectangle with sharp corners. **Amount** (0–100 %, presets Off / Soft / Square) blends linearly.
- A counter uses its own box and becomes a smaller concentric rectangle, so stroke thickness at the side midpoints is unchanged (Roboto O: left stem 191 units, bottom 163 units at 100 %).
- **Applies to: Round contours** (default) squares only contours close to the ellipse that fills their box (edge-weighted mean deviation ≤ 0.06 fully, ≥ 0.16 not at all); stems, triangles, S-curves, and B/D shapes stay as they are. **All contours** pushes every contour toward its box.
- Runs right after flattening, so anchor reduction can then drop the collinear points on the straight sides (a squared O reduces to 4 corners plus its start point).
- At 100 % the O, o, and 0 of Roboto, Inter, and Andale Mono — outer contour and counter — reach an area-to-box ratio of 1.00 (a circle is about 0.79).

### Anchor spacing and reduction

`src/geometry/anchors.ts`. 0 turns either step off; **Reset anchors** turns both off.

- **Anchor spacing** (0–200 font units): every edge, including the closing edge, is split into equal parts no longer than the target. New points lie on the existing edges, so the shape is unchanged. Skipped (with a warning) above 50,000 vertices per glyph.
- **Anchor reduction** (0–100 font units): Ramer–Douglas–Peucker on each closed contour, split at its start point (always kept) and at the vertex farthest from it. Larger values remove more points and can erase small details. Fonts that already contain self-crossing contours keep those crossings but gain none.
- Because spacing points are collinear with their edge, reduction removes them again when both are on; the panel warns about this. Reduction thresholds are absolute font units.

### Grid snapping and angle lock

`src/geometry/constraints.ts`. **Reset grid & angles** restores the defaults (both off, grid 10 u, 45°).

- **Snap to grid** (grid size 0–200 font units; 0 = off): each coordinate becomes `round(v / g) × g`, with the grid anchored at the glyph origin; exact halves round toward the centre of the glyph's bounding box, so a symmetric letter stays symmetric. Neighbours landing on the same point are merged. The canvas draws the grid for reference only (not when denser than 4 px).
- **Angle lock** (multiples of 90°, 45°, 30°, or 15°, counter-clockwise from horizontal): each edge turns to the nearest allowed direction (ties go counter-clockwise), then only edge lengths are adjusted — a length-weighted least-squares change that makes the contour close again. Each edge keeps only the part of its length along its new direction, so locking shrinks curves (at 90° an O loses about 30 % of its width and height); the result is therefore fitted to the original's bounding box instead of pinning the start vertex: at 90° width and height are scaled separately (every edge is horizontal or vertical, so angles are kept), otherwise one scale keeps the box's area, the contour is centred sideways and keeps its bottom, so letters stay on the baseline. Locking is rejected when it changes the shape too much — a vertex moves more than 20 % of the contour's bounding-box diagonal, or the area changes by more than 30 % (an S whose openings close up) — and retries simplify the contour by at most 4 % of that diagonal. A glyph is locked or stepped as a whole: if any contour is rejected, or locking every contour on its own would pull the glyph apart (Roboto builds a V from two overlapping legs; locked separately they become two bars), every contour gets stair steps. Stairs keep every vertex; off-angle edges longer than 1/40 em are first split, so a long diagonal becomes a fine staircase that follows it; corners go away from the ink (outward on outer contours, into counters); and where two neighbouring steps would cross at a sharp inner turn, one is flipped. Only if those cross too does a contour keep its previous shape. Before, Arial's Z at 90° slid about 800 units left onto the previous letter and its X dropped 512 units below the baseline; both now keep their bounding box. On printable ASCII, the largest vertex move at 90° went from 1024 to 290 units in Arial, and contours left unlocked went from 15 to 0 (Arial 90°), 8 to 0 (Arial 45°), 2 to 0 (Arial 30°), and 24 to 20 (New York 90°, whose hairlines are only a few units thick); New York went from 8 to 11 at 45° and 4 to 5 at 30°, because overlaps that used to pass are now caught. "Largest move" measures each original vertex's distance to the new outline.
- Snapping runs first; angle lock then changes edge lengths, so some vertices leave the grid. The panel warns about this.

### Vertex distortion

`src/geometry/distortion.ts`. **Reset distortion** restores the defaults (amplitude 0, few anchors off) but keeps the current seed.

- **Noise amplitude** (0–200 font units): the largest distance a vertex can move; 0 is off.
- **Noise frequency** (0.5–50): noise features per 1000 font units of outline length, sampled by arc length and periodic around each contour, so there is no seam.
- **Normal bias** (0–100 %): 0 % slides vertices along the outline, 100 % pushes them across it.
- **Seed** (0–999,999) and **Next variant** (seed + 1). No `Math.random`, time, or render count is involved; the same glyph, parameters, and seed always give the same shape.
- Edge protection limits only how far the two ends of an edge may move toward each other along it (at most half its length), so no edge collapses or reverses; movement across the outline is not limited. Along-the-outline movement is shortened first, movement across it only where that is not enough (the inside of a tight curve). Limiting all relative movement, as before, made the distortion weaker the denser the outline, because neighbouring vertices of a dense outline are close together.
- Where a distorted contour crosses itself or another contour (dense outlines at inner corners, thin strokes, counters near their outer contour), the amplitude is halved around the crossing, fading out over one amplitude of outline on each side, up to 12 times; the rest of the contour keeps the full amplitude. If that is not enough, the whole contour is retried at 1/2 down to 1/16 of the amplitude, then left undistorted.
- Measured on 32 Arial letters and digits, the median vertex movement at amplitude 40 is now 18 / 18 / 16 units with Anchor spacing off / 10 / 1 (before: 18 / 6.5 / 0), and at amplitude 200 it is 67 / 46 / 25 (before: 22 / 0.3 / 0).
- **Few anchors** (`sparse` in the settings; `pickMovers` and `SPARSE_LIMITS`): a mode with no control of its own. Only the Sound tab's **Flicker** preset turns it on; **Reset distortion**, or loading another preset, turns it off; it is not a Sound target. Only a few anchors of each letter move, and every other vertex stays exactly in place, so the letter keeps its shape.
  - **Locked:** corners (the outline turns by more than 30°; exactly 30°, which Angle lock often makes, is not a corner), the extremes in x and y (a flat run counts whole when it is a top, bottom, or side, not when it is a step), vertices on a zero-length edge, and every vertex of a contour with fewer than 8 vertices.
  - **Candidates:** every other vertex, and the midpoint of every straight edge at least 10 % of the em long, on any contour of 3 or more vertices, small ones included (the 4-vertex I, i, or hyphen). A picked midpoint is inserted as a new vertex and moves like any other mover, while the edge's ends stay put, so letters made only of corners and extremes (l, H, T) move too. A midpoint is skipped where inserting it would touch another edge of its contour (an outline that runs back along the edge, as grid snapping can leave).
  - **Picking:** the candidates are ranked by a hash of the seed, the contour, and their position, and the first ones move: 6 % of the letter's vertices, rounded, from 1 to 5, at most 2 on one contour, and more than 4 vertices apart along it (a midpoint counts as halfway between its edge's ends). A new seed picks a new set, so Beat → Distortion · Seed moves other anchors on every beat.
  - **Movement:** the same noise as above, but each mover's part across the outline and its part along it are each raised to at least 60 % of their share of the amplitude (in the Normal bias proportions; a seeded direction where the noise is 0), so every jump shows. Edge protection and the repairs above can still lower it.
  - While it is on, the panel shows the note "Only a few anchors move (set by the Flicker preset in the Sound tab). Reset distortion moves every anchor again." and the statistic **Anchors moved** (the vertices that actually moved, inserted midpoints included), and the status bar's description reads "distortion N u, few anchors, …". Off, or missing in older settings, the result is exactly as before.
  - Checked on the Latin glyphs of Arial, Georgia, and New York. At the default Geometry (Noise amplitude 2 and 120, Normal bias 90 %, seeds 1–10), every glyph moves at least one anchor, and in every test run no locked vertex moved, no letter had more movers than its count, and no contour more than 2. At 48 Geometry settings × 4 seeds per font: no broken layout and no export failure, with 2.8 / 3.3 / 3.2 anchors moved per glyph on average (Arial / Georgia / New York). Known gaps: on New York's hairline strokes (# and $), a picked midpoint cannot move across a 6-unit bar without crossing, so that contour falls back at some seeds (about 0.2 % of glyph runs at the default Geometry); with very dense anchors (Anchor spacing 5) every edge is shorter than 10 % of the em, so a few rectangle shapes (I, l, i, hyphen, period, =) have no candidate and stay still.

### Random anchors

`src/geometry/randomAnchors.ts`. The last group in the Geometry tab, off by default. When on, anchors are placed at random arc-length positions on the **original curves** instead of Flatten's regular sampling; each anchor is evaluated on the source Bézier, so it lies exactly on the glyph outline. The result then goes through Squaring, Anchors, Grid, and Distortion as usual. Because Flatten's polygon is replaced, the whole Curve flattening group is greyed out while this is on (its settings would only shape contours that fall back).

- **Density** (1–100): about how many anchors per 1000 font units of outline; every contour keeps at least 3.
- **Randomness** (0–100 %): stratified sampling. Each anchor has its own stretch of outline; 0 % puts it in the middle, 100 % anywhere inside it. Anchors never change order, so the outline cannot fold back.
- **Keep sharp corners** (on by default): source joints that turn by more than 30° stay as fixed anchors, and each stretch between two corners is sampled on its own.
- **Seed** (0–999,999; greyed out at 0 % randomness, where it has no effect): **Shuffle** picks a new seed (only the button uses the browser's random generator); **Copy** copies it; **Previous** lists the last six seeds of this session so you can go back. The seed also appears in the status bar and the export dialog.
- Reproducible: the random numbers come from a hash of (seed, the contour's outline, attempt), so the same font, settings, and seed always give the same polygon. Repeated letters in the text look identical, and so do different glyphs that share an outline (Latin A and Greek Alpha); different outlines get different draws.
- Validation: a draw that reverses a contour, collapses it, adds self-crossings, or crosses or leaves another contour is redrawn with a derived seed (up to 4 draws, still deterministic); if none is valid, that contour uses Flatten's result and the panel says so.
- **Reset random anchors** restores the defaults but keeps the current seed.

### Experimental: Noise, Ripple, Curl, Wind, and Spikes

`src/geometry/noise.ts`, `src/geometry/ripple.ts`, `src/geometry/curl.ts`, and `src/geometry/wind.ts` on the shared warp in `src/geometry/warp.ts`, and `src/geometry/spikes.ts`, run by `src/geometry/experimental.ts` in the fixed order Noise → Ripple → Curl → Wind → Spikes. The **Experimental** tab, beside **Geometry**, holds effects that run after the whole Geometry pipeline and can all be on together (plan: [docs/EXPERIMENTAL_PLAN.md](docs/EXPERIMENTAL_PLAN.md)). The tab has one **Seed** with **Next variant**, shared by every effect, and **Reset experimental** (keeps the seed).

- **Every effect but Spikes is a piecewise-linear warp.** The plane is cut into triangles and each moves by its own linear map, continuously across their edges. A straight edge stays exactly straight inside a triangle and bends only where it crosses a triangle edge (a crease); new vertices go only there. No effect samples a smooth function along the outline, so the letters gain corners, never curves.
- **Valid by construction, so effects stack.** Up to 100%, no triangle flips or flattens, which makes every warp one-to-one: it cannot make an outline cross itself or another contour, or push a counter out of its letter, and neither can several warps in a row. Contours are still checked after each effect. All contours start as their exact images (valid together); each is then replaced by its tidied image if that is valid against the others. A crossing counts only where the input's edges neither crossed nor touched (heavy Geometry settings can leave outlines lying on top of themselves), and not between two edges still exactly as the warp mapped them whose input edges lie less than 0.05 units apart: a one-to-one warp cannot make those cross, but a strong Wind can squeeze a sharp spike that heavy Distortion leaves so thin that rounding does. A crossing between untouched edges that lie further apart in the input would be a real fault and is still rejected. If rounding ever breaks an exact image, that contour is retried at 1/2 down to 1/16 strength; if nothing works the glyph is left as it was.
- **Tidying, so nothing reads as a curve.** Creases that turn the outline by less than 3° are left out (each left-out crease stays within 1 % of the em of the edge that replaces it). Then, in every run of five or more vertices that all turn the same way by 0.5°–20° between edges shorter than 4 % of the em (how a polyline starts to look like a curve), the weakest crease is removed until no such run needs a crease to exist. Runs the input's own vertices already form are left alone; the input's vertices are never removed. Creases of earlier effects count as creases too, so a later effect can also remove an earlier one's, and a run that only several effects together form is broken up as well. If tidying makes a contour touch itself or another, every crease the offending edge replaced is restored and the rest is tidied again (up to 8 times), then tighter drift limits are tried. Spikes thinner than 0.01 units in the input (heavy Geometry settings can leave them) are dropped first.
- **Noise** (off by default) crumples the letters like paper. The mesh is a square lattice turned by an angle from the seed, each square split along a diagonal chosen by the seed. Every lattice point moves by a random vector from the seed, up to **Amount** × 30 % of the **Facet size** (8–100 % of the em, default 18 %). **Turn** (0–345°, default 0°) turns every movement by the same angle, so the folds go another way over the same creases (180°: the opposite way). Below 30 % no triangle can flip (each keeps about 15 % of its area or more), whatever the turn, so Noise never needs weakening. **Amount** runs from 0 to 500 % (default 70 %): above 100 % the points move further along the same directions, and facets fold over each other (see Folds below). The lattice is fixed in glyph coordinates, so every copy of a letter has the same shape and fonts export as shown.
- **Ripple** (off by default; `src/geometry/ripple.ts`) sends polygonal waves out from a point. The mesh is a set of concentric regular polygons with **Sides** (3–12, default 8) sides and a flat side at the bottom, centred at **Center X / Center Y** (a share of the glyph's ink box, −50 % to 150 %, default the middle), one ring every half **Wavelength** (8–200 % of the em, default 30 %) measured across the sides. Rays through the polygon corners cut the rings into cells, each split into two triangles. Every ring moves out or in as a whole, in turn, by up to **Amount** (0–400 %, default 50 %) × 45 % of the ring spacing, so it stays a regular polygon and the outline zigzags where it crosses the rings (a triangle wave, not a sine). **Fade** lowers the amplitude linearly with distance from the centre, down to (1 − Fade) at the farthest corner of the ink box. Up to 100 % rings never pass each other (neighbours stay at least 10 % of the spacing apart), so no triangle flips; above it they overtake each other and fold; the ring just outside the glyph stays put and, without Petals, everything beyond it is left alone. **Petals** (0–300 %, default 0 %) bends every ring into a flower with one petal per side: three more rays from the centre cut each side evenly (tip at the corner, shoulder, notch at the middle, shoulder), and each ray scales the rippled rings along it by 1 + its share of the depth, with shares 1 / 0.7 / −1 / 0.7. The depth is 0.9 at 100 % (tips reach 90 % further out, notches keep 10 % of their distance); above it tips and shoulders keep growing while notches never go below 10 %. Corners only move along their own ray and stay on the same side of the centre, so Petals is one-to-one at any depth and never folds on its own; beyond the last ring the same scaling continues, linear in each slice, so the plane stays continuous. Ripple uses no randomness.
- **Curl** (off by default; `src/geometry/curl.ts`) swirls each letter around the centre of its ink box. The mesh is Ripple's: concentric regular polygons with **Sides** (3–12, default 8) sides and a flat side at the bottom, rays through the corners, each cell split into two triangles; the outermost of the **Rings** (2–12, default 6) lies half the ink box's height from the centre (at least 5 % of the em), so the letter's top and bottom sit on it. Instead of moving out and in, every ring turns as a whole about the centre, so it stays a regular polygon, and the outline bends only at ring sides, rays, and cell diagonals inside the rings. With **Pin top and bottom** on (the default), the outermost ring and everything beyond it stay put and the rings turn more toward the centre; off, the centre stays put, the rings turn more toward the outside, and everything beyond the outermost ring turns with it as one rigid piece. Neighbouring rings turn by the same step relative to each other. At **Amount** 100 % (−400 % to 400 %, default 60 %; below 0 % it turns clockwise) the step is 90 % of the largest that keeps every triangle the same way round, worked out for the Sides and Rings in use with the cell diagonals laid along the swirl (whichever diagonal direction lets the rings turn further), so up to 100 % either way Curl is one-to-one. The whole swirl then turns from about 30° with 3 sides to well over a full turn with 12 sides and many rings. Beyond 100 % either way, triangles flip and the letter folds (see Folds). Curl uses no randomness. Checked on the Latin glyphs of Arial, New York, and Georgia at 12 settings each (±30–100 %, pinned and whole, on Geometry settings, and with the other effects): no new crossing, no weakened contour, and every glyph exports.
- **Wind** (off by default; `src/geometry/wind.ts`) draws the letters out along the wind. Every point moves toward **Direction** (0° right, 90° up) by **Strength** (0–800 %, default 30 %) × its band's gust × its distance downwind of the glyph's upwind edge (taken from the ink box), so that edge stays put and stays crisp and the outline is pulled further the further downwind it lies. Bands run with the wind, one **Gust size** apart (6–50 % of the em, default 12 %), anchored at the glyph origin, so with a level wind every letter on a line shares the same gusts; each band's gust is a share of the full strength from the seed, between 1 − **Gustiness** (0–200 %, default 60 %) and 1, and no point moves more than 4 em. The bands are cut into square cells, each split along a diagonal chosen by the seed. Up to 100 % Gustiness, gusts are never negative and the movement only grows downwind, so every triangle is stretched along the wind, never squeezed (its area ratio is at least 1): Wind is one-to-one at any strength. Above 100 % some gusts blow backwards and tear the letter (see Folds).
- **Spikes** (off by default; **Use spikes**; `src/geometry/spikes.ts`) runs last and shoots a few anchors of each letter out into the canvas, so their edges become long, straight spikes. Only anchors on the letter's outside jump (contours that do not lie inside another contour, so counters never spike), each away from the ink: along the mean of its two edges' outward normals, turned to either side by up to **Spread** (0–100 %, default 50 %) × 90°, so 0 % is straight out from the outline. **Anchors** (1–12, default 3) is how many anchors of each letter jump, and **Reach** (0–200 % of the em, default 60 %) how far: each goes a seeded 35–100 % of it. **Width** (0–100 %, default 30 %) is how wide each spike is where it leaves the letter, as a share of the anchor's shorter edge: two new anchors on the anchor's edges, that far from it, keep the rest of each edge in place. At 0 % the spike is a thin needle (at least 2 %); at 100 % the jumping anchor pulls its whole edges along, a wide wedge. Which anchors jump, in which direction, and how far all come from a hash of the shared **Seed** and each anchor's position, so the same seed gives the same spikes and **Next variant** moves them; driven by Sound (Beat → Seed) they jump somewhere new on every beat. Every edge stays straight. A spike may cross the letter or another spike, so whenever an anchor jumps the outlines are merged into one clean outline, the same merge as when an effect folds (see Folds), and the letters still export. Statistics: **Spikes** (how many anchors jumped) and **Longest** (the longest jump, in font units). Checked on the Latin glyphs of Arial, Georgia, and New York at 4 Geometry settings (default, Tolerance 1, Anchor spacing 5, and a heavy combination) and 6 Spikes settings (1–12 anchors, Reach 30–200 %, Spread 0–100 %, Width 0–100 %), with and without Noise and Wind, at 3 seeds (141 combinations): no crossing in the output and no export failure; the farthest point lies about 3 em from the glyph's origin. A glyph takes 0.2–0.9 ms at the default Geometry settings, up to about 6 ms with dense anchors plus Noise and Wind.
- **Folds** (`src/geometry/overlaps.ts`): once any effect goes beyond 100 %, the letters may fold onto themselves, so no effect checks its contours, and at the end the glyph is redrawn as the outline of exactly what the nonzero rule fills. The same merge runs after Spikes whenever an anchor jumps. Snap rounding on a grid of whole font units turns every vertex and every crossing into a grid point and routes each edge through every grid point whose cell it passes, so rounded edges meet only at their ends; each region then gets its winding number, and the edges between ink and no ink are joined into contours (outer ones counter-clockwise, holes clockwise; where two inked regions touch at a point, each keeps its own contour). Contours under 4 square units or under one unit wide on average are dropped. Only straight edges come out, with new vertices only where outlines crossed (plus detours under half a unit), and the result always passes export. The intro of the tab then shows how many crossings were merged and slivers dropped (**Crossings merged**, **Slivers dropped**), and does so whenever Spikes is on. Measured on the Latin glyphs of Arial, New York, and Georgia at 16 folding settings each: no crossing and no export failure; whole fonts at the maxima write and read back as OTF (except Arial with all three effects at once, which exceeds the 1,000,000-point limit); every result within 100 % is unchanged.
- Statistics, per effect: largest move and the number of creases added (Spikes: how many jumped and the longest jump); a warning if a contour needed a weaker effect or a glyph was left without it.
- Measured on the Latin glyphs of Arial, New York, and Georgia, each effect alone, on top of Geometry settings (fine and coarse flattening, Anchor spacing 5, angle lock, grid, Distortion 80, Random anchors, and a heavy combination), and all three together (78 font and setting combinations): no new crossing within or between contours, no contour weakened, and every glyph exports. Curve-like runs that need a crease remain only in New York (7 glyphs across 6 combinations), all where two parts of the outline are less than one unit apart. At their defaults Noise and Ripple each add about 30 vertices per glyph (about 80 at the smallest facet, 100 at the shortest wavelength) and Wind about 10; each roughly doubles the geometry time, all three together five to seven times (about 0.5 ms per glyph). Across 19,440 random combinations of Geometry, Noise, Ripple, and Wind settings on the three fonts, nothing crosses, no contour is weakened, and every glyph exports.

## Export

Open **Export…** from the top-right corner of the header. Nothing is downloaded until you press a download button. Every export uses the same final polygons as the canvas.

### SVG and PNG

- **SVG — main view** (default) and **PNG — main view** export the canvas: its size, the text placed by the Typography settings, and the Color settings. With **Transparent background** on (Color tab) the background is left out, for SVG and for PNG with transparency; this applies to the preview look too. The SVG is width × height px; the PNG is that times the **Canvas size** multiplier, rendered from the same SVG.
- **Export the preview look** (checkbox, off by default) exports the bottom-right preview instead: its colours (swapped when **Invert** is on) on a solid background, with its **Blur**. The blur is converted from preview pixels to font units and then to canvas pixels, so it keeps its size relative to the letters at any resolution; in SVG it is an `feGaussianBlur` filter on an untransformed group.
- Each glyph is one path in its own font units (y up, so outline coordinates keep full precision), placed with `translate(…) skewX(…) scale(1 −1)` inside a group that scales font units to canvas pixels. Paths use only `M`, `L`, and `Z` with `fill-rule="nonzero"`; contour order and direction are kept. Kerning, tracking, and line breaks match the canvas. Missing characters are blank advances, named in an XML comment.
- **Coordinate precision** 0–4 decimal places. Rounding is checked and repaired as for the font file (below); if a contour would still collapse, flip, or cross itself, the export stops and asks for a higher precision.
- Text in `<title>` / `<desc>` is XML-escaped; file names use only ASCII letters, digits, `.`, `-`, and `_`.

### Font file

- Format: **OpenType with CFF outlines (`.otf`)**, written with opentype.js (fontkit can only read fonts). Loaded only when you build a font.
- Glyph set: the current glyph, the characters in the text, or all mapped characters (up to 5000 glyphs and 1,000,000 outline points — very dense settings such as Anchor spacing 1, or every Experimental effect at its maximum, reach the point limit with a whole font, and the build stops with a message), plus a `.notdef` box. A glyph more than 32,767 units across is left out and named, as is one with coordinates beyond ±32,767. Every glyph goes through the same pipeline and cache as the canvas.
- Naming: family and style (printable ASCII). The default family adds "Poly" (and drops a leading ".", which hides a font from menus). The PostScript name is `Family-Style` without spaces or reserved characters, at most 63 characters; the unique ID is `1.000;None-Curve;<PostScript name>`. If the source's SIL OFL copyright or license reserves a font name ("Reserved Font Name") and the family name contains it, the dialog warns that a modified version must be renamed.
- Kept: character mapping, advance widths, contour order, counters, units per em, ascender, and descender. Side bearings follow the final polygon. Contours are written in the CFF direction (outer contours counter-clockwise; a glyph whose largest contour runs clockwise, as in TrueType sources, is reversed as a whole).
- Copied from the source: OS/2 weight and width class, style bits (`fsSelection`, kept consistent with head `macStyle`), embedding permissions (`fsType`), panose, family class, sub- and superscript and strikeout metrics, typo ascender / descender / line gap, x-height and cap height; the hhea line gap; the post italic angle, underline position and thickness, and fixed pitch. The Windows ascent and descent are the source's, raised if the new outlines reach further (Windows clips outside them). Name records copied: copyright, trademark, manufacturer, designer, vendor and designer URLs, license, and license URL; the description says the outlines were rebuilt with None-Curve. Entries the source lacks are left out instead of written as blanks. The CFF FontBBox is the real bounding box. Fields the writer (opentype.js) cannot set — hhea line gap, head `macStyle`, CFF FontBBox — are patched into the finished file (`src/export/sfnt.ts`), which is then re-checksummed.
- Rounding (`src/export/quantize.ts`): each contour is rounded to whole units, then repeated points, zero-length edges, and points on a straight line between their neighbours (including back-and-forth spikes) are removed. It must keep at least three points, its direction, and non-zero area, and gain no new self-crossings. A crossing counts as new only where the unrounded contour neither crossed itself nor ran within two units of itself — outlines that already overlap (common in fonts), or whose parts nearly touch, cannot avoid that at whole units, and the difference is below one unit. Rounding crossings are first repaired by removing one of the vertices involved; failing that, the contour is simplified very slightly (0.5–2 units) and rounded again. A collapsed contour smaller than 4 square units, or narrower on average than one unit (twice its area over its perimeter — a sliver that strong Experimental effects can squeeze out of a stroke), is left out on its own. Each rounded contour must also sit against the glyph's other contours as before; a new crossing between two contours is accepted only where both already ran within two units of each other, and a repair that would push a contour into another is passed over for the next attempt. Contours are rounded one after another, so if one leaves a neighbour no room, the glyph is rounded again in the reverse contour order. Crossing checks sweep segments sorted by x, so contours with thousands of points (Anchor spacing 1) stay fast. Measured on New York and Arial, no glyph is left out at the default settings, with Squaring at Square / All contours, with Anchor spacing 1, or with Distortion 40 (before: 42 New York glyphs at the defaults, including every "a", and 26 % with Square / All).
- **Build & verify**, then **Download .otf**. The file is reopened with fontkit and compared glyph by glyph (signature, family name, glyph count, every mapping, every advance, every contour point and direction), then loaded through the browser's font engine (`FontFace`, OTS sanitizer). If any check fails, no download is offered. Glyphs that cannot be stored safely are left out and listed, with a note that a font stores whole font units (no precision setting applies).
- Not included: TTF / WOFF / WOFF2 output; kerning, ligatures, and other OpenType layout features; hinting; variation axes (a variable font exports the instance shown on the canvas); glyphs reachable only through layout features; characters above U+FFFF. Coordinates are rounded to whole font units.

## Sound

`src/sound/`, shown in the **Sound** tab (`src/components/SoundControls.tsx`); plan: [docs/SOUND_PLAN.md](docs/SOUND_PLAN.md). Phase 1 plays or listens, measures, and shows meters. Phase 2 lets the features move the sliders of the Geometry and Experimental tabs while a file plays or the microphone listens. Phase 3 is built in part: the three seeds are targets that jump with the sound, so every anchor lands somewhere new; Beat and Kick are features that a mapping can follow; picking a target switches on what it needs; and ten presets set the letters up and fill in the mappings. Phase 4's Pitch and Balance are built too, among 20 features in all. Step mappings (Allowed directions, Sides, Rings) are still to come in phase 3.

- **Sources:** **Off** (default), **File** (Choose file, Play / Pause, Loop, Position), and **Microphone** (Start listening / Stop listening; choosing it only shows these, and the microphone opens only when you press Start listening). While the microphone listens, the tab shows **Listening** and the status bar **Microphone on**.
- **Meters** (the **Levels** group): one compact line per feature (label, bar, number) under six small group headings, **Loudness**, **Bands**, **Narrow bands**, **Tone**, **Rhythm**, and **Stereo**, each with an ⓘ that explains its meters in plain words. The numbers show Level in dB, Pitch in Hz, Balance as the side it leans to ("L 40", "R 40", or "C" within 5 % of the centre), and every other feature in percent; "—" with nothing to read. Balance's bar fills from the centre, to the left or to the right. **Beat** and **Kick** are pulse bars that jump to full on each onset and fall back with **Smoothing**; they replace the earlier lights. Each bar is a `role="meter"` (Balance −100 to 100) whose spoken value says the same ("40 percent left", "Centre", "No reading"). The meters are written to the DOM from a per-frame callback, with no React state per frame: the bars every frame, the numbers at most about 10 times a second, the spoken values at most 4 times. The bars move without transitions, so they look the same with `prefers-reduced-motion`.
- **Mappings** (between Levels and Analysis):
  - **Drive letters:** sound moves the letters only while this is on and a file plays or the microphone listens. It is on at the start, unless the system asks for reduced motion (`prefers-reduced-motion`): then it starts off and the tab says "Off because your system asks for reduced motion." (the note is also the switch's description). Turning reduced motion on during the visit switches it off too; turning it off leaves the switch as it is.
  - **Preset** and **Load** (`PRESETS` and `presetSettings` in `presets.ts`): ready-made set-ups to start from, with an ⓘ that says what Load resets and lists each preset with one line. Choosing in the list only selects (it starts on Flicker), so moving through it with the keyboard replaces nothing. **Load**:
    1. resets every Geometry and Experimental group (Curve flattening, Random anchors, Squaring, Anchors, Grid & angles, Distortion, and the Experimental effects) to its defaults, keeping the three seeds; Typography, Color, the canvas, and the Sound tab's source, Drive letters, Sensitivity, and Smoothing are left alone;
    2. sets the preset's start values (only what differs from the defaults), as one parameter update per group that changed;
    3. replaces every mapping with the preset's rows, and clears the earlier row notices;
    4. shows a status line under the Preset row: "Loaded Flicker.", then "Turned off Noise and Ripple." for the Experimental effects it turned off, "Turned off Random anchors." when it did, and "Other Geometry and Experimental settings back to defaults (seeds kept)." when any other setting the preset does not set went back to its default. It stays until the next Load or until another preset is chosen in the list.

    So a preset always starts from the same letters, whatever was set before, and its rows need nothing switched on; should one still need something, it is switched on as when its target is picked by hand, in row order, with the row's notice. Picking a target by hand still only switches on what it needs (below); it resets nothing. The presets, with Depth (or Rate, on a seed) in brackets, then the start values:
    - **Flicker:** Level → Distortion · Noise amplitude (+90 %), Kick → Distortion · Noise amplitude (+30 %), Beat → Distortion · Seed (Rate 100 %). Start: few anchors on (see [Vertex distortion](#vertex-distortion)), Noise amplitude 2, Normal bias 90 %. The tiny amplitude keeps Distortion on, so the Seed row acts while it is quiet.
    - **Scatter:** Level → Random anchors · Randomness (+90 %), Level → Random anchors · Density (−9 %), Beat → Random anchors · Seed (Rate 50 %). Start: Use random anchors on, Density 10, Randomness 5 %.
    - **Pixel:** Bass → Grid & angles · Grid size (+70 %), High → Anchors · Anchor reduction (+40 %). Start: Snap to grid on.
    - **Low poly:** Level → Curve flattening · Tolerance (+70 %), Noisiness → Anchors · Anchor reduction (+50 %). Start: Merge joined curves on, so a large Tolerance reaches whole bowls.
    - **Block:** Swell → Squaring · Amount (+90 %), Kick → Squaring · Amount (+40 %). Start: the defaults.
    - **Jitter:** High → Distortion · Noise amplitude (+60 %), Brightness → Distortion · Noise frequency (+30 %). Start: Noise amplitude 2 (so the Noise frequency row acts while it is quiet), Noise frequency 20.
    - **Facet:** Level → Curve flattening · Segments per curve (−15 %), Kick → Curve flattening · Segments per curve (−15 %), Pitch → Curve flattening · Segments per curve (+20 %). Start: Mode Fixed segments, Merge joined curves on, Segments per curve 6.
    - **Bloom:** Kick → Ripple · Amount (+15 %), Bass → Ripple · Petals (+30 %). Start: Use ripple on, Amount 30 %.
    - **Flare:** Beat → Seed (Rate 100 %), Level → Spikes · Reach (+40 %), Kick → Spikes · Anchors (+20 %). Start: Use spikes on, Anchors 1, Reach 0 % em (no spikes while it is quiet).
    - **Gale:** Level → Wind · Strength (+10 %), Pace → Wind · Gustiness (+25 %). Start: Use wind on, Strength 0 %.
  - Up to 8 rows (`MAPPING_LIMITS.maxMappings`), each with a **Feature** (the 20 features, grouped as the meters are), a **Target** (grouped Geometry / Experimental, named "Section · Label", such as "Distortion · Noise amplitude", or just "Seed" for the Experimental tab's seed), a **Depth** (−100 % to +100 % in steps of 5 %), an on/off switch ("Use mapping 1", "Use mapping 2", …), and a remove button ("Remove mapping 1", …; it hands keyboard focus to the next row's remove button, else the previous one's, else Add mapping). On a seed the Depth slider reads **Rate** (0–100 % in steps of 5 %, with its own ⓘ; see Seeds below), and a negative Depth turns positive when the row switches to a seed. **Add mapping** adds Level → Distortion · Noise amplitude at +50 % (once that target is used, the first target no row uses yet that already acts, else the first unused one) and switches on what it needs, as picking a target does; with 8 rows it adds nothing (it stays focusable, `aria-disabled`) and the tab says "Up to 8 mappings." Mappings are not saved: like the sliders, they last for the visit.
  - **Switching on what a target needs:** picking a target that does nothing with the current settings changes what it needs (switches its step or effect on, sets a Mode, or turns Random anchors off for the Curve flattening sliders) and says so under the row, for example "Turned on Ripple.", "Set Noise amplitude to 40.", or "Turned off Random anchors. Set Mode to Adaptive." (the rules are in the table below). The notice is a status line that stays until the row's target changes again or the row is removed. Switching a row to another target, or removing it, never switches anything off. With the keyboard, moving through the Target list (arrow keys, or typing on the closed list) switches things on only on Enter or when focus leaves the list, so the targets passed on the way change no setting; a pick with the mouse switches them on at once.
  - Whenever a row's target does nothing right now (for example, because its setting was turned off again later), a note under the row says why instead of the notice (the notes are in the table below; the note is also the Target select's description). An **Enable** button beside it ("Enable, mapping 1", …) makes the same changes as picking the target, shows the notice, and hands keyboard focus to the row's Target. Until then the row moves nothing.
- **Targets** (`TARGETS` in `mapping.ts`), in panel order: every continuous slider of both tabs, with that slider's own range, step, and scale, and the three seeds, as whole numbers in the seed field's own range (0–999,999).
  - Geometry: Curve flattening Tolerance, Segments per curve, and Corner angle; Squaring Amount; Anchors Anchor spacing and Anchor reduction; Grid & angles Grid size; Distortion Noise amplitude, Noise frequency, Normal bias, and **Seed**; Random anchors Density, Randomness, and **Seed**.
  - Experimental: Noise Amount, Facet size, and Turn; Ripple Amount, Wavelength, Sides, Center X, Center Y, Fade, and Petals; Curl Amount, Rings, and Sides; Wind Direction, Strength, Gust size, and Gustiness; Spikes Anchors, Reach, Spread, and Width; and the shared **Seed**.
  - Not targets: switches and choices (Mode, Break merged curves at, Applies to, Allowed directions), and Distortion's few anchors mode. While it plays, sound never turns a step on or off; only picking a target, Add mapping, or Enable switches one on, once, and Load resets the settings and sets the preset's own (above).

- **Modulation** (`modulate`, pure): for each slider target with at least one enabled mapping whose Depth is not 0 and whose step or effect is on, the live position is the slider's position (0–1 along the slider as drawn) plus the sum of Depth × feature over those mappings, clamped to 0–1, then converted back to a value and rounded to the slider's step. Positions are measured along the slider, so the log-scaled Tolerance moves evenly along its slider, not evenly in font units. Mappings on one target add up before clamping. Balance is the only two-sided feature (−1 to 1): at a positive Depth it moves a slider down for sound on the left and up for sound on the right; every other feature runs 0–1. When nothing contributes (no mapping, all off, Depth 0, every feature at 0, no seed moved on, or every target inactive), the slider values themselves are returned (the same object), so the letters go back exactly. Every live frame is therefore a parameter set the sliders and seed fields can produce (no new geometry, no tweening between frames).
- **Seeds** (jump targets; `JumpTracker` in `jumps.ts`, pure): a mapping to a seed takes no part in the sum above. Instead the seed moves on by one on each jump (past 999,999 it wraps to 0), so every anchor (Distortion, Random anchors) or every fold, gust, and spike (Experimental) lands somewhere new; with Distortion's few anchors (Flicker), a new few anchors of each letter move instead. The row's **Rate** sets how often; the sign of Depth is ignored.
  - With **Beat** or **Kick**, the seed counts onsets: Rate 100 % moves on at every onset, 50 % at every other one, 25 % at every fourth.
  - With any other feature, it jumps at up to 4.8 times a second × Rate × the feature's value (Balance on either side). A gap of more than 100 ms between frames counts as 100 ms, so a stall releases no burst of jumps.
  - **Flash limit:** at most 6 jump frames in any 1.25 s (seeds that jump in the same frame count once), that is 3 flashes a second, counted like the sliders' flash limit below. A jump beyond it is skipped, not put off.
  - Jumps are counted only while Sound can drive the letters and the seed's target acts. Pausing, stopping, or turning Drive letters off returns every seed to its field's value (exact restore), and playing again starts from there; the flash window is kept, and the return counts in it, so a quick pause and play cannot let a second burst through. A seed no longer driven (its mapping off, removed, or moved to another target) goes back to its field's value on the next frame.
  - While a seed is driven, a small live number appears next to its field (`src/components/LiveSeed.tsx`, with the tooltip "Live seed", hidden from screen readers, updated at most about 15 times a second), and the Distortion and Random anchors statistics show the live seed. The field keeps its own value.
- **Live scheduling** (`useLiveParams`, called once in `App.tsx`): Sound drives the letters while a file plays or the microphone listens, Drive letters is on, and a mapping acts on an active target (a slider or a seed). Every measured frame first moves the driven seeds on (when they jump) and is then modulated, but a new live parameter set goes to the geometry only when it differs from the last one sent, no geometry request is in flight, and at least 33 ms have passed. So the frame rate follows the cost, capped at 30 fps. The canvas then shows the newest shapes, each live frame only once all its glyphs have arrived (`geometryClient.ts` holds a live frame's results until its request is done), so a frame never mixes two parameter sets. The snap grid on the canvas and the preview follows the live Grid size, and the status bar's View line describes the parameters shown. The Export dialog keeps using the slider values, and so do **Fit text** and **Free** (Typography), which measure the slider letters (`sliderScene` in `useDerivedGeometry.ts`); dragging free text uses the letters as shown, so they stay where they are dropped. When Sound stops driving (paused, Off, Drive letters off, or no mapping acts), the canvas goes straight back to the slider values and seed fields, and the markers and live seeds disappear.
- **Flash limit** (`FlashLimiter` in `live.ts`, `LIVE_LIMITS.maxFlashes` and `flashSwing`; the seeds have their own, above): a driven slider may turn back by 10 % or more of its travel at most 6 times (3 flashes) in any second, counted on the slider positions as shown (after rounding to the step) over 1.25 s, so frames that reach the screen a little later still keep to it. A further turn keeps that slider's last value until the window has passed. Held values are values the slider produced a moment earlier, and the markers and Freeze use the same values as the screen.
- **Live cache:** live requests carry `live: true` (`protocol.ts`). The worker keeps their results in a second, smaller cache per font (600 glyphs or 200 000 points; `glyphGeometry(…, live)` in `cache.ts`), and the page keeps the results of only the last two live parameter sets (`geometryClient.ts`), so a song never evicts the results of normal editing.
- **Live markers** (`src/components/LiveMarker.tsx`): each target slider is wrapped in a `.live-slider` span; while Sound drives it, a thin accent line over the track shows its live position, lined up with where the thumb would be. Markers update at most about 15 times a second and are hidden from screen readers. The sliders keep their own values. (A seed shows its live number instead; see Seeds above.)
- **Frame rate:** while Sound drives the letters, the tab and the status bar (before **Microphone on**) show "Live · N fps", where N is how many live results per second the geometry keeps up with (1000 ms ÷ the smoothed time from sending a frame to its last result, at most 30), so it holds steady while the live values stay the same. Below 8 fps for 2 s, the tab warns "Too slow to follow the sound: try fewer effects or a shorter text."
- **Freeze** (available while Sound drives the letters; `aria-disabled` otherwise, so it keeps keyboard focus): writes the live values on screen into the sliders and the live seeds into the seed fields (one parameter update per changed group) and pauses the sound (pauses the file or stops listening), so the frozen look stays on screen and can be exported. Pressed while the letters match the sliders (for example between two drum hits), it only pauses. Exports (SVG, PNG, OTF) always use the slider values, never live audio; while Sound drives the letters, the Export dialog says so and points to Freeze.
- **Analysis:** **Sensitivity** (−24 to +24 dB, added to the input before measuring), **Smoothing** (the release time constant, 20–1000 ms, default 150 ms; it also sets how fast the Beat and Kick pulses fall back), and **Reset sound**.
- **Test track:** `test-audio/sound-test.wav` (42 s, 16-bit stereo, 44.1 kHz, fully synthetic) has one section per reading. Centred, the same in both channels: kick only (0–4 s), kick and hi-hats (4–8 s), kick and a rising chord (8–12 s), silence (12–15.5 s), a full mix fading out (15.5–21.5 s), and hi-hats only at 16 a second (21.5–26 s). Then a single-note melody, one note every half second, A2 → A5 and back (26–32 s, for Pitch); hi-hats switching hard left and hard right every half second over a quiet bass in the centre (32–38 s, for Balance); and wide, unrelated noise in the two channels, fading out (38–42 s, for Width).
- **Measured:** measuring one frame (`FeatureExtractor.process`) takes about 90 µs at 48 kHz, against about 35 µs before the new features. In the geometry worker (Node, Arial, the default text's 24 distinct glyphs), one seed jump recomputes every glyph in about 2–3.5 ms; live slider frames cost what they did (Level → Distortion · Noise amplitude about 2.4 ms; Level → Distortion · Noise amplitude, Level → Noise · Amount, and Low → Ripple · Petals together about 12 ms; with every Experimental effect on, 37–41 ms, 24–27 fps). On the test track, Beat → Distortion · Seed jumps 1.89 times a second on the kick-only section (the beat rate) and is held to about 4.3–4.5 times a second on 8 beats a second.

Modules:

- `types.ts`: the shared types (`FeatureFrame` with every feature, `StereoSamples`), `SOUND_LIMITS` (the measuring limits and the file size limit below; the analyser's dB range and the position update rate are set in `engine.ts`), `SILENT_FRAME`, and the initial state.
- `features.ts`: `FeatureExtractor`, pure (no DOM, no Web Audio), so it can be tested on synthetic signals. Each frame it takes the analyser's spectrum (fftSize / 2 bins in dBFS; bin k is centred at k × sample rate / fftSize), its time-domain samples (the channels mixed down), and the left and right channels' samples, and it allocates nothing but the frame it returns.
  - **Level:** 20 log10 of the RMS of the samples with their mean (DC offset) removed, plus Sensitivity; −60 dB reads 0 and 0 dB reads 1. Below −60 dB after Sensitivity the frame counts as silent: every continuous feature falls to 0 (Pace as the beats leave its window) and no onset fires.
  - **Swell:** Level, smoothed with its own time constants, 300 ms while rising and 2 s while falling, whatever Smoothing says.
  - **Bands:** **Low**, **Mid**, and **High** (20–250 Hz, 250–2000 Hz, 2000 Hz – Nyquist) and the narrow bands **Sub** (20–60 Hz), **Bass** (60–250 Hz), **Low mid** (250–500 Hz), **High mid** (2–4 kHz), **Presence** (4–6 kHz), and **Air** (6–20 kHz, or up to Nyquist): the energy (sum of squared linear magnitudes) of the bins centred in the band, in dB plus Sensitivity. Each of the nine bands keeps its own running maximum that follows a rise at once and otherwise halves in energy every 3 s. A band reads 1 at its maximum and 0 at 40 dB below it or at −68 dB, whichever is higher. −68 dB is the silence threshold in band terms, because the Blackman-windowed spectrum puts band energy about 8 dB under the RMS level. Hiss below the silence threshold therefore reads 0 even while another band is loud.
  - **Brightness:** the spectral centroid (magnitude-weighted mean frequency of the bins from 20 Hz to 20 kHz, so ultrasonic hiss at high sample rates does not count) on a log scale, 100 Hz → 0, 8 kHz → 1.
  - **Noisiness:** the spectral flatness (geometric over arithmetic mean of the power) of the bins from 20 Hz up to the frame's real bandwidth, in dB: −24 dB reads 0 and −3 dB reads 1. The real bandwidth ends at the highest bin within 60 dB of the loudest one (at least 1 kHz, at most 20 kHz), because lossy encoders cut the top of the spectrum (often at 16 kHz), and the empty top made white noise read 0.02 instead of 1. Measured on synthetic signals: tones and chords read 0, a sawtooth at most 0.26, hi-hats about 0.85, pink noise 0.82–0.86, and white noise 1; the same within 0.06 when low-passed as lossy encoders do.
  - **Pitch:** the fundamental by YIN on the samples decimated to at most 24 kHz (the mean of each run): the first lag between 1/1760 s and 1/55 s whose cumulative-mean-normalised difference falls below 0.15, walked on to its local minimum and refined by a parabola. 55 Hz reads 0 and 1760 Hz reads 1, on a log scale (5 octaves). A frame with no such lag (unvoiced: noise, drums) holds the last note; silence sends it to 0. It follows with 30 ms both ways, and falls to 0 on silence with the release time.
  - **Smoothing:** each continuous feature follows its target with a one-pole filter, a = 1 − exp(−dt / τ), where τ is 10 ms while rising and Smoothing while falling; Swell and Pitch have their own time constants (above), and Balance follows with Smoothing both ways. The first frame after a reset jumps straight to the target.
  - **Beat / Kick:** spectral flux, the sum of the rises of the compressed magnitudes ln(1 + 1000 g m), where g = 10^(Sensitivity / 20), over the bins from 20 Hz up (Kick: 20–150 Hz only). An onset fires when the flux exceeds the median of the last second × 1.5 (Kick: × 3, because its few bins make steady noise jumpy) plus a small fixed floor (`fluxFloor`, `kickFluxFloor`), and also exceeds half the last onset's flux, decaying with a 120 ms time constant (so the noisy tail of a snare, clap, or reverb does not fire again); at least 100 ms after the previous one, in a frame that is not silent, and once at least 250 ms of history has built up (so none fires right after a reset). Every Kick also counts as a Beat (within Beat's 100 ms gap), so a bass drum under broadband sound still sets off Beat. Onsets are judged at most about 60 times a second (on faster displays, against the spectrum of about 1/60 s earlier), so the floors mean the same at any display rate. A gap of more than 500 ms between frames (a hidden tab) restarts the onset history but keeps the smoothing and the band maxima. The features **Beat** and **Kick** (`beatPulse`, `kickPulse`) are pulses: 1 on an onset frame, then falling exponentially with the release time.
  - **Change:** how far the full-band flux of the last judged frame rises above Beat's median of the last second, against the largest such rise lately (a running maximum that halves every 3 s like the bands' maxima), but never against less than `fluxFloor` or a quarter of the frame's compressed spectrum (the sum of the compressed magnitudes the flux compares); in silence it falls to 0. The median takes out the flux that steady noise always has, and the quarter keeps a steady sound's own jitter low however long it lasts: near 0 on steady sound, tones and noise alike (under 0.15 over 25 s of a 110 Hz sawtooth, a chord, or white or pink noise; a 55 Hz sawtooth's buzz beats against the frame rate and reads about 0.28), and high on attacks after quiet; an onset over loud noise shows only a little.
  - **Pace:** the Beat onsets in the last 2 s, as onsets a second, ÷ 8 (8 a second read 1).
  - **Balance:** (R − L) / (R + L) of the left and right RMS (DC offset removed), from −1 (left) to +1 (right). **Width:** the RMS of the side, (L − R) / 2, over the RMS of the mid, (L + R) / 2, clamped to 0–1: mono reads 0, unrelated left and right about 1. Both read 0 in silence and without the two channels. A file is measured in stereo; a microphone is usually mono, so it reads centred with no width.
- `engine.ts`: `SoundEngine` and the page's single instance, `getSoundEngine()`.
  - One `AudioContext`, created on the first user gesture, resumed whenever playback or listening starts, and suspended after 2 s with nothing playing or listening. Sources feed a 20 Hz high-pass that removes DC offset from what is measured (not from playback). After it, one `AnalyserNode` hears the channels mixed down (FFT size 2048 at 44.1 and 48 kHz, doubled at 88.2 and 96 kHz so the window stays about 43 ms; no smoothing of its own; −100 to 0 dB), and a stereo branch gives Balance and Width: a gain node that makes exactly two channels by the speaker rules (mono becomes identical left and right, more channels mix down), a channel splitter, and one more analyser for each side (same FFT size, no smoothing). The extractor is reset on every source change and new file.
  - **Reading a frame:** the three analysers are read one after another, and the audio thread can render in between (in Chrome up to one frame in 300), leaving one block a little behind, which would make a mono source read as wide for that frame. So each frame checks that the mixed-down samples are the mean of the left and right ones and reads again, up to 3 times; when no read agrees, Balance and Width use the last left and right that did. A source of more than two channels never agrees (the analyser mixes it down by other weights), so after one held frame its reads are used as they are.
  - **File:** an `HTMLAudioElement` created in code (not in the page) plays an object URL (`URL.createObjectURL`) through a `MediaElementAudioSourceNode` into the measuring path and the speakers. Files over 512 MB, and empty (0-byte) files, are refused without being read. The position updates from `timeupdate` (about 4 times a second), never per frame.
  - **Microphone:** `getUserMedia` with echo cancellation, noise suppression, and automatic gain off, connected to the measuring path only, never to the speakers, so there is no feedback. It opens only from Start listening, never by choosing a source. It needs a secure page (https or localhost). Stop listening, switching source, an unplugged device, and closing the page (`pagehide`) stop every track.
  - Features are measured every animation frame while a file plays or the microphone listens; when that stops, one silent frame resets the meters. After 3 s without sound the state reports it ("No sound detected.").
  - Errors: `unsupported`, `decode`, `empty`, `too-large`, `permission`, `no-device`, `device-busy`, and `insecure`, each with its own message in the tab.
- `useSound.ts`: `useSoundEngine` (actions), `useSoundState` (`useSyncExternalStore`; re-renders on state changes only, not per frame), and `useSoundFrames` (a callback for every measured frame).
- `mapping.ts`: `FEATURES` (each with its label, its group, and whether it is two-sided or counts onsets on a seed), `FEATURE_GROUPS`, `featureById`, and `featureValue`; `TARGETS` and `targetById` (each target with its kind, `slider` or `jump`, its range, step, `get` / `set`, `toSlider` / `fromSlider`, `inactive`, the reason it does nothing right now, and `activate`, the changes that make it act and their notice); `applyPatches`, `seedAfter`, `Mapping`, and `modulate`. Pure: no React, DOM, or Web Audio.
- `jumps.ts`: `JUMP_LIMITS` and `JumpTracker`, which counts the driven seeds' jumps from the measured frames and keeps them to the flash limit. Pure: no React, DOM, or Web Audio.
- `mappingStore.ts`: the mappings and Drive letters, a small store outside React state read with `useMappingState` (it follows `prefers-reduced-motion` while the page is open; `replace` loads a preset's rows); `MAPPING_LIMITS`.
- `presets.ts`: `PRESETS`, each with its name, the one line its ⓘ shows, its start values, and its mappings; and `presetSettings`, which gives what Load leaves: the settings (every Geometry and Experimental group reset, seeds kept, then the start values), the groups that changed, and the notice. Pure: no React or DOM.
- `live.ts`: `LiveScheduler` (frame timing and the seeds' jumps, testable through injected dependencies) and `FlashLimiter`; `useLiveParams` (the page's scheduler), `useLivePosition` (one target's marker; re-renders only when its rounded position changes), `useLiveSeed` (one seed's live value, for `LiveSeed`), `useLiveStatus` (driving, fps, slow, differs; re-renders only when one changes), `useLiveDriving` (driving only), and `freezeLive`.
- **Privacy:** no network. Files are read in the browser through object URLs and never uploaded; microphone sound is only measured, never recorded or played back, and the microphone is open only while listening.

## Development

Tech stack: Vite + React + TypeScript, with [fontkit](https://github.com/foliojs/fontkit) for reading fonts and [opentype.js](https://github.com/opentypejs/opentype.js) for writing them (both loaded on demand).


- State has three layers: document state and parameter state in `src/state/`, and derived geometry (never stored in the reducer) computed in the geometry worker and assembled by `useGeometry` (`src/state/useDerivedGeometry.ts`). Text and typography are deferred with `useDeferredValue` so typing stays responsive. While Sound drives the letters, `useLiveParams` (`src/sound/live.ts`) hands `useGeometry` live parameters instead of the slider values; Sound changes the parameters in the reducer (the sliders and seed fields) only on Freeze, on Load (which resets the Geometry and Experimental groups and sets the preset's start values), and when picking a target, Add mapping, or Enable switches on what a target needs. React components only render state and dispatch actions; geometry stays in `src/geometry/`.
- Conventions, such as an English-only UI and separate English / Chinese documents, are in [docs/BEST_PRACTICE.md](docs/BEST_PRACTICE.md).

## Deploy to GitHub Pages

- **Release branch:** `main`. `.github/workflows/deploy.yml` runs only on pushes to `main` (or a manual run on `main`); `develop` and `feature/*` never deploy.
- **Base path:** production builds use `/None-Curve/` (`pagesBase` in `vite.config.ts`). Update it if the repository is renamed. Files in a `public/` folder must be referenced through `import.meta.env.BASE_URL`.

1. In the repository, open **Settings → Pages** and set **Source** to **GitHub Actions**.
2. Merge into `main` and push (or run **Deploy to GitHub Pages** from the **Actions** tab with `main` selected). The workflow runs `npm ci`, `npm run build`, and publishes `dist/`.
3. The site is served at `https://<owner>.github.io/<repo>/`, i.e. `https://m1ingx1xx1.github.io/None-Curve/`.

## Roadmap: Sound

Phases 1, 2, and 4 are built, and phase 3 in part: the **Sound** tab plays a local audio file or listens to the microphone, shows live meters for 20 features in six groups (loudness, bands, narrow bands, tone with pitch, rhythm with the beat and kick pulses, and stereo balance and width), and lets up to 8 mappings move the Geometry and Experimental sliders and make the three seeds jump, so the anchors jump to new places on the beat. Picking a target switches on what it needs, and ten presets set the letters up and fill in the mappings to start from. Every frame is an ordinary, valid, straight-edged result, and **Freeze** keeps a moment for export (see [Sound](#sound)).

Planned from phase 3, **not implemented yet**:
- **Step** event mappings: on each Beat or Kick, the next of a few choices, such as Allowed directions (the angle step), Sides, or Rings.
- Measuring the live SVG redraw in the browser.
- Later: video recording.
